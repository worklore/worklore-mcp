## Other things a real client will trip over (seen in the source, not probed)

- **`add_note` without a token returns a bare HTTP 401** `{"error":"sign in required"}` (`server.py:172-173`). It has no JSON-RPC envelope and no `WWW-Authenticate` / protected-resource metadata. Clients will either throw or start an OAuth flow that has nowhere to go. A tool result with `isError: true` saying "sign in required" would be readable by the model. The same applies to the resources 401 in C1.
- **Exceptions other than `ValueError` aren't caught.** For example, `search_notes {"query":"x","limit":"abc"}` raises `ValueError`, which becomes `-32602`. But `"arguments": []` or `limit: null` raises `AttributeError`/`TypeError` inside `do_POST`, and the client gets a dropped connection instead of an answer. I didn't send these (no fuzzing).
- `limit` from `inputSchema` (1–50) isn't enforced: `limit: 0` silently returns no hits.
- The server issues an `Mcp-Session-Id` but never checks it, and it accepts batches even though it negotiates `2025-06-18`, which removed batching.
