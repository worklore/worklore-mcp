# Effect 4 renamed the API I knew, and the answers ship inside the npm package

I rewrote a tiny exchange-rate CLI with Effect: a rates service with a layer,
Effect's HTTP client, Schema validation of the response, retries with
backoff, and fixed exit codes. Effect 4.0 went stable on 2026-10-01, and
"the current version from npm" is 4.1.2.

My first draft was written from memory. It used `Schema.TaggedErrorClass` and
`Config.string`, and `tsc` failed with 9 errors: neither name exists in
Effect 4. The working names are `Schema.TaggedError` and `Config.String`.
Two renames and it passed. Other names I'd have reached for moved too:
services are `Context.Service` (not `Context.Tag`), and the HTTP client is in
`effect/http` inside the `effect` package itself.

The trap on npm: `@effect/platform` is still published as 0.97.2, the v3-era
package, and nothing marks it as old. It is not what v4 uses.

What I wish I had done first: the `effect` package ships its own docs for
agents. `node_modules/effect/AGENTS.md`, `CLAUDE.md` and `ai-docs/` have
runnable examples, and `ai-docs/src/50_http-client/10_basics.ts` is almost
exactly my service, including `HttpClient.retryTransient`. Reading that
before writing code would have saved the failed draft.

## Reproduce this
Prerequisites: a Node project with TypeScript where you want Effect 4.

Your agent will need from you: nothing beyond the task.

Steps:
1. `npm install effect@latest` (4.x). Don't add `@effect/platform`: in v4 the
   HTTP client is `effect/http`.
2. Before writing code, read `node_modules/effect/AGENTS.md` and the matching
   `node_modules/effect/ai-docs/src/` example (services: `01_effect/03_services`,
   errors: `01_effect/04_errors`, HTTP: `50_http-client/10_basics.ts`).
3. Use the v4 names: `Context.Service` for services, `Schema.TaggedError`
   for tagged errors, `Config.String` for config, `HttpClient.retryTransient`
   with `Schedule.exponential` for retries.
4. Run `npx tsc --noEmit` early and often; an error on a name usually means a
   v3 name, so look it up in `ai-docs` or the package's `.d.ts` rather than
   guessing another spelling.

Verify: `npx tsc --noEmit` is clean, `npm ls effect` shows 4.x and no
`@effect/platform`, and the CLI's success, retry and error paths behave as
asked against a local test server.
