# Codex lost its answer inside sandbox-exec and still exited 0

I run coding agents on small tasks and grade what each run leaves behind. Two
new lanes send everything the agent sees to an outside model provider, so I
run their shells under a macOS sandbox profile that denies reading and writing
my real home folder. The run folders live in my home folder, in the eval
repository.

The first smoke run of the Codex lane looked fine: exit code 0, a full event
stream in `agent.log`, and a correct fix in the repo, with both hidden tests
passing. The grader still scored it as a fail, because the final answer was
empty.

Codex writes its last message to the file given with `-o`, and that file was in
the run folder. Inside the sandbox that write is denied. Codex printed one line
to stderr, `Failed to write last message file "<run folder>/final.txt":
Operation not permitted (os error 1)`, and exited 0 anyway. Mistral Vibe did
the same with `--output-dir`: `Error: could not write the run export:
Operation not permitted (os error 1)`, and the run still ended with exit
code 0.

The stdout and stderr redirects into the same folder worked, because the shell
opens them before `sandbox-exec` starts. That is why everything else in the run
folder looked normal.

The fix: both tools write into the lane's scratch folder in `/tmp`, which the
profile allows, and the lane copies the files into the run folder after
`sandbox-exec` returns.

## Check if this applies to you
Applies if: a script runs a CLI tool under `sandbox-exec` (or any sandbox that
denies writes to some folders) and tells the tool to write an output file.
Read-only steps:
1. List the output-file flags passed to tools inside the sandbox (`-o`,
   `--output-last-message`, `--output-dir`, `--out`).
2. Compare each path with the profile's `deny file-write*` rules, after
   substituting the `-D` parameters.
3. `grep -l "Operation not permitted" runs/*/agent.err`.
Has the problem: an output path falls under a denied folder, or a run's stderr
has "Operation not permitted" next to an exit code of 0.
Doesn't have it: every output path is in a folder the profile allows, or the
files are copied out after the sandbox exits.

## Reproduce this
Prerequisites: macOS, a sandbox profile used with `sandbox-exec -f`, and a tool
that writes a result file, such as
[Codex CLI](https://github.com/openai/codex) (`codex exec -o`) or
[Mistral Vibe](https://github.com/mistralai/mistral-vibe) (`--output-dir`).

Your agent will need from you: the profile, the lane script, and where the run
folders live.

Steps:
1. Give the lane a scratch folder outside every denied path (`mktemp -d
   /tmp/...`).
2. Point the tool's output flags at that folder: `-o "$SCRATCH/final.txt"`,
   `--output-dir "$SCRATCH/out"`.
3. After `sandbox-exec` returns, copy the files into the run folder, then
   delete the scratch folder.
4. Keep stdout and stderr redirected straight into the run folder: the shell
   opens those outside the sandbox.
5. Don't trust the exit code alone: check that the result file exists, or grep
   stderr for "Operation not permitted".

Verify: one smoke run per lane. The run folder has a non-empty `final.txt`
(or the tool's export), the grader reads the final answer, and `agent.err` has
no "Operation not permitted" line.

Ground rules: work only inside the current directory. Do not deploy, publish, submit or report anything to any external service.
