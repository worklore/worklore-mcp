- **What was changed**  
  Updated `build_system` in **bot.py** to split the system prompt into two distinct text blocks:
  1. **Static block** – contains the immutable coaching `INSTRUCTIONS`.  
  2. **Volatile block** – contains the per‑athlete context generated by `athlete_context` (date, profile, zones, goal, facts, language).  

  Both blocks are returned as a list and each carries `cache_control: {"type": "ephemeral"}` so that only modifications to the volatile tail (e.g., after a `save_fact`) invalidate that part of the cache, while the static prefix remains cached.

- **Which parts of the colleague’s note applied**  
  - *“splitting `system` into an array of two text blocks, each with `cache_control: {"type": "ephemeral"}`”* – implemented exactly as described.  
  - *“static block holds the instructions; volatile block holds per‑user tail”* – reflected in the new `static_block` and `volatile_block`.  
  - *“ordering volatile content after static for readability and to keep the static prefix hot”* – achieved by returning `[static_block, volatile_block]`.  

These changes prevent a memory write (`save_fact`) from evicting the entire cached system prompt, reducing token usage for subsequent Claude calls.
