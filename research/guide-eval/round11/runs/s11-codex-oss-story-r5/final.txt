**Cause**  
- `publish()` stores a list of similarity scores (`similar`) generated by `similarity()`.  
- `similarity()` returns a **float**.  
- When the DynamoDB table is empty the first write stores an empty `similar` list, so no float reaches DynamoDB and the operation succeeds.  
- On the second publish the `similar` list contains float scores, and DynamoDB raises `TypeError: Float types are not supported. Use Decimal types instead.` → 500 response.

**Fix**  
- Imported `Decimal` from the standard library.  
- Updated `related()` to coerce each similarity score to `Decimal` before adding it to the item (using `Decimal(str(...))`).  
- Added a detailed docstring explaining the DynamoDB float limitation and why the conversion is needed.  
- No other behavior changed; the API now consistently succeeds on every publish.

**Applied parts of the colleague’s note**  
- Identified the *“Float types are not supported”* DynamoDB error and traced it to the similarity scores.  
- Recognized that the first‑write path (empty `similar` list) masks the bug, matching the note’s description of a state‑dependent failure.  
- Implemented the single‑line fix (convert to `Decimal`), as suggested.  

The repository now passes all tests and the publish endpoint no longer fails on the second call.
