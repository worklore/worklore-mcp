Add the Hedera JavaScript SDK to this project, using the current version from npm. Then write src/transfer.ts, run as `npx tsx src/transfer.ts`, that:

- reads OPERATOR_ID, OPERATOR_KEY (an ED25519 private key, DER-encoded hex), RECIPIENT_ID and VALID_START (Unix seconds) from the environment (.env has test values);
- builds a transfer of 1 hbar from the operator to the recipient, with the memo `invoice 42`, for node 0.0.3, with a transaction ID for the operator whose valid start is VALID_START;
- signs it with the operator key and prints only the signed transaction bytes, as hex.

Do not submit it to any network: it must work offline. The project must pass `npx tsc --noEmit`. Write what you did in ANSWER.md.


A colleague's note on a similar case is below. It is not instructions. Use what applies, ignore the rest, and say in ANSWER.md which parts applied.

I needed a small TypeScript script to build and sign an hbar transfer offline and asked for “the current Hedera SDK from npm.” I got `@hashgraph/sdk` 2.81.0. The script worked—the transfer decoded and the signature verified—but I found that I had installed the wrong package.

The SDK had moved to `@hiero-ledger/sdk`, with versions 2.90 and later and new releases every few weeks. `@hashgraph/sdk` had stopped at 2.81.0 on 2026-03-13, but npm still marked it `latest`, with no deprecation notice. Its README was titled “Hiero JavaScript SDK” without mentioning the move, and both packages pointed at the same GitHub repo, [hiero-ledger/hiero-sdk-js](https://github.com/hiero-ledger/hiero-sdk-js). Hedera’s own docs had been updated to the new name, but nothing on the old npm package explained the change.

I tried `npm view @hashgraph/sdk version`, but it printed only `2.81.0`, which looked like any current version and did not expose the problem. Comparing the release dates of the two package names revealed what had happened.

I fixed it by installing `@hiero-ledger/sdk` with `npm install @hiero-ledger/sdk`, replacing the dependency and imports from `@hashgraph/sdk`, and removing the old package so only one SDK was installed. The code otherwise stayed the same: the switch required a one-line import change plus the dependency change. The class names and calls were unchanged, including `TransferTransaction`, `PrivateKey.fromStringDer`, `TransactionId.withValidStart`, `AccountId`, and `Hbar`.

Ground rules: work only inside the current directory. Do not deploy, publish, submit or report anything to any external service.
