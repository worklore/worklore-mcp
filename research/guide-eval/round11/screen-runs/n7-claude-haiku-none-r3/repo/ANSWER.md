# Pollar 0.10 → 0.12 upgrade

The app now uses `@pollar/core` and `@pollar/react` `^0.12.0`, the current `latest` on npm. `npx tsc --noEmit` passes.

## Dependencies

- `package.json`: `@pollar/core` and `@pollar/react` moved from `^0.10.1` to `^0.12.0`.
- `package-lock.json` regenerated by `npm install`.

## Changes by file

### `src/pollar.ts`: API endpoint (the retirement fix)
- `baseUrl` was `https://sdk.api.pollar.xyz/v1`. In 0.12, `baseUrl` is an origin only, and the SDK appends its own `/v3` prefix. The `/v1` path is the one being retired on 2026-11-30, so it is now `https://sdk.api.pollar.xyz`.

### `src/trust.ts`: "Accept USDC"
- `setTrustline(USDC, { sponsored: true })` became `setTrustline(USDC)`. 0.12 removed the `sponsored` option. Sponsorship is now on by default: the app covers the 0.5 XLM reserve and fee when eligible, which is what the old flag asked for. Only the `skipSponsorship` opt-out remains.

### `src/ramp.ts`: "Add money" rate
- `getRampsQuote({ country, currency, amount, direction })` no longer exists. The replacement is a two-step flow: `getRampRoutes('ONRAMP')` lists the fiat and asset pairs, then `quoteRamp(...)` quotes one.
- The new code finds every route for ARS in AR to USDC, quotes each one for `10_000` ARS (`denomination: 'in'`), and returns the lowest pesos-per-USDC rate. The old code took the first quote's `rate`, which 0.12 no longer returns, so the rate is now computed as `amountIn / amountOut`.
- Routes or quotes that find no path (`SDK_RAMPS_NO_ROUTE`) are treated as "no quote", so the function still returns `null` when nothing quotes. Other errors are rethrown.
- The `Wallet` screen is unchanged: it still shows `1 USDC = {rate} ARS`.

### `src/balances.ts`: wallet balances
- `WalletBalanceRecord.balance` is now `string | null`. `null` means the chain could not be read. The old code called `parseFloat` on it, which would throw a type error (and a `NaN` at runtime). A `null` balance now renders as `"<CODE> unavailable"`, not as zero, as the SDK asks.

### `src/kyc.ts`: KYC status message
- `KycStatus` gained `'expired'`. The `switch` now handles it with the line "Verification expired". The `switch` had no default, so without this case the typecheck fails.

### `src/App.tsx`, `src/Wallet.tsx`
- No change. `PollarProvider`, `usePollar`, `login`, `wallet`, `walletBalance`, `refreshWalletBalance` and `getClient` all still exist with the same shapes in 0.12.

## Assumptions to check

- **Ramp units.** The 0.12 typings do not say whether `amountIn` and `amountOut` are human-readable decimals or base units. I assumed decimals, as in the request's `amount.value`. If they are base units, the rate is off by a fixed factor.
- **Ramp rails.** The app previously let the server choose the payment rail. The new code quotes all AR/ARS/USDC routes, so it is the same request, expressed per rail.
- **Trustline return value.** `enableUsdc` still returns `true` only for `status === 'success'`. 0.12 can also return `'pending'` (the server-orchestrated path, where the hash is optional). That still returns `false`, as before. I did not change it.
- **Not tested against the network.** I did not call the Pollar API. The app uses a demo testnet key, and the typecheck is the only check I ran.
