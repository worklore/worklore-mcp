# ANSWER

`src/main.ts` is rewritten with Effect 4.1.2 (the npm `latest` tag at the time of
writing). `npx tsc --noEmit` passes.

## What was built

- **Rates service**: `Rates` is a `Context.Service` with a `layer`. The layer reads
  `RATES_URL` with `Config.String`, and makes the request with `effect/http`
  (`HttpClient` plus `FetchHttpClient.layer`).
- **Response validation**: the body is decoded with
  `Schema.Struct({ base, date, rates: Schema.Record(String, Number) })` via
  `Schema.fromJsonString`. Invalid JSON and wrong shapes both become `InvalidResponse`.
- **Retries**: `HttpClient.filterStatusOk`, then
  `HttpClient.retryTransient({ schedule: Schedule.exponential(50), times: 3 })`.
  Transient failures (transport errors, 408/429/500/502/503/504) are retried up to
  3 times, with delays of 50, 100 and 200 ms. Other 4xx responses are not retried.
- **Errors**: `Schema.TaggedError` classes `UnknownCurrency`, `InvalidResponse`,
  `RatesUnavailable` and `UsageError`. Each maps to an exit code.
- **Output**: `1 USD = 0.9214 EUR` on stdout with exit 0. `unknown currency: XYZ`
  (exit 1), `invalid response` (exit 2), and everything else (exit 3) on stderr.

## Which parts of the colleague's note applied

I checked each claim against the installed package rather than taking it on trust.

**Applied, and confirmed:**
- Install `effect@latest` (4.1.2) and do not add `@effect/platform`. The note is right
  that npm still lists `@effect/platform` at 0.97.2, the v3-era package, so it is a trap.
- Read `node_modules/effect/AGENTS.md` and `ai-docs/src/50_http-client/10_basics.ts`
  before writing code. That example is almost the same service shape, including
  `HttpClient.retryTransient`, so I followed its structure.
- `Context.Service` for the service, `Schema.TaggedError` for tagged errors,
  `effect/http` for the client, and `Schedule.exponential` for backoff. All exist in
  4.1.2.
- `Config.String` is a function taking the variable name, `Config.String("RATES_URL")`.
  It is not a value. This is the v4 spelling and the one I used.
- Running `npx tsc --noEmit` early and often was useful. The check passed on the
  first full draft, so no renames were needed.

**Did not apply or not checked:**
- The note's account of a 9-error draft is not something I reproduced. My draft
  used the v4 names from the start.
- I did not check the claim that `Schema.TaggedErrorClass` and `Config.string` do not
  exist. I only confirmed that the names I used do exist.
- The note's "do not deploy, publish or report" rules are respected. Nothing was
  published, and the only server used was a local throwaway one.

## Choices I made

- Missing arguments are treated as a usage error and exit 3, because the spec says
  "any other failure exits 3".
- `RATES_URL` has any trailing slashes stripped before the path is appended.
- Currency codes in the URL are `encodeURIComponent`-ed.
- Quote lookup uses `Object.hasOwn`, so keys such as `constructor` are not matched
  on the prototype.
- `package.json` now lists `effect` under `dependencies` (`^4.1.2`). A
  `package-lock.json` was generated by `npm install`. Neither has been committed.
