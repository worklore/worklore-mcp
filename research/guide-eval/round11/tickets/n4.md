I hit this while running coding agents on small tasks and grading what each run left behind. The two new lanes sent everything the agent saw to an outside model provider, so I ran their shells under a macOS sandbox profile that denied reads and writes to my real home folder. The run folders were inside that home folder, in the eval repository.

The first Codex lane smoke run looked successful: it exited 0, left a full event stream in `agent.log`, and made the correct fix in the repo, with both hidden tests passing. The grader still marked it as a failure because the final answer was empty.

I found that Codex wrote its last message to the path passed with `-o`, which pointed to `final.txt` in the run folder. The sandbox denied that write. Codex printed `Failed to write last message file "<run folder>/final.txt": Operation not permitted (os error 1)` to stderr and still exited 0. Mistral Vibe failed the same way with `--output-dir`: it printed `Error: could not write the run export: Operation not permitted (os error 1)` and also exited 0.

The misleading part was that stdout and stderr redirects into the same run folder worked. The shell opened those files before `sandbox-exec` started, so everything else in the run folder looked normal. The tool’s own output write happened inside the sandbox, where the profile’s `deny file-write*` rules applied to the paths after substitution of the `-D` parameters. The output-file flags involved included `-o`, `--output-last-message`, `--output-dir`, and `--out`; an exit code of 0 alone did not establish that the result file had been written.

I fixed both lanes by giving each a scratch folder in `/tmp`, outside every denied path, using `mktemp -d /tmp/...`. I pointed Codex at `-o "$SCRATCH/final.txt"` and Mistral Vibe at `--output-dir "$SCRATCH/out"`. After `sandbox-exec` returned, the lane copied the files into the run folder and deleted the scratch folder. I kept stdout and stderr redirected straight into the run folder because the shell opened those outside the sandbox.
