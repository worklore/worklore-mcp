I hit a case where the publish endpoint worked on the first story, then returned Internal Server Error on the second. The log said: "TypeError: Float types are not supported. Use Decimal types instead."

The API computed similarity scores between the incoming story and existing stories and stored the top matches. The first publish succeeded because the table was empty: there were no matches, so there were no scores or floats to write. Once the table contained a story, the scoring path ran and passed Python floats to DynamoDB, which did not accept them.

My initial “it works” test had only exercised the empty-database path, so it missed the failure entirely. The trap was that scoring, deduplication, aggregation and “related items” logic had another path that depended on existing state. Divisions, averages and rounded scores feeding item dictionaries were places where computed floats could reach the write.

I fixed it with a one-line change that made the scores integer percentages. DynamoDB accepted ints and Decimals. I also changed every write-path test to seed the table with one record before testing the write, so the populated-table path actually ran. The empty-table path had hidden the bug until the data existed.
