I migrated my multi-tenant triathlon agent from per-user API keys to Intervals.icu OAuth so athletes could connect their account with two clicks instead of pasting a key. The flow mostly followed the standard authorization-code flow, but I ran into four quirks that cost me debugging time.

The token response had no `refresh_token` or `expires_in`. I found that the access token lasted until the athlete revoked it in the Intervals UI, so there was no refresh machinery to implement and no way to know the token was dead before an API request failed. I stored the token encrypted at rest as a perpetual credential. On the first API 401, I cleared the stored token, marked the user as disconnected, and surfaced a "reconnect" prompt.

I also hit `Duplicate scope` when requesting `ACTIVITY:READ,ACTIVITY:WRITE`. `:WRITE` implied `:READ`, and naming the same area twice caused the error. I changed the scope string to list each area at most once: `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE,SETTINGS:WRITE`.

I found that `POST /api/oauth/token` wanted only the form fields `client_id`, `client_secret`, and `code`, with no `grant_type` or `redirect_uri` echo. I used `POST https://intervals.icu/api/oauth/token` for the exchange. The response bundled `athlete: {id, name}`, which saved a "who am I" round-trip. I took `access_token`, `scope`, and `athlete.id` from the JSON response and used the athlete id in every API path, sending `Authorization: Bearer <token>` against `https://intervals.icu/api/v1/athlete/{athlete_id}/...`.

The self-inflicted failure was the init endpoint. I initially shipped it as GET behind a plain `<a href="/api/intervals/auth/init">` link that built the authorize URL and redirected. It returned 401 for every user because a full-page navigation did not send the `Authorization` header the SPA kept in localStorage; that header only traveled on XHR/fetch. I rewrote init the same day as an authenticated `POST /auth/init`, called through XHR, which built `https://intervals.icu/oauth/authorize?client_id=...&redirect_uri=...&scope=...&state=...` and returned `{authorize_url}` as JSON. The frontend then called `window.location.assign(authorize_url)`.

The callback also arrived without an auth header because it was a redirect from Intervals. I kept the callback endpoint as an unauthenticated GET and carried the user identity in `state`, using a signed JWT `{sub: user_id, purpose: "intervals_oauth", exp: now+15min}`. I validated its signature, TTL, and purpose before exchanging the code. On reconnect, I added an account-mismatch guard that rejected the callback if the incoming athlete id differed from the one already stored.
