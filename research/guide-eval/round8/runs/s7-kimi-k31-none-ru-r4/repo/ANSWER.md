# Причины сбоя интеграции Intervals.icu

1. **Кнопка Connect не передавала учётные данные tricoach.** Ссылка в `static/app.js` выполняла обычную навигацию браузера на `/api/intervals/auth/init`, а не вызов через `fetch`-обёртку. Поэтому заголовок `Authorization: Bearer ...` отсутствовал, и сервер возвращал 401 всем атлетам. Теперь кнопка получает authorize URL авторизованным API-запросом и только затем перенаправляет браузер.

2. **Authorize-запрос содержал неподдерживаемый scope `CALENDAR:READ`.** После добавления календарной синхронизации Intervals.icu отклонял весь запрос с `invalid_request` ещё до экрана согласия. Для нужной записи тренировок в календарь оставлен поддерживаемый `CALENDAR:WRITE`; недопустимый scope удалён из `config.py`.

3. **Не запрашивался offline-доступ.** Без `access_type=offline` Intervals.icu выдал только access token, без refresh token. Код использовал срок жизни по умолчанию 3600 секунд и по истечении часа не мог обновить токен, поэтому менял статус на `expired, reconnect`. Параметр `access_type=offline` добавлен в authorize-запрос в `server.py`; существующий фоновый обновлятор теперь получает и сохраняет refresh token, включая его ротацию.
