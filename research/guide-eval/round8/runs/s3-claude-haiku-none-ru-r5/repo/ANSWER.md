# Почему nightly-review ничего не сообщала

## Что видно в данных

- `launchctl-print.txt`: `runs = 6`, `last exit code = 1`. Задача запускалась 6 раз и каждый раз падала.
- `Library/Logs/nightly-review.out` пустой.
- `Library/Logs/nightly-review.err` содержит 6 одинаковых пар строк:
  ```
  Not logged in · Please run /login
  /Users/vk/bin/nightly-review.zsh:19: read-only variable: status
  ```

## Причина 1 (главная): `status` — read-only в zsh

В строке 19 скрипта `status=$?`. В zsh `status` — встроенный read-only параметр (синоним `$?`). Присваивание падает, а в неинтерактивном скрипте это фатальная ошибка: shell завершается с кодом 1. Проверено локально: `zsh -c 'false; status=$?'` даёт `read-only variable: status` и exit 1.

Из-за этого:
- ветка `if [ $status -ne 0 ]` с уведомлением `FAILED` никогда не выполняется;
- ветка успеха тоже не выполняется;
- `notify.sh` не вызывается вообще, поэтому в Telegram ничего не приходит, ни успех, ни ошибка.

Сбой в `claude` тоже не был бы виден сам по себе, потому что код возврата `claude` никогда не проверялся до того места, где скрипт падал.

## Причина 2: скрипт не сообщает о падениях, которые не предусмотрены явно

Даже без бага с `status` скрипт сообщал бы только об ошибках, которые он сам распознал. Любой аварийный выход (неопределённая переменная при `set -u`, неудачный `cd`, опечатка вроде этой) завершал бы его молча. Нужен обработчик `EXIT`, который уведомляет о любом ненулевом коде.

## Причина 3: `notify.sh` молча проглатывает ошибки отправки

- `: "${TG_BOT_TOKEN:=$(security ...)}"`: если `security` не смог прочитать токен из Keychain, подстановка падает, но `set -e` это не ловит (проверено: `: "${T:=$(false)}"` продолжает работу с пустым `T`). В итоге запрос уходит на `…/bot/sendMessage` с пустым токеном.
- `curl -sS` без `-f`: HTTP-ошибки (404 на неверный токен, 400 и т. д.) не считаются ошибкой curl, тело ответа уходит в `/dev/null`. Скрипт «успешно» завершается, ничего не отправив.

Поэтому даже ручной тест может выглядеть рабочим, а из ночного запуска сообщения не будет.

## Причина 4 (не исправлена кодом, нужна проверка): `claude` в launchd говорит «Not logged in»

Это отдельная проблема, и её нельзя решить правкой скрипта. При запуске из launchd `claude -p` не видит авторизацию. Исходя из данных, не могу сказать точно, какая именно. Возможные варианты:
- ключ API экспортирован в `~/.zshrc`, а launchd его не читает (`.zshrc` для LaunchAgent не загружается);
- учётные данные Claude Code в Keychain, и для фонового запуска они недоступны.

Чтобы проверить, стоит временно запустить `claude auth status` (или аналог) из того же окружения, что и launchd, и посмотреть переменные окружения: `launchctl print gui/501/com.vk.nightly-review` показывает только PATH и XPC. Ключи в plist не хранить: если нужен API-ключ, читать его из Keychain в скрипте, как сделано с токеном Telegram.

## Что изменено в этом снимке

1. `bin/nightly-review.zsh`
   - `status` переименован в `claude_rc`.
   - Добавлен обработчик `EXIT` (`finish`): при любом ненулевом коде отправляется `FAILED` с первыми 300 байтами stderr. Пишет и `|| true`, чтобы сбой уведомления не маскировал исходную ошибку.
   - stderr `claude` теперь пишется в `~/Library/Logs/nightly-review-YYYY-MM-DD.err`, а не в общий лог launchd. Файл для каждого дня, поэтому старые логи не перезаписываются.
   - Пустой вывод при коде 0 считается ошибкой (код 2).
2. `bin/notify.sh`
   - Если токен не читается из Keychain, скрипт пишет понятную ошибку в stderr и выходит с кодом 1.
   - `curl -fsS`: HTTP-ошибки Telegram теперь дают ненулевой код и видны в логах.

Проверено в песочнице внутри этой директории (заглушки `claude` и `notify`, `HOME` подменён; реальный Telegram не вызывался):
- `claude` падает с кодом 1 → уходит `FAILED (exit 1): Not logged in …`, код скрипта 1;
- `claude` выходит с 0 и пустым выводом → `FAILED (exit 2)`;
- `claude` выходит с 0 и выводом → `done: …`, код 0;
- Keychain недоступен → `notify.sh` выводит ошибку и выходит с кодом 1.

Настоящий запуск через launchd и отправка в Telegram не проверялись: это нужно сделать вами.

## Что нужно сделать вам

1. Скопировать исправленные файлы в `~/bin/` (`nightly-review.zsh`, `notify.sh`), сохранив права на исполнение.
2. Решить проблему авторизации `claude` из пункта 4. Без неё скрипт теперь будет честно присылать `FAILED … Not logged in`, но отчётов не будет.
3. Перезагрузить агент, чтобы не ждать 02:30: `launchctl kickstart -k gui/$(id -u)/com.vk.nightly-review`. Этот запуск вызовет реальный `claude` и реальный Telegram, поэтому я его не выполнял.
