# Почему ночная задача молчала

`launchd` запускал задачу: в `launchctl-print.txt` указано `runs = 6` и `last exit code = 1`. Расписание и загрузка агента не были причиной проблемы. В `Library/Logs/nightly-review.err` шесть раз повторяются две ошибки:

1. `Not logged in · Please run /login` — вызов `claude` завершался ошибкой. В `EnvironmentVariables` plist не было `USER`, поэтому CLI в контексте launchd не мог обратиться к сохранённому логину в Keychain.
2. `nightly-review.zsh:19: read-only variable: status` — после ошибки CLI скрипт выполнял `status=$?`. В zsh `status` является специальной переменной только для чтения, поэтому это присваивание аварийно завершало скрипт до ветки с `notify.sh`. Именно поэтому не приходило даже уведомление об ошибке.

# Исправления

- В `Library/LaunchAgents/com.vk.nightly-review.plist` добавлено `USER=vk` в `EnvironmentVariables`.
- В `bin/nightly-review.zsh` переменная `status` заменена на обычную `rc`; теперь ненулевой код `claude` доходит до failure-уведомления и возвращается из скрипта.
- Вызову `claude`, который получает prompt аргументом, добавлен `< /dev/null`, чтобы под launchd он не ждал ввода из stdin.

# Что пригодилось из заметки коллеги

- Сначала проверить `launchctl print`: счётчик запусков опроверг предположение, что задача вообще не стартует.
- Прочитать журнал `StandardErrorPath` до дальнейших предположений: именно он показал обе причины.
- Не присваивать `status` в zsh, а использовать `rc=$?`.
- Добавить `USER` в `EnvironmentVariables` для доступа headless CLI к логину в Keychain.
- Закрыть stdin через `< /dev/null`, когда prompt передаётся аргументом.
- Проверять не только код выхода, но и реальный результат, а также отдельно принудительно проверить failure-уведомление.

Вариант с передачей prompt через stdin не применён: здесь prompt уже передаётся одним корректно quoted-аргументом, поэтому достаточно закрыть stdin. Добавление логирования длительности не требовалось для устранения найденных причин.

# Проверка

- `/bin/zsh -n bin/nightly-review.zsh` — успешно.
- `plutil -lint Library/LaunchAgents/com.vk.nightly-review.plist` — успешно.
- Настоящий скрипт запущен с локальными заглушками `claude` и `notify.sh`: успешный путь создал отчёт и success-уведомление; принудительная ошибка с кодом 7 создала failure-уведомление и вернула код 7.

Реальные Claude, Keychain и Telegram не вызывались: проверка выполнена полностью локально, без внешних сервисов. Изменён только снимок в текущей директории; агент в домашней директории не перезагружался.
