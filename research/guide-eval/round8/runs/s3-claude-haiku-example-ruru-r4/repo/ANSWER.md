# Почему ночная задача nightly-review ничего не сообщала

## Что показал лог

`Library/Logs/nightly-review.err` содержит две строки, повторённые при каждом запуске (всего 6 запусков, как в `launchctl-print.txt`: `runs = 6`, `last exit code = 1`):

```
Not logged in · Please run /login
/Users/vk/bin/nightly-review.zsh:19: read-only variable: status
```

Задача запускалась по расписанию. Проблема не в launchd и не в расписании.

## Причина 1: скрипт умирал до уведомления

Строка 19 — `status=$?`. В zsh `status` — read-only переменная, присваивание завершает скрипт с кодом 1. Эта строка стоит между вызовом `claude` и проверкой кода, поэтому `notify.sh` с сообщением об ошибке не вызывался никогда. Проверено локально: `zsh -c 'false; status=$?; echo after'` печатает ошибку и не доходит до `after`; с `rc=$?` всё работает.

Это и есть «репортёр ошибок умер вместе с задачей»: сообщение об ошибке не отправлялось, а успешного сообщения тоже не было.

## Причина 2: claude не видел свой логин

`Not logged in · Please run /login` — headless `claude` не нашёл учётные данные. В plist задан только `PATH`, а launchd не выставляет `USER` в окружение задачи. По этой причине CLI не может найти логин в keychain. Это совпадает с заметкой коллеги (раздел «Две ловушки для claude -p»), но **на живом launchd я это не проверял**: здесь нет доступа к вашей системе. Фикс — установить `USER` и проверить через `kickstart` (см. ниже).

Причина 2 не была бы видна без причины 1: из-за неё `claude` падал, а падение не доходило до уведомления.

## Что исправлено

**`bin/nightly-review.zsh`**
- `status=$?` заменено на `rc=$?`.
- Промпт передаётся через stdin (`print -r -- "$PROMPT" | claude -p ...`), а не многострочным аргументом.
- Успех определяется не только кодом выхода: пустой отчёт (`! -s "$OUT"`) считается сбоем, даже при коде 0. Это закрывает случай «вышел с 0 и ничего не сделал».
- В лог (`nightly-review.out`) пишется время запуска, код и длительность; длительность попадает и в уведомление.
- Если уведомление само не отправилось, это пишется в stderr, а не глотается молча.

**`Library/LaunchAgents/com.vk.nightly-review.plist`**
- Добавлен `USER` = `vk` в `EnvironmentVariables`. Имя должно совпадать с тем, что выдаёт `id -un` на вашей машине (пути в проекте указывают на `/Users/vk`).

## Что из заметки коллеги пригодилось, а что нет

Пригодилось:
- `rc=$?` вместо `status` — та же ошибка, что и у вас.
- Промпт через stdin.
- `USER` в `EnvironmentVariables` при «Not logged in».
- Проверка реального результата, а не только кода выхода: пустой отчёт считается сбоем; длительность запуска в логе и уведомлении.
- Уведомление об ошибке должно срабатывать на любой путь отказа — и проверяется это намеренно сломанным запуском.

Не пригодилось / не применимо:
- Ошибка `Input must be provided either through stdin or as a prompt argument` — в вашем логе её нет, потому что до неё дело не дошло. Stdin-вариант всё равно применён заранее, поэтому `< /dev/null` не нужен.
- `launchctl print` как доказательство запуска — здесь он уже был в `launchctl-print.txt` и дал нужный сигнал (`runs = 6`, `last exit code = 1`).

## Проверка

**Локально (в песочнице внутри репозитория, потом удалена):** подменены `HOME`, `claude` и `notify.sh`:

| Сценарий | Код скрипта | Уведомление |
|---|---|---|
| `claude` вернул отчёт, код 0 | 0 | `nightly review done (0s): ...` |
| `claude` упал с кодом 1 | 1 | `nightly review FAILED (exit 1, 0s)...` |
| `claude` вышел с 0, отчёт пустой | 1 | `nightly review FAILED (exit 0, 0s)...` |

**На вашей машине (не выполнено здесь, это нужно сделать вам):**

1. Скопировать исправленные файлы в `~/bin/nightly-review.zsh` и `~/Library/LaunchAgents/com.vk.nightly-review.plist`.
2. Перезагрузить задачу, чтобы launchd подхватил новый plist:
   ```
   launchctl bootout gui/501/com.vk.nightly-review
   launchctl bootstrap gui/501 ~/Library/LaunchAgents/com.vk.nightly-review.plist
   ```
3. Запустить вручную: `launchctl kickstart -k gui/501/com.vk.nightly-review`.
4. Проверить все три условия:
   - `launchctl print gui/501/com.vk.nightly-review` показывает `last exit code = 0`;
   - `~/Library/Logs/nightly-review-<дата>.md` существует, свежий и непустой;
   - в `nightly-review.out` длительность правдоподобная (десятки секунд, не 0–2 секунды), и пришло сообщение в Telegram.
5. Намеренно сломать сценарий (например, переименовать `~/projects/shop` или временно подставить несуществующий путь к `claude`) и убедиться, что пришло сообщение `FAILED`. После этого вернуть всё обратно.

Если на шаге 4 в логе снова `Not logged in`, значит `USER` не помог и нужно смотреть, где именно `claude` ищет логин (например, через `~/.claude` или `HOME` в plist). Этого я не могу проверить из снимка.

## Что не проверено

- Работа `notify.sh` под launchd: он читает токен через `security find-generic-password`. В gui-домене это обычно работает, но в логе это не видно, пока уведомления не придут.
- Реальный запуск `claude -p` под launchd: здесь доступны только файлы снимка, поэтому запуск симулирован подменой `claude`.
