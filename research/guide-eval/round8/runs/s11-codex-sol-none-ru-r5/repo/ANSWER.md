# Почему вторая публикация возвращала 500

При первой публикации таблица пуста, поэтому поле `similar` — пустой список и запись проходит. При следующей публикации `related()` добавляет в `similar` оценку сходства из `similarity()`. Расчёт через `/` и коэффициенты `0.7`/`0.3` возвращал `float`. Ресурс DynamoDB в boto3 не сериализует `float` даже внутри вложенного списка и выбрасывает `TypeError: Float types are not supported. Use Decimal types instead.` Это соответствует трассировке в `logs/error.log`; обработчик превращал исключение в ответ 500.

# Исправление

Расчёт сходства теперь использует `Decimal` от начала до конца, включая коэффициенты и случай нулевого сходства. Поэтому каждое значение `similar[].score`, передаваемое в `put_item`, имеет поддерживаемый DynamoDB тип `Decimal`; дробное значение не может вновь попасть туда как `float` через этот расчёт.

Добавлен тест двух последовательных запросов к `handler()`: оба возвращают 201, а второй сохраняет положительную оценку сходства типа `Decimal` в таблице, которая проверяет типы как boto3.

Проверка: `python3 -m unittest discover tests -v` — 2 теста прошли.
