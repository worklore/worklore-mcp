# Почему nightly-review молчал

Задача запускалась (в `launchctl-print.txt`: `runs = 6`, `last exit code = 1`) — молчал сам скрипт.

## Причины
1. **`claude -p` падает: «Not logged in · Please run /login»** (в `.err` перед каждой ошибкой). Под launchd нет `USER`
   (в окружении только `PATH`), и CLI не находит свой логин в keychain.
   Исправление: `USER` и `HOME` добавлены в `EnvironmentVariables` plist. Не проверено у вас на машине: если после
   этого ошибка останется, один раз выполните `claude /login` в обычном терминале.
2. **`status=$?` в zsh** — `status` переменная только для чтения, скрипт умирает на строке 19
   (`read-only variable: status`) до вызова `notify.sh`. Поэтому уведомления об ошибке не было никогда.
   Исправление: `rc=$?`.

Итог: ошибка 1 → отправитель ошибок убит ошибкой 2 → тишина; stdout пуст, а `.err` никто не читал.

## Дополнительно изменено
- `< /dev/null` для `claude -p` (промпт идёт аргументом, иначе возможно ожидание stdin).
- Логируется длительность запуска; пустой вывод при коде 0 считается ошибкой (код 2).
- Сбой `notify.sh` теперь виден в `.err` и не маскирует исходную ошибку.
- После правок: `launchctl bootout gui/$UID/com.vk.nightly-review` и снова `bootstrap` (plist изменён),
  затем `launchctl kickstart -k gui/$UID/com.vk.nightly-review`. Проверьте код 0, свежий `nightly-review-<дата>.md`,
  длительность и сообщение в Telegram; потом намеренно сломайте скрипт и убедитесь, что придёт FAILED.
  Здесь я этого сделать не мог (нет launchd/claude/Telegram в снимке).

## Что пригодилось из заметки коллеги
- Пригодилось: `launchctl print` как первый шаг; запрет `status=$?` (точное совпадение); `USER` в plist;
  `< /dev/null`; проверка реального результата, а не только кода выхода; логирование длительности.
- Не пригодилось: передача промпта через stdin (у вас нет ошибки «Input must be provided», промпт — один
  аргумент); время 16:50 (у вас 02:30); её лог/код выхода — у вас другие.
