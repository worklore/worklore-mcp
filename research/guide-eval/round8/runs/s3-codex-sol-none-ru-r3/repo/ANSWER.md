# Почему ночная задача молчала

`launchd` запускал её. В снимке `launchctl print` указаны `runs = 6`, `last exit code = 1` и календарный триггер на 02:30. Значит, расписание и загрузка агента не были причиной молчания.

Каждый из шести запусков оставил в `nightly-review.err` две строки: `Not logged in · Please run /login` от `claude` и `read-only variable: status` от zsh. У процесса `claude`, запущенного через `launchd`, не оказалось пригодной авторизации. Затем скрипт пытался присвоить код выхода переменной `status`, которая в zsh доступна только для чтения. На этом исполнение прекращалось до ветки `nightly review FAILED`, поэтому даже сообщение об ошибке не отправлялось. Ручная проверка `notify.sh` подтверждала работу отправки в ручной среде, но не авторизацию `claude` в ночном процессе.

## Что исправлено в снимке

- `bin/nightly-review.zsh` получает учётные данные для безинтерактивного запуска из переменной `ANTHROPIC_API_KEY` или `CLAUDE_CODE_OAUTH_TOKEN`, а при их отсутствии пробует запись Keychain с именем `nightly-review-anthropic-api-key`. Если учётные данные недоступны, скрипт пишет понятную ошибку и пытается отправить её в Telegram.
- Код выхода `claude` теперь сохраняется в обычную переменную `exit_code`; об ошибке и пустом результате отправляется уведомление. Права на создаваемый файл отчёта ограничены через `umask 077`.
- `bin/notify.sh` сообщает в stderr о недоступном токене Telegram и о неуспешной отправке. Он проверяет HTTP-ошибку и подтверждение `ok` в ответе Telegram, а также повторяет попытки при временном сбое соединения.

## Что нужно сделать на настоящем Mac

Перенести исправленные скрипты из этого снимка на соответствующие пути в домашней директории. В Keychain пользователя создать запись типа **generic password** с именем службы `nightly-review-anthropic-api-key` и действующим Anthropic API key в поле пароля; либо предоставить процессу `launchd` один из двух указанных выше токенов через его окружение. Убедиться, что ночной процесс может читать эту запись и существующую запись `tg-bot` без интерактивного запроса Keychain. Без доступных учётных данных отчёт и уведомление доставить невозможно; причина отказа теперь будет видна в `nightly-review.err`.

Проверены синтаксис обоих скриптов и plist, а также ветки успешного ответа, ошибки `claude` и пустого ответа с локальными подставными командами. Настоящие `claude`, Keychain и Telegram не вызывались; исправление не переносилось за пределы этой папки.
