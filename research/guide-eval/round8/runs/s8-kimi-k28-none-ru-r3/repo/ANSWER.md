# ANSWER

## Проблема

В `bot.py` функция `build_system()` собирала системный промпт в один блок:
статические инструкции (`INSTRUCTIONS`, ~1000 токенов) + контекст атлета
(профиль, зоны, цель, список фактов из `athlete_context()`), и ставила один
маркер `cache_control` на весь блок целиком.

У промпт-кеша Anthropic префиксная семантика: запись кеша создаётся для
префикса до маркера, и любое изменение текста внутри этого префикса
инвалидирует всю запись. Каждый `save_fact` меняет список фактов, значит
менялся весь системный промпт — вместе со статическими инструкциями. Следующий
вызов получал `cache_read_input_tokens: 0` и заново платил полную цену записи
кеша за все ~1000+ токенов (видно в `logs/usage.jsonl`: каждый вызов сразу
после `save_fact` имеет `cache_creation_input_tokens` ~1000–1300).

## Исправление

`build_system()` (bot.py) теперь возвращает два блока, каждый со своим
маркером `cache_control`:

1. Первый блок — статические `INSTRUCTIONS`. Они неизменны, префикс кеша
   стабилен, поэтому `save_fact` больше не вытесняет их: круги тул-лупа и
   следующие сообщения в пределах TTL читают их из кеша.
2. Второй блок — изменяемый `athlete_context()` (дата, профиль, факты).
   Добавление факта меняет только этот маленький блок; он пересчитывается как
   обычный ввод (или дешёвая перезапись кеша ~десятков токенов), а не ~1000
   токенов инструкций.

Комментарий в `build_system()` обновлён под новое поведение.

## Проверка

Скриптом на `bot.py`: при добавлении факта первый блок побайтово идентичен,
меняется только второй; `build_request()` и цикл `reply()` (с фейковым LLM)
работают с двухблочным системным промптом. Тестовый прогон через `reply()`
дописал строку в `logs/usage.jsonl` — строка удалена, лог приведён к исходному
состоянию.
