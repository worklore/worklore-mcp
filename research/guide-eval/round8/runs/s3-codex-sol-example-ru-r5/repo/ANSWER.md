# Почему ночная задача молчала

Задача **запускалась**: в `launchctl-print.txt` указаны `runs = 6` и `last exit code = 1`. В `Library/Logs/nightly-review.err` для каждого запуска повторяются две ошибки:

1. `claude` сразу завершался с `Not logged in · Please run /login`. В окружении загруженного LaunchAgent есть `PATH`, но нет `USER`. Для доступа CLI к учётным данным в этом контексте добавил `USER=vk` в `EnvironmentVariables` plist. Это наиболее вероятная причина ошибки авторизации по имеющимся данным; снимок не позволяет проверить состояние связки ключей на настоящем Mac.
2. После завершения `claude` скрипт пытался выполнить `status=$?`. В zsh `status` — переменная только для чтения. Эта ошибка останавливала скрипт **перед** веткой отправки сообщения об ошибке, поэтому не приходило даже уведомление о сбое. Переменная заменена на `rc`.

Файл `nightly-review.out` пуст, поскольку ответ агента перенаправлялся в отдельный датированный `nightly-review-YYYY-MM-DD.md`; ошибки попадали в `nightly-review.err`.

## Что исправлено

- В plist задан `USER=vk`.
- Вызов `claude -p` получает закрытый stdin (`< /dev/null`), так как prompt уже передаётся аргументом. Это исключает ожидание ввода в фоновом запуске.
- Скрипт логирует код выхода и длительность вызова агента, сообщает о его ошибке и считает пустой ответ ошибкой даже при коде выхода 0.
- `notify.sh` использует `curl -f`, чтобы ответ Telegram с HTTP-ошибкой не выглядел успешной отправкой.

## Проверка

`plutil -lint`, `zsh -n`, `bash -n` и `git diff --check` прошли. Локальный прогон с заглушками `claude` и уведомителя подтвердил три ветки: ошибка агента (код 7 и сообщение о сбое), пустой ответ (код 1 и сообщение о сбое), непустой ответ (код 0 и сообщение об успехе). Заглушка также проверяла, что stdin агента закрыт. Реальные `launchctl`, связка ключей, `claude` и Telegram здесь не запускались: доступен только снимок, отправка во внешний сервис запрещена.

## Что пригодилось из заметки коллеги

Пригодились проверка `runs` и кода выхода через `launchctl print`, чтение stderr, предупреждение о переменной zsh `status`, установка `USER` для headless CLI, закрытие stdin при передаче prompt аргументом и проверка фактического результата наряду с кодом выхода. Prompt здесь уже был одним аргументом, поэтому совет передавать его через pipe не требовался. `kickstart` и реальную отправку тестовых уведомлений не выполнял: они затронули бы систему и внешний сервис за пределами разрешённого снимка.
