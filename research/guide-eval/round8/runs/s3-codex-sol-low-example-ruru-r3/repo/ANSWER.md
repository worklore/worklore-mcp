# Почему задача молчала

Снимок `launchctl print` показывает `runs = 6` и `last exit code = 1`: launchd запускал задачу, расписание работало. В `Library/Logs/nightly-review.err` для каждого запуска есть пара ошибок.

1. `claude` завершался с `Not logged in · Please run /login`. В окружении задачи был `PATH`, но не было `USER`; для этого headless CLI это мешает найти сохранённый логин. В plist добавлен `USER=vk`.
2. Сразу после `claude` скрипт делал `status=$?`. В zsh `status` доступна только для чтения, поэтому скрипт аварийно завершался до ветки, которая отправляет сообщение об ошибке. Переменная заменена на `rc`.

Промпт теперь передаётся через stdin, а не многострочным аргументом. Скрипт записывает код выхода и длительность запуска в stdout, сообщает об ошибке при пустом результате и лишь затем отправляет сводку. В `notify.sh` добавлен `curl -f`, чтобы HTTP-ошибка Telegram приводила к ненулевому коду выхода, а не выглядела успешной отправкой.

Из заметки коллеги пригодились проверка `launchctl print` и stderr, правило про `status` в zsh, `USER` для headless CLI, передача промпта через stdin и проверка реального результата. Ошибка отсутствующего промпта из заметки здесь не наблюдалась: лог указывает на отсутствие логина. Проверка через `kickstart` и реальную доставку Telegram в этот снимок не входит: она потребовала бы запуска задачи и обращения к внешним сервисам, что запрещено условием.
