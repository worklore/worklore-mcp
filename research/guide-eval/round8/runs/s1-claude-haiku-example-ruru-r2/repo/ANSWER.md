# Пульсовые коридоры на часах: что исправлено

## Что изменил

В `gen.py`, функция `hr_target`: нижняя граница коридора теперь передаётся
ключом `start`, а не `value`.

```python
# было
return {"units": "%lthr", "value": lo, "end": hi}
# стало
return {"units": "%lthr", "start": lo, "end": hi}
```

Добавил в docstring короткое пояснение, почему ключ важен, чтобы это не
откатили «для единообразия».

## Почему

По `readback/watch-notes.md` часы показывали не коридор из плана, а свои
зоны (118–137, 151–162 и т. д.). Это значит, что Intervals экспортирует
цель как «Lap-HR / по зонам», которую часы обрезают под свои зоны.

Заметка коллеги (`Точные пульсовые коридоры на Garmin...`) описывает то же
поведение и его устранение: с ключом `value` цель уходит в зонном режиме,
а с `start` — в режиме Instant-HR коридора, где часы показывают bpm,
посчитанные из процентов × LTHR из Intervals. Это совпадает с симптомами
из `watch-notes.md`, поэтому я взял именно эту правку.

Проверка по выводу генератора: для `plans/tempo-run.json` все коридоры
теперь имеют `start`/`end` (например, Tempo: `start: 88, end: 93`), без `value`.

## Что не проверено

- **На часах не проверял.** Нет доступа к Intervals/Garmin, и по правилам
  работы я ничего не отправлял (`push.sh` не запускал). Ожидаемое поведение
  (коридор = % × LTHR из Intervals, например Tempo 151–160 при LTHR 172)
  основано на заметке коллеги и на расчётах, но подтвердить его может только
  тестовое событие и синхронизация часов.
- `readback/event-184233-as-sent.json` описывает старую отправку с `value`.
  Файл я не трогал: он отражает то, что реально ушло в API. После следующей
  отправки его стоит перезаписать новым ответом.

## Что из заметки коллеги не применял

- **Поле `description` и грамматика Intervals** (`m`/`mtr`, `Z<число>`,
  цифры в начале подписи и т. д.). Это отдельная проблема веб-отображения
  шагов, а не причина неверных пульсовых зон. Если нужно, сделаю отдельным
  изменением.
- **Проверка через `GET /events/{id}`** (`workout_doc.steps` пустой → парсер
  споткнулся). Полезно при следующей отправке, но в скрипт пока не добавлял.
- **Сценарий с абсолютными bpm и `start_bpm`/`end_bpm`** — не использую, в
  этом проекте он не нужен.
