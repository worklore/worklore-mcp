# ANSWER: события аналитики из docs/EVENTS.md

Реализованы все 6 событий через существующую обёртку `Analytics` (lib/analytics.dart).
Имена и свойства совпадают со спецификацией один в один, PII (email, телефон)
никуда не отправляется.

## Экран регистрации — lib/screens/registration_screen.dart

| Событие | Где срабатывает | Свойства |
|---|---|---|
| `registration_email_started` | `onChanged` email-поля, один раз за визит по флагу `_emailInputFired` | — |
| `registration_phone_started` | `onChanged` phone-поля, один раз за визит по флагу `_phoneInputFired` | — |
| `loan_amount_changed` | `Slider.onChangeEnd` — в конце перетаскивания, не на каждом шаге | `amount` (int, округлённое выбранное значение) |
| `terms_accepted` | `CheckboxListTile.onChanged`, только при установке галочки (value == true) | — |
| `registration_continue_tapped` | `onPressed` кнопки Continue, перед навигацией на /offers | `amount` (int), `terms` (bool) |

## Экран предложений — lib/screens/offer_screen.dart

| Событие | Где срабатывает | Свойства |
|---|---|---|
| `offers_scrolled` | `NotificationListener<ScrollEndNotification>` вокруг списка — в конце жеста прокрутки, а не на каждом обновлении скролла | `offset` (double, `metrics.pixels` на момент остановки) |

## Что пригодилось из заметки коллеги

Заметка описывает ровно наш случай (Flutter + PostHog, события «начал вводить
email» и «двинул слайдер суммы»), и из неё применено:

1. **Текстовые поля — один раз за визит по флагу.** Без этого каждый ввод email
   давал бы по событию на каждое нажатие клавиши. Флаги `_emailInputFired` /
   `_phoneInputFired` живут в state экрана и сбрасываются при повторном входе
   на экран — «один раз» = «один раз за визит».
2. **Слайдер — событие в `onChangeEnd`, а не в `onChanged`.** Одно перетаскивание
   через 49 делений давало бы ~49 событий; теперь одно, с финальным значением —
   заодно это именно то значение `amount`, которое нужно по спецификации.
3. **Скролл — `ScrollEndNotification` вместо scroll-update.** Одно событие на
   жест прокрутки с текущим offset, а не поток событий на каждый тик скролла.
4. **Не менять имена и свойства событий** — соблюдено: имена snake_case из
   таблицы EVENTS.md, свойства и типы (`amount` int, `terms` bool, `offset`
   double) точные.

Пропущено как неподходящее:

- **Захват финального значения поля по потере фокуса (FocusNode).** Ни одно
  событие не требует значения поля; по спецификации значения email/phone
  отправлять нельзя (PII), так что отслеживать что-либо по фокусу незачем.
- **Шаг проверки с `PostHogConfig.debug = true`.** В этой среде бинарники
  Flutter/Dart не запускаются (macOS «Operation not permitted»), поэтому
  проверка ограничилась ручным ревью кода; запуск анализатора/дебаг-сборки
  нужно сделать на машине, где Flutter доступен.

## Проверка

- Все вызовы `Analytics.capture` идут через единственную точку (обёртку), ключ
  и хост PostHog не дублируются.
- Capture-вызовов внутри `onChanged`/листенеров без защиты флагом не осталось:
  email/phone — за флагами «раз за визит», слайдер — в `onChangeEnd`, скролл —
  в `ScrollEndNotification`. Чекбокс и кнопка изначально срабатывают раз за
  тап, там дополнительная защита не нужна.
