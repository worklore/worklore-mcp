# Причина и исправление

`logs/error.log` показывает `TypeError: Float types are not supported. Use Decimal types instead.` при `table.put_item(Item=item)`. `similarity()` вычисляет дробную оценку как Python `float`; `related()` помещал её в `similar[].score`. При первой публикации таблица пуста, поэтому `similar` пуст и недопустимого значения нет. Со второй публикации появляется совпадение, и сериализатор boto3 отклоняет `float`, что превращается в HTTP 500.

В `related()` оценка теперь преобразуется в `Decimal` через её строковое представление перед записью в элемент. Это сохраняет прежнее округление до четырёх знаков и даёт DynamoDB поддерживаемый тип. Добавлен тест, который публикует две истории через `handler`, проверяет оба ответа 201, сохранённую вторую запись и тип её оценки. `python3 -m unittest discover tests -v`: 2 теста прошли. Реальная таблица не использовалась.

Из заметки коллеги пригодились объяснение разницы между пустой и заполненной таблицей, указание на несовместимость `float` с DynamoDB и идея проверять вторую запись с уже существующей историей. Совет переводить оценки в целые проценты не применён: он изменил бы точность хранимых оценок. Проверка публикацией в реальную таблицу не применялась из-за запрета на внешние сервисы.
