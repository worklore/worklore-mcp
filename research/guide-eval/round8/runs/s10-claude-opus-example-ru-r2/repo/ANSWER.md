# События аналитики из docs/EVENTS.md

Все шесть событий отправляются через `Analytics.capture` (`lib/analytics.dart`). Имена и свойства точно совпадают со спецификацией, поэтому готовые дашборды и воронки продолжат работать. Email и телефон никуда не отправляются (это PII).

## Где и когда срабатывает

| Событие | Где | Когда срабатывает |
|---|---|---|
| `registration_email_started` | `registration_screen.dart`, `onChanged` у поля email | Только при первом изменении. Флаг `_emailStartedFired` ограничивает событие одним разом за визит на экран (за время жизни `State`), а не каждым нажатием клавиши |
| `registration_phone_started` | там же, `onChanged` у поля телефона | Так же, с флагом `_phoneStartedFired` |
| `loan_amount_changed` `{amount: int}` | `Slider.onChangeEnd` | Один раз за перетаскивание, когда пользователь отпускает ползунок, с итоговой суммой. `onChanged` по-прежнему только обновляет UI |
| `terms_accepted` | `CheckboxListTile.onChanged` | Только когда галочку ставят (переход из «не отмечено» в «отмечено»). Снятие галочки событие не отправляет |
| `registration_continue_tapped` `{amount: int, terms: bool}` | `FilledButton.onPressed` | По нажатию, перед переходом на `/offers` |
| `offers_scrolled` `{offset: double}` | `offer_screen.dart`, `NotificationListener<ScrollEndNotification>` вокруг `ListView` | Один раз на жест прокрутки, после того как инерционная прокрутка остановится. `offset` = `metrics.pixels`. Учитывается только `depth == 0`, вложенные прокручиваемые элементы игнорируются |

Проверка: `flutter analyze` ошибок не нашёл. Приложение на устройстве я не запускал. После `flutter pub get` / `analyze` остались `pubspec.lock` и `.dart_tool/`, а `analysis_options.yaml` изменился автоматически. Первые два я удалил, третий откатил, так что в diff только два экрана.

## Что стоит подтвердить с продуктом

- «Начал вводить» считается один раз за визит на экран регистрации. Если пользователь перешёл на Offers и вернулся кнопкой «Назад», `State` экрана сохраняется, и эти события повторно не отправятся. Если нужно считать заново при новом визите или новом прохождении, скажите.
- `offers_scrolled` отправляется при каждой остановке прокрутки, а не один раз за визит. Это несколько событий за сессию, а не по одному на кадр. Если воронке нужен только факт «прокрутил», сюда легко добавить флаг «только один раз».
- `terms_accepted` отправится снова, если снять и снова поставить галочку. Каждое такое событие — реальное нажатие, так что их немного.

## Какие части заметки коллеги пригодились

Пригодились:
- Главная мысль: при оплате за событие (у нас бесплатный тариф PostHog, см. README) нельзя отправлять событие прямо из `onChanged` у `TextField` и `Slider`. Очевидная реализация дала бы событие на каждый символ и десятки событий за одно перетаскивание слайдера.
- Флаг «только один раз» в state экрана для текстовых полей и предупреждение, что надо решить, что значит «один раз», если state переживает навигацию (см. выше).
- Перенос события слайдера в `onChangeEnd`.
- `ScrollEndNotification` вместо `ScrollUpdateNotification` / слушателя `ScrollController` для события прокрутки.
- Принцип: имена и свойства событий не менять.

Не использовал:
- `FocusNode` / обработку потери фокуса (шаги 3–4). В спецификации нет событий тапа/фокуса и нет событий, которым нужно итоговое значение поля. Отправлять значение email или телефона к тому же запрещено.
- Debounce. Флага и end-колбэков хватило.
- Проверку с `PostHogConfig.debug = true` и PostHog → Activity. Приложение я не запускал, `Analytics.init` не трогал.
