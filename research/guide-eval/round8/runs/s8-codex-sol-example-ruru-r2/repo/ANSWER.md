# Исправление кеширования

В `logs/usage.jsonl` после `save_fact` следующий раунд раньше показывал `cache_read_input_tokens: 0` и повторное создание кеша на 1039–1104 токена. Причина: `build_system()` помещал неизменные инструкции и изменяемые факты в один блок с одним маркером `cache_control`.

В `bot.py` системный промпт теперь состоит из двух текстовых блоков с `cache_control: {"type": "ephemeral"}`. Первый содержит одинаковые для всех спортсменов инструкции, второй — дату, профиль и факты. После `save_fact` меняется только второй блок; префикс с инструкциями остаётся тем же. Добавил в статический блок пояснения к существующим правилам, чтобы он был достаточно длинным для минимального размера кешируемого префикса модели. `README.md` обновлён под новую структуру.

Из заметки пригодились разделение по стабильности на два маркера, требование сохранять префикс побайтно одинаковым и проверка через `cache_read_input_tokens` / `cache_creation_input_tokens`. Выбор инструментов по ключевым словам уже был в проекте и остался прежним; внутри одного цикла список инструментов не меняется. Отбор top-N фактов не применялся и не добавлялся: он менял бы кешируемый хвост для каждого сообщения. Разные наборы инструментов между сообщениями всё ещё могут давать отдельные ключи кеша, поскольку схемы идут перед `system`.

Локально проверил сборку запросов и цикл с имитацией вызова `save_fact`: первый блок и список инструментов совпадают до и после записи, новый факт появляется во втором блоке следующего раунда. Внешних вызовов не было, поэтому реальные счётчики кеша после изменения пока не измерены. При следующем разрешённом запуске после `save_fact` ожидается ненулевой `cache_read_input_tokens` для статического префикса и создание кеша только для изменившегося хвоста.
