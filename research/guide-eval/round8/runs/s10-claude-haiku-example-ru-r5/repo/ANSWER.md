# Аналитика на экранах регистрации и списка предложений

Реализованы события из `docs/EVENTS.md` через существующую обёртку `Analytics.capture`
(`lib/analytics.dart`). Имена и свойства событий не менялись. Изменения только в
`lib/screens/registration_screen.dart` и `lib/screens/offer_screen.dart`.

## Что сделано

| Событие | Где отправляется | Свойства |
|---|---|---|
| `registration_email_started` | `onChanged` поля email, один раз за визит | — |
| `registration_phone_started` | `onChanged` поля phone, один раз за визит | — |
| `loan_amount_changed` | `Slider.onChangeEnd`, один раз при отпускании | `amount` (int) |
| `terms_accepted` | `CheckboxListTile.onChanged`, когда галочка поставлена | — |
| `registration_continue_tapped` | `onPressed` кнопки Continue | `amount` (int), `terms` (bool) |
| `offers_scrolled` | `NotificationListener<ScrollEndNotification>` вокруг списка | `offset` (double) |

Детали:
- **Поля ввода.** `onChanged` срабатывает на каждый символ, поэтому в состоянии экрана
  добавлены флаги `_emailStartedFired` и `_phoneStartedFired`. Событие уходит при первом
  изменении поля. Флаги живут в состоянии экрана, поэтому при новом визите сбрасываются.
- **Слайдер.** `onChanged` оставлен только для обновления UI, событие перенесено в
  `onChangeEnd`. В Flutter `onChangeEnd` срабатывает и при тапе по слайдеру, так что
  одиночный тап тоже даёт одно событие.
- **Список предложений.** Событие уходит по `ScrollEndNotification`, а не на каждом
  кадре прокрутки. `ScrollEndNotification` возвращает `false`, чтобы не перехватывать
  уведомление.
- **PII.** Email и телефон в свойства не попадают.

## Решения, которые стоит проверить

1. **`registration_continue_tapped`** отправляется только когда кнопка активна
   (`_canContinue`). Тап по неактивной кнопке не считается нажатием Continue, потому
   что `onPressed` в этом случае `null`. Если продукт хочет считать и такие тапы, это
   отдельная задача: кнопку придётся обернуть в `GestureDetector`.
2. **`terms_accepted`** срабатывает только при установке галочки, снятие не отправляется.
3. **`offers_scrolled.offset`** это позиция `metrics.pixels` в конце прокрутки
   (смещение от начала списка), а не величина прокрутки за жест. Если нужна величина
   за жест, потребуется запоминать позицию в начале прокрутки.

## Что из заметки коллеги пригодилось

- **Пригодилось:** флаг «один раз за визит» для текстовых полей, перенос слайдера на
  `onChangeEnd`, `ScrollEndNotification` вместо обработки каждого кадра. Это те же
  причины дублирования событий, которые есть и здесь.
- **Не понадобилось:** `FocusNode` и отправка по потере фокуса. Ни одно событие из
  `EVENTS.md` не требует финального значения поля. Отдельный тап- или фокус-флаг тоже
  не нужен, у кнопок и галочки отдельные события без повторов.
- **Не выполнено:** проверка по PostHog (Activity, счётчики по сессии) и отладочный запуск
  с `PostHogConfig.debug`. В `lib/analytics.dart` стоит заглушка ключа
  `phc_REPLACE_ME_IN_CI`, а отправка в PostHog в этой работе не делалась. Проверка
  ограничена статическим анализом и чтением кода.
