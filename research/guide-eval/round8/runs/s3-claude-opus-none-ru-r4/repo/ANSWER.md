# Почему nightly-review молчал

launchd отрабатывал как положено: в `launchctl-print.txt` видно `runs = 6`
(6 ночей с 13 по 18 октября) и `last exit code = 1`. Задача каждую ночь
запускалась и падала, а сообщить об этом не могла. Это видно по
`Library/Logs/nightly-review.err` — каждый запуск оставил там две строки:

```
Not logged in · Please run /login
/Users/vk/bin/nightly-review.zsh:19: read-only variable: status
```

## Причина 1 (из-за неё не было даже сообщения об ошибке): `status` в zsh только для чтения

В zsh `$status` — это специальный параметр, синоним `$?`, и он read-only.
Строка `status=$?` (строка 19) — фатальная ошибка: zsh сразу завершает
скрипт с кодом 1. До веток `if [ $status -ne 0 ]` и
`"$NOTIFY" "nightly review FAILED ..."` дело не доходит, и `notify.sh`
не запускается ни в каком случае, ни при успехе, ни при ошибке. Проверка:
`zsh -c 'status=1'` → `read-only variable: status`.

**Исправление:** переменная переименована в `rc`. Плюс на `EXIT` поставлен
`trap`: если скрипт умрёт на любом неожиданном месте, всё равно уйдёт
сообщение «died unexpectedly».

## Причина 2 (из-за неё не было сводок): `claude` под launchd не залогинен

`claude -p` пишет `Not logged in · Please run /login` и выходит с
ненулевым кодом. Окружение launchd совсем не похоже на окружение
терминала: zsh, запущенный неинтерактивно, не читает `~/.zshrc` и
`~/.zprofile` (поэтому туда не попадают, например, `ANTHROPIC_API_KEY` или
`CLAUDE_CODE_OAUTH_TOKEN`, если они экспортированы там), а login‑keychain,
где Claude Code хранит OAuth‑логин, в 02:30 может быть заблокирован или
недоступен фоновому процессу. Из снимка нельзя понять, какой из двух
вариантов твой, но лечится оба одинаково.

**Исправление:** скрипт теперь подхватывает приватный env‑файл
`~/.config/nightly-review/env`, если он есть. Что сделать руками
(в этот снимок я ничего не устанавливал):

```sh
claude setup-token            # выдаст долгоживущий OAuth-токен
mkdir -p ~/.config/nightly-review
printf 'CLAUDE_CODE_OAUTH_TOKEN=%s\n' '<токен>' > ~/.config/nightly-review/env
# по желанию сюда же TG_BOT_TOKEN=..., чтобы notify.sh не зависел от keychain
chmod 600 ~/.config/nightly-review/env
```

Токены сознательно не положены в plist: plist лежит открыто, а
`launchctl print` показывает переменные окружения в выводе.

## Причина 3 (скрытая, сработала бы следующей): `notify.sh` мог молча терять сообщения

- `: "${TG_BOT_TOKEN:=$(security ...)}"`: если `security` не может
  прочитать keychain (под launchd — та же проблема, что в п. 2), `set -e`
  этого **не** ловит, потому что статус команды `:` всегда 0. Токен
  оказывается пустым, запрос уходит на `/bot/sendMessage`.
- `curl -sS` без `-f` считает HTTP 401/404/400 от Telegram успехом, а ответ
  с ошибкой уходил в `/dev/null`. Итог — «отправлено», хотя ничего не
  пришло. (Руками всё работало, потому что из терминала keychain открыт.)
- Сообщения Telegram длиннее 4096 символов отклоняются.

**Исправление:** если ключ из keychain не прочитался, скрипт явно выходит
с ошибкой; у curl добавлены `--fail-with-body` и `--max-time 30`, тело
ответа с ошибкой пишется в stderr; текст обрезается до 4000 символов.
В `nightly-review.zsh` ошибка `notify.sh` больше не теряется, она пишется
в `nightly-review.err`.

## Прочие улучшения в `nightly-review.zsh`

- stderr от `claude` сохраняется в `nightly-review-ДАТА.err`, и его начало
  вставляется в сообщение о сбое (раньше в сообщении было «see $OUT», а
  `$OUT` при ошибке пустой).
- Пустой вывод `claude` считается ошибкой.
- Если `claude` нет в `PATH`, приходит отдельное понятное сообщение.

Plist я не менял, с ним всё в порядке. Изменения в скрипте `launchctl` не
требуют, а вот файл с токеном нужно создать, иначе следующей ночью придёт
уже *сообщение* «claude exit 1: Not logged in». Проверить сразу, не дожидаясь
02:30: `launchctl kickstart gui/$UID/com.vk.nightly-review`.

## Как проверено

Скрипт гонялся на заглушках `claude`/`notify.sh` во временном HOME. Во всех
четырёх сценариях — claude падает с «Not logged in», успех, пустой вывод,
нет репозитория — уведомление отправляется с нужным текстом. Реальные
вызовы Telegram/Claude не выполнялись.
