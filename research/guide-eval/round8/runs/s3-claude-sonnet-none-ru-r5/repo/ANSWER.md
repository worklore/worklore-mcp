# Почему nightly-review молчал

Задача запускалась (runs = 6, расписание 02:30 верное), но ни одного сообщения не отправила. Причин две, и они наслаиваются друг на друга.

1. **`claude` в launchd не авторизован** (`Not logged in · Please run /login` в `nightly-review.err`, 6 раз). Агент выходит с кодом 1 — это и есть `last exit code = 1`. Вручную всё работает, потому что в интерактивной сессии логин есть, а у фонового агента launchd его нет.
2. **Баг в скрипте: `status` — read-only переменная в zsh** (`read-only variable: status`, строка 19). Из-за `status=$?` zsh падал сразу после запуска `claude`, и до ветки `if ... notify.sh "FAILED"` дело не доходило. Уведомление об ошибке было мертво, поэтому первая причина оставалась невидимой в Telegram.

`notify.sh` и Telegram ни при чём: он работает вручную и просто ни разу не вызывался.

## Что исправлено
- `bin/nightly-review.zsh`: переменная `status` переименована в `rc`, теперь сообщение о сбое реально отправляется.
- `bin/notify.sh`: добавлен `curl --fail`, чтобы HTTP-ошибки Telegram (неверный токен и т.п.) давали ненулевой код, а не молчали.

## Что нужно сделать вам (я не могу это сделать из снимка)
- Дать фоновому запуску авторизацию: выполнить `claude setup-token` и добавить полученный токен в `EnvironmentVariables` плиста как `CLAUDE_CODE_OAUTH_TOKEN` (или залогиниться так, чтобы учётные данные были доступны из сессии gui/501). Затем перезагрузить агент: `launchctl bootout gui/$UID/com.vk.nightly-review && launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.vk.nightly-review.plist`, и проверить `launchctl kickstart gui/$UID/com.vk.nightly-review`.
- До этого шага ночной запуск будет приходить в Telegram как «FAILED» — это ожидаемо и уже лучше тишины.
- Скопировать исправленные файлы из этой папки в домашнюю директорию.
