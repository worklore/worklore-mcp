# Почему вторая публикация возвращает 500

## Причина
`similarity()` в `src/app.py` возвращает `float` (`round(0.7 * ... , 4)`), и `related()` кладёт его в `similar[].score`. boto3 не сериализует float в DynamoDB: `TypeError: Float types are not supported. Use Decimal types instead.` (logs/error.log).
Первая публикация проходила, потому что таблица была пуста: `existing == []`, оценок нет, `similar == []`, float'ов в записи нет. Ошибка проявляется только когда есть с чем сравнивать. Единственный тест публиковал только в пустую таблицу, поэтому её не ловил.

## Исправление
- `related()` приводит оценку к `Decimal(str(similarity(...)))` на границе записи (str сохраняет 4 знака точно, без артефактов двоичного float).
- Добавлен тест `test_publish_second_story_with_similarity`: публикует две истории, так что выполняется путь с непустой таблицей; `FakeTable` отвергает float так же, как boto3.

## Что пригодилось из заметки коллеги
- Диагноз (float → DynamoDB, первая запись выживает из-за пустой таблицы) — совпал полностью.
- Идея «конвертировать на границе» и тест с засеянной таблицей — применены.
- Не применено: округление до целых процентов. Я выбрал Decimal, чтобы не менять формат/точность хранимой оценки. Поиск `round(` и `/` в коде дал только `similarity()`; проверка на реальной таблице и деплой не выполнялись (запрещено условиями).
