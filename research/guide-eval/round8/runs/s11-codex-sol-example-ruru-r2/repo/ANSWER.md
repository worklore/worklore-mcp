# Почему вторая публикация возвращала 500

`logs/error.log` показывает `TypeError: Float types are not supported. Use Decimal types instead.` при `table.put_item(Item=item)`. В `src/app.py` список `similar` содержит оценки похожести уже опубликованных историй. `similarity()` вычисляла их через `/` и `round()` с коэффициентами `0.7` и `0.3`, поэтому результатом был Python `float`. Boto3 не сериализует `float` в DynamoDB.

Первая публикация проходила, потому что таблица была пустой: `related()` возвращала пустой список и в записываемом элементе не было оценок. На второй публикации появлялась первая оценка, и сериализация элемента завершалась ошибкой. Обработчик преобразовывал это исключение в HTTP 500.

# Исправление и проверка

Расчёт долей и весов в `similarity()` переведён на `decimal.Decimal`; результат по-прежнему находится в диапазоне 0–1 и округляется до четырёх знаков, но теперь подходит для DynamoDB. Добавлен тест, который публикует две истории через `handler()`, проверяет оба ответа 201 и сохранённую дробную оценку второй истории. Тестовая таблица отклоняет `float` так же, как сериализатор boto3, поэтому этот тест поймал бы прежний сбой.

Проверка: `python3 -m unittest discover tests -v` — 2 теста прошли. Публикация в настоящую таблицу не выполнялась.

# Что пригодилось из заметки коллеги

Пригодились указание на запрет `float` в DynamoDB, объяснение разницы между пустой и заполненной таблицей, поиск делений и `round()` в данных для `put_item` и идея теста со второй записью. Вариант с целыми процентами не использован: `Decimal` сохраняет существующий смысл и точность оценки. Рекомендация дважды публиковать в реальную таблицу не применялась из-за запрета на внешние сервисы; локальный тест проверяет этот путь без AWS.
