# Аналитика: события воронки регистрации

Реализованы все шесть событий из `docs/EVENTS.md` на экранах регистрации и списка предложений. Отправка идёт только через `Analytics.capture`. Имена событий и свойства совпадают со спецификацией.

## Что сделано

### `lib/screens/registration_screen.dart`

| Событие | Где срабатывает | Свойства |
|---|---|---|
| `registration_email_started` | `onChanged` поля email, один раз за визит (флаг `_emailStartedFired`) | — |
| `registration_phone_started` | `onChanged` поля телефона, один раз за визит (флаг `_phoneStartedFired`) | — |
| `loan_amount_changed` | `Slider.onChangeEnd`, один раз за протягивание | `amount` (int) |
| `terms_accepted` | `CheckboxListTile.onChanged`, только когда чекбокс отмечен | — |
| `registration_continue_tapped` | `onPressed` кнопки Continue (кнопка активна только при валидной форме) | `amount` (int), `terms` (bool) |

- Email и телефон в свойствах не отправляются (PII).
- `onChanged` слайдера оставлен только для обновления UI.

### `lib/screens/offer_screen.dart`

| Событие | Где срабатывает | Свойства |
|---|---|---|
| `offers_scrolled` | `NotificationListener<ScrollEndNotification>` вокруг `ListView` | `offset` (double, `metrics.pixels` на конце прокрутки) |

Событие шлётся один раз за жест прокрутки, а не на каждый кадр.

## Что взято из заметки коллеги

- **Флаг «один раз» для текстовых полей.** Нужен, потому что `onChanged` срабатывает на каждое нажатие. Флаги лежат в состоянии экрана.
- **`onChangeEnd` для слайдера.** Событие уходит один раз, когда пользователь отпускает ползунок, а не на каждый шаг.
- **`ScrollEndNotification` вместо обновлений скролла.** Именно это я сделал для списка предложений.

## Что пропущено и почему

- **Шаги аудита через `grep` и чек-лист проверки.** В репозитории ровно два экрана, я просмотрел их целиком.
- **Событие «итоговое значение поля на потере фокуса».** В спецификации нет события, которому оно нужно. Поля отправляют только «начал вводить».
- **Событие на фокус `FocusNode`.** Спецификация его не описывает. Добавлять его сверх спецификации я не стал.
- **Проверка через debug-сборку и PostHog → Activity.** Не выполнялась, см. ниже.

## Открытые решения

- **Что считается «визитом» для флагов `*_started`.** Экран регистрации — корневой маршрут `/`. Флаги живут, пока жив его `State`, поэтому возврат с `/offers` их не сбрасывает. Если нужен сброс при каждом возврате, это делается в `Navigator.pop`/`then` на `pushNamed('/offers')`.
- **`terms_accepted` срабатывает при каждой отметке чекбокса.** Если пользователь снимает и ставит галочку снова, событие уйдёт дважды. Спецификация этого не запрещает, но если нужно строго «один раз», понадобится такой же флаг.
- **`offset` — это позиция на конце прокрутки, а не дельта.** Спецификация говорит «how far they scrolled», и я понял это как позицию.
