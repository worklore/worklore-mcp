# Причина ошибки 500 при повторной публикации и способ её устранения

## Почему первая публикация работала, а вторая возвращала 500

1. **Первая публикация**:
   - При первом запросе таблица DynamoDB пуста (`existing = []`).
   - Функция `related(story, existing)` не находит существующих историй и возвращает пустой список `similar: []`.
   - В сохраняемом объекте `item` отсутствуют числовые поля с плавающей точкой (`float`), поэтому вызов `table.put_item(Item=item)` проходит успешно и возвращает статус 201.

2. **Вторая (и последующие) публикации**:
   - В таблице уже есть сохранённая первая статья (`existing` содержит элементы).
   - Вызывается функция `related(story, existing)`, которая для каждой существующей истории рассчитывает коэффициент схожести с помощью функции `similarity(a, b)`.
   - Функция `similarity()` возвращала результат вызова `round(...)`, имеющий стандартный тип Python `float`.
   - Поле `item["similar"]` содержало список объектов вида `{"slug": ..., "score": <float>}`.
   - Клиент `boto3` (модуль `boto3.dynamodb.types.TypeSerializer`) намеренно запрещает тип `float` при сериализации атрибутов элементов DynamoDB во избежание потерь точности и требует использовать тип `Decimal` из стандартного модуля `decimal`.
   - При попытке выполнить `table.put_item(Item=item)` возникло исключение:
     ```text
     TypeError: Float types are not supported. Use Decimal types instead.
     ```
   - В функции `handler()` исключение попало в общий блок `except Exception:`, где было записано в лог как `publish failed` и привело к ответу с HTTP-кодом 500 (`Internal Server Error`).

## Исправление

1. **В `src/app.py`**:
   - Импортирован класс `Decimal` из модуля `decimal`.
   - Значение схожести в функции `similarity()` преобразуется в `Decimal`:
     ```python
     return Decimal(str(round(0.7 * tag_score + 0.3 * word_score, 4)))
     ```
     Теперь поле `score` сериализуется как числовой тип DynamoDB (`N`) без ошибок валидации типов.

2. **В `tests/test_publish.py`**:
   - Добавлен тест `test_subsequent_publishes_succeed_with_decimal_score`, проверяющий успешность публикации второй истории и валидность типа `Decimal` для поля `score` в списке `similar`.
   - Добавлен тест `test_handler_second_publish_returns_201_not_500`, проверяющий успешный возврат статуса 201 (вместо 500) при последовательных вызовах `handler`.
