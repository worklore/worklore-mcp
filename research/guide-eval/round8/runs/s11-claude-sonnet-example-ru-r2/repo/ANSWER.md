# Почему вторая публикация падает с 500

**Причина.** `similarity()` возвращает `float` (`round(0.7*... , 4)`), а `publish()` кладёт эти значения в `similar[].score` и вызывает `table.put_item`. boto3 не принимает float (`TypeError: Float types are not supported`). При первой публикации таблица пуста, `related()` возвращает `[]` — float'ов нет, всё проходит. Со второй публикации в таблице уже есть истории, появляются score-ы и запись падает. Тест покрывал только путь с пустой таблицей.

**Исправление.**
- `src/app.py`: добавлена `to_dynamo()` (рекурсивно float → `Decimal(str(x))`), применяется к item прямо перед `put_item`. Так любое вычисляемое значение, добавленное в item позже, не сможет снова сломать запись; точность score сохранена.
- `tests/test_publish.py`: новый тест публикует две истории подряд (вторая идёт через путь с существующими данными) и проверяет 201 через `handler`. Без исправления он падает.

## Что пригодилось из заметки коллеги
- Диагноз «первая запись проходит, потому что нет данных для расчёта» — совпал полностью.
- Идея конвертировать на границе записи и тест с предзаполненной таблицей — использованы.
- Не использовано: перевод score в целые проценты — выбрал Decimal, чтобы не менять формат хранимых данных. Проверка на реальной таблице не делалась (по условиям ничего не деплоится и не отправляется).
