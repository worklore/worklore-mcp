# Почему вторая публикация даёт 500

**Причина.** `publish()` кладёт в item поле `similar` со списком `{slug, score}`, где `score` — Python `float`
(результат `round(..., 4)` в `similarity()`). boto3 не умеет сериализовать `float` в DynamoDB и бросает
`TypeError: Float types are not supported. Use Decimal types instead.` (см. `logs/error.log`).

Первая публикация проходит, потому что таблица пуста: `similar` — пустой список, float'ов в item нет.
Начиная со второй публикации в таблице уже есть истории, `similar` непустой, в нём есть float — `put_item` падает,
`handler` превращает исключение в 500. Тест проверял только первую публикацию, поэтому баг не был виден.

**Исправление.**
- `src/app.py`: добавлена `to_dynamo()`, рекурсивно заменяющая `float` на `Decimal(str(x))`; `put_item` вызывается
  с `to_dynamo(item)`. Это защищает весь item, а не только `score`, так что новое float-поле тоже не повторит ошибку.
- `tests/test_publish.py`: добавлен тест второй публикации (непустой `similar`), который падал до исправления.

Замечание (не менялось): `scan` читает только первую страницу (до 1 МБ), так что при большой библиотеке
«похожие» будут считаться по неполному набору — стоит добавить пагинацию по `LastEvaluatedKey`.
