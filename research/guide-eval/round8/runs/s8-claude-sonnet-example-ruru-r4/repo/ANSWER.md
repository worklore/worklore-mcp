# Что изменено

**Причина.** В `build_system` (bot.py) инструкции и контекст атлета (дата, профиль, зоны, цель, факты, язык) склеивались в один блок с одним `cache_control`. `save_fact` меняет факты, значит меняется хеш префикса, и вместе с хвостом пересоздаются ~800 токенов неизменных инструкций. В `logs/usage.jsonl` это видно: после `save_fact` `cache_read_input_tokens: 0` и `cache_creation_input_tokens` ≈ 1100–1300.

**Исправление.** `build_system` теперь возвращает два текстовых блока, у каждого `cache_control: ephemeral`:
1. `INSTRUCTIONS`. Это константа без подстановок (ни даты, ни имён), она одинакова байт в байт.
2. `athlete_context(...)`. Это изменчивый хвост, и запись в память инвалидирует только его.

Инструменты стоят выше системного промпта и не менялись (фильтрация по ключевым словам осталась как есть). Из логики памяти ничего не менял.

**Что пригодилось из заметки коллеги:**
- Идея двух маркеров: статика отдельно, изменчивое отдельно.
- Проверка, что статический блок не содержит подставленных значений. Я проверил, что в `INSTRUCTIONS` их нет.
- Не отбирать факты под сообщение: по-прежнему грузим все, чтобы хвост был стабилен между сообщениями.
- Не трогать порядок и формулировки схем инструментов.
- Проверка по `usage`.

**Что пропущено:**
- Фильтрация инструментов: она уже есть.
- Конкретные числа токенов: у нас свои.

**Проверка.** Я не запускал код с реальным API (ключа и вызовов наружу нет). Ожидаемо в логе: после `save_fact` `cache_read` ≈ размер инструкций, а `cache_creation` — только размер хвоста (сотни токенов, а не ~1100). Дату в хвосте это тоже касается: она меняется раз в сутки и пересоздаёт только хвост.
