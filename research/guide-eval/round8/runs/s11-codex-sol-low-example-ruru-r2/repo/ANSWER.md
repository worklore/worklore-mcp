# Причина

`logs/error.log` показывает ошибку сериализации DynamoDB при `table.put_item`: `Float types are not supported`. `similarity()` вычисляла оценку через деление и возвращала `float`; `related()` помещала её в `similar[].score` сохраняемого элемента. При первой публикации таблица пуста, поэтому `similar` пуст и недопустимого значения в записи нет. На второй публикации появляется совпадение с `float`, и обработчик возвращает 500.

# Исправление

`similarity()` теперь возвращает оценку в целых процентах (`int` от 0 до 100). DynamoDB принимает такой тип. Добавлен регрессионный тест: он публикует две истории через `handler()` в одну таблицу, проверяет оба ответа 201, сохранённое совпадение и целочисленный тип оценки. Это покрывает путь с уже существующей записью.

# Что пригодилось из заметки

Пригодились указание проверить вычисляемые значения в словаре для DynamoDB, объяснение разницы между пустой и заполненной таблицей и идея тестировать вторую запись после первой. Выбран предложенный вариант с целыми процентами. Совет публиковать в реальную таблицу не применялся: задача запрещает внешние сервисы, а локальный `FakeTable` проверяет типы как сериализатор boto3.
