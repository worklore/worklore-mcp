# Что изменено

Причина лишних списаний: `build_system()` объединял статические инструкции и контекст спортсмена, включая долговременные факты, в один блок с `cache_control`. После `save_fact` менялся весь этот блок, поэтому следующий запрос не мог прочитать инструкции из кеша и снова оплачивал их создание.

В `bot.py` функция `build_system()` теперь возвращает два системных блока:

1. Неизменные `INSTRUCTIONS` с `cache_control: {"type": "ephemeral"}`.
2. Динамический `athlete_context()` без маркера кеширования: дата, профиль, цель, зоны и долговременные факты.

Теперь `save_fact` меняет только второй блок. Байтовое содержимое кешируемого префикса инструкций остаётся прежним как во втором раунде tool-use, так и в следующих сообщениях, поэтому запись в память не вытесняет статические инструкции из кеша. Описание поведения в `README.md` обновлено.

Проверка выполнена локально с подменённым LLM, без внешних запросов: смоделированы вызов `save_fact`, второй раунд и следующее сообщение. Во всех трёх запросах кешируемый блок инструкций совпал, а новый факт появился только в динамическом контексте после сохранения.
