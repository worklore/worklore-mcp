# Причина

Вторая публикация падала с `TypeError: Float types are not supported. Use Decimal types instead.`, как показано в `logs/error.log`.

При публикации `publish()` сканирует уже сохранённые истории и вычисляет для них оценки похожести. Функция `similarity()` в `src/app.py` использовала деление и возвращала `float`; эти значения попадали в `item["similar"][*]["score"]`, а затем в `table.put_item()`. Сериализатор boto3 для DynamoDB не принимает Python `float`.

Первая публикация работала, потому что таблица была пуста: список `similar` был пуст, и ни одного `float` в записываемом элементе не было. Существующий тест проверял только этот сценарий, поэтому не обнаруживал ошибку.

# Исправление

В `src/app.py` оценка похожести теперь преобразуется в целое число процентов от 0 до 100 с помощью `int(round(...))`. Таким образом, в DynamoDB передаются поддерживаемые целочисленные значения, а не `float`. Порядок сортировки похожих историй сохраняется, но числовой формат поля `score` изменился с дробной доли на целочисленный процент.

В `tests/test_publish.py` добавлен регрессионный тест `test_publish_with_existing_story_stores_integer_similarity_scores`: он сначала записывает историю, затем публикует вторую, проверяет содержимое `similar`, целочисленный тип `score` и наличие обеих записей. Тестовая таблица отклоняет `float` так же, как сериализатор boto3, поэтому возврат к прежнему поведению снова сломает этот тест.

# Проверка

- `python3 -m unittest discover tests` — 2 теста, все успешно.
- Два последовательных вызова `handler()` с независимыми историями — оба вернули HTTP 201; вторая история сохранилась с целочисленной оценкой похожести.

Проверка выполнена локально с `FakeTable`; обращения к реальному AWS не производились.

# Что пригодилось из заметки коллеги

Пригодились три части: объяснение, почему ошибка проявляется только на непустой таблице; рекомендация преобразовать вычисляемые оценки в целочисленные проценты на границе записи; рекомендация добавить тест записи с предварительно заполненной таблицей. Предложение использовать `Decimal` не потребовалось, поскольку выбран вариант с целыми процентами. Проверка на реальной таблице и внешняя публикация не выполнялись.
