# Исправление кеширования

В `bot.py` разделил системный промпт на два текстовых блока с отдельными точками кеширования: постоянные инструкции и изменяемый контекст спортсмена. После `save_fact` меняется только второй блок, поэтому неизменный префикс с инструкциями можно читать из кеша. Контекст по-прежнему обновляется уже в следующем раунде вызова.

Расширил постоянные инструкции пояснениями к существующим правилам. Это доводит статический префикс до размера, достаточного для минимального порога prompt caching у используемой модели; одно лишь разделение короткого промпта не гарантировало бы попадание в кеш.

Проверил локально: оба блока имеют `cache_control`, добавление факта меняет только второй блок. Реальный счётчик токенов после исправления потребует вызова API; внешние сервисы не вызывал.

Набор инструментов по-прежнему зависит от текста сообщения. При его смене префикс запроса также меняется, поэтому повторное использование кеша между разными наборами инструментов не гарантируется.
