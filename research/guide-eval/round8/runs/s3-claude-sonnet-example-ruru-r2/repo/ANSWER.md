# Почему nightly-review молчала

Задача запускалась (в `launchctl-print.txt`: `runs = 6`, `last exit code = 1`), но падала и не могла об этом сообщить. Два слоя:

1. **`claude -p` падает с «Not logged in · Please run /login»** (это видно в `nightly-review.err`). Под launchd в окружении нет `USER`, и CLI не находит свой логин в keychain. Исправление: в `EnvironmentVariables` plist добавлен `USER=vk`. Это исправление я не проверил, потому что здесь нет ни launchd, ни claude.
2. **`status=$?` в zsh.** `status` — переменная только для чтения, поэтому скрипт умирал на строке 19 («read-only variable: status»). Это происходило до вызова `notify.sh`, так что уведомление об ошибке не отправлялось никогда. Исправление: `rc=$?`. Заодно сбой самого `notify.sh` теперь пишется в stderr, а не теряется.

Дополнительно: `claude -p` теперь получает `< /dev/null`, чтобы не ждать stdin.

## Что пригодилось из заметки коллеги
- Сначала доказать, что задача запускалась (`launchctl print`), и читать лог из `StandardErrorPath` — пригодилось: это сразу дало обе причины.
- Ловушка с `status` в zsh — совпала один в один.
- `USER` в `EnvironmentVariables` — совпало с «Not logged in».
- `< /dev/null` при промпте-аргументе — применено как профилактика.
- Поправка про код выхода: после починки проверяйте не только код 0, но и свежий файл `nightly-review-ДАТА.md` и длительность запуска.

## Что не пригодилось
- Передача промпта через stdin: в логе нет ошибки «Input must be provided…», промпт доходил, поэтому оставлен аргумент.
- Ссылка на статью и общий совет про логирование длительности — не применялись (не проверено, нужно ли).

## Как проверить у себя
`launchctl bootout gui/501/com.vk.nightly-review; launchctl bootstrap gui/501 ~/Library/LaunchAgents/com.vk.nightly-review.plist` (plist изменён, перезагрузить обязательно), затем `launchctl kickstart -k gui/501/com.vk.nightly-review`. Проверьте код 0, свежий `.md`, сообщение в Telegram. Один раз намеренно сломайте запуск (например, неверный `REPO`), чтобы убедиться, что уведомление об ошибке приходит. Если «Not logged in» останется, нужно ещё разобраться с доступом к keychain из сессии launchd.
