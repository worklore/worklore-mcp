# Причина

Вторая публикация падала с `TypeError: Float types are not supported. Use Decimal types instead.` при `table.put_item`.

Функция `similarity()` в `src/app.py` вычисляет коэффициент сходства делением и возвращает `float`. При первой публикации таблица пуста, поэтому список `similar` пуст и проблемного значения в записи нет. При второй публикации `related()` добавляет в `similar` вычисленный `score` типа `float`, а сериализатор DynamoDB такие значения не принимает. Обработчик перехватывает исключение и возвращает 500.

# Исправление

В `src/app.py` значение `score` преобразуется при формировании связанной записи в целочисленный процент от 0 до 100: `int(round(similarity(...) * 100))`. DynamoDB принимает такие значения как числа; внутренний расчёт и сортировка по сходству не изменены.

В `tests/test_publish.py` добавлен регрессионный тест `test_second_publish_with_existing_story`: он последовательно вызывает `handler()` для двух историй, проверяет два ответа 201, наличие обеих записей и целочисленный `score` у второй записи. Так тест обязательно проходит путь с уже заполненной таблицей, который раньше не проверялся.

Проверка: `python3 -m unittest discover tests -v` — 2 теста, все успешно. До исправления отдельный сценарий двух публикаций воспроизвёл 201 на первом запросе и 500 на втором.

# Что пригодилось из заметки коллеги

- Объяснение, почему ошибка проявляется только на второй записи: на пустой таблице не вычисляются оценки сходства.
- Рекомендация проследить вычисляемые значения до записи и преобразовать оценку в целочисленные проценты на границе с DynamoDB.
- Рекомендация добавить тест записи при уже заполненной таблице.

Проверка на реальной таблице AWS не выполнялась: использовался имеющийся `FakeTable`, который воспроизводит проверку типов сериализатора boto3; внешние сервисы не вызывались.
