# Исправление Intervals.icu

## Причины

1. Кнопка была ссылкой на `GET /api/intervals/auth/init`. Переход браузера не передавал токен tricoach из `localStorage` в заголовке `Authorization`, поэтому сервер отвечал 401 всем атлетам. Это прямо видно в `logs/connect-attempt.log`.
2. Запрашивались `ACTIVITY:READ` вместе с `ACTIVITY:WRITE` и `CALENDAR:READ` вместе с `CALENDAR:WRITE`. `WRITE` уже включает `READ`; повтор области приводил к ошибке авторизации до экрана согласия. По журналу это началось после добавления календаря.
3. Ответ Intervals для успешно подключённого атлета не содержал `expires_in` и `refresh_token`. Код назначал произвольный срок в 3600 секунд и фоновым потоком очищал действующий токен. Поэтому Rivera получил приглашение подключиться заново примерно через час.

## Что изменено

- SPA вызывает авторизованный `POST /api/intervals/auth/init` через `fetch` и переходит по возвращённому `authorize_url`.
- Scope содержит каждую область один раз: `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`.
- Убраны вымышленный срок действия и обновление токена. При 401 от API Intervals токен очищается, а статус становится `revoked, reconnect`.
- Обмен кода отправляет только `client_id`, `client_secret`, `code`. Подписанный `state` проверяет назначение, возраст не более 15 минут и существование пользователя. Повторное подключение к другому athlete ID отклоняется.

## Что пригодилось из заметки

Пригодились сведения об отсутствии `refresh_token`/`expires_in`, правиле уникальности scope, полях обмена кода, необходимости авторизованного POST для init, использовании `state` в callback и обработке отзыва токена по 401. Вместо JWT оставлена существующая подпись HMAC с назначением и TTL: для этого приложения она обеспечивает нужную проверку без новой зависимости. Рекомендация о шифровании хранения относится к постоянному хранилищу; этот учебный сервер держит подключения только в памяти, а производственное хранение здесь не реализовано.

## Проверка

Локально проверены синтаксис Python и `git diff --check`; HTTP-проверка подтвердила 404 для прежнего GET, 401 для POST без авторизации, корректный authorize URL для авторизованного POST, точные поля обмена токена, сохранение подключения без срока действия и очистку токена после смоделированного 401. Реальный OAuth с Intervals не выполнялся: нет рабочих учётных данных, и внешние запросы запрещены условием задачи.
