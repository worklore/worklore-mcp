# Что изменено

## Проблема

`build_system()` собирал системный промпт в один блок с одним маркером
`cache_control: ephemeral`. Кеш Anthropic — хеш префикса: каждый вызов
`save_fact` добавлял факт в хвост блока, ломал хеш, и весь блок (~1000 токенов,
включая никогда не меняющиеся инструкции) пересоздавался. Это видно в
`logs/usage.jsonl`: после каждого `save_fact` у следующего раунда
`cache_read_input_tokens: 0` и `cache_creation_input_tokens` ~1060+.

## Изменение (bot.py, `build_system`)

Системный промпт разбит на два блока, каждый со своим маркером
`cache_control: {"type": "ephemeral"}`:

1. **Блок 1 — статические инструкции** (`INSTRUCTIONS`): байт в байт одинаковые
   для всех атлетов и дат. Никаких подстановок внутри.
2. **Блок 2 — изменчивый хвост** (`athlete_context`): дата, имя, зоны, цель,
   долговременные факты, язык.

Теперь запись в память инвалидирует только блок 2 (~150–250 токенов); блок 1
остаётся горячим. Итерации цикла инструментов и следующие сообщения в пределах
5-минутного TTL снова читают инструкции из кеша по ~10% цены.

Заодно обновлена фраза в README.md: раньше там было «the system prompt carries
a `cache_control` marker» (теперь сегментов два).

## Проверка

Без обращения к реальному API (фейковый LLM, изолированные копии
`athletes.json` и `usage.jsonl`, удалены после прогона):

- прогнан сценарий «сообщение → save_fact → следующий раунд»: текст блока 1
  после `save_fact` байт-в-байт равен `INSTRUCTIONS`, блок 2 изменился и
  содержит новый факт;
- оба блока несут свой `cache_control`;
- блок 1 идентичен для разных атлетов и разных дат.

В проде контроль по `logs/usage.jsonl`: после `save_fact` у следующего вызова
`cache_read_input_tokens` должен покрывать блок инструкций, а
`cache_creation_input_tokens` — быть размером только с контекстный хвост.

## Что взято из заметки коллеги

Пригодилось:

- **Ключевая идея — два сегмента `cache_control` вместо одного**: статика
  отдельно, изменчивый хвост отдельно. Это и есть весь фикс.
- **Правило «статика байт-в-байт»**: в блок инструкций не подставляется ни
  дата, ни имя, ни счётчики — всё изменчивое уехало во второй блок. Дата
  (`Today: ...`) лежит именно там.
- **Проверка через `usage`**: `cache_creation_input_tokens` /
  `cache_read_input_tokens` — точный индикатор того, что инвалидировалось.
- **Отказ от top-N отбора фактов под сообщение**: весь список фактов
  включается целиком, чтобы хвост не становился разным для каждого сообщения.

Пропущено (не требовалось для этой задачи):

- Фильтрация инструментов по ключевым словам — в этом боте она уже была из
  марта и в NOTES.md отмечена как явный выигрыш, трогать не стал. В логе
  видно напряжение из заметки (сообщение с `plan_week`/`predict_race` один раз
  перечитывает всё из-за смены списка инструментов выше системного промпта),
  но оставлено как есть: внутри цикла одного сообщения список постоянен, а
  базовый набор покрывает типичный случай.
- Ограничение «4 маркера на запрос» — используем только 2, проблемы нет.
