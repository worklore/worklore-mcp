# Исправление пульсовых коридоров

В `gen.py` нижняя граница HR-цели теперь записывается в поле `start` вместо `value`: `{"units": "%lthr", "start": <нижняя>, "end": <верхняя>}`. Для каждого шага, включая шаги внутри повторов, генератор формирует коридор Instant HR. Проценты LTHR сохранены: Intervals должен пересчитать их в bpm по своему LTHR (172), чтобы на часах появились запланированные границы, например 129–141 для 75–82%.

Из заметки коллеги пригодилось различие между `start/end` и `value/end` и подтверждение, что нужно оставлять единицы `%lthr`. Описанные там попытки с `bpm` и `start_bpm`/`end_bpm` согласуются с уже записанными неудачными пробами в `readback/watch-notes.md`. Советы про текстовое поле `description` здесь не применял: в нашем readback `workout_doc.steps` уже заполнено, а задача касается границ пульса, не отображения шагов в веб-интерфейсе.

Локально проверено, что генератор выдаёт `start/end` для всех четырёх HR-шагов и больше не выдаёт `value`. Синхронизацию с Garmin и проверку на часах не выполнял: по условию задачи ничего не отправлял во внешние сервисы.
