# Реализация событий аналитики

Были реализованы все события аналитики из `docs/EVENTS.md` с использованием существующей обёртки `Analytics` (`Analytics.capture(...)`).

## 1. Что сделано

### Экран регистрации (`lib/screens/registration_screen.dart`):
1. **`registration_email_started`**: отправляется при начале ввода email пользователем (однократно за визит на экран с использованием флага `_emailInputFired`). Никакие PII (сам email) не передаются.
2. **`registration_phone_started`**: отправляется при начале ввода телефона пользователем (однократно за визит на экран с использованием флага `_phoneInputFired`). Номер телефона не передаётся.
3. **`loan_amount_changed`**: отправляется в коллбэке `onChangeEnd` у виджета `Slider` при отпускании ползунка. Передаёт свойство `amount` (int: `v.round()`).
4. **`terms_accepted`**: отправляется при установке чекбокса принятия условий (`_terms == true`).
5. **`registration_continue_tapped`**: отправляется при нажатии кнопки «Continue». Передаёт свойства `amount` (int: `_amount.round()`) и `terms` (bool: `_terms`).

### Экран списка предложений (`lib/screens/offer_screen.dart`):
6. **`offers_scrolled`**: отправляется по завершении прокрутки списка предложений с использованием `NotificationListener<ScrollEndNotification>`. Передаёт свойство `offset` (double: `notification.metrics.pixels`).

---

## 2. Какие части заметки коллеги пригодились

Из заметки коллеги пригодились следующие ключевые подходы к оптимизации расхода квоты событий аналитики:
- **Однократная отправка при начале ввода в текстовые поля**: использование булевых флагов в состоянии экрана (`_emailInputFired`, `_phoneInputFired`), чтобы событие старта ввода (`*_started`) отправлялось ровно один раз за визит при первой правке, а не на каждое нажатие клавиши в `onChanged`.
- **Использование `onChangeEnd` для слайдера**: отправка события `loan_amount_changed` вынесена в `onChangeEnd`, предотвращая лавину событий на каждый промежуточный шаг перетаскивания ползунка (`onChanged` оставлен только для перерисовки UI).
- **Слушатель `ScrollEndNotification` для списков**: использование `NotificationListener<ScrollEndNotification>` вместо отслеживания каждого шага прокрутки, чтобы событие `offers_scrolled` отправлялось один раз в момент завершения скролла.
- **Сохранение точных названий событий и параметров**: имена событий и состав полей сохранены в строгом соответствии со спецификацией в `docs/EVENTS.md`.

Не потребовались рекомендации по работе с `FocusNode` (для отслеживания потери фокуса или тапов), так как в спецификации требовались именно события начала ввода и действия по нажатию кнопок/завершению перетаскивания.
