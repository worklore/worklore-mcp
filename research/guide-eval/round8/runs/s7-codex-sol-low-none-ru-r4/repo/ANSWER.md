# Причины сбоев Intervals.icu

1. Кнопка была обычной ссылкой на `/api/intervals/auth/init`. Переход браузера по ссылке не использует SPA-обёртку `fetch`, которая добавляет `Authorization: Bearer`. Поэтому сервер отвечал 401 каждому атлету. Теперь кнопка запрашивает URL через авторизованный API-вызов и затем открывает его.
2. После добавления синхронизации календаря в `scope` появились `CALENDAR:READ` и `CALENDAR:WRITE`. Записанный в логах запрос с ними получает `invalid_request` до экрана согласия. Плановые тренировки в Intervals.icu относятся к activities; для них запрашивается `ACTIVITY:WRITE`. Неподдерживаемые календарные scopes удалены.
3. Ответ токен-сервера для Rivera не содержал ни `expires_in`, ни `refresh_token`. Сервер сам назначал срок в 3600 секунд и затем помечал подключение истёкшим. Теперь при отсутствии `expires_in` срок не назначается; при явно указанном сроке обновление выполняется только при наличии refresh token, иначе подключение считается истёкшим по фактическому сроку.
