# Исправление кеширования промпта

В `bot.py` системный промпт разбит на два текстовых блока с отдельными маркерами `cache_control: ephemeral`. Первый содержит неизменные инструкции; второй — дату, профиль, зоны, цель, факты и язык спортсмена. `save_fact` меняет только второй блок, поэтому статический префикс запроса остаётся прежним. Суммарный текст промпта сохранён байт в байт.

Добавлены локальные тесты: они проверяют текст промпта, неизменность блока инструкций и списка инструментов после `save_fact`, а также обновление фактов в следующем раунде. Команда `python3 -m unittest -v test_bot.py` прошла: 2 теста.

Из заметки коллеги пригодились принцип кеширования по префиксу, два маркера для статической и изменчивой частей, а также проверка через поля `cache_creation_input_tokens` и `cache_read_input_tokens`. Отбор фактов под отдельное сообщение здесь не внедрялся: он менял бы кешируемый контекст на каждом запросе. Фильтрация инструментов уже была в проекте и сохранена без изменений.

В `logs/usage.jsonl` до исправления после `save_fact` видно `cache_read_input_tokens: 0` и создание кеша на 1039–1104 токена. Фактические значения после исправления не измерялись: обращения к Claude API запрещены условиями задачи. Проверка на реальном трафике должна показать чтение статического префикса из кеша после записи факта; результат также зависит от ограничений провайдера на минимальный размер кешируемого префикса и времени жизни кеша.
