# Причина сбоя и внесенные исправления

## 1. Почему первая публикация работала, а вторая возвращала 500

В [logs/error.log](file:///tmp/h-KKYQk7/logs/error.log) зафиксирована ошибка:
```
TypeError: Float types are not supported. Use Decimal types instead.
```
возникающая при вызове `table.put_item(Item=item)` в [src/app.py](file:///tmp/h-KKYQk7/src/app.py#L63).

### Механизм возникновения ошибки:
1. DynamoDB / Boto3 (`TypeSerializer`) не поддерживает стандартный тип Python `float`. Числа с плавающей точкой должны быть представлены типом `decimal.Decimal` или целыми числами (`int`).
2. При вызове функции `publish(table, story)` вычисляется список похожих публикаций: `item["similar"] = related(story, existing)`.
3. Для каждой существующей публикации вычисляется оценка сходства через функцию `similarity(a, b)`, возвращавшую `float`:
   ```python
   round(0.7 * tag_score + 0.3 * word_score, 4)
   ```
4. **Первая публикация**: таблица DynamoDB была пуста (`existing == []`). Цикл в `related()` ни разу не выполнился, список `item["similar"]` остался пустым (`[]`), и в сохраняемый `item` значения `float` не попали.
5. **Вторая публикация**: в таблице уже была сохранена одна публикация (`len(existing) > 0`). Функция `related()` вычислила сходство со старой записью и добавила в `similar` объект с ключом `score` типа `float`. При сериализации `put_item` boto3 выбросил исключение `TypeError`, что привело к ответу 500 Internal Server Error.

---

## 2. Что было исправлено, чтобы это не могло повториться

1. **Исправлен тип возвращаемого значения в [src/app.py](file:///tmp/h-KKYQk7/src/app.py#L31)**:
   - Импортирован класс `Decimal` из модуля `decimal`.
   - В функции `similarity()` результат преобразуется в `Decimal(str(round(...)))`:
     ```python
     return Decimal(str(round(0.7 * tag_score + 0.3 * word_score, 4)))
     ```
   - Это гарантирует полную совместимость с DynamoDB / boto3 и сохраняет точность до 4 знаков.

2. **Добавлены регрессионные тесты в [tests/test_publish.py](file:///tmp/h-KKYQk7/tests/test_publish.py)**:
   - `test_publish_second_story_succeeds`: проверяет публикацию второй статьи в уже непустую таблицу (заполненную первой статьей) и корректное вычисление и сохранение похожих статей (`similar`).
   - `test_handler_second_publish_returns_201`: проверяет полный путь запроса через `handler()` при повторной публикации и возвращение кода ответа 201.

## 3. Какие части заметки коллеги пригодились

### Что пригодилось:
- **Диагноз ошибки**: объяснение того, почему DynamoDB падает именно на второй записи (`TypeError: Float types are not supported. Use Decimal types instead.`) из-за вычисления оценок сходства (`similarity scores`), когда база перестает быть пустой.
- **Подход к исправлению типа**: использование `Decimal` на границе записи в DynamoDB.
- **Подход к тестированию**: рекомендация создавать тесты, которые тестируют путь записи при уже непустой базе (seed table with one record before testing the write), так как код, зависящий от состояния (scoring, related items), выполняется только при наличии данных.

### Что было пропущено / не понадобилось:
- Преобразование оценки в целочисленные проценты (в текущем сервисе сохранен исходный масштаб с точностью до 4 знаков через `Decimal`).
- Рекомендации по поиску через grep по всем местам кодовой базы (проект компактный, место вычисления `round` было одно — в функции `similarity`).
- Шаги, относящиеся к AWS Lambda / внешним окружениям и реальным развертываниям DynamoDB.
