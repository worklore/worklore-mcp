# Реализация событий аналитики (docs/EVENTS.md)

## Что сделано

Реализованы все 6 событий из спецификации через существующую обёртку
`Analytics.capture` (`lib/analytics.dart`). Имена и свойства совпадают со
спецификацией один в один, чтобы не сломать уже построенные дашборды и воронки.

**`lib/screens/registration_screen.dart`**

| Событие | Где срабатывает |
|---|---|
| `registration_email_started` | При первом редактировании поля email (флаг `_emailStartedFired`). Без свойств — PII не отправляем. |
| `registration_phone_started` | При первом редактировании поля телефона (флаг `_phoneStartedFired`). Без свойств — PII не отправляем. |
| `loan_amount_changed` | В `onChangeEnd` слайдера — один раз за протягивание, при отпускании. Свойство `amount` (int, округлённое значение). |
| `terms_accepted` | Один раз, при первой установке галочки (флаг `_termsAcceptedFired`). Снятие/повторная установка галочки не дублирует событие. |
| `registration_continue_tapped` | В `onPressed` кнопки Continue перед навигацией. Свойства `amount` (int), `terms` (bool). |

**`lib/screens/offer_screen.dart`**

| Событие | Где срабатывает |
|---|---|
| `offers_scrolled` | В `NotificationListener<ScrollEndNotification>` поверх `ListView.builder` — один раз за окончание жеста прокрутки, не на каждое обновление скролла. Свойство `offset` (double, `metrics.pixels`). |

## Какие части заметки коллеги пригодились

- **Главный принцип — не слать событие на каждое срабатывание `onChanged`** —
  применён ко всем «шумным» коллбэкам. Без этого адрес email дал бы ~20
  событий, а одно протягивание слайдера — десятки. Заметка буквально описывает
  текущую спецификацию (`registration_email_started`, `loan_amount_changed`),
  так что это был не теоретический риск, а готовая ловушка.
- **Текстовые поля: один раз за посещение через `bool`-флаг в состоянии
  экрана** — использовано для email и phone (`_emailStartedFired`,
  `_phoneStartedFired`).
- **Слайдер: событие в `onChangeEnd`, `onChanged` только для UI** — использовано
  для `loan_amount_changed`.
- **Скролл: `ScrollEndNotification` вместо `ScrollUpdateNotification`** —
  использовано для `offers_scrolled`.
- **Не менять имена событий и свойства, чтобы дашборды продолжали работать** —
  имена взяты из EVENTS.md точно, без «улучшений».

Пропущено как неприменимое:

- События по потере фокуса (`FocusNode`) — ни одному событию не нужно итоговое
  значение поля, спецификация это явно запрещает (PII).
- Слушатели `ScrollController` / проверка через `grep` — проект маленький, все
  capture добавлены заново и сразу с правильным триггером.
- Шаг про `PostHogConfig.debug = true` и проверку в дашборде PostHog — не
  выполнял: окружение не позволяет запустить Flutter/приложение и не должен
  отправлять события во внешние сервисы.

Дополнительно, по духу заметки: `terms_accepted` тоже поставлен за флагом
«один раз», чтобы снятие/повторная установка галочки не дублировала событие.

## Проверка

- `flutter analyze` / `dart analyze` запустить не удалось: SDK установлен
  (`~/development/flutter`), но macOS блокирует его запуск из этой сессии
  («Operation not permitted»). Код проверен вручную на корректность скобок,
  типов (`amount` — `int` через `.round()`, `offset` — `double` из
  `metrics.pixels`) и имён событий по таблице EVENTS.md.
- Рекомендую после пуша прогнать `flutter analyze` в нормальном окружении и
  одну ручную сессию с `PostHogConfig.debug = true`: ввести 20 символов в
  каждое поле (по одному `*_started`-событию), протянуть слайдер (одно
  `loan_amount_changed` при отпускании), проскроллить список (по одному
  `offers_scrolled` на каждое окончание скролла).
