# Причина

`similarity()` в `src/app.py` вычисляет оценку похожести через деление и `round()`, поэтому возвращает `float`. При наличии других историй `related()` помещал это значение в `similar[].score`, после чего `put_item()` отклонял всю запись: DynamoDB через boto3 не принимает Python `float` и требует `int` или `Decimal`.

Первая публикация проходила, потому что `scan()` возвращал пустой список: похожих историй не было, оценки не вычислялись и `similar` сохранялся как пустой список. На второй публикации выполнялся уже путь с существующими данными, и возникал `TypeError: Float types are not supported. Use Decimal types instead.`, который `handler()` превращал в ответ 500.

# Исправление

В `src/app.py` оценка теперь преобразуется на границе формирования сохраняемых данных в целое число процентов от 0 до 100:

```python
int(round(similarity(story, other) * 100))
```

Внутренний расчёт похожести не изменился, но в DynamoDB больше не передаётся `float` в `similar[].score`.

В `tests/test_publish.py` добавлен регрессионный тест `test_second_publish_with_existing_story`: он последовательно вызывает `handler()` для двух историй, проверяет два ответа 201 и убеждается, что вторая запись содержит целочисленную оценку похожести. Таким образом тестируется путь с непустой таблицей, который раньше оставался непроверенным.

Проверка: `python3 -m unittest discover tests` — 2 теста, все проходят.

# Что пригодилось из заметки коллеги

- Объяснение, почему ошибка проявляется только при второй записи: пустая база скрывает вычисление оценок.
- Рекомендация проследить вычисляемые значения с делением и `round()` до записи в DynamoDB.
- Вариант исправления через целые проценты вместо `float`.
- Рекомендация добавить регрессионный тест, который сначала заполняет таблицу, а затем выполняет вторую запись.
