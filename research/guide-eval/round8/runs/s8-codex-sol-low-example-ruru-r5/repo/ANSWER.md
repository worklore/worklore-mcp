# Исправление кеширования

В `bot.py` функция `build_system` теперь отправляет два текстовых блока с отдельными `cache_control: ephemeral`. Первый содержит неизменные инструкции `INSTRUCTIONS`, второй — дату и данные спортсмена, включая долговременные факты. После `save_fact` меняется только второй блок, поэтому статический префикс может читаться из кеша.

В `logs/usage.jsonl` до исправления после `save_fact` видно `cache_read_input_tokens: 0` и повторное создание примерно 1000 токенов. Это подтверждает причину, но в репозитории нет нового вызова Anthropic API для измерения эффекта после правки. Локальная проверка подтвердила два маркера и неизменность первого блока при добавлении факта.

Из заметки коллеги пригодились разделение стабильных инструкций и изменчивого контекста на два кешируемых блока, а также проверка по `cache_creation_input_tokens` и `cache_read_input_tokens`. Идеи об отборе top-N фактов и изменении фильтрации инструментов не применял: такого отбора здесь нет, а существующую фильтрацию `NOTES.md` просит сохранить. Смена набора инструментов по теме сообщения всё ещё может вызвать отдельный промах кеша, как уже видно в журнале для `plan_week` и `predict_race`.
