# Почему уведомлений не было

`launchctl-print.txt` подтверждает, что агент запускался шесть раз и завершался с кодом 1. В `Library/Logs/nightly-review.err` каждый запуск оставил две строки:

1. `Not logged in · Please run /login`: `claude -p` не был авторизован в окружении launchd. Фоновый агент получает ограниченное окружение и не может полагаться на интерактивный вход в CLI.
2. `read-only variable: status`: в zsh `status` — специальная переменная только для чтения. Присваивание после `claude` прерывало скрипт до ветки отправки сообщения об ошибке. Поэтому не приходило даже сообщение о сбое.

Исправлено: код завершения сохраняется в `rc`; stderr `claude` пишется в отдельный датированный файл; при отсутствии репозитория, ключа или ошибке `claude` скрипт вызывает уведомление и пишет причину в stderr launchd. Для фоновой авторизации скрипт читает `ANTHROPIC_API_KEY` из переменной окружения либо из login Keychain (generic password с service `anthropic-api-key`). Также `notify.sh` теперь считает HTTP-ошибку Telegram ошибкой, которую видно в логе.

Для работы на исходном Mac нужно **создать в login Keychain запись `anthropic-api-key` с действующим Anthropic API key** (либо передать `ANTHROPIC_API_KEY` агенту через защищённый механизм) и убедиться, что launchd может читать записи `anthropic-api-key` и `tg-bot` без интерактивного запроса. Снимок не содержит секретов, поэтому это действие нельзя выполнить здесь. Исправленные файлы из снимка затем нужно перенести в соответствующие пути домашней директории; здесь ничего не устанавливалось и не отправлялось.
