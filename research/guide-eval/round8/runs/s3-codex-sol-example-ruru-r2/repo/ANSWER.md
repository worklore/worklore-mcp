# Почему ночная задача молчала

`launchctl-print.txt` показывает `runs = 6` и `last exit code = 1`: launchd запускал задачу. В `Library/Logs/nightly-review.err` для каждого запуска повторяется одна и та же пара ошибок:

1. `claude` завершался с `Not logged in · Please run /login`. В окружении задачи есть `PATH`, но нет `USER`. Это вероятная причина, по которой CLI не находил сохранённую авторизацию в контексте launchd. В plist добавлен `USER=vk`. По одному снимку нельзя доказать, что сама авторизация в keychain действительна; это проверяется только на исходном Mac после загрузки обновлённого агента.
2. Следующая строка скрипта, `status=$?`, завершала zsh с `read-only variable: status`. В zsh `status` — специальная переменная только для чтения. Поэтому скрипт не доходил до уведомления о сбое. Код выхода теперь сохраняется в `rc`, а ошибка сразу передаётся в `notify.sh` и пишется в stderr.

Дополнительно скрипт закрывает stdin для `claude -p`, проверяет, что успешная команда создала непустой обзор, и пишет длительность запуска. `notify.sh` теперь использует `curl -f`: отказ HTTP больше не выглядит успешной отправкой. При ошибке отправки скрипт пишет её в stderr и выходит с ненулевым кодом.

## Что пригодилось из заметки коллеги

- Проверка `launchctl print` и stderr: они отделили запуск задачи от успешного результата и указали на обе реальные ошибки.
- Предупреждение о `status` в zsh: это точная причина отсутствия уведомлений об ошибке.
- `USER` в `EnvironmentVariables`: применено из-за отсутствующего `USER` и ошибки входа в `claude`.
- Закрытие stdin при промпте аргументом, проверка реального результата и длительности: применены для диагностики и защиты от ложного успеха.

Передача промпта через stdin здесь не потребовалась: лог не содержит ошибки об отсутствующем вводе, а вызов уже передаёт промпт одним аргументом `"$PROMPT"`. `kickstart` и проверка настоящего Telegram-сообщения не выполнялись: это снимок домашней директории, а внешние вызовы запрещены.

Локально проверены синтаксис zsh/bash, корректность plist и четыре сценария с заглушками: успешный обзор, ошибка `claude`, пустой обзор и отказ уведомления. После переноса исправлений на исходный Mac потребуется перезагрузить LaunchAgent и проверить свежий обзор, stderr и сообщение в Telegram.
