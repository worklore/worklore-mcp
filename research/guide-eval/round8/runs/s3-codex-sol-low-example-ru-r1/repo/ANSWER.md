# Почему задача молчала

`launchctl-print.txt` показывает `runs = 6` и `last exit code = 1`: launchd запускал задачу. В `Library/Logs/nightly-review.err` для каждого запуска видна цепочка из двух ошибок:

1. `claude` завершался с `Not logged in · Please run /login`. В окружении задачи из plist отсутствовал `USER`; добавлено `USER=vk`, чтобы CLI мог найти вход в связке ключей при запуске через launchd.
2. Сразу после вызова CLI скрипт присваивал `status=$?`. В zsh `status` — переменная только для чтения. Ошибка на этой строке прекращала выполнение до ветки, отправляющей сообщение об ошибке. Теперь код возврата хранится в `rc`.

Промпт уже передавался аргументом `-p`, поэтому перенаправлять его через stdin не требовалось. Для такого вызова stdin закрыт через `< /dev/null`. Также добавлена проверка непустого отчёта: успешный код возврата сам по себе не доказывает, что обзор создан. Если отправка сообщения об ошибке тоже не удастся, скрипт запишет это в stderr.

Из заметки коллеги пригодились проверка `launchctl print` и stderr, замена `status` на `rc`, установка `USER`, закрытие stdin при промпте-аргументе и проверка реального результата. Совет передавать промпт через stdin здесь не нужен: аргумент `-p "$PROMPT"` уже корректно заключён в кавычки. Проверку через `kickstart` и реальную отправку в Telegram не проводил: по условию нельзя ничего отправлять во внешний сервис и работать вне текущей папки. Исправленный plist потребуется загрузить в настоящий launchd отдельно; снимок сам по себе действующую задачу не меняет.
