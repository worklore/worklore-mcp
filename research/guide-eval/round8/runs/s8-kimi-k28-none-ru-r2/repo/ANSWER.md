# Что изменено

## Проблема

`build_system()` собирал системный промпт в один текстовый блок: статические
инструкции (~1000 токенов) + контекст атлета (профиль, зоны, цель, список
фактов) — и ставил `cache_control` на этот блок целиком. Кеш промпта в Anthropic
префиксный: при изменении текста инвалидируется всё от первого отличающегося
символа. Каждый `save_fact` дописывает факт в конец списка → меняется текст
блока → кеш-попадание на следующем вызове равно нулю, и ~1000 токенов
инструкций заново пишутся в кеш (`cache_creation_input_tokens ~1000`,
`cache_read_input_tokens: 0` на втором раунде после каждого `save_fact` в
`logs/usage.jsonl`).

## Исправление

- `bot.py`, `build_system()`: системный промпт теперь два блока вместо одного —
  1. статические `INSTRUCTIONS` с маркером `cache_control` (точка разрыва кеша
     сразу после инструкций);
  2. динамический `athlete_context()` (дата, профиль, факты) без маркера.
- `README.md`: описание кеширования приведено в соответствие с новой схемой.

Изменения фактов теперь попадают только во второй, немаркированный блок:
префикс запроса до точки разрыва остаётся байт-в-байт прежним, поэтому
инструкции читаются из кеша, а добавленный факт оплачивается как обычные
input-токены (единицы токенов вместо ~1000 за пересоздание кеша). Дата
`Today:` изначально живёт в контекстном блоке, так что смена дня тоже не
трогает кеш. Статический блок одинаков для всех атлетов — бонусом инструкции
теперь попадают в кеш и между пользователями (первое сообщение нового атлета
читает уже подогретый кеш, как у пользователя 77 в логе раньше не получалось).

## Проверка

- `build_system()` возвращает два блока, маркер только на первом.
- После `run_tool(a, "save_fact", ...)` повторный запрос содержит тот же
  байт-в-байт первый блок; меняется только второй (в нём появляется новый факт).
- Полный цикл `reply()` с фейковым LLM (раунд `save_fact` + финальный текст)
  работает, логирование usage не затронуто.
- `data/athletes.json` и `logs/usage.jsonl` после проверки восстановлены
  (`git checkout`), сторонних файлов не осталось.

Замечание: строки лога с `cache_creation ~1300` после `plan_week` /
`predict_race` — отдельное явление (между сообщениями меняется блок tools,
идущий после системного промпта, поэтому суффикс кеша пересоздаётся). На
статические инструкции это после исправления не влияет — они теперь
заканчиваются точкой разрыва до блока tools и продолжают попадать в кеш.
