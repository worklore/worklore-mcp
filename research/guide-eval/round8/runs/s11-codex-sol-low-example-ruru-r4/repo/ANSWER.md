# Почему вторая публикация возвращала 500

Первая публикация проходит по пустой таблице: `related()` возвращает пустой список. При второй публикации в `similar` появляется вычисленный `score` типа Python `float`. В `logs/error.log` ошибка возникает в `table.put_item`: сериализатор boto3 для DynamoDB не принимает `float`, в том числе внутри вложенного списка.

# Исправление

В `src/app.py` оценка переводится в `Decimal` при формировании записи `similar`. Преобразование через строку сохраняет рассчитанное и округлённое значение без внесения артефактов двоичной арифметики. Теперь `put_item` получает допустимый для DynamoDB числовой тип на пути с уже заполненной таблицей.

Добавлен тест двух последовательных вызовов `handler()` с одной таблицей. Он проверяет оба ответа `201`, наличие второй записи и сохранённую оценку типа `Decimal`. Команда `python3 -m unittest discover tests -v` прошла: 2 теста.

# Что пригодилось из заметки коллеги

Пригодились объяснение различия между первой и второй записью, указание проверить вычисляемые значения во вложенном элементе DynamoDB и совет тестировать запись после предварительного заполнения таблицы. Вариант с целыми процентами не применялся: он изменил бы шкалу `score` с 0–1 на 0–100. Совет публиковать в реальную таблицу не применялся из-за ограничения работать локально и не обращаться к внешним сервисам.
