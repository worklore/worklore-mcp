# Реализация событий аналитики

Все события из `docs/EVENTS.md` отправляются через существующую обёртку `Analytics.capture`.

## Экран регистрации

В `lib/screens/registration_screen.dart` добавлены:
- `registration_email_started` — один раз за посещение экрана при первом редактировании email;
- `registration_phone_started` — один раз за посещение экрана при первом редактировании телефона;
- `loan_amount_changed` — в `Slider.onChangeEnd`, с целочисленным свойством `amount`;
- `terms_accepted` — только при установке флага согласия, без события при его снятии;
- `registration_continue_tapped` — при нажатии Continue, со свойствами `amount` (int) и `terms` (bool), перед переходом к предложениям.

Email и телефон в свойства событий не передаются. Автоматические события просмотра экранов не изменялись.

## Экран предложений

В `lib/screens/offer_screen.dart` список обёрнут в `NotificationListener<ScrollEndNotification>`. По завершении прокрутки отправляется `offers_scrolled` со свойством `offset` (double), равным `notification.metrics.pixels`.

## Что пригодилось из заметки коллеги

Использованы рекомендации:
- ограничить события текстовых полей флагами первого редактирования;
- отправлять событие слайдера из `onChangeEnd`, оставив в `onChanged` только обновление UI;
- отправлять событие прокрутки из `ScrollEndNotification`;
- сохранить точные имена событий и наборы свойств.

Обработчики фокуса, передача итоговых текстовых значений и дебаунс не применялись: спецификация этого не требует, а содержимое email и телефона нельзя отправлять как PII.
