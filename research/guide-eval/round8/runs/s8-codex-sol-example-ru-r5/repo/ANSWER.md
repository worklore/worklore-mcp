# Исправление кеширования промпта

В `bot.py` функция `build_system` теперь отправляет два текстовых блока с `cache_control: {"type": "ephemeral"}`: неизменные `INSTRUCTIONS` и отдельно контекст спортсмена (дата, профиль, зоны, цель, факты, язык). После `save_fact` меняется только второй блок. Набор и порядок инструментов в пределах одного сообщения остаются прежними.

Проблема видна в `logs/usage.jsonl`: после `save_fact` у пользователя `42` следующий раунд (строки 4–5) создал кеш для 1061 токена и прочитал 0. Это соответствует прежнему единому блоку, в котором изменение факта меняло весь кешируемый префикс.

Из заметки коллеги пригодились разделение статического и изменяемого текста двумя маркерами, требование сохранять статический префикс и проверка через `cache_creation_input_tokens` и `cache_read_input_tokens`. Сокращение набора инструментов уже реализовано здесь; менять его или добавлять выбор отдельных фактов для каждого сообщения не потребовалось. Числа экономии из заметки к этому проекту не переносил.

Проверка: `python3 -m unittest -v test_bot.py` проходит. Тест моделирует `save_fact` внутри цикла: первый блок и инструменты одинаковы в обоих запросах, а сохранённый факт появляется во втором блоке следующего запроса. Реальный кеш API этим тестом не измеряется; для подтверждения в рабочем окружении после записи факта нужно увидеть ненулевой `cache_read_input_tokens` для статического префикса и создание кеша только для изменившегося хвоста. Внешних вызовов при проверке не было.
