# Почему nightly-review молчал

Задача запускается (в `launchctl print`: `runs = 6`, `last exit code = 1`), но падает, и уведомление о падении отправить не может. Причин две, одна прячет другую.

1. **Скрипт не умеет сообщать об ошибках.** В `bin/nightly-review.zsh` стояло `status=$?`. В zsh `status` — read-only переменная (синоним `$?`), поэтому в `.err` на каждом запуске строка `read-only variable: status`. Присваивание падает, скрипт завершается с кодом 1 и до `notify.sh` не доходит. Ветка «FAILED» была недостижима, поэтому в Telegram не приходило ничего. Это же объясняет `last exit code = 1`.
   **Исправлено:** переменная переименована в `rc`. Stderr claude теперь пишется в `~/Library/Logs/nightly-review-<дата>.err`, и первые 200 символов попадают в уведомление об ошибке.

2. **Первопричина самих падений — `Not logged in · Please run /login`.** Под launchd `claude -p` не авторизован: сессия, которую ты открыл в терминале, в фоновом задании недоступна. Так что даже с исправленным скриптом ночной запуск пока будет падать, но теперь ты получишь в Telegram сообщение с причиной.
   **Это нужно сделать тебе** (я не могу выполнить логин за тебя):
   - либо выполни `claude setup-token` и передай задаче токен (`CLAUDE_CODE_OAUTH_TOKEN`) или `ANTHROPIC_API_KEY`. Лучше брать из keychain, как сделано для `tg-bot`, а не писать в plist открытым текстом;
   - либо проверь, что логин действует в той же GUI-сессии (`gui/501`).
   После этого проверь запуск: `launchctl kickstart -k gui/501/com.vk.nightly-review`.

Пояснение: `.out` пустой, потому что весь вывод шёл в stderr и в файл отчёта. `notify.sh` и plist в порядке, расписание 02:30 верное. `PATH` в plist содержит `/opt/homebrew/bin`, и `claude` находится, раз он выдаёт «Not logged in». Если `claude` лежит в `~/.local/bin`, добавь этот путь в `PATH` в plist.
