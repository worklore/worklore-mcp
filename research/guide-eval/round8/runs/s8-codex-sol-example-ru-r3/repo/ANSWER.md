# Исправление кеширования

В `bot.py` системный промпт разбит на два текстовых блока с отдельными `cache_control: ephemeral`: постоянные правила тренера и изменяемые данные атлета (дата, профиль, зоны, цель, факты, язык). После `save_fact` меняется только второй блок, поэтому неизменный префикс инструкций может читаться из кеша. Состав и порядок инструментов оставлены прежними.

Добавлен локальный тест `test_bot.py`: он сохраняет факт, заново загружает атлета и проверяет, что первый блок запроса не изменился, второй содержит новый факт, а оба маркера на месте. `python3 -m unittest -v test_bot.py` проходит. Обновлено описание кеширования в `README.md`.

Из заметки коллеги пригодились два отдельных маркера на границе постоянного и изменяемого текста, требование сохранять байтовую стабильность инструкций и проверка через поля `cache_creation_input_tokens` и `cache_read_input_tokens`. Существующую фильтрацию инструментов и загрузку всех фактов заимствованная идея менять не требует; выбор релевантных фактов для каждого сообщения не добавлялся. Логирование полей `usage` уже было в коде.

Проверить фактическую долю кешированных токенов по новым записям `logs/usage.jsonl` здесь не удалось: для этого нужны вызовы Claude API, а внешние сервисы по условию не использовались. У провайдера также может быть минимальная длина кешируемого префикса; локальный тест подтверждает форму запроса, но не гарантирует кеш-попадание на реальном API.
