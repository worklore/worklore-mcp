# Почему второй publish возвращает 500

## Причина

`similarity()` в `src/app.py` возвращает `round(..., 4)`. В Python это `float`.
`related()` кладёт этот float в `similar[].score`, и весь элемент уходит в
`table.put_item(...)`. DynamoDB через boto3 не принимает float и кидает
`TypeError: Float types are not supported`.

Первый publish проходит, потому что таблица пустая: `existing` пуст, `related()`
ничего не считает, и в элементе нет ни одного float. Второй publish видит одну
историю, считает похожесть и падает. Это совпадает с `logs/error.log`: первая
запись `similar=0 stored`, вторая с 500.

Тесты не ловили это, потому что все проверяли только пустой путь: publish в
пустую таблицу. Тестов на второй publish с уже существующими историями не было.

Воспроизведено: первый `handler()` даёт 201, второй даёт 500 с той же ошибкой
из лога.

## Исправление

- `src/app.py`: добавлена `to_dynamo(value)`. Она рекурсивно переводит все
  `float` в `Decimal(str(value))` (точное значение, без двоичного хвоста).
  `publish()` вызывает её прямо перед `put_item`, и возвращает ровно то, что
  записано. Значения score не меняются (`0.4286` остаётся `0.4286`), так что
  контракт для страницы чтения сохраняется.
- `tests/test_publish.py`: добавлены тесты:
  - второй publish при существующих историях (проверяет `similar` и тип `Decimal`);
  - `handler()` дважды возвращает 201;
  - `to_dynamo` конвертирует float рекурсивно.

## Как не допустить повтора

1. Все float переводятся в одной точке записи, а не точечно для `score`. Новое
   поле с float (процент, среднее, округлённый счёт) не сломает запись.
2. Тест на заполненную таблицу: `test_second_publish_with_existing_stories` и
   `test_handler_second_publish_returns_201`. `FakeTable` уже валидирует типы как
   boto3, поэтому тест упал бы до исправления. Раньше он просто не выполнял
   этот путь.

Ограничение: `to_dynamo` нужно вызывать в любом новом пути записи. Если появится
второй `put_item`, который её обойдёт, защита не сработает. Это проверяется
ревью, а не тестом.

## Что из заметки коллеги пригодилось

- Главное: тест должен засевать таблицу одной записью, иначе путь «похожие
  истории» не выполняется. Применено.
- Шаг «найти `round(` и `/`, которые попадают в элемент». Пригодился: нашёл
  `round` в `similarity()`. Деления в `similarity()` дают float, но `round`
  возвращает float в любом случае.
- Не пригодилось: перевод score в целые проценты. Это меняет формат данных,
  который читает страница, и не нужно для исправления. Выбран `Decimal`.
- Не выполнено: публикация дважды на реальной таблице DynamoDB. Нет доступа к
  AWS, и по правилам ничего не деплоится и не публикуется. Проверка сделана на
  `FakeTable`, который валидирует типы так же, как boto3.

## Что заметил, но не менял

- `publish()` делает один `table.scan(...)` без пагинации. DynamoDB возвращает
  до 1 МБ за вызов, поэтому при росте библиотеки `similar` будет считаться
  только по части историй. Это отдельная задача.
- Значения score теперь читаются как `Decimal`. Если страница чтения будет
  отдавать их через `json.dumps`, понадобится кастомный encoder. Сейчас
  `handler()` возвращает только `slug`, так что на текущий путь это не влияет.
