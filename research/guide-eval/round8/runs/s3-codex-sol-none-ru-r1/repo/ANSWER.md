# Почему ночная задача молчала

`launchd` запускал задачу: в `launchctl-print.txt` указаны шесть запусков, последний код выхода — `1`, а календарный триггер настроен на 02:30. Значит, проблема не в загрузке plist. `Library/Logs/nightly-review.err` показывает повторяющуюся цепочку из двух ошибок:

1. `claude` отвечал `Not logged in · Please run /login`. У процесса, запущенного `launchd`, нет нужной авторизации Claude. Переменные, заданные в интерактивной оболочке, он не наследует; в plist передан только `PATH`.
2. Сразу после этого `nightly-review.zsh` выполнял `status=$?`. В zsh `status` — специальный параметр только для чтения. Присваивание завершало скрипт до ветки, которая должна была отправить сообщение об ошибке. Поэтому не приходило даже уведомление о сбое.

## Что исправлено в снимке

- `bin/nightly-review.zsh` сохраняет код выхода Claude в `rc` и вызывает уведомитель через обработчик `EXIT`. Ошибка Claude, отсутствие репозитория и пустой ответ теперь приводят к сообщению о сбое. Интервал обзора ограничен вчерашними сутками.
- Скрипт может получить `ANTHROPIC_API_KEY` из пользовательского Keychain, из записи с именем сервиса `nightly-review-anthropic-api-key`. Если ключа нет, Claude по-прежнему может использовать свою уже доступную авторизацию; при её отсутствии задача сообщит об ошибке вместо молчаливого завершения.
- `bin/notify.sh` теперь явно сообщает в stderr, если токен Telegram недоступен, и возвращает ошибку при неуспешном HTTP-ответе Telegram.

## Что требуется на настоящем компьютере

Перенести исправленные скрипты из снимка на их пути в домашней директории. Для работы Claude без интерактивного входа нужен действующий способ авторизации именно для процесса `launchd`. Предусмотренный скриптом способ — добавить API-ключ Claude как обычный пароль в пользовательский Keychain с именем сервиса `nightly-review-anthropic-api-key` и разрешить фоновому процессу читать эту запись. Секрета в снимке нет, поэтому здесь его установить или проверить невозможно. Если используется другой способ фоновой авторизации Claude, достаточно обеспечить его доступность этому процессу.

Проверены синтаксис обоих скриптов, plist и локальные сценарии с заглушками: успех, ошибка Claude, пустой ответ, отсутствие репозитория, отсутствие токена Telegram и ошибка HTTP. Настоящие Claude и Telegram не вызывались; файлы вне текущей директории не менялись.
