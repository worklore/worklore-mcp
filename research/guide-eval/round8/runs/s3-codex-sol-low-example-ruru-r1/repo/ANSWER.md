# Почему задача молчала

`launchctl-print.txt` показывает `runs = 6` и `last exit code = 1`: launchd запускал задачу по расписанию. В `nightly-review.err` каждый запуск оставил две строки: `Not logged in · Please run /login` от `claude`, затем `read-only variable: status` на строке 19 скрипта. У zsh переменная `status` доступна только для чтения. Присваивание прерывало скрипт до ветки с уведомлением об ошибке. Поэтому не пришло ни обзора, ни сообщения о сбое.

В plist добавлен `USER=vk`: в сохранённом окружении launchd этой переменной не было, что соответствует описанной в заметке проблеме доступа headless CLI к учётным данным. Скрипт теперь передаёт промпт через stdin, сохраняет код выхода в `rc`, проверяет пустой результат и сообщает о сбое. Ошибка отправки уведомления дополнительно пишется в stderr launchd. Передача промпта через stdin убирает зависимость от разбора многострочного аргумента; лог снимка не доказывает, что этот разбор уже ломался здесь.

Из заметки пригодились проверка `launchctl print`, чтение `StandardErrorPath`, отказ от `status=$?`, явное задание `USER` и передача промпта через stdin. Совет закрывать stdin при передаче промпта аргументом здесь не нужен: скрипт использует stdin для промпта. Рекомендации о длительности запуска и проверке реального результата учтены частично: пустой файл теперь считается ошибкой, но в снимке нет данных о длительности и нельзя доказать качество будущего обзора.

Это исправление сделано только в снимке. Реальные учётные данные `claude`, доступ к keychain и доставку Telegram здесь без внешних вызовов проверить нельзя. После переноса изменений нужно перезагрузить агент launchd и проверить запуск, свежий непустой файл обзора, сообщение и stderr; при оставшейся ошибке входа выполнить авторизацию `claude` в пользовательской сессии.

Локальная проверка: `zsh -n`, `plutil -lint` и `xmllint` прошли. С заглушками `claude` и уведомителя проверены три случая: успешный ответ (`rc=0` и уведомление), ошибка агента (`rc=7` и уведомление об ошибке), пустой ответ (`rc=1` и уведомление об ошибке).
