# Почему не было сообщений

`launchd` запускал задачу: в `launchctl-print.txt` указаны `runs = 6`, календарный триггер на 02:30 и `last exit code = 1`. Пустой `nightly-review.out` сам по себе не означает, что задача не стартовала.

В `nightly-review.err` шесть раз повторяется одна последовательность:

1. `claude` завершился с сообщением `Not logged in · Please run /login`. В контексте ночного запуска CLI не был авторизован, поэтому обзор не создавался.
2. После этого скрипт пытался выполнить `status=$?`. В zsh `status` — специальная переменная только для чтения. Присваивание прерывало скрипт **до** ветки, которая должна была отправить сообщение об ошибке.

Дополнительно `notify.sh` раньше не проверял, удалось ли прочитать токен из Keychain, а `curl` без `-f` мог завершиться с кодом 0 при HTTP-ошибке Telegram. Работоспособность уведомителя при ручном запуске не доказывает доступность Keychain для запуска из `launchd`; снимок не содержит данных, позволяющих утверждать, что это уже происходило.

# Что исправлено

- `bin/nightly-review.zsh`: убрано присваивание `status`; вывод ошибок Claude сохраняется в датированный `.err` и включается в сообщение об отказе. Успешный запуск по-прежнему отправляет краткую сводку.
- `bin/notify.sh`: ошибка получения токена и HTTP-ошибка теперь дают ненулевой код и диагностическое сообщение в stderr.
- Plist оставлен без изменений: он загружен, расписание присутствует, а причина молчания находится в скрипте и авторизации.

Для получения **самих обзоров** потребуется авторизовать `claude` в реальном аккаунте пользователя `vk` (CLI прямо просит выполнить `/login`) и убедиться, что эта авторизация доступна при запуске из `launchd`. Если Keychain недоступен агенту, `notify.sh` теперь явно сообщит об этом в `Library/Logs/nightly-review.err`; доступ к токену нужно обеспечить в реальном окружении. В этом снимке нет ни учётных данных, ни возможности проверить их доступность; никакие сообщения во внешние сервисы при исправлении не отправлялись.

Проверка: синтаксис обоих скриптов и plist прошёл проверку; локальные подставные `claude` и `notify.sh` подтвердили успешную ветку и ветку ошибки без сетевых вызовов.
