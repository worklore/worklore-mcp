# Причина ошибки 500 и её исправление

## 1. Причина ошибки

В логе [error.log](file:///tmp/h-No2lSj/logs/error.log) зафиксировано исключение:
`TypeError: Float types are not supported. Use Decimal types instead.`

- При **первой публикации** (`POST /stories`) база данных DynamoDB была пуста (`table.scan()` вернул пустой список записей). Функция `related(story, existing)` вернула пустой список `similar: []`, и в DynamoDB не попало никаких вычисленных оценок сходства.
- При **второй публикации** в таблице уже была сохранена первая статья. Функция `related(story, existing)` вызвала `similarity(story, other)`, возвращавшую значение типа `float` (`round(0.7 * tag_score + 0.3 * word_score, 4)`).
- DynamoDB (библиотека `boto3`) не поддерживает тип данных Python `float` при сохранении элементов в таблицу (`put_item`), требуя вместо него `Decimal` или `int`. Попытка сериализации объекта с полем типа `float` вызвала `TypeError`, что привело к возврату статуса 500 (`Internal Server Error`).

## 2. Исправление

В файле [src/app.py](file:///tmp/h-No2lSj/src/app.py):
1. Импортирован класс `Decimal` из стандартного модуля `decimal`.
2. Функция `similarity` теперь возвращает `Decimal(str(round(...)))` вместо `float`:
   ```python
   return Decimal(str(round(0.7 * tag_score + 0.3 * word_score, 4)))
   ```

Для предотвращения повторения ошибки в тестах [tests/test_publish.py](file:///tmp/h-No2lSj/tests/test_publish.py):
- Добавлен тест `test_publish_second_story_succeeds`, проверяющий публикацию второй истории в уже непустую таблицу с формированием элементов `similar`.
- Добавлен тест `test_handler_second_publish_returns_201`, проверяющий корректность ответа (HTTP 201) при повторном вызове `handler()`.

## 3. Какие части заметки коллеги пригодились

- **Пригодилось**:
  - Диагностика причины: указание на то, что DynamoDB (`boto3`) не поддерживает Python `float`, требуя `Decimal`, и что при первой записи таблица пуста, из-за чего блок расчета схожести/оценок не генерирует `float`.
  - Рекомендация проверки и конвертации вычисляемых значений (деления, коэффициенты схожести) в `Decimal` на границе с DynamoDB.
  - Рекомендация добавить интеграционный тест, который сначала заполняет таблицу одной записью, а затем публикует вторую, покрывая зависимый от состояния базы путь выполнения.
- **Было пропущено / не понадобилось**:
  - Предложение преобразовать оценки в целые числа/проценты (`int`): в сервисе сохраняется точный score с округлением до 4 знаков, поэтому использован тип `decimal.Decimal`.
  - Упоминание о необходимости запросить у пользователя расположение вызовов `put_item` / `update_item` и тестового сетапа (все файлы уже находились в репозитории: `src/app.py`, `tests/fake_dynamo.py`, `tests/test_publish.py`).
