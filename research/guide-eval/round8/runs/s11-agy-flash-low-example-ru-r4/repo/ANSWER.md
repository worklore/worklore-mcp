# Анализ проблемы и исправление

## 1. Причина ошибки (HTTP 500)

В логах `logs/error.log` зафиксирована ошибка при втором вызове:
```text
TypeError: Float types are not supported. Use Decimal types instead.
```
- При **первой публикации** таблица DynamoDB была пуста (`table.scan(...)` возвращал `[]`). Функция `related(story, existing)` возвращала пустой список `[]`, и в записываемый объект попадало `"similar": []`. В объекте не было чисел с плавающей точкой (тип `float`), поэтому вызов `table.put_item(Item=item)` завершался успешно.
- При **второй публикации** в таблице уже существовала одна запись. Функция `related(story, existing)` вызвала `similarity(...)`, которая рассчитывает оценку сходства выражением:
  ```python
  round(0.7 * tag_score + 0.3 * word_score, 4)
  ```
  Результатом этой операции является стандартный тип `float`.
- Библиотека `boto3` (и её сериализатор DynamoDB) не поддерживает тип Python `float` при записи элементов, требуя использовать `decimal.Decimal` или целые числа (`int`). Из-за наличия `float` в поле `similar[0]["score"]` вызов `table.put_item` выбросил исключение `TypeError`, которое перехватил `handler` и вернул статус-код `500`.

---

## 2. Исправление

1. **Код сервиса (`src/app.py`):**
   - Импортирован класс `Decimal` из стандартного модуля `decimal`.
   - В функции `similarity(a, b)` возвращаемое значение обёрнуто в `Decimal(str(...))`:
     ```python
     return Decimal(str(round(0.7 * tag_score + 0.3 * word_score, 4)))
     ```
   Это гарантирует, что в поле `score` внутри `similar` передаётся поддерживаемый DynamoDB тип `Decimal`, предотвращая падение при сериализации в `boto3`.

2. **Тесты (`tests/test_publish.py`):**
   - Добавлен тест `test_publish_second_story_succeeds`, выполняющий публикацию второй истории при уже заполненной таблице, что тестирует путь вычисления сходства и валидацию `similar` в DynamoDB.
   - Добавлен интеграционный тест `test_handler_second_publish_succeeds`, эмулирующий последовательные вызовы функции `handler` и проверяющий возврат `201 Created` для обеих записей.

---

## 3. Какие части заметки коллеги пригодились

- **Пригодилось:**
  - Точный диагноз причины сбоя: DynamoDB через boto3 отклоняет Python `float` с сообщением `TypeError: Float types are not supported. Use Decimal types instead.`.
  - Объяснение того, почему первая запись проходит успешно (пустая таблица не порождает похожих историй, поэтому вычисленные значения `float` не попадают в итоговый словарь `item`).
  - Рекомендация использовать `decimal.Decimal` для сохранения числовой оценки.
  - Рекомендация по тестированию: добавить тест с предварительно заполненной таблицей (запись второй истории), чтобы тестировать поведение кода при наличии существующего состояния.

- **Не пригодилось / пропущено:**
  - Предложение преобразовать оценку в целые проценты (`int`): в проекте сохранён исходный формат точности до 4 знаков после запятой с использованием `Decimal`.
  - Общие шаги по аудиту внешних систем / AWS Lambda и grep всего репозитория, так как проект локальный и содержит единственный файл реализации (`src/app.py`).
