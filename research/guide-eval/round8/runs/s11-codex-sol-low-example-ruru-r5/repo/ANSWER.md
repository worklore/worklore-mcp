# Почему вторая публикация возвращала 500

`logs/error.log` показывает `TypeError: Float types are not supported. Use Decimal types instead` при `table.put_item`. При первой публикации таблица пуста, поэтому список `similar` пуст. При второй `related()` вычисляет `score` через деление и `round()`; результат имеет тип `float`. Boto3 не умеет сериализовать его в DynamoDB, и обработчик возвращает 500.

# Исправление

Перед добавлением оценки в сохраняемый `similar` она преобразуется в `Decimal` через строковое представление. Это сохраняет прежнее округлённое значение и даёт DynamoDB поддерживаемый тип. Добавлен тест двух последовательных вызовов `handler()` с одной таблицей: оба возвращают 201, вторая запись содержит похожую историю с оценкой типа `Decimal`. `python3 -m unittest discover tests -v` — 2 теста прошли.

# Что пригодилось из заметки коллеги

Пригодились объяснение различия между пустой и заполненной таблицей, указание на несовместимость `float` с DynamoDB и идея тестировать запись после предварительного заполнения таблицы. Проверка через настоящую таблицу не потребовалась: локальный `FakeTable` проверяет типы так же, как сериализатор boto3; внешние сервисы не использовались.
