# Аналитика на экранах регистрации и предложений

## Что сделано

Все шесть событий из `docs/EVENTS.md` подключены через существующую обёртку
`Analytics.capture` (`lib/analytics.dart`). Имена событий и свойства совпадают
со спецификацией. Email и телефон в свойствах не отправляются.

### `lib/screens/registration_screen.dart`

| Событие | Когда срабатывает | Свойства |
|---|---|---|
| `registration_email_started` | первое редактирование поля email за визит на экран | — |
| `registration_phone_started` | первое редактирование поля phone за визит на экран | — |
| `loan_amount_changed` | в `Slider.onChangeEnd`, то есть когда пользователь отпустил слайдер | `amount` (int) |
| `terms_accepted` | при включении чекбокса (при снятии не срабатывает) | — |
| `registration_continue_tapped` | при нажатии Continue, только когда кнопка активна | `amount` (int), `terms` (bool) |

- Для полей `email` и `phone` добавлены флаги `_emailStartedSent` и
  `_phoneStartedSent` в состоянии экрана. `onChanged` срабатывает на каждое
  нажатие клавиши, поэтому без флага пришло бы событие на каждый символ.
- Слайдер: `onChanged` оставлен только для обновления UI, событие отправляется
  из `onChangeEnd`.

### `lib/screens/offer_screen.dart`

| Событие | Когда срабатывает | Свойства |
|---|---|---|
| `offers_scrolled` | в `ScrollEndNotification`, один раз за жест скролла | `offset` (double, `metrics.pixels`) |

`OfferScreen` был `StatelessWidget` и остался им. `ListView` обёрнут в
`NotificationListener<ScrollEndNotification>`, который возвращает `false`,
чтобы уведомление продолжало всплывать.

## Что взято из заметки коллеги

Пригодилось:
- флаг «один раз за визит» для текстовых полей (п. 2 заметки);
- перенос события слайдера из `onChanged` в `onChangeEnd` (п. 5);
- `ScrollEndNotification` вместо обновлений скролла (п. 6);
- правило «имена событий и свойства не меняем», чтобы дашборды не сломались.

Не пригодилось или не применялось:
- шаг 1 (grep по существующему коду): репозиторий новый, `Posthog().capture`
  в экранах раньше не было;
- события фокуса и срабатывание по потере фокуса: в `EVENTS.md` таких событий
  нет, итоговое значение поля никуда не передаётся;
- проверка через PostHog → Activity: не выполнялась, см. ниже.

## Оставшиеся вопросы и допущения

1. **`terms_accepted` срабатывает при каждом включении чекбокса.** Если
   пользователь включает и снимает его несколько раз, событий будет несколько.
   Если нужно только первое включение, это меняется флагом по образцу полей
   ввода. Спецификация этого не уточняет, поэтому я выбрал «каждое включение».
2. **`offset` в `offers_scrolled` — текущая позиция скролла (`metrics.pixels`),
   а не дельта за жест.** Спецификация говорит «how far they scrolled», и я
   прочитал это как позицию. Если нужна дельта, понадобится запоминать позицию
   в начале жеста.
3. **Флаги `*_started` живут в состоянии экрана.** «За визит» означает
   «пока экран смонтирован»: после возврата с экрана офферов флаги сохраняются,
   после перезапуска приложения сбрасываются.
4. Ключ PostHog в `lib/analytics.dart` остался заглушкой `phc_REPLACE_ME_IN_CI`.
   Я его не менял.
