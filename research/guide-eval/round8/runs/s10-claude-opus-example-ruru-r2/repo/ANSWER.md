# События аналитики из docs/EVENTS.md

Все шесть событий отправляются через существующую обёртку `Analytics.capture`
(`lib/analytics.dart`). Имена и свойства точно такие, как в спецификации.
Email и телефон в свойства не попадают (это PII). Отдельных событий для просмотра
экранов нет, их уже отслеживает `PosthogObserver`.

| Событие | Где | Когда срабатывает |
|---|---|---|
| `registration_email_started` | `registration_screen.dart`, `onChanged` поля Email | Один раз за посещение экрана, при первом вводе (флаг `_emailStartedSent`) |
| `registration_phone_started` | `registration_screen.dart`, `onChanged` поля Phone | Один раз за посещение экрана (флаг `_phoneStartedSent`) |
| `loan_amount_changed` `{amount: int}` | `Slider.onChangeEnd` | Один раз за протягивание, когда пользователь отпускает ползунок. `onChanged` только обновляет UI |
| `terms_accepted` | `CheckboxListTile.onChanged` | Когда галочку ставят (`true`). Снятие галочки событие не отправляет |
| `registration_continue_tapped` `{amount: int, terms: bool}` | `FilledButton.onPressed` | При каждом нажатии, перед переходом на `/offers` |
| `offers_scrolled` `{offset: double}` | `offer_screen.dart`, `NotificationListener<ScrollEndNotification>` вокруг `ListView` | Один раз за жест прокрутки (с инерцией), `offset = metrics.pixels`. Учитывается только сам список (`depth == 0`) |

Проверка: `dart format` и `flutter analyze` прошли, ошибок нет. В приложении на
устройстве не запускал, отправку событий в PostHog не проверял. Служебные файлы,
которые создала `flutter pub get` (`.dart_tool/`, `pubspec.lock`, правка
`analysis_options.yaml`), удалил или откатил.

## Принятые решения и оговорки
- «Один раз» означает один раз за посещение экрана: флаги хранятся в `State`,
  поэтому если пользователь вернётся на экран регистрации заново, события
  отправятся снова. Если продукту нужно «один раз за весь поток», флаги надо
  перенести в объект, который переживает навигацию.
- `loan_amount_changed` срабатывает только при протягивании или нажатии на
  слайдер. Значение по умолчанию (50000) событие не отправляет, поэтому
  пользователь, который не трогал слайдер, выпадет на этом шаге воронки. По
  спецификации так и должно быть (событие про «moved the slider»), но об этом
  стоит знать при чтении воронки.
- В списке 10 предложений. На высоком экране он может поместиться целиком без
  прокрутки, и тогда `offers_scrolled` не придёт никогда.
- `offers_scrolled` отправляется после каждого жеста, а не один раз за
  посещение. Это несколько событий на экран, а не по одному на кадр. Если квота
  станет проблемой, можно добавить флаг «только один раз».

## Что пригодилось из заметки коллеги
- **Пригодилось:** главная мысль, что `onChanged` срабатывает на каждую
  клавишу или шаг слайдера, а PostHog на бесплатном тарифе (наш случай, см.
  README) считает каждое событие. Отсюда три решения:
  - флаг «один раз за посещение» для `*_started` в `onChanged` текстовых полей;
  - `onChangeEnd` вместо `onChanged` для слайдера;
  - `ScrollEndNotification` вместо `ScrollUpdateNotification` или слушателя
    `ScrollController` для скролла.
- **Пригодилось:** правило не менять имена и свойства событий. Дашборды уже
  построены на них, это сказано и в EVENTS.md.
- **Не понадобилось:** события тапа или фокуса через `FocusNode` и отправка
  итогового значения при потере фокуса. В спецификации нет событий, которым
  нужно итоговое значение поля, а email и телефон отправлять нельзя.
- **Не понадобилось:** ручная проверка через `PostHogConfig.debug = true` и
  PostHog → Activity. Приложение не запускал и в PostHog ничего не отправлял;
  это можно сделать как ручную проверку перед релизом.
