# События аналитики

Реализованы все события из `docs/EVENTS.md` через существующую обёртку `Analytics.capture`.

## Экран регистрации

Изменения в `lib/screens/registration_screen.dart`:

- `registration_email_started` отправляется при первом изменении email за посещение экрана; повторные нажатия клавиш событий не создают.
- `registration_phone_started` отправляется при первом изменении телефона за посещение экрана. Значения email и телефона в аналитику не передаются.
- `loan_amount_changed` отправляется из `onChangeEnd` после завершения движения слайдера со свойством `amount` типа `int`.
- `terms_accepted` отправляется только при установке флага согласия, но не при его снятии.
- `registration_continue_tapped` отправляется при нажатии доступной кнопки Continue перед переходом к предложениям со свойствами `amount` (`int`) и `terms` (`bool`).

## Экран предложений

В `lib/screens/offer_screen.dart` список обёрнут в `NotificationListener<ScrollEndNotification>`. Событие `offers_scrolled` отправляется один раз по завершении скролла со свойством `offset` типа `double`, равным `notification.metrics.pixels`.

## Заметка коллеги

Пригодились рекомендации:

- ограничить события начала ввода флагами «один раз за посещение»;
- перенести событие слайдера из `onChanged` в `onChangeEnd`;
- использовать `ScrollEndNotification` вместо событий на каждое обновление скролла;
- сохранить точные имена событий и свойств и не передавать персональные данные.

Рекомендации про `FocusNode` и итоговые значения полей не понадобились: спецификация таких свойств не требует. Проверка через внешний PostHog Activity не выполнялась.
