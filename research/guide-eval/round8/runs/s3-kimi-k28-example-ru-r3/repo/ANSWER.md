# Почему nightly-review молчал

## Диагностика

Задача работала исправно и молчала намеренно — то есть оба её компонента
делали не то, что ожидалось:

- `launchctl print` (снимок от 2026-10-18): `runs = 6`,
  `last exit code = 1`, `state = waiting`. Агент запускался все 6 ночей
  после bootstrap и каждый раз завершался с кодом 1. launchd ни при чём —
  дебажить надо было не «почему не стартует», а «почему падает, не сказав».
- `Library/Logs/nightly-review.err` содержит 6 одинаковых пар строк — по паре
  на запуск:
  1. `Not logged in · Please run /login` — `claude -p` падает;
  2. `/Users/vk/bin/nightly-review.zsh:19: read-only variable: status` —
     скрипт умирает на следующей же строке, до вызова `notify.sh`.
- В `launchctl print` окружение задания — только `PATH` (и служебный
  `XPC_SERVICE_NAME`): `USER` не задан (как и `HOME` явно).

## Причины

### 1. Причина тишины: присваивание `status` в zsh (bin/nightly-review.zsh:19)

В zsh `status` — встроенная переменная только для чтения (синоним `$?`).
Присваивание `status=$?` — фатальная ошибка: скрипт завершается немедленно.
Эта строка стояла между вызовом `claude` (который и так падал) и блоком,
отправляющим уведомление об ошибке. Поэтому задача падала каждую ночь,
а мессенджер погибал раньше, чем успевал сказать, что она упала.
Исправлено: `rc=$?`.

### 2. Первопричина падения: claude «Not logged in» под launchd

Каждый запуск `claude -p` умирал с «Not logged in · Please run /login».
В plist'е заданы только `PATH` в `EnvironmentVariables`; `USER` (и `HOME`)
launchd этому заданию не передаёт (видно в снимке `launchctl print`).
Без `USER` headless-CLI не находит свою учётку в связке ключей.
Исправлено: в plist добавлены `USER=vk` и `HOME=/Users/vk`.

### 3. Потенциальная (тот же класс, что у коллеги): многострочный промпт аргументом

Промпт передавался как многострочный аргумент `claude -p "$PROMPT"`.
В этом снимке до разбора аргументов выполнение не доходило (падало раньше,
на проверке логина), но такая передача хрупка в запланированном shell.
Исправлено: промпт передаётся через stdin —
`print -r -- "$PROMPT" | claude -p --output-format text` (stdin закрывается
сам после промпта, отдельный `< /dev/null` не нужен).

Дополнительно в stdout-лог пишутся длительность запуска и код возврата —
чтобы «зелёный» прогон за пару секунд (знак молчаливого фейла) сразу
бросался в глаза. `bin/notify.sh` не менялся.

## Что пригодилось из заметки коллеги

- `launchctl print gui/$UID/<label>` как первый шаг (`runs`, `last exit
  code`) — сразу перевёл диагностику с «не стартует» на «падает молча».
- «в zsh никогда не присваивать `status`, использовать `rc=$?`» — точное
  совпадение с причиной №1, проверено вживую: `zsh -c 'false; status=$?'`
  умирает с тем же сообщением, что в логе.
- `USER` в `EnvironmentVariables` против «Not logged in» — точное
  совпадение с причиной №2.
- Промпт через stdin вместо многострочного аргумента — применено как
  профилактика причины №3.
- Идеи «логировать длительность» и «верифицировать через kickstart + один
  принудительный фейл» — заложены в скрипт и в шаги проверки ниже.
- Не пригодилось: `< /dev/null` (не нужен при промпте через stdin);
  эпизод про «Input must be provided either through stdin or as a prompt
  argument» (здесь промпт до claude доходил — падение было позже);
  оговорка про ненадёжность exit code 0 (здесь код был честным 1, но
  длительность логируется всё равно).

## Проверено здесь

- `zsh -n` и `plutil -lint` — оба файла валидны.
- Сквозная симуляция обоих путей с подставными `claude` и `notify.sh`
  (локально, внутри снимка):
  - успех: exit 0, уведомление `nightly review done: …`, промпт получен
    через stdin, длительность в логе;
  - падение (точная реплика боя: «Not logged in», exit 1): exit 1,
    уведомление `nightly review FAILED (exit 1), see …` — раньше оно
    никогда не отправлялось.

## Как проверить на реальной машине

1. Перечитать агент: `launchctl bootout gui/$UID/com.vk.nightly-review`,
   затем `launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.vk.nightly-review.plist`.
2. `launchctl kickstart -k gui/$UID/com.vk.nightly-review`.
3. Убедиться: `launchctl print gui/$UID/com.vk.nightly-review` →
   `last exit code = 0`; в `~/Library/Logs/nightly-review.out` строка
   `claude finished in Ns, rc=0` с правдоподобной N (не пара секунд);
   свежий файл `nightly-review-<дата>.md` с реальным ревью; пришло
   success-уведомление.
4. Сломать намеренно (например, временно переименовать `~/projects/shop`),
   снова kickstart — должно прийти failure-уведомление. Вернуть как было.

После этого молчание должно стать невозможным в обе стороны.
