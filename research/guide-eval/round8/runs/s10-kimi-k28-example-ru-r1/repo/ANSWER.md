# Реализация событий аналитики

Реализованы все 6 событий из `docs/EVENTS.md` через обёртку `Analytics`
(`lib/analytics.dart`). Имена и свойства событий совпадают со спецификацией
в точности — дашборды и воронки продолжат работать.

## Что сделано

### `lib/screens/registration_screen.dart`

- `registration_email_started` — первое редактирование поля email.
  Раньше соблазн был повесить на `onChanged` напрямую, но там событие шло бы
  на каждый keystroke. Добавлен флаг `_emailStartedFired`: событие отправляется
  один раз за визит экрана, при первом изменении. Значение поля не передаётся
  (PII, по спецификации свойств нет).
- `registration_phone_started` — аналогично, флаг `_phoneStartedFired`.
- `loan_amount_changed` — отправляется в `onChangeEnd` слайдера (один раз за
  перетаскивание, когда пользователь отпустил), со свойством `amount` (int).
  `onChanged` оставлен только для обновления UI.
- `terms_accepted` — при проставлении галочки (переход в `true`), без свойств.
- `registration_continue_tapped` — в `onPressed` кнопки Continue, со свойствами
  `amount` (int) и `terms` (bool), перед навигацией на `/offers`.

### `lib/screens/offer_screen.dart`

Экран конвертирован из `StatelessWidget` в `StatefulWidget`.

- `offers_scrolled` — через `NotificationListener<ScrollEndNotification>`
  вокруг `ListView`, один раз за жест прокрутки, со свойством `offset`
  (double, `metrics.pixels` на момент окончания скролла).

## Что пригодилось из заметки коллеги

Заметка оказалась прямо в точку — спецификация содержит ровно те события
(«начал вводить email», «двинул слайдер»), которые при наивной реализации
утекали бы по квоте событий:

- **Разовый флаг для текстовых полей** — применено для email и phone:
  `bool _<field>StartedFired` на состоянии экрана, событие один раз за визит.
  Это ключевое изменение: email из 20 символов даёт 1 событие вместо 20.
- **Слайдер: `onChangeEnd` вместо `onChanged`** — применено. Один прогон
  слайдера даёт 1 событие вместо десятков.
- **Скролл: `ScrollEndNotification` вместо обновлений скролла** — применено.
- **Сохранить имена и свойства событий** — применено, спецификация не меняется.

Не пригодилось / осознанно пропущено:

- **Проверка через grep + debug-сборка с `PostHogConfig.debug = true`** —
  шаги воспроизведения из заметки не выполнялись: песочница не даёт исполнить
  `flutter`/`dart` из установки вне рабочей директории (`Operation not
  permitted`), зависимости проекта не выкачаны. Проверка — ручной пересмотр
  кода и соответствие спецификации событий. Рекомендую прогнать
  `flutter pub get && flutter analyze` локально.
- **FocusNode-обработчики** (события по потере фокуса) — не понадобились:
  ни одно событие не требует финального значения поля, все свойства в
  спецификации нечувствительные.
- **Флаг «once per visit» для галочки и скролла** — не добавлен: `onChanged`
  чекбокса и конец скролла срабатывают дискретно (раз за действие), а не
  непрерывно, поэтому в переборе событий нет. События «accepted»/«scrolled»
  по смыслу и должны идти за каждое такое действие.
- **Пометка «once per flow» для флагов между шагами навигации** — здесь не
  применима: экран регистрации один, флаги живут в его `State`, то есть
  «раз» = за один визит экрана.

## Проверка

- Все 6 событий из таблицы `docs/EVENTS.md` отправляются через
  `Analytics.capture` с именами и типами свойств из спецификации.
- PII (email, телефон) нигде не передаётся.
- `flutter analyze` не запускался (см. выше) — код проверен вручную на
  соответствие API Flutter (`Slider.onChangeEnd`, `NotificationListener`,
  `CheckboxListTile`) и обёртке `Analytics`.
