# Причина

Первая публикация проходит, потому что таблица пуста и `similar` получается пустым списком. При следующей публикации `similarity()` вычисляет оценку для уже существующей истории через деление и возвращает Python `float`. Этот `float` попадает в `item["similar"][...]["score"]`; сериализатор boto3 для DynamoDB отвергает его при `table.put_item(Item=item)`. Именно этот `TypeError` виден в `logs/error.log`, после чего обработчик отвечает 500.

# Исправление

Расчёт сходства в `src/app.py` теперь использует `Decimal` от деления до округления. Оценка остаётся в прежней шкале 0–1 с четырьмя знаками после запятой, но в сохраняемом элементе больше нет `float`. Добавлен тест, который публикует три истории через обработчик в одну таблицу, проверяет успешные ответы и тип сохранённых оценок. `python3 -m unittest discover tests -v`: 2 теста прошли.

# Что пригодилось из заметки коллеги

Пригодились указание на запрет `float` в DynamoDB, объяснение различия между пустой и заполненной таблицей и рекомендация проверять запись после предварительного заполнения таблицы. Вариант перевести оценку в целые проценты не использован: он изменил бы существующую шкалу и точность оценки. Проверка на настоящей таблице не проводилась: тесты выполнялись локально с `FakeTable`, без обращения к внешним сервисам.
