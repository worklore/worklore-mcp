# Вторая публикация возвращает 500

## Причина

`publish()` сохраняет вместе с историей список похожих (`similar: [{slug, score}]`).
`score` считает `similarity()`: это деления (Jaccard по тегам и словам) и
`round(..., 4)`, то есть результат — Python `float`. boto3 не сериализует float
в DynamoDB и бросает
`TypeError: Float types are not supported. Use Decimal types instead.`
(см. `logs/error.log`, `app.py` line 63 → `put_item`).

Почему первая публикация прошла: таблица была пуста, `scan` ничего не вернул,
`similar == []` — в item не было ни одного float (`published_at` — `int`).
Начиная со второй публикации в таблице есть хотя бы одна история, появляется
оценка-float, и каждый `put_item` падает. `handler` ловит `TypeError` общим
`except Exception` и отдаёт 500.

Тест этого не ловил, потому что проверял только публикацию в пустую таблицу:
код подсчёта похожести под тестом вообще не выполнялся.

## Исправление

- `src/app.py`: добавил `to_dynamo()`, которая рекурсивно заменяет каждый `float`
  на `Decimal(str(value))` (через `str`, чтобы хранилось `0.4567`, а не
  `0.456699999…`). `publish()` пропускает через неё весь item прямо перед
  `put_item`. Конвертация стоит на границе с DynamoDB, а не только в
  `similarity()`, поэтому новое вычисляемое поле (среднее, процент и т. п.) не
  вернёт тот же баг. Сортировка в `related()` по-прежнему идёт по float, а при
  чтении из реальной таблицы оценки приходят как `Decimal`; это нормально.
- `tests/test_publish.py`:
  - `test_publish_into_seeded_table` — сначала сажает одну историю, потом
    публикует вторую и проверяет, что `similar` сохранён, а `score` имеет тип `Decimal`;
  - `test_handler_second_publish_returns_201` — повторяет сценарий из лога
    через `handler` (две публикации, обе должны вернуть 201);
  - `test_to_dynamo_converts_nested_floats` — юнит-тест на конвертер;
  - старый тест пустой таблицы оставил, он ещё проверяет `similar == []`.

Проверка: до исправления новые тесты падают с той же ошибкой `Float types are
not supported`, после исправления `python3 -m unittest discover tests` — 4/4 OK.
Ничего не деплоил; повторную публикацию в реальную таблицу не делал.

## Что пригодилось из заметки коллеги

- **Пригодилось:** диагноз полностью совпал — float в item для DynamoDB,
  появляется только когда в таблице уже есть данные, потому что оценки
  похожести считаются по существующим записям. Пригодились и совет конвертировать
  в `int`/`Decimal` на границе, и совет искать `round(` и `/`, которые попадают в
  item (нашлись в `similarity()`). Главный урок тоже пригодился: тест пути
  записи должен сначала посадить запись в таблицу, иначе код, зависящий от
  состояния, не выполняется. Такой тест я добавил.
- **Взял иначе:** коллега перевёл оценки в целые проценты. Я оставил дробную
  оценку как `Decimal`: формат `score` не меняется для страницы чтения, и
  конвертация стоит централизованно перед `put_item`, а не в одной функции.
  Так этот класс ошибок закрыт и для будущих полей.
- **Не пригодилось / пропустил:** «опубликовать дважды в реальную таблицу» —
  по условию задачи ничего не деплою и во внешние сервисы не хожу. Эту проверку
  заменяет `FakeTable`: он валидирует значения так же, как сериализатор boto3.
