# Причина

При первой публикации таблица пуста, поэтому `related()` возвращает пустой список. При второй публикации она вычисляет `similarity()`, которая возвращает Python `float` (в том числе при нулевой оценке). Этот `float` попадает в `item["similar"][...]["score"]`; сериализатор boto3 для DynamoDB отклоняет его в `put_item`, что видно в `logs/error.log`, и обработчик возвращает 500.

# Исправление

В `related()` оценка преобразуется в `Decimal` через строковое представление перед добавлением в сохраняемый элемент. Это сохраняет прежнюю точность оценки и исключает `float` из этого вложенного поля DynamoDB.

Добавлен тест, который публикует две истории через обработчик с одной таблицей и проверяет успешный ответ, сохранённую оценку типа `Decimal` и число записей. `python3 -m unittest discover -s tests -v`: 2 теста прошли.

# Что пригодилось из заметки

Пригодились указание на ограничение boto3 для `float`, объяснение разницы между пустой и заполненной таблицей, проверка вычисляемых значений в элементе DynamoDB и тест второй записи с уже существующей историей. Вариант с целыми процентами не использован: он изменил бы шкалу и точность оценки; здесь подходит `Decimal`.
