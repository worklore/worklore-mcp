# Почему save_fact сбрасывал кеш и что изменено

## Причина
`build_system` собирал **один** текстовый блок: инструкции + контекст атлета, где
посередине стоял список фактов, а после него ещё строка `Language`. Единственный
`cache_control` стоял на конце этого блока. Кеш Anthropic работает по точному
префиксу (tools → system → messages), поэтому любой новый факт менял блок целиком,
и ~1000 токенов приходилось записывать в кеш заново (`cache_read_input_tokens: 0`,
`cache_creation_input_tokens` ≈ 1000+ в `logs/usage.jsonl`). Причём уже на 2-м
раунде того же сообщения: `run_tool` дописывает факт в `a.facts`, и следующий
запрос строит системный промпт заново.

## Что изменено (`bot.py`)
1. **Системный промпт разбит на блоки** в порядке «от стабильного к изменчивому»:
   `[INSTRUCTIONS] [профиль: дата, имя, зоны, цель, язык, заголовок фактов] [- факт 1] … [- факт N]`.
   Строка `Language` перенесена выше фактов, так что после фактов ничего нет.
2. **Каждый факт — отдельный блок**, `cache_control` на последнем. Когда добавляется
   факт N+1, префикс до факта N остаётся байт-в-байт прежним. API при промахе на
   breakpoint проверяет предыдущие границы блоков (lookback ~20 блоков) и находит
   запись, сделанную прошлым запросом. Дозаписывается только новый факт (~15–20 токенов).
3. **Второй breakpoint — на блоке профиля.** Это страховка на случай, если lookback
   не дотянется (вручную отредактировали или переупорядочили факты, добавили >20 разом).
   Если префикс до этого блока короче минимума для кеша (1024 токена у Sonnet 4.5),
   breakpoint просто ничего не делает, ошибки не будет.
4. `save_fact` теперь **только дописывает**: нормализует пробелы, игнорирует пустые
   строки и точные дубли (пустой текстовый блок API бы отклонил, а дубль лишь
   раздувает промпт). Почему порядок фактов нельзя менять, объяснено в комментарии в `build_system`.
5. README обновлён: теперь в нём описана новая схема кеширования.

## Проверка
Реальный API я не вызывал. Проверял локальной симуляцией правил кеша (запись на
breakpoint, lookback по границам блоков) через `reply()` с фейковым LLM:

| вызов | read | create |
|---|---|---|
| сообщение, раунд 1 | 0 | 1139 (холодный кеш) |
| раунд 2 после save_fact | 1139+ | **~20** |
| следующее сообщение | весь префикс | 0 |
| ещё один save_fact → раунд 2 | 1159 | **18** |

До изменений на месте «~20» было ≈1050–1100.

## Что не трогал, но стоит знать
- **Фильтрация инструментов по ключевым словам** (по NOTES.md её оставить) тоже сбрасывает
  кеш: tools идут в префиксе раньше system, поэтому сообщение со словами «plan»/«race»
  и т.п. переписывает весь промпт (в логе это строки с 1305/1334). Это отдельный
  компромисс, к save_fact он не относится.
- Строка `Today` меняется раз в сутки, а TTL кеша 5 минут, так что на кеш это не влияет.
- После деплоя проверить по `logs/usage.jsonl`: на раунде после `save_fact`
  `cache_read_input_tokens` должен быть ≈ размеру промпта, а `cache_creation_input_tokens`
  должен быть порядка десятков токенов.
