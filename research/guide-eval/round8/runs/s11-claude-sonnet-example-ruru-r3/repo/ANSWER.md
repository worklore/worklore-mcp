# Почему вторая публикация возвращает 500

## Причина
`similarity()` в `src/app.py` возвращает `round(..., 4)`, то есть Python `float`. `related()` кладёт эти значения в `item["similar"][*]["score"]`, и `table.put_item` падает с
`TypeError: Float types are not supported. Use Decimal types instead.` (boto3 не сериализует float).

Первая публикация проходит, потому что таблица пуста: `related()` получает пустой список, оценок нет, float в элементе нет. Со второй публикации появляются соседние истории, а с ними float-оценки, и запись падает. Единственный тест проверял только путь с пустой таблицей.

## Исправление
- `similarity()` теперь возвращает `Decimal(str(round(..., 4)))`. Значение то же, но DynamoDB его принимает; сортировка по score работает как раньше.
- Добавлен тест `test_second_publish_with_existing_stories`: сначала сажает одну историю, потом публикует вторую (`FakeTable` отвергает float так же, как boto3). Он падал бы на старом коде.

## Что пригодилось из заметки коллеги
- Диагноз (float в DynamoDB, ошибка видна только когда в таблице уже есть данные) совпал полностью.
- Совет «конвертировать на границе и тестировать с засеянной таблицей» — использован.
- Не использовано: перевод оценок в целые проценты. Я оставил Decimal, чтобы не менять формат хранимых данных (`score` остаётся долей 0..1). Поиск `round(`, `/` по кодовой базе: других вычисляемых значений в элементе нет (`published_at` — int). Публикацию в реальную таблицу не делал (запрещено правилами); проверка выполнена на `FakeTable`.
