# Исправление Intervals.icu OAuth

## Причины

1. Кнопка была ссылкой на `GET /api/intervals/auth/init`. Переход по ссылке не передаёт `Authorization` из SPA, поэтому сервер отвечал 401 всем атлетам. Теперь кнопка делает авторизованный `POST` через `fetch`, получает `authorize_url` и переводит браузер на него.
2. В запросе согласия одновременно стояли `ACTIVITY:READ` и `ACTIVITY:WRITE`, а также `CALENDAR:READ` и `CALENDAR:WRITE`. Для Intervals это повтор области: `WRITE` уже включает `READ`. Теперь запрашиваются `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`.
3. Ответ Intervals не содержал `expires_in` и `refresh_token`, но приложение назначало токену вымышленный срок 3600 секунд. Фоновый поток через час удалял рабочий токен и требовал переподключения. Вымышленный срок и обновление убраны; при реальном 401 от API токен удаляется и статус меняется на `reconnect required`.
4. `config.py` держал тестовые OAuth-реквизиты и localhost redirect URI константами, несмотря на описание переменных окружения в README. Теперь их можно задать через `INTERVALS_CLIENT_ID`, `INTERVALS_CLIENT_SECRET`, `INTERVALS_REDIRECT_URI`; секрет подписи state — через `APP_SECRET`.

## Что пригодилось из заметки коллеги

- Подход с авторизованным `POST` для init и переходом на выданный URL в SPA.
- Правило о неповторяющихся scope и включении `READ` в `WRITE`.
- Формат обмена кода: отправляются только `client_id`, `client_secret`, `code`; `athlete.id` берётся из ответа.
- Отсутствие refresh token и срока истечения; обработка отзыва при 401.
- Подписанный state с назначением и сроком 15 минут для callback без заголовка авторизации; проверка id атлета при повторном подключении. Здесь использована подпись HMAC существующего формата state вместо JWT: для этой локальной реализации она решает ту же задачу без новой зависимости.

Шифрование токена при хранении из заметки не применено: эта версия хранит связи только в памяти и не записывает токены на диск. При подключении постоянного хранилища в production токены следует шифровать до записи. Шаги заметки с реальным аккаунтом и отзывом приложения не выполнялись: проверка проведена локально без обращений к внешним сервисам.

## Проверка

`python3 -m unittest -v test_intervals.py` — 3 теста проходят. Они проверяют требования к init, состав URL и scope, callback и поля обмена кода, сохранение соединения, 401 при отзыве и запрет подмены id атлета.
