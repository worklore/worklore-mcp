# Prompt cache fix

`build_system` now sends two text blocks with `cache_control: ephemeral`: stable coaching instructions first, then the date and athlete profile, zones, goal, facts and language. After `save_fact`, only the second block changes. I added stable examples of the existing coaching rules to give the first cache breakpoint headroom against Claude's minimum cacheable prefix size. The selected tools stay in their existing order, and the same set is used throughout a message's tool loop.

The colleague's note applied to the two cache breakpoints, keeping volatile memory after the static instructions, retaining all facts rather than selecting a different subset per message, and checking `cache_creation_input_tokens` and `cache_read_input_tokens`. Tool filtering was already present and remains in place. A different selected tool group can still cause a separate cache miss because tools precede the system prompt in the request. The note's token counts and claimed savings were for a different bot, so they are not used as measurements here.

Verification: `python3 -m unittest -v test_bot.py` passes. Its regression test saves a fact and confirms that the tools and first cached block remain identical while the second block includes the new fact. `python3 -m py_compile bot.py test_bot.py` also passes. Live cache hit and creation counts could not be measured here because this workspace has neither the Anthropic SDK nor an API key; `logs/usage.jsonl` contains only pre-change calls. A live check should compare the first call after `save_fact` with the preceding call: the static prefix should still register as cache read, while cache creation covers the changed tail.
