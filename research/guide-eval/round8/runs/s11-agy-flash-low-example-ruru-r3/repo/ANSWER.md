# Анализ падения DynamoDB при второй публикации и его исправление

## 1. Причина ошибки

В [logs/error.log](file:///tmp/h-HOXOzO/logs/error.log) зафиксировано падение:
```
TypeError: Float types are not supported. Use Decimal types instead.
```

- DynamoDB (через `boto3`) не поддерживает стандартный тип Python `float`. Числа с плавающей точкой должны передаваться как `decimal.Decimal` (или целые числа `int`).
- При сохранении первой истории таблица DynamoDB была пуста (`existing = []`). Список похожих историй `similar = related(story, existing)` был пустым (`[]`), поэтому значения оценок похожести `score` не вычислялись и не попадали в итоговый словарь для `put_item()`.
- При публикации второй истории в таблице уже присутствовала первая запись. Функция [`similarity()`](file:///tmp/h-HOXOzO/src/app.py#L25-L32) рассчитала коэффициент схожести и вернула значение типа `float` (`round(...)`). Это значение попало в поле `item["similar"][...]["score"]`. При вызове `table.put_item(Item=item)` сериализатор `boto3` выбросил `TypeError: Float types are not supported. Use Decimal types instead.`, что привело к ответу 500.

## 2. Внесённые исправления

1. **Конвертация оценки в `Decimal`**:
   - В [src/app.py](file:///tmp/h-HOXOzO/src/app.py) импортирован класс `Decimal` из модуля `decimal`.
   - В функции [`similarity()`](file:///tmp/h-HOXOzO/src/app.py#L25-L32) возвращаемое значение преобразуется в `Decimal(str(score))`. Теперь в сохраняемый словарь всегда попадает `Decimal`, допустимый для DynamoDB.

2. **Тестирование второй публикации**:
   - В [tests/test_publish.py](file:///tmp/h-HOXOzO/tests/test_publish.py) добавлен тест `test_publish_second_story_succeeds_with_similarity`, который публикует первую историю, а затем выполняет публикацию второй истории при непустой таблице. Тест валидирует расчёт поля `similar` и гарантирует успешную запись через `FakeTable` (которая строго проверяет типы по правилам `boto3`).

## 3. Какие части заметки коллеги пригодились

- **Пригодилось:**
  - Объяснение механизма бага: `float` не поддерживается в DynamoDB/boto3, а первая запись проходит из-за пустой таблицы (нет похожих элементов, поэтому нет `score`).
  - Рекомендация по исправлению: использование `decimal.Decimal` на границе сохранения данных.
  - Рекомендация по тестированию: добавление интеграционного/модульного теста с предварительно заполненной таблицей (запись второй публикации), предотвращающего регрессию кода, зависящего от состояния базы.
- **Было пропущено / не понадобилось:**
  - Перевод оценок в целые проценты (`int`): в проекте сохранён исходный формат точности (до 4 знаков после запятой) с помощью `Decimal(str(score))`.
  - Упоминания внешних деплоев, проверок в реальной AWS-таблице и поиска по другим эндпоинтам: в репозитории используется локальная `FakeTable`, эмулирующая сериализатор DynamoDB без необходимости обращения к внешним сервисам.
