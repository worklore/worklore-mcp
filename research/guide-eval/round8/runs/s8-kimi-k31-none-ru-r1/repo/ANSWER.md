# Исправление кеширования

Причина: `build_system()` объединял статические правила и контекст спортсмена в один блок с `cache_control`. После `save_fact` менялся список фактов, а вместе с ним и весь кешируемый префикс. Поэтому следующий вызов снова оплачивал создание кеша для всех инструкций, что видно по `cache_read_input_tokens: 0` в `logs/usage.jsonl`.

Изменения:
- В `bot.py` системный промпт разделён на два блока. Первый содержит только неизменный `INSTRUCTIONS` и сохраняет `cache_control: {"type": "ephemeral"}`.
- Профиль, дата, цели, зоны и долговременные факты перенесены во второй блок без `cache_control`. `save_fact` теперь меняет только этот некешируемый блок.
- Описание поведения кеша обновлено в `README.md`.

Проверка: локально выполнен двухраундовый сценарий `reply()` с поддельным LLM и вызовом `save_fact`, без обращения к API и без записи в данные спортсменов. Проверено, что новый факт появляется во втором запросе, а первый системный блок с инструкциями остаётся неизменным; `git diff --check` также проходит. Фактические значения `cache_read_input_tokens` без вызова внешнего API не измерялись.
