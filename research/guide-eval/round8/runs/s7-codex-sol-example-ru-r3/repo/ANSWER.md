# Исправление Intervals.icu

## Причины

1. Кнопка была обычной ссылкой на защищённый `GET /api/intervals/auth/init`. При переходе браузер не отправляет `Authorization` из SPA, поэтому сервер отвечал 401. Это видно в `logs/connect-attempt.log`.
2. Запрошенные области содержали `ACTIVITY:READ` вместе с `ACTIVITY:WRITE` и `CALENDAR:READ` вместе с `CALENDAR:WRITE`. Intervals.icu считает это повторением области и отклоняет авторизацию до экрана согласия. Именно после добавления доступа к календарю вручную открытый URL начал давать 400.
3. Ответ токена в логе не содержит ни `expires_in`, ни `refresh_token`. Сервер выдумывал срок в 3600 секунд, а затем удалял действующий токен. Так возникал запрос повторного подключения у Rivera примерно через час.

## Что изменено

- Инициализация OAuth теперь доступна через авторизованный POST, возвращает `authorize_url` в JSON; кнопка вызывает его через `fetch` и переводит браузер на этот URL.
- Области доступа заданы по одной на тип данных: `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`.
- Обмен кода отправляет `client_id`, `client_secret` и `code`. Из ответа используются токен и `athlete.id`; искусственный срок действия и фоновое обновление удалены.
- При 401 от API токен очищается и статус становится `reconnect required`. Подписанный `state` проверяет назначение, возраст и пользователя; повторное подключение к другому athlete ID отклоняется.

## Что пригодилось из заметки коллеги

Пригодились сведения о бессрочном токене без refresh, повторяющихся областях, полях обмена кода и `athlete.id`, а также схема POST + `fetch` для инициализации и обработка 401. Идею привязки callback к пользователю через подписанный `state` применили с существующим HMAC форматом, добавив назначение и проверку срока. JWT для этого не нужен. Шифрование при хранении здесь не реализовано: этот демонстрационный сервер хранит подключения только в памяти; в постоянном хранилище токен следует шифровать. Внешние шаги из заметки (проверка на реальном аккаунте и отзыв доступа в Intervals.icu) не выполнялись по ограничению задачи.

## Проверка

`python3 -m unittest -v` проверяет локально авторизацию POST, URL и области доступа, callback и поля обмена, сохранение подключения спустя два часа, отклонение испорченного или просроченного `state`, запрет смены athlete ID и переход к повторному подключению после 401. В тестах внешние вызовы заменены заглушками.
