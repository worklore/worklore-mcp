# Intervals.icu: причины и исправление

1. Кнопка вела обычной ссылкой на `GET /api/intervals/auth/init`. При переходе браузер не передаёт заголовок `Authorization`, в котором tricoach хранит авторизацию пользователя. Поэтому init отвечал `401` всем атлетам (точное подтверждение в `logs/connect-attempt.log`). Теперь кнопка делает авторизованный `POST` через `fetch`, получает `{authorize_url}` и переводит браузер на этот URL. Старый `GET` отвечает `405`.
2. После обхода кнопки URL авторизации содержал `ACTIVITY:READ,ACTIVITY:WRITE` и `CALENDAR:READ,CALENDAR:WRITE`. В журнале Intervals отвечал `400 invalid_request` до экрана согласия. Сама ошибка не называет проблемный параметр, поэтому связь с повторяющимися областями доступа следует из заметки коллеги и состава URL, а не доказывается текстом ответа. Оставлены `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE` — по одной записи на область, с правом записи там, где приложение записывает данные.
3. У единственного подключённого атлета ответ на обмен кода не содержал `refresh_token` и `expires_in` (записан в журнале). Код назначал токену вымышленный срок 3600 секунд; фоновый процесс затем удалил его, хотя атлет доступ не отзывал. Удалены вымышленный срок и механизм обновления. Подключение сохраняется до отключения пользователем или ответа `401` от API Intervals; при таком ответе токен очищается, а статус требует повторного подключения.

Из заметки коллеги пригодились: `POST` init с заголовком авторизации, `state` для связи callback с пользователем, правило об уникальной области в `scope`, обмен кода только с `client_id`, `client_secret`, `code`, использование `athlete.id` из ответа, отсутствие срока и refresh-токена, обработка отзыва через `401`, а также защита от подключения другого аккаунта Intervals поверх прежнего. `state` здесь реализован подписанным HMAC значением с назначением и сроком 15 минут; JWT не требуется для этих свойств. Совет шифровать токен при хранении на диске пока неприменим: эта версия хранит подключения только в памяти; при переносе в постоянное хранилище его нужно учесть.

Проверка: `python3 -m unittest -v test_intervals` — 3 локальных теста прошли. Они проверяют init, callback без заголовка, поля обмена кода, подключение без срока, отказ при другом `athlete.id` и переход к повторному подключению после `401`. Реальный обмен с Intervals.icu не выполнялся: в `config.py` указаны тестовые реквизиты, а внешние запросы запрещены условиями задачи.
