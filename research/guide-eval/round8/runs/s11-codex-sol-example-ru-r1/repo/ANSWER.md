# Почему вторая публикация возвращала 500

`logs/error.log` показывает `TypeError: Float types are not supported. Use Decimal types instead.` при `table.put_item(Item=item)`. При первой публикации таблица пуста, поэтому `similar` пуст и в записываемом объекте нет оценок. При следующей публикации `similarity()` вычисляет оценку для уже сохранённой истории обычным делением и возвращает Python `float`. Эта оценка попадает в `similar[].score`, который сериализатор boto3 для DynamoDB не принимает. Исключение превращается в HTTP 500.

# Исправление

`similarity()` теперь считает отношения и веса через `decimal.Decimal` и округляет результат до прежних четырёх знаков. Диапазон оценки 0–1 сохранён, а записываемый `score` имеет поддерживаемый DynamoDB тип. Валидация входной истории также не пропускает числовые значения в `tags` и некорректные типы основных полей: такие запросы получают 400 до записи.

Добавлены локальные тесты с таблицей, которая проверяет типы как сериализатор boto3: две последовательные публикации через обработчик, сохранение дробной оценки и отказ для дробного значения в `tags`. Проверка: `python3 -m unittest discover tests -v` — 4 теста прошли. Внешняя DynamoDB не использовалась.

# Что пригодилось из заметки коллеги

- Объяснение различия между пустой и заполненной таблицей: оно точно соответствует `similar` в этом сервисе.
- Указание проследить вычисляемые значения до `put_item` и проверить вторую запись в тесте.
- Требование использовать тип, принимаемый DynamoDB: выбран `Decimal`.

Совет переводить оценки в целые проценты не применён: это изменило бы существующий диапазон и точность `score`. Проверка на реальной таблице не проводилась, поскольку задача ограничена текущей директорией и запрещает обращения к внешним сервисам.
