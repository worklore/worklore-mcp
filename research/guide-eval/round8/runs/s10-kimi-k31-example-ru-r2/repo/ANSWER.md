# Что сделано

Реализованы все события из `docs/EVENTS.md` через существующую обёртку `Analytics`.

## Экран регистрации

Изменения в `lib/screens/registration_screen.dart`:

- `registration_email_started` отправляется при первом изменении email за время жизни состояния экрана.
- `registration_phone_started` отправляется при первом изменении телефона за время жизни состояния экрана.
- `loan_amount_changed` отправляется в `onChangeEnd` после завершения перемещения слайдера; свойство `amount` передаётся как `int`.
- `terms_accepted` отправляется только при установке флажка согласия, но не при его снятии.
- `registration_continue_tapped` отправляется при нажатии Continue перед переходом к предложениям; свойства: `amount` (`int`) и `terms` (`bool`).
- Email и номер телефона в свойства событий не передаются.

## Экран предложений

В `lib/screens/offer_screen.dart` список обёрнут в `NotificationListener<ScrollEndNotification>`. После завершения прокрутки отправляется `offers_scrolled` со свойством `offset` (`double`, текущее значение `pixels`).

Дополнительные события просмотра экранов не добавлялись: они уже отслеживаются автоматически.

## Что пригодилось из заметки коллеги

- Однократная отправка событий начала ввода с флагами `_emailInputFired` и `_phoneInputFired`, чтобы не отправлять событие на каждое нажатие клавиши.
- Перенос события слайдера из `onChanged` в `onChangeEnd`, чтобы отправлять одно событие с выбранной суммой после завершения перемещения.
- Использование `ScrollEndNotification` вместо событий каждого обновления прокрутки.
- Сохранение точных имён событий и типов свойств из спецификации.

Отправка при потере фокуса не понадобилась: события начала ввода не должны содержать итоговое значение поля.
