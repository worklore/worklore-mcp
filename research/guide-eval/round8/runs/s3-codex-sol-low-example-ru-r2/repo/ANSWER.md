# Почему задача молчала

Задача запускалась: снимок `launchctl print` от 2026-10-18 показывает `runs = 6` и `last exit code = 1`. В `Library/Logs/nightly-review.err` для каждого запуска записаны две последовательные ошибки.

1. `claude` завершался с `Not logged in · Please run /login`. В окружении launchd не было `USER`; добавил `USER=vk` в `EnvironmentVariables` plist, чтобы CLI мог найти учётные данные пользователя. После установки исправленного plist это нужно проверить на настоящем Mac: один только снимок не доказывает, что авторизация восстановится.
2. Следующая строка скрипта присваивала код выхода переменной `status`. В zsh она только для чтения, поэтому скрипт аварийно завершался до вызова `notify.sh`. Заменил её на `rc` и сохранил уведомление об ошибке в ветке ненулевого кода выхода.

Дополнительно передаю многострочный запрос через stdin и проверяю, что при коде выхода 0 агент создал непустой файл. Пустой результат теперь вызывает уведомление об ошибке. В этой папке внешние команды не запускались: нельзя подтвердить доставку Telegram или реальную авторизацию без запуска на исходном Mac.

Из заметки коллеги пригодились проверка `runs` и stderr, предупреждение о переменной zsh `status`, передача запроса через stdin, установка `USER` и проверка фактического результата помимо кода выхода. Совет закрыть stdin через `/dev/null` относится к варианту, где запрос передаётся аргументом; здесь он не нужен. Указанная в заметке ошибка о непереданном запросе в нашем логе не встречается. Принудительный `kickstart` и отправку тестовых уведомлений не выполнял из-за запрета на внешние действия и потому, что здесь лишь снимок домашней директории.
