# Почему задача молчала

Снимок `launchctl print` от 2026-10-18 показывает `runs = 6` и `last exit code = 1`: launchd запускал задачу. В `Library/Logs/nightly-review.err` шесть раз повторяется одна цепочка ошибок:

1. `claude` завершался с `Not logged in · Please run /login`. В окружении задачи из plist был только `PATH`; `USER` отсутствовал. Для headless CLI это мешает найти авторизацию в keychain. В plist добавлен `USER=vk`. Вывод о роли `USER` основан на сочетании конфигурации и ошибки; подтвердить успешную авторизацию можно только после установки исправления в настоящей домашней директории.
2. Сразу после неудачного запуска скрипт делал `status=$?`. В zsh `status` — переменная только для чтения. Эта ошибка обрывала скрипт до вызова `notify.sh`, поэтому сообщение о неудаче не отправлялось. Переменная заменена на `rc`.

Скрипт теперь закрывает stdin у `claude`, проверяет его код выхода и непустой файл обзора, пишет длительность запуска и сообщает об ошибках. У `curl` включён `-f`, чтобы HTTP-ошибка Telegram не считалась успешной отправкой. При неудаче самого уведомления ошибка остаётся в stderr задачи.

## Что пригодилось из заметки коллеги

- Проверка `launchctl print` и чтение `StandardErrorPath` выявили реальные запуски и последовательность отказов.
- Предупреждение о переменной zsh `status` точно совпало с ошибкой в скрипте.
- Совет задать `USER` в plist подходит к `Not logged in` и отсутствующему `USER` в снимке окружения.
- Проверка реального результата, длительности и обоих путей уведомления помогла усилить контроль выполнения.
- Совет закрыть stdin применён, поскольку этот скрипт передаёт промпт аргументом. Перенос промпта в stdin не требовался: в логе нет ошибки разбора промпта, а непосредственный отказ связан с авторизацией.

## Проверка

`zsh -n`, `plutil -lint` и `git diff --check` прошли. Локальный прогон с заглушками `claude` и уведомителя подтвердил: успех даёт код 0 и сообщение с обзором; ошибка `claude` даёт его код 7 и сообщение об ошибке; пустой ответ с кодом 0 превращается в ошибку с уведомлением. Внешние сервисы не вызывались.

Это снимок, поэтому живой `launchctl kickstart`, доступ к keychain и доставка Telegram здесь не проверялись. Для настоящего исправления нужно перенести изменённые файлы в соответствующие пути домашней директории и перезагрузить LaunchAgent; затем проверить свежий обзор, stderr и доставку сообщений при успехе и намеренной ошибке.
