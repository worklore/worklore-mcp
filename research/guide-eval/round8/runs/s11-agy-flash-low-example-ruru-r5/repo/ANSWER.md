# Анализ и исправление ошибки публикации в DynamoDB

## Причина сбоя (logs/error.log)

В журнале `logs/error.log` зафиксирована ошибка при втором вызове `publish`:
```text
TypeError: Float types are not supported. Use Decimal types instead.
```

### Почему первая публикация работала, а вторая завершалась ошибкой 500:
1. При первой публикации таблица `stories` в DynamoDB была пуста (`table.scan(...)` возвращал пустой список элементов).
2. Функция `related(story, existing)` не находила существующих историй для сравнения, поэтому список `similar` оставался пустым (`[]`).
3. При второй публикации в базе уже присутствовала первая история. Функция `related()` вызвала `similarity(story, other)`, которая вычисляет оценку близости:
   ```python
   round(0.7 * tag_score + 0.3 * word_score, 4)
   ```
   Результатом этого выражения является число с плавающей точкой (`float`).
4. Поле `similar` во второй записи содержало структуру вида `[{"slug": "...", "score": 0.xxxx}]`.
5. Библиотека `boto3` (и сериализатор DynamoDB) не поддерживает стандартный тип `float` в Python и требует использования `decimal.Decimal` (или целых чисел `int`), что привело к исключению `TypeError` в методе `table.put_item(Item=item)` и возврату HTTP 500.

---

## Исправление

1. В файле [`src/app.py`](file:///tmp/h-XDtHZZ/src/app.py):
   - Импортирован класс `Decimal` из модуля `decimal`.
   - В функции `similarity()` возвращаемое значение преобразовано в `Decimal(str(round(...)))`:
     ```python
     return Decimal(str(round(0.7 * tag_score + 0.3 * word_score, 4)))
     ```
     Это гарантирует корректную сериализацию значений оценок для DynamoDB.

2. В файле [`tests/test_publish.py`](file:///tmp/h-XDtHZZ/tests/test_publish.py):
   - Добавлен тест `test_publish_second_story_succeeds_with_similarity_scores`, проверяющий сохранение второй записи при непустой базе, когда заполняется массив `similar` со значениями `score`.
   - Добавлен тест `test_handler_second_publish_status_code_201`, проверяющий обработку запроса через `handler` и возврат статуса 201 на обеих публикациях.

---

## Какие части заметки коллеги пригодились

1. **Точная диагностика корневой причины (`float` в DynamoDB)**: 
   - Заметка точно указала, что DynamoDB не принимает питоновский `float`, а ошибка проявляется только при наличии данных в базе (когда начинают вычисляться оценки похожести).
2. **Паттерн исправления**:
   - Преобразование вычисленного `float` на границе сохранения в `Decimal` (через `from decimal import Decimal`).
3. **Рекомендация по тестированию**:
   - Заметка подчеркнула проблему тестов, проверяющих только пустую базу, и необходимость добавления тестов, где в таблицу предварительно сажается запись и проверяется поведение второй публикации при непустом состоянии.

### Что было пропущено / адаптировано:
- В заметке упоминался вариант перевода оценок в целые проценты (`int`). Для сохранения существующей точности до 4 знаков после запятой (как было задумано в `round(..., 4)`) использован `Decimal(str(...))`.
