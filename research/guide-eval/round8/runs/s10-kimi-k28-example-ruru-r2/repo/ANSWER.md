# Реализация событий аналитики

Реализованы все 6 событий из `docs/EVENTS.md` на экранах регистрации
(`lib/screens/registration_screen.dart`) и предложений
(`lib/screens/offer_screen.dart`) через существующую обёртку `Analytics`
(`lib/analytics.dart`). Имена событий и свойства совпадают со спецификацией
один в один, PII (email, телефон) нигде не отправляется.

## Что сделано

| Событие | Где | Когда срабатывает | Свойства |
|---|---|---|---|
| `registration_email_started` | `registration_screen.dart:43` | Один раз за посещение экрана, при первом редактировании поля Email | — |
| `registration_phone_started` | `registration_screen.dart:56` | Один раз за посещение экрана, при первом редактировании поля Phone | — |
| `loan_amount_changed` | `registration_screen.dart:73` | В `onChangeEnd` слайдера — один раз за протягивание, когда пользователь отпускает | `amount` (int) |
| `terms_accepted` | `registration_screen.dart:82` | При установке галочки (только при переходе в `true`) | — |
| `registration_continue_tapped` | `registration_screen.dart:91` | При тапе на активную кнопку Continue (кнопка неактивна, пока форма невалидна) | `amount` (int), `terms` (bool) |
| `offers_scrolled` | `offer_screen.dart:32` | По `ScrollEndNotification` вокруг `ListView` — один раз в конце жеста скролла | `offset` (double, `metrics.pixels`) |

Дополнительно: импорты `../analytics.dart` в обоих экранах; флаги
`_emailStartedFired` / `_phoneStartedFired` в состоянии экрана регистрации.

## Почему события срабатывают именно так

`onChanged` текстового поля во Flutter вызывается на каждое нажатие клавиши,
а `onChanged` слайдера — на каждый шаг протягивания. Если слать события
напрямую из этих коллбэков, один ввод email даст ~20 событий, одно
протягивание слайдера — десятки. Сервисы аналитики с оплатой за событие
(PostHog) сожгут квоту за дни, при этом дашборды будут выглядеть «правильно».
Поэтому:

- Текстовые поля — событие только при первом редактировании (флаг в state).
  Состояние экрана переживает только текущее посещение, так что «один раз»
  = один раз за посещение.
- Слайдер — событие в `onChangeEnd`, итоговое значение `amount` берётся
  из аргумента коллбэка.
- Скролл — `ScrollEndNotification`, а не обновления скролла.

## Что пригодилось из заметки коллеги

Пригодилось (применено):
- Флаг «один раз за посещение» (`bool _<field>InputFired`) для текстовых
  полей — использован для `registration_email_started` и
  `registration_phone_started`.
- Перенос события слайдера из `onChanged` в `onChangeEnd` — использован для
  `loan_amount_changed`.
- Скролл через `NotificationListener<ScrollEndNotification>` — использован
  для `offers_scrolled`.
- Правило «не менять имена событий и свойства, чтобы дашборды и воронки
  продолжали работать» — соблюдено.

Не пригодилось (пропущено):
- Шаги «Проверьте, касается ли это вас» через grep — здесь задача обратная:
  событий не было, реализуем с нуля, ловить нечего.
- Воспроизведение и проверка с `PostHogConfig.debug = true` на debug-сборке —
  в этой среде нельзя запустить Flutter/девайс, проверка только чтением кода.
- Слушатель `FocusNode` для событий с итоговым значением поля — ни одно
  событие не требует итогового значения поля, и по спецификации значения
  полей (PII) отправлять нельзя.
