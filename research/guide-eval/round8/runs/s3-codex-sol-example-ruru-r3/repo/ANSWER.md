# Почему задача молчала

По снимку `launchctl print` задача запускалась шесть раз (`runs = 6`), и последний запуск завершился с кодом 1. Значит, расписание и загрузка агента работали. В `Library/Logs/nightly-review.err` для каждого запуска повторяются две строки: `Not logged in · Please run /login` и `read-only variable: status`.

1. В окружении launchd из снимка задан `PATH`, но отсутствует `USER`. Headless `claude` не смог получить авторизацию и завершился с ошибкой `Not logged in`. В plist добавлено `USER=vk` (имя пользователя следует из путей `/Users/vk/...`). Это исправление для показанного контекста запуска; реальную доступность авторизации в снимке проверить нельзя.
2. Сразу после вызова `claude` скрипт делал `status=$?`. В zsh `status` — специальная переменная только для чтения. Присваивание прерывало скрипт до ветки, отправляющей уведомление о неудаче. Теперь код ошибки сохраняется в `rc` внутри ветки ошибки.
3. Уведомитель подавлял тело ответа Telegram, а `curl` без `-f` мог вернуть код 0 при HTTP-ошибке. Добавлены `-f` и ограничение времени запроса, чтобы такая ошибка стала видна в stderr и коде выхода.

Скрипт теперь передаёт промпт через stdin, пишет в stderr длительность работы, сообщает об ошибке агента и считает пустой файл обзора неудачей даже при коде 0. Это защищает от ложного успеха; в данном снимке ошибки передачи промпта нет, поэтому я не называю её установленной причиной.

## Что пригодилось из заметки коллеги

Пригодились проверка `launchctl print` вместе с stderr, предостережение о `status` в zsh, указание на `USER` для headless CLI и проверка результата сверх кода выхода. Передача промпта через stdin и запись длительности добавлены как меры против описанных там тихих отказов. Совет закрывать stdin при передаче промпта аргументом здесь неприменим: промпт теперь поступает через stdin. Команды `kickstart` и намеренная поломка настоящей задачи не выполнялись: снимок не является работающей домашней директорией, а по условию нельзя выходить за пределы этой папки или отправлять сообщения наружу.

## Локальная проверка

`zsh -n`, `plutil -lint`, `bash -n` и `git diff --check` прошли. С подставными `claude` и уведомителем проверены три сценария без сетевых запросов: успешный обзор (код 0 и сообщение об успехе), ошибка агента (код 7 и сообщение об ошибке), пустой обзор (код 1 и сообщение об ошибке). Настоящую авторизацию Claude, доступ к репозиторию `/Users/vk/projects/shop` и доставку Telegram в этом снимке проверить нельзя. После переноса исправлений в домашнюю директорию plist потребуется заново загрузить в launchd, затем проверить реальный обзор и уведомление.
