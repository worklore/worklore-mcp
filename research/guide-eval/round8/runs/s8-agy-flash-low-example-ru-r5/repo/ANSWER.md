# Изменения в кешировании промпта

## Что было исправлено

В `bot.py` функция `build_system(a, today)` объединяла статические инструкции (`INSTRUCTIONS`) и динамический контекст атлета (`athlete_context(a, today)`, включающий дату, профиль и факты долговременной памяти `a.facts`) в один текстовый блок с единственным маркером `cache_control: {"type": "ephemeral"}`:

```python
# Было:
def build_system(a, today):
    text = INSTRUCTIONS + "\n\n" + athlete_context(a, today)
    return [{"type": "text", "text": text, "cache_control": {"type": "ephemeral"}}]
```

Так как prompt caching в Claude работает как префиксный хеш, при вызове `save_fact` изменение фактов перезаписывало весь блок и приводило к полному сбросу кеша (cache miss на весь системный промпт, ~1000+ токенов).

Функция `build_system` была разделена на два независимых блока с маркерами `cache_control`:
1. **Статический блок**: `INSTRUCTIONS` — неизменный текст инструкций тренера без динамических подстановок (одинаковый для всех пользователей и дней).
2. **Динамический блок (хвост)**: `athlete_context(a, today)` — изменяемые данные (текущая дата, профиль, зоны, цель, факты памяти).

```python
# Стало:
def build_system(a, today):
    return [
        {"type": "text", "text": INSTRUCTIONS, "cache_control": {"type": "ephemeral"}},
        {"type": "text", "text": athlete_context(a, today), "cache_control": {"type": "ephemeral"}},
    ]
```

Теперь при выполнении `save_fact` инвалидируется только второй блок (хвост с фактами и профилем, ~240 токенов), а статический префикс с инструкциями остаётся закешированным.

---

## Какие части заметки коллеги пригодились

1. **Разделение системного промпта на два сегмента с `cache_control: {"type": "ephemeral"}` (Шаг 1 заметки)**:
   - Пригодилась ключевая идея: первый блок — гарантированно неизменяемые статические инструкции (`INSTRUCTIONS`), второй блок — переменный хвост (дата, профиль, факты). Это прямое решение проблемы вытеснения инструкций при `save_fact`.

2. **Анализ стабильности префикса (Шаг 2 заметки)**:
   - В запросе массив `tools` находится выше `system`. В проекте набор `CORE_TOOLS` и порядок групп в `select_tools` детерминированы. Стабильность первого сегмента промпта гарантирует попадание в кеш для статических инструкций.

3. **Отказ от top-N / per-message фильтрации фактов (Шаг 3 заметки)**:
   - В коде уже передаются все факты целиком (`lines += [f"- {f}" for f in a.facts]`), и этот подход был сохранён, чтобы хвост оставался стабильным между сообщениями без изменения фактов.

### Что из заметки было пропущено / не понадобилось

- **Фильтрация инструментов**: в заметке упоминалась оптимизация и риски агрессивной фильтрации 55 инструментов. В текущем боте уже реализована фильтрация по ключевым словам из двух групп (`plan` и `race`) с гарантированным ядром `CORE_TOOLS`, её трогать не требовалось.
- **Интеграция с Telegram**: в репозитории содержится автономное ядро бота (`bot.py`), транспорт находится в отдельном месте.
