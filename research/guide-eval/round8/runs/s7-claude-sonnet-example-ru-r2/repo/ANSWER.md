# Почему не подключался Intervals.icu

Три независимые причины (плюс одна, из-за которой подключение «протухало»):

1. **Кнопка Connect была ссылкой `<a href>` на GET `/api/intervals/auth/init`.** Переход по ссылке — навигация страницы, заголовок `Authorization` (токен лежит в localStorage и добавляется только fetch-обёрткой) не отправляется → 401 `{"error":"unauthorized"}` у всех. Исправлено: init теперь `POST`, возвращает JSON `{authorize_url}`; кнопка вызывает его через `api()` и делает `window.location.assign(authorize_url)`.
2. **Authorize-ссылка отвечала 400 `invalid_request` из-за дублирующихся scope** (`ACTIVITY:READ,ACTIVITY:WRITE` и `CALENDAR:READ,CALENDAR:WRITE`; после релиза календаря 2026-10-02 добавилось второе дублирование). `:WRITE` уже включает `:READ`. Теперь `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`. Это вывод из заметки и логов (тело ошибки Intervals не называет параметр); у Rivera, подключённого до релиза, был scope без дублей — это согласуется.
3. **Подключение «истекало» через час.** Токен Intervals не имеет `refresh_token` и `expires_in` — живёт до отзыва. Код подставлял выдуманный TTL 3600 с и фоновый процесс помечал соединение как expired. Убраны TTL и refresher; теперь при 401 от Intervals токен очищается, статус становится «expired, reconnect» (ленивая обработка отзыва).
4. **Обмен кода**: теперь отправляются только `client_id`, `client_secret`, `code` (без `grant_type` и `redirect_uri`), как в заметке. Это не проверено против живого Intervals — по логам обмен у Rivera проходил и с лишними полями, так что это скорее выравнивание, чем подтверждённая причина.

## Что пригодилось из заметки коллеги
- Пункт 1 (нет refresh_token, ленивая обработка 401) — да, причина 3.
- Пункт 2 (Duplicate scope) — да, причина 2.
- Пункт 3 (упрощённый обмен токена, athlete в ответе) — частично (см. п. 4; athlete из ответа уже использовался).
- Пункт 4 (GET → POST) — да, причина 1.

## Не взято
- JWT в `state` с `purpose`, guard на несовпадение athlete id при переподключении, шифрование токена в хранилище, `SETTINGS:WRITE` в scope — не нужны для этого бага; текущий HMAC-`state` с TTL 15 мин работает. Стоит сделать отдельно (шифрование — желательно в проде).

## Проверка
Только `py_compile`; с реальным аккаунтом Intervals и клиентскими ключами не прогонялось (нет доступа, внешних запросов не делал).
