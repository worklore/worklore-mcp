# Причины сбоя интеграции Intervals.icu

1. **Кнопка Connect теряла аутентификацию.** Она была обычной ссылкой на `GET /api/intervals/auth/init`. При полном переходе браузер не добавляет `Authorization: Bearer ...`, который SPA передаёт только через `fetch`, поэтому endpoint отвечал 401 всем пользователям. Это подтверждается записью от 2026-10-14 в `logs/connect-attempt.log`.

2. **Authorize URL содержал повторяющиеся области.** В `config.py` были одновременно `ACTIVITY:READ,ACTIVITY:WRITE` и `CALENDAR:READ,CALENDAR:WRITE`. У Intervals.icu `:WRITE` уже включает чтение, а повтор области приводит к ошибке на authorize-шаге до показа consent screen. После добавления календарной синхронизации это сломало и обходной путь с ручной ссылкой.

3. **Приложение само истекало действующий токен через час.** Intervals.icu не возвращает ни `refresh_token`, ни `expires_in`: access token действует до отзыва. Код подставлял TTL 3600 секунд, а фоновой refresher затем удалял токен и ставил статус `expired, reconnect`. Поэтому подключение T. Rivera было ошибочно сброшено примерно через час, хотя атлет доступ не отзывал.

4. **Обмен кода содержал лишние form-поля.** В `POST /api/oauth/token` отправлялись `grant_type` и `redirect_uri`. Для Intervals.icu нужны только `client_id`, `client_secret` и `code`.

# Исправления

- Connect теперь делает аутентифицированный `POST /api/intervals/auth/init`, получает `{authorize_url}` и переходит по нему через `window.location.assign`.
- Scope сокращены до `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`, без повторов и лишних READ.
- Обмен кода отправляет только три поддерживаемых поля.
- Токен хранится без выдуманного срока действия; refresh-цикл удалён.
- При реальном 401 от API токен очищается, а статус становится `revoked, reconnect`. Остальные ошибки API не разрывают подключение.
- Подписанный `state` с TTL 15 минут сохранён: он по-прежнему связывает неаутентифицированный callback с пользователем.

# Что пригодилось из заметки коллеги

Пригодились все четыре описанные особенности: POST для init, уникальные scope с `:WRITE` вместо пары READ/WRITE, состав запроса обмена кода и бессрочный токен без refresh. Также применена рекомендация лениво обрабатывать отзыв по 401. Существующая реализация подписанного `state` уже решала задачу идентификации callback, поэтому заменять её на JWT не потребовалось. `SETTINGS:WRITE`, шифрование постоянного хранилища и проверка смены athlete при повторном подключении к этим сбоям не относились и не добавлялись.

# Проверка

Синтаксис Python и JavaScript проверен. Через локальные HTTP-серверы приложения и имитации Intervals.icu пройдены init, callback, обмен кода, status, wellness и отзыв доступа. Проверено, что запрос токена не содержит лишних полей, подключение не имеет `expires_at`/`refresh_token`, а 401 приводит к предложению подключиться заново. Внешние сервисы не вызывались; реальный аккаунт Intervals.icu в соответствии с ограничением не использовался.
