# Почему ночная задача молчала

## Причина 1 (главная): скрипт умирал до вызова уведомления — молчал даже об ошибке

В `bin/nightly-review.zsh` использовалась переменная `status`:

```zsh
claude -p "$PROMPT" --output-format text > "$OUT"
status=$?
```

В **zsh** `status` — это встроенная read-only переменная (синоним `$?`). Присваивание
`status=$?` падает с ошибкой `read-only variable: status`, и — что важно —
**весь скрипт немедленно завершается** (проверено: zsh прерывает исполнение
скрипта даже без `set -e`). Код выхода при этом 1.

Ход каждого ночного запуска (все 6 совпадают с `launchctl print`:
`runs = 6`, `last exit code = 1`, и ровно по 2 строки на запуск в
`nightly-review.err`):

1. `claude` падает → «Not logged in · Please run /login» в stderr;
2. `status=$?` обрывает скрипт;
3. ветка `"$NOTIFY" "nightly review FAILED..."` **не выполнялась никогда** —
   поэтому в Telegram не приходило вообще ничего, включая сообщения об ошибке.

Дополнительно, даже если бы обрыва не было, сообщение об ошибке содержало бы
неверный «(exit 0)»: `[ $status -ne 0 ]` перезаписывает `$?` успешным тестом.

**Исправлено:** переменная переименована в `rc` (`bin/nightly-review.zsh:19-24`),
скрипт доводит оба пути (успех/падение) до вызова `notify.sh`. Проверено
со стабами: падение claude → уведомление `FAILED (exit 1)`, exit 1; успех →
`done: ...`, exit 0.

## Причина 2: под launchd claude не аутентифицирован

В `nightly-review.err` первой строкой каждого запуска идёт
«Not logged in · Please run /login» — то есть даже без причины 1 задача бы
каждую ночь только слала «FAILED». В терминале у пользователя claude
залогинен, а в окружении launchd учётных данных нет. Типичные объяснения:

- launchd **не читает shell-профили** (`~/.zshrc`, `~/.zprofile`). Если токен
  задаётся там (например `export ANTHROPIC_API_KEY=...`), ночной запуск его
  не видит.
- Если это OAuth в связке ключей (элемент `Claude Code-credentials`), то
  ночью, при заблокированном экране/заблокированной связке ключей, токен
  тоже недоступен.

**Что сделать (интерактивно, от пользователя):**
1. Либо добавить `ANTHROPIC_API_KEY` (или `CLAUDE_CODE_OAUTH_TOKEN`) в
   `EnvironmentVariables` плиста `Library/LaunchAgents/com.vk.nightly-review.plist`;
2. либо убедиться, что связка ключей доступна сессии ночью;
3. проверить вручную: `launchctl kickstart gui/501/com.vk.nightly-review`,
   затем посмотреть `~/Library/Logs/nightly-review.err|.out`.

## Причина 3 (замаскированная): notify.sh молча терял ошибки

`bin/notify.sh` отправлял ответ Telegram в `/dev/null` и всегда завершался
с кодом 0: при недоступности токена из связки ключей или ответе
`{"ok":false}` от API сообщение просто не уходило, не оставляя следов.

**Исправлено:** недоступность токена и ответ API без `"ok":true` теперь
пишутся в stderr (попадают в `nightly-review.err`) и дают exit 1
(`bin/notify.sh:4-9,14-18`).

## Итог

Плист и расписание здоровы (`launchctl print`: задача загружена, триггер
02:30 зарегистрирован, логи подключены). Молчание объясняется цепочкой:
`status` в zsh обрывала скрипт до уведомления (причина 1), а claude под
launchd не имеет учётных данных (причина 2). Оба дефекта скриптов исправлены;
аутентификацию claude под launchd нужно настроить по шагам из причины 2.
