# Исправление подключения Intervals.icu

## Причины

1. Кнопка Connect была ссылкой на `GET /api/intervals/auth/init`. При переходе браузер не добавлял `Authorization` из SPA, поэтому сервер отвечал 401. Это видно в `logs/connect-attempt.log` и совпадает с заявками в `logs/support-tickets.md`. Теперь кнопка делает авторизованный `POST` через существующий `api()` и переходит по полученному `authorize_url`.
2. В `SCOPES` одновременно запрашивались `ACTIVITY:READ` и `ACTIVITY:WRITE`, а также `CALENDAR:READ` и `CALENDAR:WRITE`. Запись уже подразумевает чтение: повтор области отклоняется Intervals.icu. В логе ручной переход по такому URL дал 400 до экрана согласия. Теперь запрашиваются `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`.
3. Ответ токена для Rivera не содержал `refresh_token` и `expires_in`. Код назначал ему срок 3600 секунд и фоново переводил соединение в `expired, reconnect`; это прямо видно в логе. Для токена Intervals.icu не нужен такой таймер и refresh. Теперь токен хранится до отключения или первого 401 от API. На 401 сервер очищает токен и показывает состояние `revoked, reconnect`.
4. Запрос обмена кода содержал лишние для Intervals.icu поля `grant_type` и `redirect_uri`. Теперь он отправляет только `client_id`, `client_secret`, `code`.

## Что пригодилось из заметки

Пригодились сведения о бессрочном токене без refresh, правиле областей доступа, формате обмена кода и о том, что переход по ссылке теряет заголовок авторизации SPA. Идея проверки `state` также уместна: здесь уже был подписанный параметр с 15-минутным сроком; дополнительно отклоняются будущие метки времени и неизвестные пользователи. Добавлена защита от подключения другого Intervals-атлета поверх существующего соединения.

JWT из заметки не вводился: существующий HMAC-подписанный `state` решает ту же задачу в этом приложении. Шифрование токена при хранении здесь неприменимо как файловая миграция: демонстрационный сервер держит соединения только в памяти. Для постоянного хранилища в продакшене токены следует шифровать. Это исправление не проверялось с реальным Intervals.icu из-за запрета на обращения к внешним сервисам.

## Проверка

`python3 -m unittest -v test_oauth` — локальный HTTP-тест проверяет авторизованный init, URL областей, callback и поля обмена кода, отсутствие выдуманного срока, очистку токена при 401, недействительный `state` и несовпадение id атлета. Тесты прошли. Также прошли `python3 -m py_compile server.py config.py`, `node --check static/app.js` и `git diff --check`.
