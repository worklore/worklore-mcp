# Причины сбоя интеграции Intervals.icu

1. **Кнопка Connect не отправляла авторизацию tricoach.** Это была обычная ссылка, поэтому браузер выполнял навигацию без заголовка `Authorization: Bearer ...`; заголовок добавлялся только в `fetch`-запросы SPA. Сервер справедливо возвращал 401. Теперь кнопка делает авторизованный запрос к `/api/intervals/auth/init`, получает подписанную ссылку и только затем перенаправляет спортсмена в Intervals.icu.

2. **В authorize-запрос добавили неподдерживаемые scope `CALENDAR:READ` и `CALENDAR:WRITE`.** После этого Intervals.icu стал возвращать `invalid_request` до показа экрана согласия. Эти scope удалены; запрошены только `ACTIVITY:READ`, `ACTIVITY:WRITE` и `WELLNESS:READ`. Для записи запланированных тренировок используется `ACTIVITY:WRITE`, отдельные calendar-scope не нужны.

3. **Отсутствие `expires_in` ошибочно означало срок жизни 3600 секунд.** Intervals.icu не сообщил срок истечения и не выдал refresh token, но код сам подставил часовой TTL. Фоновая задача затем помечала рабочее подключение как `expired, reconnect`. Теперь токен без `expires_in` хранится без искусственного срока истечения и не попадает в процедуру refresh. Если провайдер явно присылает `expires_in`, обновление по refresh token сохраняется.
