# Причины сбоя nightly-review и внесенные исправления

## Почему задача ни разу ничего не сообщила

1. **Ошибка авторизации `claude` (`Not logged in · Please run /login`)**:
   - В `Library/LaunchAgents/com.vk.nightly-review.plist` в секции `EnvironmentVariables` не была задана переменная окружения `USER`.
   - В контексте launchd CLI-утилита `claude` без переменной `USER` не может корректно обратиться к Keychain/хранилищу сессий текущего пользователя macOS и завершается с ошибкой авторизации (`Not logged in`).

2. **Аварийное завершение скрипта в zsh при попытке присвоения `status=$?`**:
   - В скрипте `bin/nightly-review.zsh` на строке 19 выполнялось присвоение: `status=$?`.
   - В shell `zsh` переменная `status` является встроенной переменной только для чтения (read-only alias для `$?`).
   - Попытка записи в нее приводит к фатальной ошибке zsh: `read-only variable: status`, из-за чего скрипт мгновенно падает до того, как управление доходит до блока отправки уведомлений (`$NOTIFY`).
   - В результате ошибка происходила, но уведомление о сбое в Telegram никогда не отправлялось.

3. **Потенциальная проблема с многострочным аргументом prompt в launchd**:
   - Передача многострочного промпта в аргументе команды `claude -p "$PROMPT"` в неинтерактивном контексте launchd может приводить к зависанию на stdin или некорректной передаче аргументов.

---

## Что было исправлено

1. **`Library/LaunchAgents/com.vk.nightly-review.plist`**:
   - В `EnvironmentVariables` добавлена переменная `USER` со значением `vk` (пользователь, для которого настроен LaunchAgent).
2. **`bin/nightly-review.zsh`**:
   - Переменная `status` заменена на `rc` (`rc=$?`).
   - Передача промпта переведена на stdin через пайп: `print -r -- "$PROMPT" | claude -p --output-format text > "$OUT"`.

---

## Какие части заметки коллеги пригодились

- **Пригодилось:**
  - **Диагностика через `StandardErrorPath`**: в логе `Library/Logs/nightly-review.err` четко зафиксированы обе ошибки: `Not logged in · Please run /login` и `read-only variable: status`.
  - **Запрет на присвоение `status` в zsh**: использование `rc=$?` вместо `status=$?`, что предотвращает падение скрипта перед отправкой уведомления об ошибке.
  - **Передача `USER` в `EnvironmentVariables` plist-файла**: именно отсутствие `USER` приводило к ошибке `Not logged in` при доступе к Keychain из-под launchd.
  - **Передача промпта через stdin (`print -r -- "$PROMPT" | claude -p ...`)**: предотвращает проблемы обработки многострочных аргументов и зависания ввода в фоновом режиме launchd.
  - **Анализ `launchctl print`**: подтвердил, что джоб запускался (`runs = 6`), но завершался с кодом 1 (`last exit code = 1`).

- **Не пригодилось / пропущено:**
  - Шаги ручной верификации в живой системе через `launchctl kickstart -k` (так как работа ведется со статическим снимком директории без модификации реальной системы/деплоя).
  - Ссылки на внешние статьи и общие рассуждения о watchdog-таймаутах.
