# Ответ: кеш сбрасывается после save_fact

## Причина

В `build_system` (bot.py) инструкции и блок с данными атлета (`athlete_context`:
факты, зоны, цель, дата) склеивались в один текстовый блок с `cache_control`.
`save_fact` добавляет факт в `athlete.facts`, меняет этот блок, и кеш на весь
префикс (инструменты + system) становится невалидным. Поэтому в `logs/usage.jsonl`
сразу после каждого `save_fact` стоит `cache_read_input_tokens: 0` и новый
`cache_creation_input_tokens` примерно на всю статичную часть.

Дополнительно: дата `Today:` тоже лежала в кешируемом блоке, так что кеш
сбрасывался раз в сутки даже без записей в память.

## Что изменил

**bot.py, `build_system`**: system теперь два блока.

1. `INSTRUCTIONS` (статичный текст, одинаковый для всех атлетов и сообщений),
   с `cache_control: ephemeral`. Это кешируемый префикс.
2. `athlete_context(...)` (факты, зоны, цель, дата, язык) без `cache_control`,
   идёт после точки кеширования. Изменения здесь больше не трогают кеш инструкций.

Остальная логика (инструменты, цикл, логирование usage, `save_fact`) не менялась.

**README.md**: абзац про кеширование переписан под новую схему.

## Проверка

Скриптом, без обращения к API: собрал system для атлета, добавил факт и
собрал снова. Текст первого блока совпал байт в байт, `cache_control` стоит на
первом блоке и не стоит на втором.

Не проверено: реальное попадание в кеш. Для этого нужен ключ API и запуск
`save_fact` с последующим сообщением. Ожидаемый признак в
`logs/usage.jsonl`: после `save_fact` у следующего вызова
`cache_read_input_tokens` ≈ размер статичного блока, а не 0.

## Риски и что осталось

- **Минимальный размер кешируемого префикса.** Модель требует минимум токенов
  для кеширования (для Sonnet около 1024). Статичный блок вместе с инструментами
  может оказаться на границе. Если в логе `cache_creation_input_tokens` остаётся
  0 даже на обычных сообщениях, значит префикс короче минимума, и его надо
  дополнить или переписать. Оценить точно без API я не смог.
- **Фильтр инструментов по ключевым словам** (`select_tools`) меняет список
  `tools` в начале префикса. Кеш тогда не работает между сообщениями с разным
  набором групп (например, «plan» и обычное сообщение). Это отдельная проблема,
  в этот запрос не входила, я её не трогал. Если нужно, можно передавать все
  инструменты всегда и управлять доступностью другим способом, либо держать
  отдельный кеш на каждый набор.
- Данные из `logs/usage.jsonl` не менял. Коммит не делал.
