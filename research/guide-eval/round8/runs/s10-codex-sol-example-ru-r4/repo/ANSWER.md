# Реализация событий аналитики

- На экране регистрации через `Analytics.capture` добавлены `registration_email_started` и `registration_phone_started` — по одному событию при первом вводе в соответствующее поле за время жизни экрана. Значения email и телефона в аналитику не передаются.
- `loan_amount_changed` отправляется после завершения изменения ползунка с целочисленным `amount`; `terms_accepted` — при установке флажка; `registration_continue_tapped` — при нажатии доступной кнопки Continue с `amount` и `terms`.
- На экране предложений `offers_scrolled` отправляется по окончании прокрутки списка с текущим `offset` типа `double`.

Из заметки коллеги пригодились ограничения частоты событий: флаги для первого ввода в текстовые поля, `onChangeEnd` для ползунка и `ScrollEndNotification` для списка. Рекомендации про `FocusNode`, потерю фокуса и финальные значения полей здесь не нужны: спецификация не требует событий фокуса или передачи содержимого полей. Отладку через PostHog и проверку в его интерфейсе не проводил, чтобы не отправлять данные во внешний сервис.

Проверка: `dart format` выполнен, `git diff --check` прошёл. `flutter analyze` не завершился: другая команда Flutter удерживала startup lock; локальные зависимости также не разрешены для `analysis_options.yaml`.
