# Причины

Задача `launchd` запускалась: в `launchctl-print.txt` указаны `runs = 6` и `last exit code = 1`, а интервал 02:30 настроен правильно. Проблема была не в расписании, а внутри сценария.

1. Команда `claude` каждый раз завершалась ошибкой аутентификации: `Not logged in · Please run /login` (`Library/Logs/nightly-review.err`). Поэтому обзор не создавался и успешное уведомление не отправлялось.
2. Обработка этой ошибки тоже падала. В zsh `status` — специальная переменная только для чтения, поэтому присваивание `status=$?` в `bin/nightly-review.zsh` завершало сценарий с ошибкой `read-only variable: status` до вызова `notify.sh`. Именно поэтому не приходило даже уведомление о сбое.

# Исправление

В `bin/nightly-review.zsh` переменная `status` заменена на `exit_code`. Теперь ненулевой код выхода `claude` доходит до ветки уведомления, сообщение содержит этот код, после чего сценарий завершается с тем же кодом.

Проверено локально без обращения к внешним сервисам: синтаксис zsh, уведомление и возврат кода 42 при смоделированной ошибке `claude`, а также успешное уведомление при нулевом коде выхода.

Для получения самих обзоров Claude CLI в реальной среде пользователя всё ещё нужно аутентифицировать. Вход не выполнялся: учётных данных в снимке нет, а обращения к внешним сервисам были запрещены. Изменён только снимок в текущей директории; ничего не развёртывалось.
