# Почему ночная задача молчала

Задача запускалась исправно — `launchctl print` показывает `runs = 6` (ровно по разу
за каждую ночь с 2026-10-12), `state = waiting` — норма. Но каждый запуск умирал
молча. В `nightly-review.err` на каждый запуск приходится пара строк:

```
Not logged in · Please run /login
/Users/vk/bin/nightly-review.zsh:19: read-only variable: status
```

Из них следуют две независимые причины, и молчание — результат их наложения.

## Причина 1 (главная): сообщение об ошибке никогда не отправлялось

`bin/nightly-review.zsh:19` делает `status=$?`, но `status` в zsh — встроенный
**read-only** параметр (синоним `$?`). Присваивание обрывает неинтерактивный
скрипт с exit code 1 *до* блока `if`, который вызывает `notify.sh`. Поэтому
сообщение «FAILED» до Telegram не доходило ни разу. Это же объясняет
`last exit code = 1` в `launchctl-print.txt`.

## Причина 2: claude не залогинен в окружении launchd

Каждый запуск `claude -p` завершался stderr'ом `Not logged in · Please run /login`.
LaunchAgent работает без интерактивной сессии, и доступных креденшелов claude
в этом контексте нет — сводки получаться не могли в принципе. Скрипт падал,
а из-за причины 1 вы об этом не узнавали.

Что сделать на реальной машине (я это не делал — запрещено обращаться к
внешним сервисам): выполнить `claude /login` в сессии пользователя, чтобы
креды попали в Keychain, либо прописать `ANTHROPIC_API_KEY` в
`EnvironmentVariables` plist'а. Проверить `claude -p 'ping'` из headless-контекста,
затем `launchctl start com.vk.nightly-review`. Пока логин не выполнен, задача
будет присылать не сводку, а осмысленное сообщение об ошибке (см. правки).

## Причина 3 (сопутствующая): notify.sh глотал свои собственные ошибки

`bin/notify.sh` выбрасывал ответ Telegram в `/dev/null`, не проверял код ответа
curl, а при ошибке чтения токена из keychain `set -e` убивал скрипт без
диагностики. Даже добравшись до отправки, при плохом токене/сети/API вы бы
не увидели ни сообщения, ни ошибки.

## Что исправлено

- `bin/nightly-review.zsh`
  - `status` → `rc` (больше не падает до вызова notify);
  - stderr claude пишется в `~/Library/Logs/nightly-review-claude-ДАТА.err`,
    а в сообщение об ошибку включён его фрагмент — теперь уведомление сразу
    говорит «Not logged in · Please run /login» и не нужно лезть в логи;
  - `mkdir -p` для директории логов; если `notify.sh` сам падает, об этом
    пишется в stderr (launchd положит это в `nightly-review.err`).
- `bin/notify.sh`
  - явная диагностика при недоступном токене keychain;
  - проверка exit-кода curl и наличия `"ok":true` в ответе API, ошибки —
    в stderr с ненулевым exit.

Plist менять не нужно: расписание, пути логов и PATH работали.

## Как проверено

`zsh -n` / `bash -n`; прогон обоих скриптов с заглушками `claude`, `notify.sh`,
`curl`, `security` во временном HOME внутри рабочей папки. Сценарии: claude
падает / claude успешен / репозиторий отсутствует / keychain отказ / curl отказ /
API-ошибка Telegram / успех — все дают ожидаемый результат (notify вызывается,
exit-коды корректны, ошибки видны). Ни один внешний сервис не вызывался.
(Мелочь: в этой песочнице `date` — GNU, поэтому `date -v-1d` ругается; на macOS
это валидный BSD-синтаксис и на реальной машине работает.)
