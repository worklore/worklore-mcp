# Почему save_fact сбрасывал кеш и что изменено

## Причина
`build_system()` склеивал инструкции и контекст атлета (дата, профиль, факты) в **один**
текстовый блок с `cache_control`. Кеш промптов матчится по точному префиксу на границах
блоков, поэтому любой новый факт менял байты этого единственного блока → промах и полная
перезапись (~1000+ токенов) на следующем же вызове (раунд 2 цикла после `save_fact` в
`logs/usage.jsonl`: `cache_read_input_tokens: 0`, `cache_creation_input_tokens` ≈ весь промпт).

Важная деталь: просто «вынести инструкции в отдельный блок с breakpoint» не помогло бы.
У пользователя 77 весь промпт (tools + инструкции + контекст с двумя фактами) — ровно 1024
токена, т.е. минимум кешируемого префикса для Sonnet 4.5. Статическая часть сама по себе
короче 1024 токенов и молча не кешировалась бы вовсе.

## Что изменено (`bot.py`, `build_system`)
Системный промпт теперь — список блоков, от самого стабильного к самому изменчивому:

1. `INSTRUCTIONS` — статические правила;
2. профиль атлета (имя, спорт, зоны, цель, язык) — `athlete_profile()`;
3. по **одному блоку на каждый факт**, в порядке добавления; `cache_control` стоит на последнем
   (если фактов нет — на профиле);
4. `Today: ...` — **после** breakpoint, не кешируется (раньше дата стояла в начале
   контекста и ежедневно инвалидировала всё, что после неё).

Факты только дописываются в конец, поэтому после `save_fact` закешированный префикс
предыдущего запроса (заканчивался на факте N) остаётся точным префиксом нового запроса.
API находит его через lookback по границам блоков (до 20 блоков назад), читает из кеша
инструкции + профиль + старые факты и записывает в кеш только новый факт (~10–20 токенов)
вместо всего промпта. Breakpoint по-прежнему один, весь кешируемый префикс ≥ 1024 токенов,
как и раньше.

`athlete_context()` заменён на `athlete_profile()`; "Language" перенесён в профиль, строка
"(none yet)" убрана (она бы заменялась первым фактом и ломала префикс) — заголовок списка
фактов сам говорит, что список может быть пуст.

Проверка (офлайн, SDK не установлен): для атлета 42 блоки до breakpoint запроса до
`save_fact` побайтно совпадают с началом блоков запроса после него.

## Ограничения / что не трогал
- Предположение: факты append-only. Если когда-нибудь появится удаление/редактирование
  фактов, изменение в середине списка даст один промах (как сейчас при каждом сохранении).
- Фильтрация tools по ключевым словам оставлена (см. NOTES.md). Tools идут в кеше раньше
  system, поэтому сообщение с другим набором инструментов (plan/race) по-прежнему
  промахивается — это отдельная, уже известная цена, к save_fact не относится.
- Ничего не деплоилось и не отправлялось; изменения только в `bot.py` и этом файле.
