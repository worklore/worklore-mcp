# Решение: Разделение системного промпта на два сегмента кеширования

## Что было изменено

В файле [`bot.py`](file:///tmp/h-kTPNsX/bot.py) в функции `build_system`:
- Ранее системный промпт формировался как единый текстовый блок, объединявший статические инструкции `INSTRUCTIONS` и динамический контекст атлета `athlete_context(a, today)` с одним маркером `cache_control: {"type": "ephemeral"}`.
- При вызове `save_fact` новый факт дописывался в список `facts`, меняя содержимое системного промпта. Так как кеширование промптов в Claude работает по префиксу, любое изменение в хвосте единого блока приводило к сбросу всего кеша — включая ~780 токенов статических инструкций, которые не меняются.
- Системный промпт был разделен на два отдельных блока, каждый со своим маркером `cache_control: {"type": "ephemeral"}`:
  1. **Сегмент 1 (статический)**: неизменяемый текст `INSTRUCTIONS`. Байт в байт идентичен для всех пользователей и запросов, поэтому остается в кеше между вызовами.
  2. **Сегмент 2 (динамический хвост)**: контекст конкретного атлета (`athlete_context(a, today)`: дата, имя, спорт, пульсовые зоны, цель, долговременные факты, язык). При вызове `save_fact` инвалидируется только этот хвост (~240–280 токенов), а статический префикс читается из кеша (`cache_read_input_tokens`).

```python
def build_system(a, today):
    # Two blocks: static instructions (shared across athletes/days) and dynamic per-athlete context.
    return [
        {"type": "text", "text": INSTRUCTIONS, "cache_control": {"type": "ephemeral"}},
        {"type": "text", "text": athlete_context(a, today), "cache_control": {"type": "ephemeral"}},
    ]
```

## Какие части заметки коллеги пригодились

1. **Разбиение `system` на два текстовых блока с `cache_control: {"type": "ephemeral"}` (Шаг 1)**:
   - Блок 1 — статические инструкции, абсолютно стабильные байт в байт.
   - Блок 2 — динамический контекст пользователя (дата, профиль, факты).
   - Это прямое решение проблемы: статический блок сохраняется в кеше при любых изменениях памяти.

2. **Анализ логов метрик кеширования (`usage.jsonl` / Шаг 4)**:
   - Заметка точно описала симптом: `cache_creation_input_tokens ~1000` и `cache_read_input_tokens: 0` на раундах сразу после вызова `save_fact`.

3. **Отказ от лишней динамической фильтрации фактов (пункт про top-N)**:
   - Подтвердило правильность текущей архитектуры: передавать все факты целиком в хвосте дешевле для кеша, чем пытаться отбирать релевантные факты под сообщение.

### Что не потребовалось или уже было реализовано
- **Фильтрация инструментов (Шаг 2)**: в `bot.py` базовая фильтрация по ключевым словам уже была внедрена ранее и оставлена без изменений.
- **Синтаксис API**: библиотека Anthropic поддерживает список словарей с `{"type": "text", "text": ..., "cache_control": ...}` в параметре `system`.
