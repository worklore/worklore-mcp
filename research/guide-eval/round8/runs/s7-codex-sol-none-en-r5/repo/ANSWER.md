# Intervals.icu connection failure

Three independent problems blocked or broke connections:

1. **The Connect button bypassed app authentication.** The SPA stores its sign-in token in `localStorage` and adds it to requests through `api()`. The Connect control was a normal link, so its document navigation to `/api/intervals/auth/init` had no `Authorization` header. The server returned 401 before building an Intervals.icu URL, matching the October 14 log. The button now calls the authenticated API wrapper, receives the authorize URL as JSON, and then navigates the browser to it.
2. **The requested scopes contained duplicate resource families.** The authorize URL requested `ACTIVITY:READ` with `ACTIVITY:WRITE`, and `CALENDAR:READ` with `CALENDAR:WRITE`. Intervals.icu treats `WRITE` as including `READ` and rejects duplicate scopes. These pairs explain the captured `invalid_request` after the link was pasted manually. The request now asks once per resource: `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`. See the [Intervals.icu OAuth scope guidance](https://forum.intervals.icu/t/intervals-icu-oauth-support/2759) and [reported duplicate scope rejection](https://forum.intervals.icu/t/icusync-claude-ai-mcp-connector-for-intervals-icu-no-technical-setup-required/126632?page=6).
3. **A missing expiry was invented as one hour.** Rivera's token response contained an access token but no `expires_in` or `refresh_token`. The server assigned a 3600-second lifetime, then marked the connection expired when it could not refresh it. Intervals.icu's OAuth flow issues access tokens without refresh tokens; absence of `expires_in` is not an instruction to expire the token after an hour. The server now schedules expiry only when `expires_in` is actually supplied. An explicit expiry without a refresh token is still honored at its expiry time. See the [Intervals.icu OAuth documentation and maintainer reply](https://forum.intervals.icu/t/intervals-icu-oauth-support/2759).

Verification: `python3 -m unittest -v test_integration.py` passes local HTTP tests for authentication, authorize URL scopes and state, callback storage, continued connection after a simulated two hours, and an explicitly expiring token. These tests mock the provider token exchange; no live Intervals.icu connection was attempted. Existing connections already marked `expired, reconnect` need the athlete to use Connect again.
