# Причина проблемы и внесенные изменения

## Что изменено
В файле `gen.py` в функции `hr_target(step)` ключ нижней границы диапазона изменен с `"value"` на `"start"`:

```python
def hr_target(step):
    """HR corridor for a step, as a percentage of the athlete's LTHR."""
    lo, hi = step["hr_pct"]
    return {"units": "%lthr", "start": lo, "end": hi}
```

## Почему это произошло и как работает исправление
1. **Причина обрезки по зонам**:
   В API Intervals.icu структура `{ "units": "%lthr", "value": lo, "end": hi }` интерпретируется экспортёром как целевой диапазон, привязанный к дискретным зонам (zone-mapped target). При выгрузке тренировки в Garmin Connect такой шаг мапится на стандартные пульсовые зоны Garmin (Z1–Z5), из-за чего часы отображают границы своих локально настроенных или автоопределенных зон вместо запланированных процентных границ.

2. **Как решает проблему `start` / `end`**:
   Использование пары ключей `"start"` и `"end"` (`{ "units": "%lthr", "start": lo, "end": hi }`) указывает Intervals.icu, что шаг задает произвольный мгновенный коридор целевого пульса (custom Instant-HR corridor). В этом режиме Intervals.icu конвертирует проценты от LTHR в точные абсолютные значения bpm и передает их в Garmin как кастомный целевой диапазон (custom target boundaries), а не как номер зоны.
