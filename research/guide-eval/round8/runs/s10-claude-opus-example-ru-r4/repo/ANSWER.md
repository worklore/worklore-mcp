# События аналитики из docs/EVENTS.md

Все шесть событий отправляются через `Analytics.capture` (`lib/analytics.dart`).
Имена и свойства точно такие, как в спецификации. Email и телефон в свойства
не попадают (это PII).

| Событие | Где | Когда срабатывает |
|---|---|---|
| `registration_email_started` | `lib/screens/registration_screen.dart`, поле Email `onChanged` | один раз за визит на экран, при первом изменении (флаг `_emailStartedFired`) |
| `registration_phone_started` | там же, поле Phone `onChanged` | один раз за визит (флаг `_phoneStartedFired`) |
| `loan_amount_changed` `{amount: int}` | `Slider.onChangeEnd` | один раз за перетаскивание или тап, когда пользователь отпускает слайдер. `onChanged` по-прежнему только обновляет UI |
| `terms_accepted` | `CheckboxListTile.onChanged` | только когда галочку ставят (`true`), снятие не отправляется |
| `registration_continue_tapped` `{amount: int, terms: bool}` | `FilledButton.onPressed` | при нажатии Continue, перед переходом на `/offers` |
| `offers_scrolled` `{offset: double}` | `lib/screens/offer_screen.dart`, `NotificationListener<ScrollEndNotification>` вокруг `ListView` | один раз за жест прокрутки, когда она останавливается (с учётом инерции). `offset = metrics.pixels`, учитывается только сам список (`depth == 0`) |

## Проверка
- `dart format lib` и `flutter analyze` прошли без замечаний. Служебные изменения,
  которые сделали инструменты (`analysis_options.yaml`, `.dart_tool/`,
  `pubspec.lock`), я откатил.
- На устройстве или эмуляторе не запускал, тестов в проекте нет. Чтобы проверить
  вручную, включите `config.debug = true` в `Analytics.init` и посмотрите лог:
  ввод email из 20 символов должен дать одно `registration_email_started`,
  одно перетаскивание слайдера одно `loan_amount_changed`.

## Что пригодилось из заметки коллеги
README говорит, что мы на бесплатном тарифе PostHog, поэтому риск из заметки
к нам прямо относится. Если сделать «в лоб», то есть повесить события на
`onChanged`, событие уходило бы на каждый символ и каждый шаг слайдера
(у слайдера 49 делений). Что я взял:
- **Флаг «один раз за визит»** для полей ввода (`_<field>StartedFired`).
- **`onChangeEnd` вместо `onChanged`** для слайдера.
- **`ScrollEndNotification` вместо `ScrollUpdateNotification`/`ScrollController`**
  для прокрутки.
- **Имена и свойства не меняются**, чтобы дашборды и воронки продолжили работать.

Что не понадобилось:
- **Отправка по потере фокуса и `FocusNode`.** Ни одному событию не нужно
  итоговое значение поля, а событий «тап по полю» в спецификации нет.
- **Отдельный выбор «один раз за визит или за весь флоу».** `RegistrationScreen`
  остаётся в стеке при переходе на офферы, так что состояние живёт весь визит
  и флаг работает естественно.
- **Шаги про PostHog Activity и проверку в рабочем окружении.** Здесь ничего
  не деплоится и никуда не отправляется.

## Решения, которые стоит подтвердить с продуктом
- `terms_accepted` отправляется при каждой постановке галочки. Если пользователь
  несколько раз снимет и поставит её, событий будет несколько. Это отдельные
  действия, а не поток событий, но при желании можно ограничить одним разом за визит.
- `offers_scrolled` отправляется на каждую остановку прокрутки, а не один раз за
  визит, потому что `offset` меняется. Если для воронки нужен только факт
  прокрутки, можно добавить флаг. На высоком экране 10 офферов могут
  поместиться целиком, тогда прокрутки не будет и события тоже не будет.
