# Почему задача молчала

`launchctl-print.txt` показывает `runs = 6` и `last exit code = 1`: launchd запускал задачу. В `Library/Logs/nightly-review.err` для каждого запуска записаны `Not logged in · Please run /login` и затем `read-only variable: status`. Значит, проблема была после запуска, а не в расписании.

1. В окружении launchd не было `USER` (это видно в `launchctl-print.txt`). `claude` не находил вход в учётную запись и завершался с ошибкой. В plist добавлено `USER=vk` для учётной записи из путей задания. Это устраняет причину, указанную сообщением CLI, но реальную авторизацию можно подтвердить только на исходном Mac.
2. Скрипт присваивал код выхода переменной `status`, которая в zsh доступна только для чтения. Ошибка обрывала скрипт до ветки с Telegram уведомлением о сбое. Переменная переименована в `rc`; при ошибке `claude` скрипт теперь доходит до вызова `notify.sh` и возвращает исходный код ошибки.

Из заметки коллеги пригодились проверка счётчика запусков и stderr, замечание о специальной переменной zsh `status` и совет задать `USER` в plist. Совет передавать prompt через stdin здесь не применялся: stderr показывает ошибку авторизации, а не отсутствие prompt; текущий вызов уже передаёт prompt аргументом. Проверка `last exit code` сама по себе не подтверждает доставку сообщения.

Локально проверены синтаксис zsh и bash, чтение plist и отсутствие ошибок в diff. Задание и уведомитель не запускались: для окончательной проверки на исходном Mac нужно заново загрузить изменённый plist, запустить задание и убедиться по свежим логам и сообщению в Telegram, что результат доставлен. После этого полезно проверить ветку ошибки с контролируемым отказом `claude`.
