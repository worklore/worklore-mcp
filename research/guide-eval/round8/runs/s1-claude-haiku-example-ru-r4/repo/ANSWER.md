# Почему пульсовые диапазоны на часах были обрезаны

## Что изменил

В `gen.py`, функция `hr_target`, нижняя граница пульсового коридора теперь
передаётся ключом `start`, а не `value`:

```python
# было
return {"units": "%lthr", "value": lo, "end": hi}

# стало
return {"units": "%lthr", "start": lo, "end": hi}
```

Добавил комментарий над строкой, чтобы причина не потерялась при следующих правках.

Остальное без изменений: `units` остаётся `%lthr`, проценты берутся из плана,
структура шагов и повторов та же.

## Почему

В `readback/watch-notes.md` видно, что часы показывают зоны собственного
пульса часов (118–137, 151–162 и т.д.), а не расчёт из плана
(например, 151–160 для Tempo). Это совпадает с описанием в заметке коллеги:
Intervals экспортирует цель по-разному в зависимости от ключа. При `value`
цель попадает в FIT как «зона» (Lap-HR), и часы подгоняют её под свои зоны.
При `start` цель попадает как «мгновенный пульс» (Instant-HR), и часы показывают
точный коридор, который посчитал Intervals из своего LTHR (172).

Эта связка подтверждает наблюдение из readback: значения совпадают с зонами
часов, а не с расчётом.

## Что проверено и что нет

- **Проверено локально:** `python3 gen.py plans/tempo-run.json` выдаёт тело
  события, в котором во всех четырёх HR-целях `value` заменён на `start`.
  Остальные поля совпадают с `readback/event-184233-as-sent.json` (diff только
  в этих четырёх строках). Файл сгенерирован в `/tmp/h-LlnT5B/event-new.json`,
  в репозиторий не записан.
- **Не проверено:** реальный push в Intervals, readback через API и отображение
  на часах. Я ничего не отправлял и не публиковал, как и требовали правила.
  Утверждение, что `start` даёт нужный коридор на часах, опирается на заметку
  коллеги, а не на мой прогон. Проверить можно так: отправить событие,
  прочитать `GET /events/{id}`, синхронизировать часы через Garmin Connect и
  сравнить шаги с расчётом `% × 172`.

## Что из заметки коллеги пригодилось, а что нет

Пригодилось:
- Главный вывод: ключ `start` вместо `value` переключает режим экспорта. Это
  и есть исправление, которое я внёс.
- Идея сверять readback с часами: `watch-notes.md` уже устроен так.

Не применял (не относится к проблеме или не подтверждено в этом репозитории):
- Поле `description` в текстовом формате Intervals и правила его разбора
  (`m`, `mtr`, `Z<number>` и т.д.). В `gen.py` поля `description` нет, а в
  readback `workout_doc.steps` уже заполнен, значит парсер API принял событие.
  Если в веб-интерфейсе шаги не видны, это отдельная задача, и её стоит
  решать отдельно.
- Инструкции по созданию событий через UI с переключателем «Instant HR» и
  чтению через API: для исправления генератора это не нужно.
- Замечание, что `value` в `%lthr` задаёт зону, я принял на веру из заметки.
  Документацию Intervals я не сверял.
