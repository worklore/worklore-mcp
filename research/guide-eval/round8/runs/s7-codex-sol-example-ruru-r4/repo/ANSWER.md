# Исправление подключения Intervals.icu

## Причины

1. Кнопка была ссылкой на `GET /api/intervals/auth/init`. При переходе браузер открывал документ без `Authorization: Bearer ...`, который SPA добавляет только к `fetch`. Поэтому init отвечал 401 всем атлетам. Это прямо видно в `logs/connect-attempt.log` и обращении #214.
2. Запрашивались одновременно `ACTIVITY:READ` и `ACTIVITY:WRITE`, а также `CALENDAR:READ` и `CALENDAR:WRITE`. По заметке коллеги `:WRITE` уже включает `:READ`; повтор области Intervals отклоняет. В логах ручной authorize URL с этими scope получил HTTP 400 `invalid_request`. Это объясняет, почему ручная ссылка перестала помогать после добавления календаря; конкретную внутреннюю причину 400 провайдер в логе не указал.
3. Ответ токена для Rivera не содержал `refresh_token` и `expires_in`. Код назначал ему вымышленный срок 3600 секунд, а фоновая задача затем очищала действующий токен. В логе записаны получение токена в 17:41 и принудительное отключение в 18:37. Признаков отзыва токена атлетом нет.

## Что изменено

- Init теперь принимает авторизованный POST и возвращает `{ "authorize_url": ... }`; кнопка вызывает его через `fetch`, затем открывает URL.
- Scope сокращён до `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`.
- Убраны вымышленный срок жизни и фоновое обновление токенов. При реальном HTTP 401 от Intervals сохранённый токен очищается, а статус предлагает подключиться снова.
- Callback использует подписанный state с идентификатором пользователя, назначением и сроком 15 минут. Обмен кода отправляет только `client_id`, `client_secret` и `code`. Повторное подключение к другому athlete ID отклоняется.

## Что взято из заметки коллеги

Пригодились сведения об отсутствии `refresh_token`/`expires_in`, правиле неповторяющихся scope, полях обмена кода, необходимости авторизованного POST для init, подписанном state для callback и обработке отзыва через 401. Использован существующий HMAC state вместо JWT: он также проверяет подпись, назначение и возраст и не требует новой зависимости. Совет о шифровании токена при хранении не применён к этому демонстрационному серверу: данные здесь находятся только в памяти; для постоянного хранилища в production это отдельное обязательное требование.

## Проверка

`PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_intervals` — 2 теста прошли. Они локально проверяют авторизованный init, scope, callback и поля обмена, запрос wellness, реакцию на 401 и защиту от смены athlete ID. Реальный OAuth с Intervals.icu не запускался, поскольку задача запрещает обращения к внешним сервисам.
