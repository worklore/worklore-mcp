# Почему nightly-review молчал

Задача запускалась (`runs = 6`, `last exit code = 1`, лог-файлы существуют) — молчание создали два бага один поверх другого. Диагноз по `Library/Logs/nightly-review.err`.

## Причины

1. **`Not logged in · Please run /login`** — headless-агент `claude` под launchd не находил логин. В plist в `EnvironmentVariables` был только `PATH`, без `USER`, поэтому CLI не мог достать учётные данные из keychain. Агент падал сразу, `$OUT` оставался пустым.
2. **`read-only variable: status`** (`nightly-review.zsh:19`) — в zsh `status` встроенная переменная только для чтения. Присваивание `status=$?` убивало скрипт сразу после падения агента, до вызова `notify.sh` с сообщением об ошибке. Поэтому не пришло даже уведомление о сбое. Код выхода 1 — от этого падения.

`notify.sh` исправен (работает вручную), он просто ни разу не был вызван.

## Исправления

- `bin/nightly-review.zsh`: `status=$?` → `rc=$?`, везде использован `$rc`. Заодно `claude -p ... < /dev/null`, чтобы агент не ждал stdin при промпте аргументом.
- `Library/LaunchAgents/com.vk.nightly-review.plist`: в `EnvironmentVariables` добавлен `USER` = `vk`.

Проверено только `zsh -n` и `plutil -lint`; реальный запуск и вход в keychain здесь проверить нельзя. После копирования файлов в домашнюю директорию нужно перезагрузить агент (`launchctl bootout` + `bootstrap` — plist изменился) и сделать `launchctl kickstart -k gui/$UID/com.vk.nightly-review`. Проверьте, что пришло уведомление, `$OUT` свежий и непустой, запуск длился не секунды. Если после этого всё ещё «Not logged in», выполните `claude /login` в обычном терминале.

## Что пригодилось из заметки коллеги

- Пригодилось: проверять запуски через `launchctl print` и читать stderr-лог до теорий; `status` read-only в zsh → `rc=$?` (точное совпадение); `USER` в `EnvironmentVariables` против «Not logged in» (точное совпадение); `< /dev/null` при промпте аргументом; совет проверять реальный результат, а не только код выхода.
- Не пригодилось: передача промпта через stdin — ошибки «Input must be provided…» в моих логах нет, промпт доходит аргументом; описанное расписание 16:50 (у вас 02:30); логирование длительности и намеренный тест уведомления об ошибке — не внедрял, только рекомендация выше.
