# Причина и исправление

В `logs/error.log` первая публикация завершилась с `similar=0` и HTTP 201, а следующая — с HTTP 500 и `TypeError: Float types are not supported. Use Decimal types instead.` Ошибка возникает в `table.put_item(Item=item)`. При пустой таблице `related()` возвращает пустой список. Когда в таблице уже есть история, `similarity()` вычисляла оценку через деление и `round()`, получая `float`; он попадал в `item["similar"][...]["score"]`. Сериализатор boto3 для DynamoDB отклоняет `float`.

В `src/app.py` расчёт оценки переведён на `decimal.Decimal`, включая коэффициенты и округление до четырёх знаков. Сохраняемая оценка остаётся в прежней шкале от 0 до 1, но её тип совместим с DynamoDB. В `tests/test_publish.py` добавлена проверка двух последовательных публикаций через `handler()` в одну таблицу: оба ответа имеют статус 201, вторая история сохранена с ожидаемой оценкой `Decimal("0.4133")`. Команда `python3 -m unittest discover tests -v` прошла: 2 теста. Проверка использует локальную `FakeTable`; обращения к внешнему DynamoDB не было.

Из заметки коллеги пригодились объяснение разницы между пустой и заполненной таблицей, указание на несовместимость `float` с DynamoDB и идея проверять запись после предварительного заполнения таблицы. Вариант с целыми процентами не применялся: он изменил бы существующую шкалу оценки и потерял бы точность до четырёх знаков. Рекомендация публиковать в реальную таблицу не применялась из-за ограничения на внешние сервисы.
