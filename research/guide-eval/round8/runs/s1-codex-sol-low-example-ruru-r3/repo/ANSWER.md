# Исправление пульсовых коридоров

В `gen.py` нижняя граница каждой цели пульса теперь записывается в `hr.start` вместо `hr.value`; верхняя остаётся в `hr.end`, единицы — `%lthr`. Это относится и к шагам внутри повторов. В заметках `readback/watch-notes.md` прежний формат давал на часах границы их локальных зон, а не запланированные интервалы. Формат `start`/`end` из заметки коллеги задаёт коридор Instant HR, который Intervals пересчитывает в bpm по своему LTHR.

Из заметки коллеги пригодились различие между `value`/`end` и `start`/`end`, а также рекомендация сохранить проценты LTHR. Попытки с `bpm` и `start_bpm`/`end_bpm` совпадают с уже зафиксированными неудачными опытами. Правила для текстового `description` не применял: заметки о данном событии подтверждают заполненный `workout_doc.steps`, а задача касается пульсовой цели на часах.

Локальная проверка: генерация `plans/tempo-run.json` дала четыре цели с ожидаемыми `start`/`end`, включая обе цели внутри повтора. Сквозную проверку на часах не выполнял: она потребовала бы отправки события во внешний сервис.
