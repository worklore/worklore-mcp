# Исправление пульсовых диапазонов

В `gen.py` нижняя граница HR-цели теперь передаётся в `workout_doc` как `start` вместо `value`. Генератор формирует `{ "units": "%lthr", "start": low, "end": high }` для каждого шага, в том числе внутри повторов. Проценты LTHR сохранены: Intervals должен пересчитывать их по своему порогу (172 уд/мин), а не по порогу часов.

Причина: по `readback/watch-notes.md` API сохранил шаги, но часы показали границы собственных зон вместо запланированных коридоров. Из заметки коллеги пригодилось наблюдение, что сочетание `value`/`end` приводит к привязке к зонам, а `start`/`end` задаёт точный коридор пульса. Его совет сохранять `%lthr` тоже соответствует текущему плану. Попытки с `bpm` и `start_bpm`/`end_bpm` уже отмечены в readback как неудачные, поэтому их не использовал. Советы про текстовое `description` относятся к отображению шагов в веб-интерфейсе; в нашем readback `workout_doc.steps` уже заполнен, и это отдельная от обрезания диапазонов проблема.

Локальная проверка: сгенерировал событие из `plans/tempo-run.json` и сверил все четыре вида шагов, включая шаги повтора: каждый содержит ожидаемые `%lthr`, `start` и `end`, без `value`. Проверка на часах не проводилась: для неё потребовалась бы отправка события во внешний сервис.
