# Почему не было сообщений

`launchctl-print.txt` показывает, что агент загружен и запускался 6 раз; последний код выхода — 1. Значит, проблема не в расписании или загрузке plist. В `Library/Logs/nightly-review.err` каждый запуск оставил две ошибки:

1. `claude -p` завершался с `Not logged in · Please run /login`. В окружении ночного запуска CLI не авторизован, поэтому обзора коммитов не было. По этому снимку нельзя восстановить авторизацию: её нужно выполнить для `claude` в рабочей учётной записи и проверить именно в окружении, доступном LaunchAgent.
2. После ошибки скрипт выполнял `status=$?`. В zsh `status` — встроенная переменная только для чтения. Присваивание обрывало скрипт до ветки `notify.sh`, поэтому не приходило даже сообщение о сбое.

Исправил `bin/nightly-review.zsh`: код возврата `claude` теперь обрабатывается внутри `if` и сохраняется в `review_exit`; при ошибке, отсутствии репозитория или пустом ответе скрипт пытается отправить сообщение о сбое. Если сама отправка не удалась, это видно в стандартном потоке ошибок задачи.

Исправил `bin/notify.sh`: ошибка чтения токена из Keychain и HTTP-ошибка Telegram теперь дают ненулевой код выхода. Раньше `curl -sS` мог завершиться с кодом 0 при HTTP-ошибке. Неисправность уведомителя не доказана журналом: до него исходный скрипт не доходил.

Проверил синтаксис обоих скриптов и plist; локальными заглушками проверил успешный и ошибочный запуск обзора, а также ошибки Keychain и HTTP. Реальные `claude`, Keychain и Telegram не вызывал. Для возобновления ночных обзоров нужно перенести исправленные скрипты в домашнюю директорию и авторизовать `claude` для запуска без интерактивного входа; это не выполнялось из-за ограничения работать только в текущей папке и не обращаться к внешним сервисам.
