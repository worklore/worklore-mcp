# Причина сбоя и исправление

## 1. Причина сбоя

При первой публикации эндпоинта `POST /stories` база данных DynamoDB была пуста (`table.scan()` вернул пустой список элементов). Функция `related(story, existing)` вернула пустой список `similar: []`. В сохраняемом объекте `item` не было вычисленных значений similarity, и `table.put_item(Item=item)` завершился успешно.

При второй публикации в таблице уже находилась первая статья. Функция `related(story, existing)` вычислила оценку сходства с помощью функции `similarity(a, b)`:
```python
round(0.7 * tag_score + 0.3 * word_score, 4)
```
Результатом выражения в Python является тип `float`. При сохранении статьи с непустым списком `similar` (`[{'slug': ..., 'score': 0.1234}]`), клиент `boto3` пытается сериализовать данные для DynamoDB и падает с исключением:
```
TypeError: Float types are not supported. Use Decimal types instead.
```
В функции `handler` это неперехваченное исключение привело к ветке `except Exception:`, логированию ошибки в `logs/error.log` и возврату HTTP-статуса `500 Internal Server Error`.

---

## 2. Что было сделано для исправления

1. **В [src/app.py](file:///tmp/h-MVp3o4/src/app.py):**
   - Импортирован класс `Decimal` из стандартного модуля `decimal`.
   - В функции `similarity(a, b)` возвращаемое значение преобразовано в `Decimal`:
     ```python
     return Decimal(str(round(0.7 * tag_score + 0.3 * word_score, 4)))
     ```
   Это полностью предотвращает появление типа `float` в атрибутах DynamoDB.

2. **В [tests/test_publish.py](file:///tmp/h-MVp3o4/tests/test_publish.py):**
   - Добавлен тест `test_publish_second_story_calculates_similarity`, проверяющий запись второй истории в непустую таблицу, корректность расчета `similar` и сохранение через `publish` и `handler` без ошибок сериализации.

## 3. Какие части заметки коллеги пригодились

- **Пригодилось полностью:**
  - Объяснение природы ошибки DynamoDB: `boto3` не поддерживает тип `float` и требует `Decimal` (или `int`).
  - Объяснение причины выживания первой записи: при пустой таблице список связанных статей пуст (`similar: []`), поэтому `float` не попадал в запрос на первой записи.
  - Рекомендация конвертировать числовые результаты вычислений (`round`, деление) в `decimal.Decimal` перед записью в DynamoDB.
  - Рекомендация добавить тест, который выполняет публикацию второй записи в непустую таблицу (засеянную первой записью), чтобы покрыть путь выполнения кода, зависящий от состояния базы данных.

- **Было пропущено / не подошло:**
  - Предложение преобразовать оценки в целые проценты (`int`): в сервисе точность сохраняется до 4 знаков после запятой, поэтому `Decimal(str(...))` сохраняет исходную точность без изменения формата данных.
  - Часть про AWS Lambda / деплой / реальную публикацию в облако: в соответствии с правилами задача решается локально без отправки запросов во внешние сервисы.
