# Почему ночная задача молчала

`launchctl-print.txt` показывает `runs = 6` и `last exit code = 1`: launchd запускал задачу, но каждый запуск завершался ошибкой. В `Library/Logs/nightly-review.err` одна и та же пара сообщений повторяется шесть раз:

1. `Not logged in · Please run /login` — Claude не смог получить авторизацию в окружении launchd. В plist был задан `PATH`, но отсутствовал `USER`. Добавлен `USER=vk`, чтобы CLI мог найти учётные данные пользователя. Это исправление соответствует наблюдаемой ошибке; подтвердить доступ к реальному keychain по одному снимку нельзя.
2. Затем zsh выдавал `read-only variable: status`. `status` — специальная переменная zsh, и присваивание `status=$?` прерывало скрипт **до** ветки с уведомлением о сбое. Код возврата теперь сохраняется в `rc`, а отказ Claude сразу передаётся в функцию `fail`, которая пишет причину в stderr и вызывает уведомитель.

Дополнительно скрипт закрывает stdin у `claude -p`, проверяет, что обзорный файл не пуст, и пишет в stderr длительность запуска. Если отправка уведомления об успехе не удалась, задача теперь завершится ошибкой с сообщением в логе. В `notify.sh` добавлен `curl -f`, чтобы HTTP-ошибки Telegram не выглядели как успешная отправка.

## Что пригодилось из заметки коллеги

- Проверка `launchctl print` и stderr: они доказали, что запуск происходил, и показали обе ошибки.
- Запрет на присваивание `status` в zsh: это непосредственная причина отсутствия сообщения об ошибке.
- `USER` в `EnvironmentVariables`: соответствует ошибке `Not logged in`.
- Закрытый stdin при передаче prompt аргументом, проверка фактического результата и длительности, проверка ветки отказа: применены как защита от следующих «тихих» запусков.

Совет передавать prompt через stdin здесь не понадобился: prompt уже передаётся одним аргументом `-p`, а лог не содержит ошибки о его отсутствии. Из-за ограничения на внешние действия не выполнялись `launchctl kickstart`, реальный вызов Claude или отправка в Telegram.

## Проверка в снимке

Синтаксис обоих скриптов, формат plist и `git diff --check` прошли. Локальный прогон с подменёнными Claude и уведомителем проверил три сценария: успешный обзор (код 0 и сообщение об успехе), отказ Claude (код 7 и сообщение об ошибке), пустой результат (код 1 и сообщение об ошибке). Ни один прогон не обращался к внешним сервисам.

После переноса исправленных файлов в домашнюю директорию потребуется перезагрузить launchd agent, поскольку изменилось окружение в plist. Для окончательной проверки там нужны новый запуск, свежий непустой обзорный файл и доставленное уведомление; в этом снимке это подтвердить нельзя.
