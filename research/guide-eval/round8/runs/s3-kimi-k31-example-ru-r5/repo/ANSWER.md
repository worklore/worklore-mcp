# Почему ночная задача молчала

Планировщик работал: в `launchctl-print.txt` видно `runs = 6` и `last exit code = 1`. В `Library/Logs/nightly-review.err` шесть раз повторяются две ошибки:

1. `Not logged in · Please run /login`. В plist задан `PATH`, но не задан `USER`; в окружении launchd CLI не мог получить свою ключевую авторизацию и завершался с ошибкой. Поэтому содержательного обзора и успешного уведомления не было.
2. `/Users/vk/bin/nightly-review.zsh:19: read-only variable: status`. В zsh `status` — встроенная переменная только для чтения. Присваивание `status=$?` аварийно завершало скрипт сразу после вызова `claude`, до ветки с `notify.sh`. Поэтому не отправлялось даже уведомление об ошибке.

Это два последовательных сбоя: сначала не выполнялся обзор, затем ломался именно обработчик его ошибки. Само расписание 02:30 и пути к журналам исправны.

# Что исправлено

- В `Library/LaunchAgents/com.vk.nightly-review.plist` добавлено `EnvironmentVariables.USER = vk`.
- В `bin/nightly-review.zsh` переменная `status` заменена на обычную `rc`; код ошибки сохраняется, передаётся в уведомление и возвращается из скрипта.
- Prompt теперь передаётся в `claude -p` через stdin (`print -r -- "$PROMPT" | claude ...`), а не многострочным аргументом. Это также не оставляет CLI ожидать данные из stdin.

# Что пригодилось из заметки коллеги

- Сначала проверить факт запуска через `launchctl print`, затем читать `StandardErrorPath`: именно эти данные локализовали обе причины.
- Не присваивать `status` в zsh, использовать `rc`.
- Передавать prompt через stdin.
- Задать `USER` в `EnvironmentVariables` для доступа headless CLI к авторизации в keychain.
- Проверять не только код выхода, но и реальный результат, а также принудительно тестировать уведомление об ошибке.

Вариант с prompt-аргументом и `< /dev/null` не применялся, потому что выбран альтернативный вариант с передачей prompt через stdin. Отдельное логирование длительности не добавлялось: оно полезно для наблюдаемости, но не относится к найденным причинам. `launchctl kickstart` и реальные сетевые вызовы не выполнялись из-за ограничения работать только со снимком и ничего не отправлять наружу.

# Проверка

- `zsh -n bin/nightly-review.zsh` — успешно.
- `plutil -lint Library/LaunchAgents/com.vk.nightly-review.plist` — успешно; значение `USER` проверено отдельно.
- Настоящий скрипт прогнан с локальными заглушками `claude` и `notify.sh`: успешный сценарий создал непустой файл обзора и вызвал уведомление; prompt пришёл через stdin, а `USER=vk` дошёл до CLI.
- Принудительный сбой `claude` с кодом 17 привёл к уведомлению `nightly review FAILED (exit 17)` и возврату кода 17 из скрипта.

Реальные авторизация Claude и доставка Telegram в снимке не проверялись; для этого потребовались бы внешние сервисы. Изменения не загружались в действующий launchd-агент.
