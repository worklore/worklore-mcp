# Prompt cache fix

`bot.py` now sends two system text blocks with `cache_control: ephemeral`: fixed coaching instructions first, then the date and athlete context. After `save_fact`, the next tool round changes only the second block, so the static prefix can still be read from cache. I added stable coaching clarification to the first block because the original full prompt was only about 1,046 cached tokens in `logs/usage.jsonl`; Claude Sonnet 4.5 requires a 1,024-token minimum at each cache breakpoint. A split without enough static content could silently fail to cache the first block.

The colleague's two-breakpoint approach and stable-prefix ordering applied. Its advice to keep all facts applied: the bot already does this. Its warning about varying tool schemas applies, but the existing keyword-based tool filtering remains because `NOTES.md` reports a substantial token saving; the selected tool list stays fixed within each message's tool loop. Usage logging was already present and is unchanged. Top-N fact selection was not implemented.

Verified with `python3 -m unittest -v test_bot`: both tests pass. They check that a memory write changes only the athlete block, including during a tool loop. No live Claude call was made because the SDK and API key are not available here; actual cache-read and cache-creation token counts still need a live check within the five-minute cache window. After a `save_fact`, `cache_read_input_tokens` should cover the static prefix, while `cache_creation_input_tokens` should cover the changed athlete tail. A change in selected tools can still produce a separate cache prefix.
