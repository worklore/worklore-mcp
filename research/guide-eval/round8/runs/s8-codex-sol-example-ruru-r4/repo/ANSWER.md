# Исправление кеширования

В `bot.py` системный промпт теперь состоит из двух текстовых блоков с отдельными `cache_control: {"type": "ephemeral"}`. Первый содержит стабильные инструкции, второй — дату, профиль, зоны, цель, факты и язык спортсмена. После `save_fact` меняется только второй блок; статический префикс остаётся тем же. В стабильные инструкции добавлены правила работы с профилем и памятью, чтобы первый кешируемый префикс с используемым небольшим набором инструментов не оказался короче минимального размера для кеширования. `README.md` обновлён под новую структуру.

Из заметки коллеги пригодились разделение промпта на стабильную и изменяемую части, отдельные маркеры кеша и проверка через поля `cache_read_input_tokens` / `cache_creation_input_tokens`. Также учтено, что инструменты находятся перед системным промптом в кешируемом префиксе: существующий порядок схем и выбор инструментов на весь цикл ответа сохранены. Отбор фактов под отдельное сообщение не добавлялся, чтобы не менять изменяемый блок на каждом вызове. Предложение менять фильтрацию инструментов здесь не применялось: по `NOTES.md` она уже снизила затраты и должна остаться.

Проверено локально: `python3 -m py_compile bot.py`, проверка двух запросов до и после добавления факта (первый блок и инструменты совпадают, второй блок меняется), `git diff --check`. В `logs/usage.jsonl` зафиксирована прежняя проблема: сразу после `save_fact` чтение кеша падало до нуля, а создание составляло 1039–1075 токенов. Новых замеров API нет: внешние вызовы не выполнялись. При реальной проверке в пределах срока жизни кеша после `save_fact` ожидается ненулевой `cache_read_input_tokens` для статического префикса и создание кеша для изменённого хвоста; смена набора инструментов или истечение срока кеша могут дать отдельный промах.
