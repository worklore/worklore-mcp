# Исправление кеширования

В `bot.py` функция `build_system` теперь возвращает два системных текстовых блока, каждый со своим `cache_control: {"type": "ephemeral"}`:

1. `INSTRUCTIONS` — неизменные инструкции, без данных атлета и даты.
2. `athlete_context(a, today)` — изменчивый контекст: дата, профиль, зоны, цель, долговременные факты и язык.

Раньше обе части объединялись в один блок. Поэтому добавление факта меняло его содержимое и следующий вызов создавал кеш для всего системного промпта заново. Теперь `save_fact` меняет только второй блок, а байтовое содержимое статических инструкций остаётся прежним и может читаться из кеша.

В `README.md` обновлено описание кеширования в соответствии с новой структурой.

## Что пригодилось из заметки коллеги

- Основное решение: два сегмента `cache_control` — отдельно для статических инструкций и изменчивого контекста.
- Диагностика по `cache_creation_input_tokens` и `cache_read_input_tokens`: в исходных логах после `save_fact` чтение кеша равно нулю, а создание снова покрывает весь промпт.
- Требование сохранять инструменты стабильными: существующий порядок и фильтрация инструментов не менялись.
- Предупреждение о персонализации контекста под каждое сообщение: отбор top-N фактов не добавлялся, чтобы не разрушать кеш изменчивого блока.

Агрессивную фильтрацию инструментов и отбор фактов под сообщение не применял: они не нужны для этого исправления.

## Проверка

Локальный тест с имитацией Claude прошёл полный цикл `reply`: первый ответ вызвал `save_fact`, второй завершил диалог. Проверено, что факт сохранился, во втором запросе появился только в динамическом блоке, а статический блок и список инструментов остались байт в байт неизменными. Оба блока имеют маркер ephemeral. Внешний API не вызывался; фактические значения `cache_read_input_tokens` после развёртывания следует проверить по новым записям `logs/usage.jsonl`.
