# Почему ночная задача молчала

`launchctl-print.txt` показывает `runs = 6` и `last exit code = 1`: launchd запускал задачу по расписанию. В `Library/Logs/nightly-review.err` шесть раз повторяется одна и та же пара ошибок:

1. `Not logged in · Please run /login`: headless CLI не получал `USER` из окружения launchd. В plist был задан только `PATH`. Добавлено `USER=vk`, чтобы CLI мог найти пользовательскую авторизацию.
2. `read-only variable: status` на строке 19: в zsh `status` — переменная только для чтения. Присваивание после вызова CLI аварийно завершало скрипт до ветки с уведомлением об ошибке. Переменная заменена на `rc`.

Дополнительно промпт передаётся через stdin, а не многострочным аргументом; после запуска проверяется код выхода **и** непустой результат. В stderr теперь пишутся код выхода и длительность. Уведомление об ошибке вызывается при ошибке CLI и при пустом результате. `notify.sh` использует `curl -f`, чтобы ошибка HTTP не маскировалась успешным кодом выхода.

## Что пригодилось из заметки коллеги

Пригодились проверка `launchctl print` и stderr, замена `status` на `rc`, задание `USER` в plist, передача промпта через stdin, проверка реального результата и запись длительности. Совет закрывать stdin через `/dev/null` здесь не нужен: промпт теперь подаётся именно через stdin. Описанный у коллеги сбой с потерянным аргументом промпта в нашем снимке не подтверждён: лог указывает на отсутствие логина.

## Проверка и применение

Локально прошли `zsh -n bin/nightly-review.zsh`, `bash -n bin/notify.sh` и `plutil -lint Library/LaunchAgents/com.vk.nightly-review.plist`. Реальный `launchctl kickstart` и отправка в Telegram не выполнялись: снимок не является загруженным агентом, а внешние обращения запрещены. После переноса файлов в домашнюю директорию обновлённый plist потребуется загрузить заново; затем проверить свежесть файла обзора, запись длительности в stderr и доставку сообщений при успехе и намеренно вызванной ошибке.
