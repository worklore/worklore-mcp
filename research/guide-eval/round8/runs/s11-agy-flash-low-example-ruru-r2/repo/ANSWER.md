# Причина падения и исправление

## 1. Причина падения (Почему первая публикация работала, а вторая возвращала 500)

В `src/app.py` при публикации статьи вызывается функция `publish(table, story)`. Перед сохранением текущей статьи она ищет похожие статьи среди уже сохранённых в DynamoDB (`table.scan()`) с помощью функции `related(story, existing)`.
Для каждой существующей статьи считается оценка сходства через `similarity(a, b)`:
```python
def similarity(a, b):
    ...
    return round(0.7 * tag_score + 0.3 * word_score, 4)
```
Результат функции `similarity` является числом с плавающей точкой (`float`). Каждая найденная похожая статья помещается в список `similar`:
```python
{"slug": other["slug"], "score": similarity(story, other)}
```
и сохраняется в поле `similar` записи DynamoDB (`table.put_item(Item=item)`).

- **При первой публикации**: таблица DynamoDB была пуста (`existing = []`). Цикл в `related` ни разу не выполнился, список `item["similar"]` был пустым `[]`. Числа типа `float` в сохраняемый `item` не попадали, поэтому запись прошла успешно.
- **При второй публикации**: в таблице уже была сохранена первая статья. Функция `related` нашла существующую запись и вычислила `score` типа `float`. Библиотека `boto3` / сериализатор типов DynamoDB не поддерживает тип `float` в Python и выбрасывает исключение:
  ```
  TypeError: Float types are not supported. Use Decimal types instead.
  ```
- В `handler` это необработанное исключение попадало в блок `except Exception:`, логировалось в `logs/error.log` и клиенту возвращался статус `500 Internal Server Error`.

---

## 2. Исправление

1. В [`src/app.py`](file:///tmp/h-ODDTCX/src/app.py):
   - Импортирован класс `Decimal` из модуля `decimal`.
   - Возвращаемое значение функции [`similarity`](file:///tmp/h-ODDTCX/src/app.py#L25-L32) обёрнуто в `Decimal(str(round(...)))`:
     ```python
     return Decimal(str(round(0.7 * tag_score + 0.3 * word_score, 4)))
     ```
   - Преобразование через строку `str(...)` гарантирует точное представление округлённого значения без артефактов двоичного представления `float`. Теперь DynamoDB принимает валидный числовой тип `Decimal`.

2. В [`tests/test_publish.py`](file:///tmp/h-ODDTCX/tests/test_publish.py):
   - Добавлен интеграционный тест [`test_second_publish_succeeds_with_existing_stories`](file:///tmp/h-ODDTCX/tests/test_publish.py#L26-L48), который выполняет две последовательные публикации в таблицу. Это гарантирует проверку пути выполнения с непустой базой и защищает от регрессий.

## 3. Какие части заметки коллеги пригодились

- **Пригодилось:**
  - Объяснение механизма бага: `TypeError: Float types are not supported. Use Decimal types instead` возникает из-за того, что DynamoDB через `boto3` не принимает `float`, а первая запись проходит только потому, что таблица пуста и вычисление оценок для похожих элементов не выполняется при пустой базе.
  - Рекомендация конвертировать вычисляемые значения сходства в `Decimal` (или `int`).
  - Рекомендация добавить тест, проверяющий публикацию в таблицу, где уже есть запись (тестирование пути с заполненной таблицей, от которого зависит расчёт схожести).
- **Не пригодилось / пропущено:**
  - Рекомендация переводить оценки в целые проценты (`int`): в сервисе сохранялся 4-значный дробный коэффициент сходства, поэтому сохранение точности с помощью `Decimal` оказалось предпочтительнее целочисленных процентов.
  - Общие рассуждения про деплой и проверку на реальной таблице AWS, так как работа велась локально в репозитории с использованием `FakeTable` и без внешних деплоев.
