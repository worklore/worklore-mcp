# Аналитика: регистрация и список предложений

Все события из `docs/EVENTS.md` отправляются через `Analytics.capture`. Имена и свойства совпадают со спецификацией. Email и телефон в свойства не попадают.

| Событие | Где и когда срабатывает |
|---|---|
| `registration_email_started` | `onChanged` поля email, один раз за посещение экрана (флаг `_emailStartedFired`) |
| `registration_phone_started` | то же для телефона (`_phoneStartedFired`) |
| `loan_amount_changed` | `Slider.onChangeEnd`, один раз за протягивание, `amount` — int |
| `terms_accepted` | только при установке галочки; снятие галочки не отправляется |
| `registration_continue_tapped` | тап по активной кнопке Continue, свойства `amount` (int) и `terms` (bool) |
| `offers_scrolled` | `NotificationListener<ScrollEndNotification>`, один раз за посещение, `offset` = `metrics.pixels` (double) |

## Что пригодилось из заметки коллеги
- Пригодилось всё из набора правил про частоту. Каждое подключение в `onChanged` на каждое нажатие клавиши и каждый шаг слайдера съело бы бесплатную квоту PostHog, а в README указано, что мы на free tier.
- Флаги «один раз за посещение» для текстовых полей.
- Перенос события слайдера в `onChangeEnd`.
- `ScrollEndNotification` вместо слушателя обновлений скролла.
- Не пригодилось: события с итоговым значением при потере фокуса (`FocusNode`). Таких событий в спецификации нет. Отдельное событие на тап по полю тоже не нужно. Отладочная проверка через `PostHogConfig.debug` не выполнялась.

## Решения, которых нет в спецификации
- `offers_scrolled` отправляется один раз за посещение, при первом завершённом скролле с `offset > 0`. Значит `offset` — расстояние первой прокрутки, а не максимальное. Спецификация этого не уточняет. Если нужна максимальная глубина, придётся отправлять по-другому, например при уходе с экрана.
- Флаги живут в состоянии экрана. Если вернуться на экран заново, они сбрасываются, и события отправятся ещё раз.
- `OfferScreen` стал `StatefulWidget`, чтобы хранить флаг.
