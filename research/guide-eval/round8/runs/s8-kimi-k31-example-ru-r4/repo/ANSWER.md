# Исправление кеширования

## Что изменил

- В `bot.py` функция `build_system()` теперь возвращает два системных блока вместо одного:
  1. неизменяемые `INSTRUCTIONS`;
  2. изменяемый `athlete_context()` с датой, профилем, зонами, целью, долговременными фактами и языком.
- Оба блока имеют собственный `cache_control: {"type": "ephemeral"}`. Поэтому `save_fact` меняет только второй блок, а байтовое содержимое статических инструкций остаётся прежним и может продолжать читаться из кеша.
- Порядок и состав инструментов не менял. Факты по-прежнему передаются целиком, без выбора релевантных фактов для каждого сообщения.
- Обновил описание поведения кеша в `README.md`.

## Что пригодилось из заметки коллеги

- Основная причина проблемы: кеш работает по префиксу, а один общий блок с одним маркером заставляет изменение фактов инвалидировать также инструкции.
- Решение с двумя `cache_control`-сегментами: стабильный префикс отдельно, пользовательский и ежедневный контекст отдельно.
- Требование побайтовой стабильности статической части: в неё нельзя подставлять дату, имя, счётчики или факты.
- Предупреждение о том, что выбор top-N фактов для каждого сообщения меняет кешируемый хвост и мешает попаданиям в кеш. Такой выбор не добавлял.
- Рекомендация сохранять стабильность списка инструментов внутри tool-use loop. Существующую фильтрацию инструментов оставил без изменений.
- Поля `cache_creation_input_tokens` и `cache_read_input_tokens` из `usage` пригодились для диагностики и подходят для последующей проверки на реальных ответах API.

## Проверка

Локально прогнал сценарий `reply()` из двух вызовов с имитированным `save_fact`: во втором запросе новый факт появился только в блоке контекста, первый блок остался побайтно неизменным, оба маркера кеширования сохранились, список инструментов не изменился. Проверка прошла успешно. Реальные вызовы внешнего API не выполнялись, поэтому новые значения `usage` в журнале не измерялись.
