# Причины

1. **Сам обзор не выполнялся: CLI `claude` не был аутентифицирован.** В `Library/Logs/nightly-review.err` шесть раз записано `Not logged in · Please run /login`. Это соответствует шести запускам из `launchctl-print.txt` (`runs = 6`, `last exit code = 1`). Расписание launchd настроено правильно и срабатывало в 02:30.

2. **Уведомление об этой ошибке не отправлялось из-за ошибки в обработке кода возврата.** В `bin/nightly-review.zsh` использовалось присваивание `status=$?`. В `zsh` `status` — специальная переменная только для чтения, поэтому интерпретатор завершал скрипт с ошибкой `read-only variable: status` непосредственно на этом присваивании. До проверки кода возврата и вызова `notify.sh` выполнение не доходило. По этой же причине ветка успешного уведомления тоже была недостижима.

# Исправление

В `bin/nightly-review.zsh` переменная `status` заменена на обычную `exit_code`. Теперь ненулевой код `claude` приводит к вызову `notify.sh` с сообщением об ошибке, после чего скрипт возвращает исходный код; успешный результат по-прежнему отправляется через `notify.sh`.

# Проверка и оставшееся действие

Локально с подменёнными `claude` и `notify.sh`, без сетевых запросов, проверены обе ветки: при ошибке отправляется `nightly review FAILED (exit 1) ...` и сохраняется код 1; при успехе отправляется `nightly review done: ...` и создаётся отчёт. Также успешно выполнены `zsh -n bin/nightly-review.zsh` и `plutil -lint Library/LaunchAgents/com.vk.nightly-review.plist`.

Аутентификацию `claude` из снимка восстановить нельзя: для получения самих обзоров на реальной машине пользователю нужно один раз выполнить `claude` и пройти `/login` (либо настроить поддерживаемую CLI аутентификацию для неинтерактивного запуска). Это действие не выполнялось, равно как не отправлялись сообщения и не изменялся загруженный LaunchAgent: изменения сделаны только в текущей папке.
