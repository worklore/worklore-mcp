# Реализация аналитики

- На экране регистрации добавлены `registration_email_started` и `registration_phone_started`: каждое событие отправляется при первом непустом вводе один раз за посещение экрана. Адрес и номер в свойства не передаются.
- `loan_amount_changed` отправляется по завершении взаимодействия со слайдером с целочисленным `amount`; `terms_accepted` — при установке галочки; `registration_continue_tapped` — при нажатии доступной кнопки с `amount` (int) и `terms` (bool).
- На экране предложений `offers_scrolled` отправляется по окончании вертикальной прокрутки с `offset` (double).
- Все шесть событий отправляются через существующую `Analytics.capture`. Автоматическое отслеживание просмотров экранов не менялось.

Из заметки коллеги пригодились флаги для однократных событий ввода, `onChangeEnd` для слайдера и `ScrollEndNotification` для списка: они не создают событие на каждый символ, шаг слайдера или обновление прокрутки. Рекомендации про `FocusNode` и итоговое значение полей не потребовались: спецификация требует только факт начала ввода и запрещает передавать email и телефон. Проверку через PostHog Activity не проводил, поскольку она обращается к внешнему сервису.

Проверка: `dart format --output=none --set-exit-if-changed` и `git diff --check` прошли. `flutter analyze` не завершился: команда ждала блокировку запуска Flutter от другого процесса; также в проекте пока нет разрешённых пакетов (`flutter_lints` не найден), а загрузка зависимостей потребовала бы обращения к внешнему сервису.
