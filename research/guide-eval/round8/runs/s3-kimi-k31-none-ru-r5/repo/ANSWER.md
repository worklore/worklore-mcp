# Почему не приходили уведомления

Проблема не в расписании `launchd`: `launchctl-print.txt` показывает шесть запусков (`runs = 6`), а `Library/Logs/nightly-review.err` содержит шесть повторяющихся ошибок.

1. **Сам обзор не выполнялся из-за отсутствия аутентификации.** `claude` каждый раз писал `Not logged in · Please run /login` и завершался с ошибкой. Поэтому успешного уведомления быть не могло.
2. **Уведомление об этой ошибке было недостижимо из-за ошибки в скрипте.** В zsh `status` — специальная переменная только для чтения. Строка `status=$?` после вызова `claude` завершала скрипт с сообщением `read-only variable: status`, до перехода в ветку с `notify.sh`. Это непосредственная причина полной тишины при сбоях.

# Что исправлено

В `bin/nightly-review.zsh` переменная `status` переименована в `exit_code`; её значение используется и в тексте уведомления, и при выходе. Теперь ненулевой код `claude` приводит к вызову `notify.sh` с сообщением `nightly review FAILED`, а не к падению интерпретатора.

Конфигурация `launchd` и `notify.sh` не менялись: сохранённые данные не показывают неисправности расписания, а по README notifier при ручном запуске работает.

**На реальной машине всё ещё нужно один раз войти в `claude` интерактивно через `/login` от пользователя `vk`.** Снимок не содержит средств восстановить эту аутентификацию. До входа должны приходить уведомления об ошибке, после входа — результаты обзора. Исправленные файлы здесь никуда не развёртывались.

# Проверка

- `/bin/zsh -n bin/nightly-review.zsh`, `/bin/bash -n bin/notify.sh` и `plutil -lint` прошли успешно.
- С локальными заглушками без сети проверены обе ветки: ошибка агента с кодом 42 вызвала уведомление `FAILED (exit 42)` и вернула код 42; успешный агент вызвал уведомление с текстом обзора.
