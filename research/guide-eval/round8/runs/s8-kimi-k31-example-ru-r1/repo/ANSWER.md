# Исправление кеширования

В `bot.py` функция `build_system` теперь возвращает два текстовых блока, каждый со своей меткой `cache_control: {"type": "ephemeral"}`:

1. `INSTRUCTIONS` — статические инструкции без данных спортсмена и даты.
2. `athlete_context(a, today)` — изменяемый контекст: дата, профиль, зоны, цель, долговременные факты и язык.

Раньше обе части объединялись в один кешируемый блок, поэтому `save_fact` менял его содержимое и следующий вызов заново создавал кеш для всего системного промпта. Теперь запись факта меняет только второй блок; статический префикс остаётся неизменным и может читаться из кеша. В `README.md` обновлено описание этого поведения.

Фильтрация инструментов, порядок их схем и загрузка всех долговременных фактов сохранены. Новых вызовов внешних сервисов и изменений данных спортсменов при проверке не было.

## Что пригодилось из заметки

- Два сегмента с отдельными `cache_control`: статические инструкции и изменяемый пользовательский контекст.
- Требование байтовой стабильности статического блока: в него не переносились дата, имя или факты.
- Сохранение стабильного списка инструментов внутри одного tool-loop и отказ от дополнительной агрессивной фильтрации.
- Отказ от выбора top-N фактов для каждого сообщения: это делало бы изменяемый блок разным даже без записи в память.
- Проверка по `cache_creation_input_tokens` и `cache_read_input_tokens`.

## Проверка

Локальный сценарий с имитацией ответов Anthropic API прогнал `reply()` через реальный `run_tool(save_fact)`; запись на диск и логирование были подменены. До записи повторный вызов читал оба блока из имитированного кеша. После записи проверено, что первый блок совпадает с предыдущим запросом, новый факт находится только во втором блоке, а метрики соответствуют чтению статического блока и созданию кеша только для изменённого контекста.

Реальный API не вызывался, поэтому фактические списания и новые записи в `logs/usage.jsonl` не проверялись.
