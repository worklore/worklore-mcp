# Почему задание молчало

`launchctl-print.txt` показывает `runs = 6` и `last exit code = 1`: launchd запускал задание. В `Library/Logs/nightly-review.err` каждый запуск оставил две ошибки. `claude` завершался с `Not logged in · Please run /login`; в окружении задания отсутствовал `USER`, который нужен CLI для поиска учётных данных в связке ключей. Затем строка `status=$?` пыталась записать в доступную только для чтения специальную переменную zsh. Интерпретатор прерывал скрипт до ветки, отправляющей сообщение об ошибке. Поэтому Telegram не получил ни результат, ни сообщение о сбое.

В plist добавлен `USER=vk`; в скрипте код возврата сохраняется в `rc`. Для аргумента `-p` закрыт stdin, чтобы фоновый CLI не ожидал ввод. Пустой файл результата теперь считается ошибкой и вызывает уведомление. Эти изменения сделаны только в снимке; установленный LaunchAgent ими пока не обновлён.

Из заметки коллеги пригодились проверка числа запусков через `launchctl print`, чтение stderr, запрет присваивания `status` в zsh, `USER` для headless CLI, закрытие stdin при передаче prompt аргументом и проверка реального результата помимо кода выхода. Совет передавать prompt через pipe не понадобился: в данном снимке ошибка связана с авторизацией, а prompt уже передаётся аргументом. Сведения о времени выполнения и тестовые уведомления в снимке отсутствуют, поэтому доставку сообщений после исправления здесь подтвердить нельзя.
