# Почему вторая публикация возвращала 500

В `logs/error.log` вторая публикация падает на `table.put_item(Item=item)` с ошибкой `TypeError: Float types are not supported. Use Decimal types instead.` Первая публикация проходит, потому что таблица пуста и поле `similar` содержит пустой список. После появления первой истории `related()` добавляет в `similar` оценку из `similarity()`. Прежняя реализация вычисляла её через `/` и `round()`, получая Python `float`, который сериализатор DynamoDB не принимает.

В `src/app.py` оценка теперь вычисляется только через `Decimal` и округляется до прежних четырёх знаков. Диапазон оценки 0–1 и структура сохраняемого элемента не изменились. Поэтому наличие похожих историй больше не добавляет `float` в запись.

В `tests/test_publish.py` добавлен тест двух последовательных запросов к одной таблице. Он проверяет оба ответа `201`, наличие второй записи и сохранённую оценку типа `Decimal`. `tests/fake_dynamo.py` отклоняет `float` так же, как сериализатор boto3, поэтому тест обнаруживает исходную ошибку без обращения к AWS.

Из заметки коллеги пригодились причина различия между первой и второй записью, подсказка проверить вычисляемые значения перед `put_item` и тест с уже заполненной таблицей. Вариант с целыми процентами не использован: он изменил бы шкалу или точность существующих оценок. Публикация в реальную таблицу не выполнялась согласно ограничению работать локально и не обращаться к внешним сервисам.

Проверка: `python3 -m unittest discover tests -v` — 2 теста прошли.
