# Причины проблемы

1. **Ошибка аутентификации Claude CLI в среде launchd (`Not logged in · Please run /login`)**:
   - При запуске через `launchd` процесс выполняется в минимальном изолированном окружении, в котором переменные окружения `$HOME` и `$USER` не передаются по умолчанию (в `plist` была задана только переменная `PATH`).
   - Утилита `claude` ищет конфигурацию и сессионные токены пользователя в каталоге `~/.claude/` (т.е. `$HOME/.claude`). В отсутствие `$HOME` утилита не может обнаружить сохранённую авторизацию пользователя и падает с сообщением `Not logged in · Please run /login` (код возврата 1).

2. **Аварийное завершение скрипта из-за попытки записи в `status` в `zsh`**:
   - В командном интерпретаторе `zsh` переменная `status` является специальным read-only псевдонимом для переменной `$?` (кода возврата последней команды).
   - В строке 19 файла `bin/nightly-review.zsh` выполнялось присваивание:
     ```zsh
     status=$?
     ```
   - При попытке переопределить встроенную переменную оболочка `zsh` завершает выполнение скрипта с фатальной ошибкой:
     ```
     /Users/vk/bin/nightly-review.zsh:19: read-only variable: status
     ```
   - Из-за этого интерпретатор `zsh` аварийно прерывал выполнение скрипта до строк 21–24, где расположен вызов `bin/notify.sh` для отправки уведомления об ошибке (`nightly review FAILED...`). В результате Telegram-сообщение об ошибке даже не успевало отправиться.

---

# Внесённые исправления

1. **Исправлен скрипт `bin/nightly-review.zsh`**:
   - Переменная `status` заменена на `exit_code`, что предотвращает фатальную ошибку `read-only variable: status` и позволяет блоку обработки ошибок корректно вызывать `$NOTIFY` при ненулевом коде завершения.
