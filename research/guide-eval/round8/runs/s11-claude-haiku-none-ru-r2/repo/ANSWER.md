# Почему вторая публикация возвращает 500

## Причина

В `similar` каждой истории записывается `score`, который считает `similarity()` в
`src/app.py`. Эта функция возвращает `round(..., 4)`, то есть Python `float`.
DynamoDB (через boto3) `float` не принимает: `TypeError: Float types are not
supported. Use Decimal types instead.` Ошибка ловится в `handler()` общим
`except Exception`, поэтому клиент получает 500.

Почему публикация «работает один раз»:

- Первая публикация: таблица пуста, `existing` пустой, `related()` возвращает
  `[]`. Во вложенном списке не оказывается ни одного `float`, запись проходит (201).
- Любая последующая публикация: в таблице уже есть хотя бы одна история, `related()`
  возвращает `[{slug, score: float}]`, и запись падает. Это происходит даже при
  `score = 0.0`, потому что тип всё равно `float`.

Лог подтверждает это: `similar=0 stored` для первой публикации, затем две ошибки
`Float types are not supported` для второй и третьей.

Воспроизведение до исправления: первый `handler()` → 201, второй → 500.

## Почему тесты это не поймали

`tests/test_publish.py` публикует только одну историю. Пустой `similar` никогда не
содержит `float`, поэтому баг не проявлялся. Фейковая таблица `tests/fake_dynamo.py`
при этом уже отклоняет `float` с тем же текстом ошибки, что и настоящий DynamoDB,
так что тест не хватало одного сценария: вторая публикация.

## Исправление

`src/app.py`, `related()`: `score` сохраняется как `Decimal`:

```python
scored.append({"slug": other["slug"], "score": Decimal(str(similarity(story, other)))})
```

`similarity()` и сортировка остаются на `float`; конвертация стоит на границе
записи в таблицу. `Decimal(str(...))` берёт строковое представление, поэтому
значение не получает лишних знаков, например `Decimal('0.3')`, а не
`Decimal('0.29999999999999998...')`.

## Защита от повторения

В `tests/test_publish.py` добавлены тесты:

- `test_second_publish_with_related_stories_is_stored`: вторая публикация
  сохраняет `similar`, и `score` имеет тип `Decimal`.
- `test_handler_returns_201_on_second_publish`: через `handler()` вторая публикация
  возвращает 201.
- `FakeTableTest.test_rejects_float_like_dynamodb`: проверяет, что фейковая таблица
  действительно отклоняет `float`, чтобы тесты на эту проверку не стали ложно
  зелёными.

Проверка: на старом `src/app.py` два новых теста падают (`FAILED (failures=1, errors=1)`),
на исправленном все 4 теста проходят (`python3 -m unittest discover tests`).

Ограничение: тесты защищают от повторения, только если их запускают перед
деплоем. Если в будущем в запись попадёт новое поле типа `float`, фейковая
таблица его поймает, но только в тестах.

## Данные

Неудачные публикации не записали ничего в таблицу (исключение срабатывает до
`put_item` успешно пройти), поэтому чистить таблицу не нужно. Уже сохранённую
первую историю исправление не затрагивает.
