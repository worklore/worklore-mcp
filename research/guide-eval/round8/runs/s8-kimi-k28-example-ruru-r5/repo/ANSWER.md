# Что изменено

**bot.py — `build_system()`**: системный промпт разбит с одного кешируемого
блока на два, у каждого свой маркер `cache_control: {"type": "ephemeral"}`:

1. Блок 1 — `INSTRUCTIONS` (правила коуча). Байт в байт одинаков для всех
   атлетов и дней, никаких подстановок. Стабилен всегда.
2. Блок 2 — `athlete_context()`: дата, профиль, зоны, цель, долговременные
   факты, язык. Это единственная часть, которую меняет `save_fact`.

Кеш промптов Anthropic — хеш префикса: раньше один маркер в конце промпта
объединял обе части, и каждый `save_fact`, дописывая факт в хвост, менял хеш
всего блока — следующий вызов получал `cache_read_input_tokens: 0` и платил
полную цену за весь промпт заново (видно в `logs/usage.jsonl`: строки после
`save_fact`, напр. 06:43:16 и 08:02:33). Теперь запись в память
инвалидирует только блок 2; статические инструкции остаются в кеше.
Дата живёт в изменчивом блоке, поэтому смена дня тоже трогает только хвост.

Итоговый запрос использует 2 маркера из разрешённых 4. Фильтрация инструментов
по ключевым словам не тронута (по NOTES.md — оставить), top-N отбор фактов
не добавлялся: грузим все факты каждый раз, как и раньше.

# Что пригодилось из заметки коллеги

- **Главная идея — два сегмента `cache_control`** (статические инструкции /
  изменчивый хвост) — применена как есть. Это и есть весь фикс.
- **Проверка через `usage`**: `cache_creation_input_tokens` после записи в
  память должен быть размером только хвоста, а `cache_read_input_tokens` —
  покрывать статический блок. Использовано как критерий приёмки при
  локальной симуляции (см. ниже).
- **Отказ от top-N отбора фактов под сообщение** — учтён: такой отбор не
  добавлялся, потому что он делает хвост разным для каждого сообщения и
  ломает кеш хвоста. Все факты грузятся целиком.
- **Терпимость к смене набора инструментов** — принято: сообщение, подтягивающее
  группу `plan_week`/`predict_race`, по-прежнему разово перечитывает промпт
  (инструменты в кешированном префиксе стоят выше системного блока). Это
  осознанная плата за фильтрацию инструментов, внутри одного цикла инструментов
  набор постоянен — а там кеш окупается сильнее всего.

# Что пропущено

- **Фильтрация инструментов по ключевым словам** из заметки — в этом репозитории
  она уже внедрена раньше (март, `select_tools()`), повторять не нужно.
- **Телеграм- и MCP-специфика** заметки к этому репозиторию не относится
  (транспорт живёт в другом деплой-репо).

# Проверка

Реальный API не вызывался (ключа нет; внешние сервисы не трогаем). Семантика
кеша Anthropic (хеш префикса по сегментам с маркерами) промоделирована
локально: `reply()` прогнан с фейковым LLM через тот же код сборки запроса,
записи лога собирались в память, `data/athletes.json` снапшотился и
восстановился — проектные файлы не изменены.

Тот же диалог «save_fact → ответ → follow-up»:

| вызов | было: created/read | стало: created/read |
|---|---|---|
| msg1 round2 (сразу после save_fact) | 701 / 0 | 83 / 621 |
| msg2 round1 (следующее сообщение) | 0 / 701 | 0 / 704 |

Статический блок (~620 токенов в модели) после `save_fact` читается из кеша,
пересоздаётся только хвост (~80). Плюс проверено: `build_system()` возвращает
два блока с маркерами, блок 1 совпадает с `INSTRUCTIONS` байт в байт.
