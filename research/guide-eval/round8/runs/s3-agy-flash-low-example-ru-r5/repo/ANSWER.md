# Причины сбоя и внесенные исправления

## Почему задача launchd ни разу ничего не сообщила

В логе ошибок `Library/Logs/nightly-review.err` и выводе `launchctl print` зафиксированы две основные проблемы, которые привели к полной тишине:

1. **Ошибка аутентификации `claude` из-за отсутствия переменной окружения `USER`:**
   - В логе: `Not logged in · Please run /login`.
   - Под управлением launchd скрипт запускается с минимальным набором переменных окружения (в `com.vk.nightly-review.plist` был задан только `PATH`). Без установленной переменной `USER` CLI `claude` не может получить доступ к учетным данным в связке ключей macOS (Keychain) и завершается с кодом ошибки 1.

2. **Аварийное завершение скрипта из-за присвоения в переменную `status` в `zsh`:**
   - В логе: `/Users/vk/bin/nightly-review.zsh:19: read-only variable: status`.
   - В оболочке `zsh` переменная `status` является встроенной и предназначена только для чтения (read-only псевдоним для `$?`).
   - Попытка выполнить присваивание `status=$?` на строке 19 приводит к фатальной ошибке zsh и немедленному падению скрипта до выполнения блока обработки ошибок и отправки уведомления в Telegram (`$NOTIFY`).

Кроме того, передача многострочного промпта как аргумента командной строки `claude -p "$PROMPT"` в автоматизациях launchd может вызывать проблемы с вводом или зависание в ожидании stdin.

---

## Что было исправлено

1. **`Library/LaunchAgents/com.vk.nightly-review.plist`**:
   - В секцию `EnvironmentVariables` добавлена переменная `<key>USER</key><string>vk</string>`, чтобы CLI `claude` мог корректно определять пользователя и обращаться к Keychain.

2. **`bin/nightly-review.zsh`**:
   - Заменено присваивание переменной только для чтения `status` на безопасную переменную `rc` (`rc=$?`), а также обновлены проверки `$rc`.
   - Передача промпта переведена на передачу через стандартный ввод: `print -r -- "$PROMPT" | claude -p --output-format text > "$OUT"`.

---

## Какие части заметки коллеги пригодились

- **Пригодилось:**
  - **Диагностика через `status=$?` в zsh**: подтвердилась строка лога `read-only variable: status`, из-за которой скрипт падал и «убивал вестника» до вызова `notify.sh`. Рекомендация использовать `rc=$?` применена в `bin/nightly-review.zsh`.
  - **Переменная окружения `USER` в plist**: рекомендация задать `USER` в `EnvironmentVariables` для доступа к Keychain решила проблему `Not logged in · Please run /login`.
  - **Передача промпта через stdin (`print -r -- "$PROMPT" | ...`)**: применена для надежной передачи многострочного промпта в `claude -p`.
  - **Анализ логов и статуса через `launchctl print` и `StandardErrorPath`**: вывод `launchctl-print.txt` и `nightly-review.err` подтвердил реальную картину запусков (`runs = 6`, `last exit code = 1`).

- **Не потребовалось / пропущено:**
  - Шаги повторной загрузки и верификации через запуск реальных сервисов (`launchctl kickstart`, обращение к Telegram API), так как работа велась исключительно со снимком файлов локально без внешних сетевых вызовов и деплоя.
