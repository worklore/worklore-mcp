# Исправление кеширования

В `bot.py` функция `build_system()` теперь возвращает два текстовых блока вместо одного общего:

1. `INSTRUCTIONS` — неизменные инструкции с отдельным `cache_control: {"type": "ephemeral"}`.
2. `athlete_context(a, today)` — дата, профиль, цель, зоны, долговременные факты и язык с собственным таким же маркером.

Теперь `save_fact` меняет только второй блок, а статические инструкции остаются байт в байт прежними и могут читаться из кеша. Порядок и фильтрация инструментов не изменялись; отбор фактов под конкретное сообщение не добавлялся.

## Что пригодилось из заметки коллеги

- Основное решение: два сегмента `cache_control` — стабильные инструкции и изменяемый контекст атлета.
- Объяснение кеширования по префиксу: изменение памяти не должно инвалидировать расположенный перед ним статический текст.
- Требование держать инструменты стабильными внутри цикла вызовов; существующая фильтрация инструментов сохранена.
- Предупреждение против top-N фактов и другой персонализации промпта под каждое сообщение.
- Поля `cache_creation_input_tokens` и `cache_read_input_tokens` из `logs/usage.jsonl` подтвердили исходную проблему: после `save_fact` чтение из кеша падало до нуля, а создание кеша повторялось для всего промпта.

Дополнительную оптимизацию фильтрации инструментов из заметки не применял: она уже реализована и не связана с этой ошибкой.

## Проверка

Прогнан полный цикл `reply()` с имитированным LLM: первый ответ вызывает `save_fact`, второй завершает диалог. Проверено, что оба системных блока имеют маркер кеша, первый блок и список инструментов остаются неизменными, а новый факт появляется только во втором блоке. Также выполнена проверка синтаксиса `bot.py`. Внешние API не вызывались, поэтому фактические значения `usage` после исправления не измерялись.
