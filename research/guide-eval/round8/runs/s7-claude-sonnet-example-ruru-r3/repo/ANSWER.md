# Почему не подключался Intervals.icu

## Причины
1. **Кнопка Connect была обычной ссылкой на GET `/api/intervals/auth/init`.** Полная навигация страницы не отправляет заголовок `Authorization` (токен лежит в localStorage и добавляется только fetch-обёрткой), поэтому сервер отвечал 401 `{"error":"unauthorized"}` всем. Исправлено: init теперь аутентифицированный `POST`, возвращает JSON `{authorize_url}`; SPA вызывает его через `api()` и делает `window.location.assign(authorize_url)`.
2. **Ручная ссылка давала 400 `invalid_request`** после релиза календаря (2026-10-02): scope `ACTIVITY:READ,ACTIVITY:WRITE,...,CALENDAR:READ,CALENDAR:WRITE` называет область дважды (`:WRITE` уже включает `:READ`), Intervals такое отклоняет («Duplicate scope», тело ответа параметр не называет). Теперь: `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`.
3. **«Протухание» через час.** Токены Intervals не истекают и не имеют `refresh_token`/`expires_in`; код подставлял TTL 3600 с по умолчанию, а фоновый рефрешер без refresh-токена помечал соединение «expired, reconnect» (так было у Rivera). Убраны `DEFAULT_TOKEN_TTL`, поток-рефрешер и `expires_at`. Отзыв токена теперь обрабатывается лениво: 401 от API → токен очищается, статус «expired, reconnect».
4. **Обмен кода** отправлял лишние `grant_type` и `redirect_uri`; Intervals ждёт только `client_id`, `client_secret`, `code`. Лишнее убрано.

## Что пригодилось из заметки коллеги
- п.1 (нет refresh, ленивая обработка 401) — да, это причина №3.
- п.2 (Duplicate scope) — причина №2. SETTINGS:WRITE не добавлял: приложению нужны только активности, wellness, календарь.
- п.3 (упрощённый обмен кода, athlete в ответе) — причина №4.
- п.4 (POST вместо GET для init) — причина №1.
- Защита от смены аккаунта при повторном подключении — добавлена (409, если athlete.id отличается от сохранённого).
- `state`: уже был подписанным HMAC с TTL 15 минут и id пользователя, оставил как есть (JWT и claim `purpose` не вводил — не нужно для починки).
- Шифрование токена при хранении — не делал: хранилище здесь в памяти (в проде — отдельная задача).
- Регистрация клиента на форуме, сторонняя проверка с реальным аккаунтом — пропущено, внешних обращений не делал.

## Проверка
Запустил сервер локально: `POST /api/intervals/auth/init` с Bearer возвращает `authorize_url` с корректным scope; GET на тот же путь теперь 404. Полный поток с реальным Intervals.icu не проверялся (нужны реальные client_id/secret). Также в `config.py` остаются dev-плейсхолдеры секретов.
