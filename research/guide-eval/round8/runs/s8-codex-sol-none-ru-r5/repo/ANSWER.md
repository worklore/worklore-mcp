# Исправление кеширования

Причина: `build_system` ставил `cache_control` после всего системного текста, включая долгосрочные факты. После `save_fact` менялся кешируемый префикс, поэтому следующий вызов создавал его заново. Это соответствует записям в `logs/usage.jsonl`: после сохранения факта `cache_read_input_tokens` становился 0, а `cache_creation_input_tokens` — около 1000.

Теперь системный промпт состоит из двух блоков. Первый содержит инструкции и устойчивый профиль спортсмена (имя, вид спорта, зоны, цель, язык) и заканчивается меткой `cache_control`. Второй содержит текущую дату и долгосрочные факты без метки. Сохранение факта меняет только второй блок, поэтому кеш инструкций и профиля остается пригодным. В инструкции добавлены уточнения применения уже существующих правил, чтобы устойчивый префикс уверенно превышал минимальный размер кешируемого промпта модели. Выбор инструментов по ключевым словам не менялся.

Проверка: `python3 -m unittest -v test_cache.py` проверяет неизменность кешируемого блока после `save_fact`, наличие нового факта в следующем запросе и изменение только некешируемого блока при смене даты. Внешних вызовов нет. Фактическое число кешированных токенов можно подтвердить только по новым записям `logs/usage.jsonl` при работе бота; текущий лог описывает поведение до исправления.
