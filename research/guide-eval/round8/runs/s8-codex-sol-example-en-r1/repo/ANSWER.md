# Prompt cache fix

`bot.py` now sends two system text blocks, each with an ephemeral cache breakpoint. The first contains byte-stable coaching instructions; the second contains the date and athlete profile, zones, goal, facts, and language. A `save_fact` write therefore changes only the second block. I added stable guidance that restates the existing coaching rules to put the first breakpoint above Claude Sonnet's minimum cacheable prefix length with the default tool set. This length is inferred from the old usage log; it still needs a live cache read to confirm.

The colleague's two-breakpoint approach applied directly. Keeping all long-term facts in the context also applied: there is no per-message fact selection to change the cached tail. The existing keyword-based tool selection is retained, and its selected list stays fixed across rounds of one reply. Its optional tool groups can still cause a cache miss when the tool list changes between messages. The existing `usage.jsonl` logging already records both cache creation and cache read tokens, so no logging change was needed. The note's claim about observed cost savings was not used as evidence for this repo.

Verification: `python3 -m unittest -v test_bot` passes. The test runs a `save_fact` tool round and confirms that the next request has an identical first system block, an updated second block, both cache breakpoints, and the same tool list. I did not make a live API call because the task is limited to local work. After deployment, the usage log should show a cache read for the fixed prefix and cache creation for the changed athlete tail after a memory write; exact token counts require a live request.
