# Аналитика по docs/EVENTS.md: экраны регистрации и предложений

## Что сделано

Все шесть событий из `docs/EVENTS.md` подключены через существующую обёртку
`Analytics.capture` (`lib/analytics.dart`). Названия и свойства совпадают с
документом. Email и телефон в свойствах не отправляются (PII).

### `lib/screens/registration_screen.dart`

| Событие | Где отправляется | Свойства |
|---|---|---|
| `registration_email_started` | `onChanged` поля email, один раз за визит (флаг `_emailStarted`) | — |
| `registration_phone_started` | `onChanged` поля phone, один раз за визит (флаг `_phoneStarted`) | — |
| `loan_amount_changed` | `Slider.onChangeEnd`, один раз за перетаскивание | `amount` (int) |
| `terms_accepted` | `CheckboxListTile.onChanged`, только когда галочка поставлена | — |
| `registration_continue_tapped` | `onPressed` кнопки Continue, до перехода на `/offers` | `amount` (int), `terms` (bool) |

`onChanged` у слайдера оставлен только для обновления UI.

### `lib/screens/offer_screen.dart`

| Событие | Где отправляется | Свойства |
|---|---|---|
| `offers_scrolled` | `NotificationListener<ScrollEndNotification>` вокруг `ListView` | `offset` (double, `metrics.pixels`) |

`OfferScreen` остался `StatelessWidget`, состояние для этого не понадобилось.

## Почему так

Заметка коллеги про лишние события в `onChanged` относится к этой задаче:
`onChanged` у текстового поля срабатывает на каждый символ, а у слайдера на
каждый шаг при перетаскивании. Без защиты email из 20 символов дал бы 20
событий. Поэтому:

- текстовые поля шлют «started» один раз за визит (флаг в state; при новом
  визите экран пересоздаётся, и флаг сбрасывается);
- слайдер шлёт событие в `onChangeEnd`;
- прокрутка шлёт событие по `ScrollEndNotification`, а не по каждому обновлению.

Имена и свойства не менялись, поэтому дашборды и воронка из документа
продолжают работать.

## Что из заметки не понадобилось

- **Обработчик потери фокуса для финального значения.** В `EVENTS.md` ни одно
  событие не требует значения поля (email и телефон не передаём), поэтому
  `FocusNode` не добавлял.
- **Проверка через `PostHogConfig.debug` и PostHog → Activity.** Это проверка
  на устройстве с настоящим ключом. Здесь её не делал (см. ниже).
- **Отдельные проверки «есть ли у вас это в проекте».** Проект маленький, все
  вызовы захвата я нашёл прямо в двух экранах.

## Решения, которые стоит проверить

- `offers_scrolled` отправляется при каждом завершённом скролле, а не раз за
  визит. `EVENTS.md` этого не уточняет. Если продукту нужен один раз за визит,
  добавьте флаг, как у полей.
- `loan_amount_changed` срабатывает и на простое нажатие на слайдер (Flutter
  вызывает `onChangeEnd` и для тапа), значение `amount` при этом финальное.
- `terms_accepted` шлётся при каждом установлении галочки. Снятие галочки
  событие не даёт.

## Проверка

- `flutter analyze`: без замечаний.
- `dart format --set-exit-if-changed lib`: изменений нет.
- Ручная проверка на устройстве с PostHog не выполнялась: в проекте стоит
  заглушка ключа `phc_REPLACE_ME_IN_CI`, и отправлять события в боевой
  PostHog я не стал. Проверить можно так: debug-сборка с
  `PostHogConfig.debug = true`, ввод 20 символов в email даёт одно событие
  `registration_email_started`, перетаскивание слайдера даёт одно
  `loan_amount_changed` при отпускании.

Ничего не деплоил и никуда не отправлял.
