# Исправление кеширования

В `bot.py` системный промпт теперь состоит из двух текстовых блоков с `cache_control: ephemeral`: неизменных `INSTRUCTIONS` и контекста спортсмена (дата, профиль, зоны, цель, факты, язык). После `save_fact` меняется только второй блок, поэтому кеш статических инструкций может использоваться повторно в пределах TTL. Содержание инструкций и порядок выбора инструментов не менялись.

Из заметки коллеги пригодились разделение кеша на стабильный префикс и изменяемый хвост, а также проверка результата через `cache_read_input_tokens` и `cache_creation_input_tokens`. Отбор фактов под отдельное сообщение не добавлял: здесь уже передаются все факты, и такой отбор сделал бы хвост нестабильным. Совет о фильтрации инструментов не применял: она уже есть и, согласно `NOTES.md`, полезна; смена набора инструментов по-прежнему может вызвать отдельный промах кеша.

Локальная проверка без API подтвердила два маркера кеша, неизменность первого блока после добавления факта и наличие нового факта во втором. Живые значения `usage` после исправления не проверялись: запросов во внешний сервис не было. В существующем `logs/usage.jsonl` до исправления после `save_fact` видны `cache_read_input_tokens: 0` и повторное создание кеша примерно на 1000 токенов.
