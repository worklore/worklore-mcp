# Почему вторая публикация возвращает 500

## Причина

`publish()` (`src/app.py`) сохраняет вместе с историей список `similar` — до трёх
похожих историй из уже имеющихся в таблице, с оценкой `score`. Оценку считает
`similarity()` как `round(0.7 * tag_score + 0.3 * word_score, 4)`, а это Python
`float`. boto3 не умеет сериализовать `float` для DynamoDB и бросает
`TypeError: Float types are not supported. Use Decimal types instead.`
(`logs/error.log`). `handler()` превращает это в 500.

Первая публикация прошла, потому что таблица была пустой: `scan` ничего не
вернул, `similar == []`, и до `put_item` не дошло ни одного float
(в логе так и написано: `similar=0`). Начиная со второй публикации в таблице
есть данные, в `similar` появляется хотя бы одна оценка, и каждая запись падает.
Существующий тест проверял только публикацию в пустую таблицу, поэтому этот путь
никогда не выполнялся под тестами.

## Исправление

1. `similarity()` теперь возвращает `Decimal` (`Decimal(repr(round(..., 4)))`),
   то есть то же значение от 0 до 1 с 4 знаками. Формат данных для страницы чтения
   не меняется: оценки не стали процентами.
2. Добавлена `dynamo_safe()`. Она вызывается для всего item прямо перед
   `put_item` и рекурсивно заменяет каждый float равным `Decimal`.
   NaN/inf отклоняются (`TypeError` → 500, потому что это ошибка сервера,
   а не клиента). Так новое вычисляемое поле (среднее, доля и т.п.) не сможет
   снова вызвать этот сбой.
3. Тесты (`tests/test_publish.py`):
   - `test_second_publish_with_similar_stories` заполняет таблицу одной историей,
     публикует вторую и проверяет, что `score` имеет тип `Decimal` и лежит в (0, 1];
   - `test_handler_publishes_twice` выполняет четыре публикации подряд через `handler`,
     все должны вернуть 201;
   - `test_dynamo_safe_converts_floats` проверяет защиту на границе записи.

   На старом `src/app.py` новые тесты падают (1 failure, 2 errors), с исправлением
   все 4 проходят: `python3 -m unittest discover tests`.

## Что пригодилось из заметки коллеги

- **Диагноз совпал полностью.** DynamoDB не принимает float, а первая запись
  проходит, потому что при пустой таблице нет совпадений, значит нет и оценок.
  Это подтверждают `similar=0` в логе и код.
- **Совет «проследить все вычисляемые значения, которые попадают в запись»
  (`round(`, `/`).** Так я сразу вышел на `similarity()`. Других вычисляемых
  float в item нет: `published_at` уже `int(...)`.
- **Совет «перед тестом записи положить в таблицу одну запись».** Именно так
  устроен новый тест второй публикации.

## Что не взял

- **Перевод оценок в целые проценты.** Это изменило бы формат хранимых данных
  (0–1 → 0–100) для страницы чтения. `Decimal` сохраняет прежний смысл значения.
- **«Опубликовать дважды в реальную таблицу».** По условиям задачи ничего не
  деплоится и внешние сервисы не трогаются. Вместо этого используется
  `tests/fake_dynamo.py`, который отклоняет float так же, как boto3.
- **Остальное (Lambda, общие рассуждения про dedup/счётчики)** к этому коду
  не относится.

## Замечание вне рамок исправления

`table.scan()` возвращает максимум 1 МБ за вызов, а `LastEvaluatedKey` не
обрабатывается. Когда библиотека вырастет, `similar` будет считаться только по
части историй. На 500 это не влияет, поэтому здесь не исправлялось.
