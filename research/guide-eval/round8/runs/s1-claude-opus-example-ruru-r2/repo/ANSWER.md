# Пульсовые коридоры на часах обрезаются под зоны часов

## Что изменено

`gen.py`, функция `hr_target`: нижняя граница пульсового коридора теперь
передаётся под ключом `start`, а не `value`:

```diff
-    return {"units": "%lthr", "value": lo, "end": hi}
+    return {"units": "%lthr", "start": lo, "end": hi}
```

В docstring добавлено объяснение, почему ключ важен. Единицы (`%lthr`), сами
проценты и структура шагов и повторов не менялись.

## Почему

По `readback/watch-notes.md` API принял событие (`workout_doc.steps` не пустой),
но каждый коридор на часах совпал с одной из зон Forerunner (118–137, 151–162,
137–151), а не с процентами × 172. Если поменять LTHR на часах, полосы сдвигаются,
но остаются границами зон. Это ровно тот симптом, который описан для формы
`{value, end}`: Intervals экспортирует её в FIT как цель Lap-HR / по зонам, и
часы подгоняют её под свои локальные зоны. Форма `{start, end}` экспортируется
как коридор Instant-HR в bpm, посчитанных по LTHR из Intervals.

Ожидаемый результат после повторной отправки (LTHR 172 в Intervals):
Warm-up 117–129, Tempo 151–160, Float 129–141, Cool-down 112–124 уд/мин, и всё
это не зависит от LTHR и зон на часах.

## Проверка

- `python3 gen.py plans/tempo-run.json`: во всех четырёх HR-целях стоит
  `start`/`end`, `value` нигде не осталось.
- Сам я ничего не отправлял: по правилам задачи событие не уходило в Intervals
  и не синхронизировалось с часами. Чтобы проверить до конца, нужно
  перегенерировать событие, выполнить `./push.sh`, затем
  `GET /events/{id}`: в `hr` должен быть `start`, а `steps` не пустой. После
  этого синхронизировать часы и сравнить с числами выше.

## Какие части заметки коллеги пригодились

- **Пригодилось, это и есть исправление:** главный вывод заметки. Ключ `start`
  вместо `value` переключает экспорт в FIT с зонной цели (Lap-HR, обрезается
  под зоны часов) на коридор Instant-HR в сырых bpm.
- **Пригодилось как подтверждение:** совет оставить проценты (`%lthr`), а не
  абсолютные bpm. Ранние попытки из watch-notes (`units: "bpm"` дал 214–249,
  `start_bpm`/`end_bpm` дал константу 101) совпадают с тупиками из заметки, так
  что к ним возвращаться не нужно. Пригодился и шаг проверки через readback
  `GET /events/{id}`.
- **Не использовал:** «бонусную ловушку» с текстовым `description` в
  грамматике Intervals. У нас `steps` после чтения через API не пустой, а
  проблем с отображением в веб-UI никто не сообщал. К тому же она не касается
  экспорта коридоров на часы. Если веб-UI когда-нибудь будет показывать только
  название и общую длительность, стоит вернуться к этой части заметки (`m` там
  означает минуты, дистанция пишется через `mtr`/`km`, голое `Z2` читается как
  зона мощности).
- **Не применимо:** шаги про OAuth, создание и удаление тестового события и
  синхронизацию с Garmin. Внешние сервисы в этой задаче трогать нельзя.
