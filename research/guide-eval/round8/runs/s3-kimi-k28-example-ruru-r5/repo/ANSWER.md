# Почему nightly-review молчал

Задача запускалась все 6 ночей (runs = 6, last exit code = 1 в `launchctl print`).
Молчание было не отсутствием запусков, а двумя багами один поверх другого,
плюс тем, что диагностика искалась не там, где лежала.

## Причины (по слоям)

1. **Скрипт убивал сам себя до любого уведомления — `status=$?`.**
   В zsh `status` — встроенная переменная только для чтения (синоним `$?`),
   и присваивание ей обрывает скрипт на месте с exit 1. Подтверждено:
   stderr-лог содержал 6 раз пару `Not logged in...` +
   `/Users/vk/bin/nightly-review.zsh:19: read-only variable: status`.
   Присваивание стояло между вызовом агента и обоими уведомлениями, поэтому
   скрипт был обречен на тишину **даже при полностью рабочем claude**:
   сообщение об успехе тоже никогда бы не ушло. Исправление: `rc=$?`.

2. **`claude` под launchd не был залогинен — «Not logged in · Please run /login».**
   В `EnvironmentVariables` plist-файла задан только PATH; переменной `USER`
   в окружении launchd нет, и CLI не может найти свой логин в связке ключей.
   Работа (обзор коммитов) не выполнялась ни разу. Исправление: добавлен
   `USER=vk` в `EnvironmentVariables`.

3. **Диагностический обход (не баг, а ловушка).** Всё необходимое было на
   виду: `launchctl print` показывал runs = 6 и last exit code = 1, а
   `Library/Logs/nightly-review.err` содержал обе ошибки. Проверка шла
   по гипотезе «не запускается», а правда была «запускается и падает,
   а репортёр об ошибках стоит ниже по течению от самой ошибки».

## Что исправлено

- `bin/nightly-review.zsh`:
  - `status=$?` → `rc=$?` (главный фикс; уведомления теперь достижимы);
  - промпт передаётся через stdin: `print -r -- "$PROMPT" | claude -p ...`
    (не зависим от разбора многострочного аргумента в запланированном шелле);
  - логируется старт и длительность каждого запуска (stdout → .out,
    длительность — в оба Telegram-сообщения): запуск, завершившийся за
    секунды, теперь видно сразу;
  - сообщение об ошибке указывает и на stdout-файл, и на stderr-лог.
- `Library/LaunchAgents/com.vk.nightly-review.plist`: в `EnvironmentVariables`
  добавлен `USER=vk` (без него claude умирает с «Not logged in»).

Применение на реальной машине: положить файлы на место, затем
`launchctl bootout gui/$UID/com.vk.nightly-review` и
`launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.vk.nightly-review.plist`
(или `launchctl kickstart -k gui/$UID/com.vk.nightly-review` для одного прогона).

## Как проверял (локально, без внешних сервисов)

- `zsh -n` — синтаксис; `plutil -lint` — валидность plist.
- Поведение zsh подтверждено напрямую: `zsh -c 'true; status=$?'` →
  `read-only variable: status`, exit 1.
- Сухой прогон скрипта с поддельным HOME: `claude` и `notify.sh` заменены
  заглушками (Telegram и реальный агент не вызывались).
  - Успех: уведомление «done» с отправленным промптом, exit 0, файл отчёта
    создан.
  - Падение (заглушка печатает «Not logged in», exit 1): уведомление
    «FAILED (exit 1)» ушло, exit скрипта 1.
  Тишина теперь невозможна в обе стороны.

## Что взято из заметки коллеги, а что нет

Пригодилось:

- **`launchctl print` как первый шаг** — снимок уже содержал его, и он сразу
  перевернул постановку: «не запускается» → «запускается и падает».
- **Читать `StandardErrorPath` до построения теорий** — лог сразу показал
  обе причины, ничего искать не пришлось.
- **Запрет присваивать `status` в zsh, использовать `rc=$?`** — точное
  попадание, это был главный баг.
- **`USER` в `EnvironmentVariables`** — точное попадание во второй баг
  (тот же текст «Not logged in»).
- **Промпт через stdin** вместо многострочного аргумента.
- **Логирование длительности** и **проверка уведомления об ошибке одним
  намеренным падением** — сделано в сухом прогоне.
- **Поправка про честность кода выхода** учтена: exit 1 здесь был честным,
  но в проверке смотрел и на реальный результат (файл/сообщение), а не
  только на код.

Пропущено:

- **`< /dev/null` при передаче промпта аргументом** — выбран альтернативный
  вариант из той же заметки (stdin-канал для промпта), поэтому не нужен.
- Отправка реальных уведомлений/запуск реального агента — по правилам
  ничего не отправлялось внешним сервисам; Telegram-путь и keychain
  остаётся проверить на машине пользователя одним `kickstart -k`.
