# Причина и исправление

При первой публикации таблица пуста, поэтому `related()` возвращает пустой список. При второй публикации `similarity()` вычисляла балл типа `float` и помещала его в `similar[].score`. `table.put_item()` передавал этот балл сериализатору boto3, который отклоняет `float` (`TypeError: Float types are not supported. Use Decimal types instead.`). Обработчик превращал исключение в HTTP 500.

Расчёт похожести теперь выполняется с `decimal.Decimal`, включая коэффициенты и итоговое округление до четырёх знаков. Поэтому вычисленный балл остаётся числом с прежней точностью, но в записываемом объекте больше не появляется `float`. Добавлен тест, который публикует две статьи через `handler()`, проверяет оба ответа 201 и сохранённый балл второй статьи. Команда `python3 -m unittest discover tests -v` проходит: 2 теста.

Из заметки коллеги пригодились указание на несовместимость `float` с DynamoDB и мысль проверить путь записи при уже заполненной таблице. Предложение переводить баллы в целые проценты не применялось: оно изменило бы точность и формат балла. Проверка на реальной таблице не проводилась, поскольку задача ограничена текущей директорией и запрещает отправку во внешние сервисы.
