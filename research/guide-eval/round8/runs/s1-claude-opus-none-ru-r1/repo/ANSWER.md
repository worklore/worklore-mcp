# Пульсовые коридоры на часах: что изменено

## Причина

`gen.py` собирал цель по пульсу так:

```json
"hr": {"units": "%lthr", "value": 68, "end": 75}
```

В `workout_doc` Intervals.icu диапазон задаётся парой **`start` / `end`**.
Поле `value` означает **одиночную** цель. Получив `value`, Intervals считал
шаг одноточечной целью и не видел корректного коридора. Одиночную пульсовую
цель он экспортирует в Garmin как **номер зоны** (FIT HR target = zone), а
часы подставляют границы *своей* зоны. Отсюда и симптомы из
`readback/watch-notes.md`:

- каждый шаг на часах совпадает с одной из зон часов (118–137, 137–151,
  151–162), а не с нашими 151–160 / 129–141;
- при смене LTHR на часах полосы сдвигаются, но остаются границами зон:
  часы пересчитывают свои зоны, и номер зоны указывает уже на новые границы.
  Будь в тренировке bpm-коридор, он бы от LTHR часов не зависел;
- API вернул событие «как отправили», а `steps` заполнены. Это не значит,
  что цель распознана как диапазон: структура валидна, только смысл у неё
  другой.

Предыдущие попытки (`units: "bpm"`, `start_bpm`/`end_bpm`) били мимо: дело
не в единицах, а в форме диапазона. Проценты LTHR оставлены, Intervals сам
переводит их в bpm по LTHR 172 из профиля атлета.

## Изменение (`gen.py`, `hr_target`)

```python
return {"units": "%lthr", "start": lo, "end": hi}
```

Добавлена проверка `lo < hi`: если в плане перепутаны границы, генератор
падает с ошибкой, а не отправляет мусор. Других изменений нет: план,
`push.sh` и readback не трогал.

## Что не проверено

Сам я ничего не отправлял в Intervals и на часы (по условию задачи).
Утверждение, что `start`/`end` экспортируется как свой bpm-коридор,
основано на формате `workout_doc` Intervals.icu. Проверить нужно так:

```
python3 gen.py plans/tempo-run.json > event.json
./push.sh event.json
```

На часах должно быть примерно 117–129 / 151–160 / 129–141 / 112–124 (при
LTHR 172 из Intervals, округление на стороне Intervals), и эти значения не
должны меняться при смене LTHR на часах. Если часы всё равно показывают
зоны, посмотрите шаг в веб-редакторе Intervals: там должно быть
`68-75% LTHR`. Если там одно число, значит Intervals не принял `start`, и
формат нужно сверить с актуальной документацией API.
