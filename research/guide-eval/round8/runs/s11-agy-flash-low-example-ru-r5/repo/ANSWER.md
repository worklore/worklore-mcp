# Анализ проблемы и исправление ошибки второй публикации

## 1. Причина ошибки

При первой публикации в DynamoDB таблица была пустой. Функция `publish` вызывает `related(story, existing)`. Так как `existing` был пуст, список похожих историй `item["similar"]` оставался пустым списком (`[]`). В DynamoDB записывался объект без числовых полей с плавающей точкой, и запись завершалась успешно со статусом `201`.

При второй публикации в таблице уже существовала первая запись (`existing` содержал 1 элемент). Функция `related()` вызвала `similarity(story, other)`, возвращающую результат формулы:
```python
round(0.7 * tag_score + 0.3 * word_score, 4)
```
Результатом вычисления в Python является тип `float`. Полученный словарь с полем `"score": float` был добавлен в массив `item["similar"]`, который затем передавался в `table.put_item(Item=item)`.

DynamoDB (библиотека `boto3`) не поддерживает стандартный тип Python `float` при сериализации атрибутов и требует использования `decimal.Decimal` или целочисленных значений (`int`). В результате `boto3` выбросил исключение:
```
TypeError: Float types are not supported. Use Decimal types instead.
```
которое перехватывалось в `handler` и возвращало ответ `500 Internal Server Error`.

---

## 2. Исправление

1. **В коде приложения ([src/app.py](file:///tmp/h-GE2mfP/src/app.py))**:
   - Импортирован класс `Decimal` из модуля `decimal`.
   - В функции `similarity()` результат вычисления преобразован в `Decimal`:
     ```python
     return Decimal(str(round(0.7 * tag_score + 0.3 * word_score, 4)))
     ```
     (Строковое представление `str(...)` гарантирует точное сохранение округлённого значения без погрешностей двоичной плавающей арифметики).

2. **В тестах ([tests/test_publish.py](file:///tmp/h-GE2mfP/tests/test_publish.py))**:
   - Добавлен тест `test_publish_second_story_calculates_similarity_without_error`, проверяющий сценарий с предварительно существующей записью в таблице и вычислением similarity.
   - Добавлен тест `test_handler_second_publish_succeeds`, проверяющий последовательные вызовы эндпоинта `handler` (как при первой, так и при второй публикации).

---

## 3. Какие части заметки коллеги пригодились

### Что пригодилось:
- **Объяснение природы ошибки**: DynamoDB не поддерживает тип `float` в Python и ожидает `Decimal` (`"TypeError: Float types are not supported. Use Decimal types instead"`).
- **Объяснение, почему первая публикация прошла успешно**: на пустой таблице список похожих историй был пуст (`similar: []`), поэтому путь выполнения с вычислением `float` не задействовался.
- **Подход к исправлению**: преобразование вычисленных float-значений на границе записи в `Decimal`.
- **Рекомендация по тестированию**: необходимость тестирования пути с предварительно заполненной таблицей (seeded state) и выполнения второй публикации в интеграционных тестах.

### Что пропущено / не подошло:
- Преобразование в целочисленные проценты (автор заметки выбрал `int`, но в нашем API для сохранения формата дробного скора с 4 знаками после запятой лучше и точнее использовать `Decimal`).
- Замечания про деплой и проверку против реальной AWS таблицы (в соответствии с правилами задача решается локально с использованием `FakeTable` и без внешних вызовов).
