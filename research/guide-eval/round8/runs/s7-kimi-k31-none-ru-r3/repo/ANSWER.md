# Причины сбоя интеграции

1. **Кнопка Connect не отправляла токен авторизации tricoach.** Она была обычной ссылкой, поэтому браузер переходил на `/api/intervals/auth/init` без заголовка `Authorization: Bearer`, который добавляет только `fetch`-обёртка SPA. Сервер справедливо возвращал 401.

2. **В authorize-запросе отсутствовал обязательный параметр `response_type=code`.** Из-за этого Intervals.icu отклонял запрос с `invalid_request` ещё до показа страницы согласия.

3. **Отсутствие `expires_in` и `refresh_token` ошибочно трактовалось как одночасовой срок жизни токена.** Код подставлял TTL 3600 секунд, а затем помечал подключение как `expired, reconnect`, потому что обновить токен было нечем. Для ответа Intervals.icu без этих полей локальный срок действия устанавливать не нужно: такой access token не считается истекающим. Поэтому повторное подключение через час было следствием локальной логики, а не отзыва доступа.

# Исправление

- Кнопка теперь вызывает `/api/intervals/auth/init` через авторизованный `fetch`, получает authorize URL в JSON и перенаправляет на него браузер.
- В authorize URL добавлен `response_type=code`.
- Если провайдер не возвращает `expires_in`, подключение сохраняется с `expires_at = None` и фоновый обновитель его не отключает. Явно ограниченные по времени токены по-прежнему поддерживаются.

Проверено синтаксисом Python и JavaScript, обработчиком кнопки с mocked DOM/fetch и полным OAuth-сценарием на локальном имитаторе провайдера, включая callback, обмен кода, статус, wellness и фоновую проверку не истекающего токена.
