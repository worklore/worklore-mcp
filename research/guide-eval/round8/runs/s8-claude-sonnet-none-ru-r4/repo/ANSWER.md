# Что изменено

**Причина:** `build_system` склеивал статические инструкции и контекст атлета (дата, зоны, цель, факты) в один text-блок с одним `cache_control`. Кеш префиксный, поэтому любое изменение факта (`save_fact`) меняло единственный блок целиком, и следующий вызов заново платил за весь промпт (`cache_creation ~1000`, `cache_read 0` в `logs/usage.jsonl`).

**Исправление (`bot.py`, `build_system`):** system теперь из двух блоков, у каждого свой `cache_control`:
1. `INSTRUCTIONS` — неизменный, кешируется независимо от памяти;
2. `athlete_context(...)` — меняется при `save_fact` и со сменой даты; внутри одного сообщения раунды tool-loop по-прежнему читают его из кеша.

Фильтрация инструментов по ключевым словам не тронута.

**Оговорка:** минимальный кешируемый префикс для claude-sonnet-4-5 — 1024 токена. Префикс «инструменты + инструкции» по оценке около 750–950 токенов (всего в логах ~1046 вместе с контекстом), то есть он может оказаться ниже порога, и тогда первый брейкпоинт не сработает. Проверьте по `usage.jsonl` после выката: после `save_fact` `cache_read_input_tokens` должен быть > 0. Если нет — нужно, чтобы статическая часть (инструкции + инструменты) превышала 1024 токена, например перенести в неё стабильные справочные данные. Тест с реальным API я не запускал.
