# Причина

Вторая публикация падала из-за оценки похожести в поле `similar`. В `src/app.py` функция `similarity()` вычисляла оценку делением и возвращала результат `round(..., 4)` типа `float`. Сериализатор DynamoDB не принимает Python `float`, поэтому `table.put_item()` выбрасывал:

```text
TypeError: Float types are not supported. Use Decimal types instead.
```

Первая публикация проходила только потому, что таблица была пуста: `related()` возвращал пустой список, функция `similarity()` не вызывалась и в запись не попадал `float`. При второй публикации появлялась существующая история, вычислялась оценка похожести, и запрос завершался ошибкой 500.

До исправления сценарий был воспроизведён через `handler()` с `FakeTable`: первая публикация вернула 201, вторая — 500 с тем же `TypeError`, что и в `logs/error.log`.

# Исправление

- В `src/app.py` оценка похожести теперь преобразуется на границе записи в целый процент от 0 до 100: `round(100 * (...))` без аргумента точности возвращает `int`, который поддерживает DynamoDB. Промежуточные вычисления остаются дробными, но в элемент таблицы попадает только целое число.
- В `tests/test_publish.py` добавлен регрессионный тест с уже заполненной таблицей. Он публикует вторую похожую историю, проверяет содержимое `similar`, тип оценки `int` и наличие обеих записей. `FakeTable` отклоняет `float` так же, как сериализатор boto3, поэтому возврат прежнего кода сломает этот тест.

# Проверка

- `python3 -m unittest discover tests` — 2 теста, все прошли.
- Два последовательных вызова `handler()` через `FakeTable` — оба вернули 201; оценка второй записи сохранена как `int`.
- Проверка в реальную таблицу AWS не выполнялась: работа ограничена локальными файлами и тестовым двойником.

# Что пригодилось из заметки коллеги

Пригодились объяснение зависимости ошибки от непустой таблицы, рекомендация преобразовать вычисляемую оценку в `int` и идея регрессионного теста с предварительно добавленной записью. Поиск вычисляемых значений, попадающих в элемент DynamoDB, также подтвердил, что проблемный путь здесь — `similarity()` → `related()` → `put_item()`.

Совет опубликовать дважды в реальную таблицу не применялся: для локальной проверки достаточно `FakeTable`, воспроизводящего проверку типов boto3, а обращения к внешним сервисам не требовались.
