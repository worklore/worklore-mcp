# Причина и исправление

**Причина.** `similarity()` в `src/app.py` возвращает `float` (`round(0.7*... , 4)`),
а `publish()` кладёт эти оценки в `item["similar"]`. boto3 не сериализует `float`
(`TypeError: Float types are not supported. Use Decimal types instead.`) → 500.
Первая публикация проходила, потому что таблица была пуста: `related()` возвращал
`[]`, ни одного float в записи не было. Баг проявляется только когда в таблице уже
есть истории (путь с непустым состоянием). Тест проверял только пустую таблицу.

**Исправление.**
- Добавлена `to_dynamo()` (рекурсивно float → `Decimal(str(x))`), применяется к
  item прямо перед `put_item` — на границе с DynamoDB, так что любое будущее
  вычисляемое float-значение тоже безопасно.
- Добавлен тест `test_second_publish_with_populated_table`: сначала сажает запись,
  потом публикует вторую — выполняется код оценок. Без исправления он падает.

**Из заметки коллеги пригодилось:** объяснение, почему первая запись выживает
(пустая таблица → нет оценок); идея конвертировать на границе записи; идея теста
с предварительно засеянной таблицей. **Не использовано:** округление оценок до
целых процентов — вместо этого оставил точность через Decimal; поиск `round(`/`/`
по кодовой базе — других мест, питающих записи, в сервисе нет.
