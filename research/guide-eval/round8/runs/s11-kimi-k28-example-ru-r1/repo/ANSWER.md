# Почему вторая публикация возвращала 500

## Причина

`similarity()` в `src/app.py` возвращала Python-float (`round(0.7 * tag_score + 0.3 * word_score, 4)`),
а DynamoDB через boto3 не принимает float — только `int`, `Decimal`, `str` и т.д.
(`TypeError: Float types are not supported. Use Decimal types instead.` в `logs/error.log`).

Почему падение проявлялось только со второй публикации: `related()` вычисляет
похожесть только по уже существующим записям. Первая публикация пишет в пустую
таблицу → `similar` — пустой список → float в item не попадает → запись успешна.
Вторая публикация находит первую запись → в `similar` попадают float-оценки →
`table.put_item(Item=item)` падает → handler ловит исключение и возвращает 500.

Тест `test_publish_stores_story` воспроизводил только «пустую» ветку, поэтому баг
не ловился в тестах.

## Исправление

- `src/app.py`: `similarity()` теперь возвращает `Decimal(str(round(..., 4)))` —
  конвертация в `Decimal` на границе записи, `str()` гарантирует точное
  десятичное представление вместо бинарных артефактов float.
- `tests/test_publish.py`: добавлен тест `test_publish_with_existing_story_computes_similarity` —
  сидирует таблицу одной записью и публикует вторую через `handler`, проверяя
  статус 201 и что оценки в `similar` имеют тип `Decimal`.

Проверка: `python3 -m unittest discover -s tests` — 2 теста OK; ручной прогон
трёх публикаций подряд через `handler` — все возвращают 201.

## Что пригодилось из заметки коллеги

- Диагноз «float в DynamoDB падает только при второй записи, потому что первая
  идёт по пустой таблице» — совпал с нашим случаем один в один и сразу указал
  на `similarity()`.
- Совет «проследить каждое вычисляемое значение, попадающее в запись, и
  сконвертировать в int/Decimal на границе» — применён как основной фикс.
- Совет «тест на запись должен сидировать таблицу одной записью, чтобы
  state-dependent код (похожесть) реально исполнялся» — применён: новый тест
  покрывает именно этот путь.

Не пригодилось: перевод оценок в целые проценты (в нашем случае дробная
точность осознанно сохранена через `Decimal`), а также grep-проверка `round(`
и делений по кодовой базе — в проекте единственное такое место было в
`similarity()`.
