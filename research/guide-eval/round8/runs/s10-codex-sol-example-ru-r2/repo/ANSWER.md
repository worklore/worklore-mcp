# События аналитики

- На экране регистрации добавлены `registration_email_started` и `registration_phone_started` при первом изменении соответствующего поля за время жизни экрана. Значения полей в аналитику не передаются.
- `loan_amount_changed` отправляется после завершения взаимодействия со слайдером с целочисленным `amount`. `terms_accepted` отправляется при установке флажка. `registration_continue_tapped` отправляется при нажатии доступной кнопки Continue с `amount` (int) и `terms` (bool).
- На экране предложений `offers_scrolled` отправляется по завершении прокрутки списка с `offset` (double).
- Все события отправляются через существующий `Analytics.capture`; имена и свойства соответствуют `docs/EVENTS.md`. Дополнительные события просмотра экранов не добавлялись.

## Что пригодилось из заметки коллеги

Пригодились ограничение событий начала ввода одним срабатыванием на поле, отправка изменения суммы в `onChangeEnd` и отправка прокрутки через `ScrollEndNotification`. Это предотвращает поток событий на каждый символ, шаг слайдера и обновление прокрутки. Также учтён совет сохранять имена и свойства событий из спецификации.

Инструкции по `FocusNode`, передаче конечного значения поля и проверке в PostHog Activity здесь не применялись: конечные значения email и телефона не нужны и не должны передаваться, а внешние сервисы по условию задачи не используются.

## Проверка

`flutter pub get --offline` разрешил зависимости из локального кэша. `flutter analyze --no-pub` завершился без замечаний. События в реальный PostHog не отправлялись.
