# Аналитика регистрационной воронки

Все шесть событий из `docs/EVENTS.md` отправляются через `Analytics.capture`
(`lib/analytics.dart`). Названия и свойства в точности как в спецификации. Email
и телефон в свойства не попадают.

| Событие | Где | Когда срабатывает |
|---|---|---|
| `registration_email_started` | `registration_screen.dart`, `onChanged` у поля Email | на первом изменении поля, **один раз за визит экрана** (флаг `_emailStartedFired`) |
| `registration_phone_started` | `registration_screen.dart`, `onChanged` у поля Phone | так же, один раз за визит (флаг `_phoneStartedFired`) |
| `loan_amount_changed` `{amount: int}` | `Slider.onChangeEnd` | один раз за жест, когда пользователь отпускает слайдер. `onChanged` только обновляет UI |
| `terms_accepted` | `CheckboxListTile.onChanged` | только когда галочку ставят (`true`); снятие галочки не отправляется |
| `registration_continue_tapped` `{amount: int, terms: bool}` | `FilledButton.onPressed` | при нажатии, перед переходом на `/offers` |
| `offers_scrolled` `{offset: double}` | `offer_screen.dart`, `NotificationListener<ScrollEndNotification>` вокруг `ListView` | один раз в конце каждого скролла. `offset` = `metrics.pixels`. Учитывается только сам список (`depth == 0`) |

Проверка: `flutter analyze` пишет "No issues found". На устройстве не запускал.
`flutter` при запуске сам дописал `analyzer.exclude` в `analysis_options.yaml`.
Я откатил это и удалил созданные `pub get` файлы `.dart_tool/` и
`pubspec.lock`. В диффе остались только два экрана.

## Что пригодилось из заметки коллеги

README прямо говорит, что мы на бесплатном тарифе PostHog. Буквальная
реализация спеки (`capture` в каждом `onChanged`) дала бы ту же проблему, что
описана в заметке. Пригодилось следующее:

- **Проверка «Check if this applies to you».** Перед изменениями `capture`
  нигде не вызывался, так что проблемы ещё не было. Заметка помогла её не создать.
- **Текстовые поля: флаг «один раз за визит» в `onChanged`.** Применил как есть.
  Это и соответствует смыслу «started typing». `State` экрана регистрации
  пересоздаётся при новом визите, поэтому «один раз» здесь значит «за визит».
- **Слайдер: `onChangeEnd` вместо `onChanged`.** Применил как есть.
- **Скролл: `ScrollEndNotification`, а не `ScrollUpdateNotification` или
  слушатель `ScrollController`.** Применил.
- **Не менять имена и свойства событий.** Соблюдено, дашборды и воронки должны работать.

Что не понадобилось:

- Отправка по потере фокуса (`FocusNode`) и события «tap/focus». Ни одно
  событие в спеке не требует финального значения поля или факта фокуса.
- Шаги проверки в PostHog (`PostHogConfig.debug`, PostHog → Activity). Не
  запускал: приложение не стартовал, во внешние сервисы ничего не отправлял.
  Чтобы проверить вручную, можно временно включить `config.debug = true` в
  `Analytics.init()` и посмотреть лог.
- Ограничения для чекбокса и кнопки Continue заметка не описывает. Это
  одиночные действия, они и так дают одно событие на действие.

## Что стоит согласовать с продуктом

- `offers_scrolled` отправляется после каждого скролла, а не один раз за визит.
  Для воронки нужен только факт прокрутки. Если важна только глубина, можно
  ограничить одним событием за визит или отправлять максимальный `offset`.
- Если пользователь, поставив галочку, снимет её и поставит снова,
  `terms_accepted` придёт повторно. Так спецификацию можно прочитать буквально.
  Если нужно одно событие, можно добавить такой же флаг, как у полей.
