# Пульсовые коридоры на часах: что изменил и почему

## Причина

`gen.py` в функции `hr_target` отправлял коридор как `{"units": "%lthr", "value": lo, "end": hi}`.
По `readback/watch-notes.md` часы показывали не запланированный коридор, а свои зоны
(например, 118–137 вместо 129–141). Ключ `value` для нижней границы, судя по заметке коллеги,
переводит цель в режим «пульс по зонам» (Lap-HR): часы обрезают её под свои локальные зоны.

## Что изменено

В `gen.py` (`hr_target`) нижняя граница теперь передаётся под ключом `start`:

```python
return {"units": "%lthr", "start": lo, "end": hi}
```

Остальное не трогал: проценты от LTHR, структура шагов, `description` не добавлял.

Проверка локально: `python3 gen.py plans/tempo-run.json` даёт для всех четырёх шагов
`{'units': '%lthr', 'start': …, 'end': …}` с теми же процентами, что в плане
(68–75, 88–93, 75–82, 65–72), и ни одного ключа `value` в выводе.

## Что не проверено

- Я не отправлял событие в Intervals и не синхронизировал часы: нет ключа API и
  разрешения на публикацию. Поэтому то, что часы покажут коридор 129–141 уд/мин (75–82% × 172),
  пока не подтверждено. Проверить можно так: `./push.sh event.json`, затем
  `GET /events/{id}` (steps должны быть непустые), синхронизация Garmin и просмотр шага на часах.
- Схема `start`/`end` для `hr` в `workout_doc` не подтверждена документацией. Поиск
  не нашёл официального описания; вывод опирается только на заметку коллеги.
- `readback/event-184233-as-sent.json` оставлен как есть: это журнал старой отправки.

## Что пригодилось из заметки коллеги

- **Использовано:** замена `value` на `start` для `%lthr`-коридора: это и есть исправление.
  Также использованы проценты от LTHR (а не абсолютные bpm) и шаг проверки через `GET`.
- **Не использовано:** правила текстовой грамматики поля `description` (минуты `m`,
  `mtr`/`km`, пустые строки вокруг `Nx`, цифры в начале подписей). В нашем генераторе
  поле `description` не формируется, поэтому эти правила сейчас не нужны. Понадобятся,
  если начнём выводить текстовое описание шагов.
- **Не применимо напрямую:** утверждение, что абсолютные bpm невозможны, и история с
  `start_bpm`/`end_bpm`: в нашем коде их нет.
