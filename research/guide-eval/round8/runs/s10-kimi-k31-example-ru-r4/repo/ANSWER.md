# События аналитики

Реализованы все события из `docs/EVENTS.md` через существующий `Analytics.capture`.

## Экран регистрации

В `lib/screens/registration_screen.dart` добавлены:

- `registration_email_started` — один раз за показ экрана при первом изменении email;
- `registration_phone_started` — один раз за показ экрана при первом изменении телефона;
- `loan_amount_changed` — по завершении перетаскивания слайдера, со свойством `amount` типа `int`;
- `terms_accepted` — при установке флажка согласия, без события при его снятии;
- `registration_continue_tapped` — при нажатии доступной кнопки Continue, со свойствами `amount` (`int`) и `terms` (`bool`), перед переходом к предложениям.

Email и телефон в свойства событий не передаются. Автоматические события просмотра экранов не изменялись.

## Экран предложений

В `lib/screens/offer_screen.dart` список обёрнут в `NotificationListener<ScrollEndNotification>`. По завершении прокрутки отправляется `offers_scrolled` со свойством `offset` типа `double`, равным `notification.metrics.pixels`.

## Что пригодилось из заметки коллеги

Использованы три рекомендации:

- флаги состояния для однократной отправки событий начала ввода вместо события на каждое нажатие клавиши;
- `onChangeEnd` для слайдера вместо отправки аналитики из `onChanged`;
- `ScrollEndNotification` вместо событий на каждое обновление прокрутки.

Обработчики потери фокуса и debounce не понадобились: спецификация фиксирует именно начало ввода и не требует итогового значения полей.
