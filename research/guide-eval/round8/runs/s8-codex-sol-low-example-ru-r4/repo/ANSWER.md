# Исправление кеширования

В `bot.py` разделил системный промпт на два текстовых блока, каждый с `cache_control: {"type": "ephemeral"}`. Первый содержит неизменные `INSTRUCTIONS`, второй — дату и данные спортсмена, включая долговременные факты. После `save_fact` обновляется только второй блок; стабильный префикс может читаться из кеша. Порядок и состав инструментов не менял.

Из заметки коллеги пригодились принцип кеширования по префиксу, две метки для статической и изменяемой частей промпта и проверка полей `cache_read_input_tokens` / `cache_creation_input_tokens`. Совет про фильтрацию инструментов здесь не применял: она уже есть, а `NOTES.md` просит её сохранить. Отбор фактов по сообщению тоже не добавлял, чтобы содержимое второго блока не менялось без записи в память.

Локально проверил, что оба блока имеют метку кеша, запись факта меняет только второй блок и новый факт попадает в следующий запрос. Реальную стоимость и попадания в кеш без обращения к внешнему API не измерял; исторические записи `logs/usage.jsonl` оставил как есть.
