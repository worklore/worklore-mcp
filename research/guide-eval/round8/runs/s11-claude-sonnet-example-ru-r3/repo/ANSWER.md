# Почему вторая публикация возвращает 500

**Причина.** `publish()` кладёт в item поле `similar` со `score`, а `score` — это `float`
(`round(0.7*… + 0.3*…, 4)` в `similarity`). boto3 не умеет сериализовать float в DynamoDB:
`TypeError: Float types are not supported. Use Decimal types instead.` (см. `logs/error.log`).
При первой публикации таблица пуста, `related()` возвращает `[]`, float'ов в item нет — и всё
проходит. Со второй публикации появляются похожие истории со score, и `put_item` падает.
Единственный существующий тест проверял только путь с пустой таблицей.

**Исправление.**
- `src/app.py`: добавлена `to_dynamo()` — рекурсивно превращает float в `Decimal(str(x))`;
  вызывается на границе, прямо перед `put_item`, поэтому любое будущее вычисляемое float-поле
  тоже будет безопасно, а не только `score`.
- `tests/test_publish.py`: тест, публикующий вторую историю в уже заполненную таблицу
  (и повторную публикацию), плюс тест на `to_dynamo`. Фейковая таблица проверяет типы как boto3.

**Что пригодилось из заметки коллеги.** Диагноз (float → DynamoDB, баг виден только при
непустых данных), конвертация на границе записи и тест с предварительно засеянной таблицей.
Не использовал: замену score на целые проценты — это меняет формат хранимых данных
(`score` 0.4321 → 43), а Decimal сохраняет прежнюю точность. Шаги с grep по `round(` и
проверкой на реальной таблице не делал (внешних сервисов трогать нельзя); `round(`/`/`
вручную просмотрены — float есть только в `similarity`.
