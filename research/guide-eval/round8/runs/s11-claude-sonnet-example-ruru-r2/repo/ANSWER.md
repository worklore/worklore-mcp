# Почему вторая публикация возвращает 500

## Причина
`publish()` кладёт в элемент поле `similar` — список `{slug, score}`, где `score` считается в `similarity()` как `round(0.7*... + 0.3*..., 4)`, то есть это Python `float`. boto3 не умеет сериализовать float в DynamoDB: `TypeError: Float types are not supported. Use Decimal types instead.` (см. `logs/error.log`).

При первой публикации таблица пуста, `related()` возвращает `[]`, float'ов в элементе нет — запись проходит. Начиная со второй публикации `similar` непустой, и `put_item` падает. Единственный тест проверял только путь с пустой таблицей, поэтому баг не ловился.

## Исправление
- `src/app.py`: оценка в `related()` теперь `Decimal(str(similarity(...)))`. Значение не меняется (4 знака), формат для читателей тот же, но тип допустим для DynamoDB.
- `tests/test_publish.py`: новый тест `test_second_publish_with_similar_story` — сначала сажает запись, потом публикует вторую (путь с заполненной таблицей). Fake-таблица отклоняет float так же, как boto3, так что при возврате к float тест упадёт.

## Что пригодилось из заметки коллеги
- Диагноз (float → DynamoDB, первая запись проходит из-за пустой таблицы) — совпал полностью.
- Идея теста «сначала засеять запись, потом писать» — применена.
- Поиск `round(` и `/` среди значений элемента — выполнен: единственный источник float — `similarity()`; остальные поля str/int/list[str].
- Не применено: целые проценты вместо Decimal (сохранил формат `score`); проверка на реальной таблице — запрещено правилами, использован fake.
