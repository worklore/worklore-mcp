# События аналитики из docs/EVENTS.md

Все шесть событий отправляются через существующий `Analytics.capture`
(`lib/analytics.dart`). Имена и свойства совпадают со спецификацией.
Email и телефон в свойствах не передаются (это PII).

| Событие | Где | Когда срабатывает |
|---|---|---|
| `registration_email_started` | `registration_screen.dart`, `onChanged` поля Email | один раз за посещение экрана, на первом вводе (флаг `_emailStartedSent`) |
| `registration_phone_started` | `registration_screen.dart`, `onChanged` поля Phone | один раз за посещение экрана (флаг `_phoneStartedSent`) |
| `loan_amount_changed` `{amount: int}` | `Slider.onChangeEnd` | один раз за протягивание, когда пользователь отпускает слайдер; если значение не изменилось с `onChangeStart`, событие не отправляется. `onChanged` только обновляет UI |
| `terms_accepted` | `CheckboxListTile.onChanged` | только когда галочку ставят (не когда снимают) |
| `registration_continue_tapped` `{amount: int, terms: bool}` | `FilledButton.onPressed` | на каждое нажатие, перед переходом на `/offers` |
| `offers_scrolled` `{offset: double}` | `offer_screen.dart`, `NotificationListener<ScrollEndNotification>` вокруг `ListView` | один раз в конце каждого жеста прокрутки (`n.depth == 0`), `offset = metrics.pixels` |

Проверка: `flutter analyze`, замечаний нет. На устройстве не запускал.

## Что пригодилось из заметки коллеги

Пригодилось почти всё, что касается момента отправки. В README сказано, что
мы на бесплатном тарифе PostHog, а «наивное» место для трёх событий из
спецификации (`onChanged` текстового поля, `onChanged` слайдера, обновления
скролла) дало бы десятки событий на одного пользователя:
- флаг «один раз за посещение» для событий «начал вводить»;
- перенос события слайдера из `onChanged` в `onChangeEnd`;
- `ScrollEndNotification` вместо `ScrollUpdateNotification`/`ScrollController`;
- имена событий и свойства не менял.

Не пригодилось или пропустил:
- слушатели `FocusNode` (события тапа/фокуса и итоговое значение при потере
  фокуса): в спецификации таких событий нет;
- шаги проверки через `PostHogConfig.debug = true` и PostHog → Activity: это
  нужно делать на запущенном приложении, здесь я его не запускал;
- от себя добавил одно, чего в заметке нет: тап по слайдеру, который не
  меняет значение, событие не шлёт.

## Что стоит решить продукту

- «Один раз» сейчас означает «за время жизни экрана регистрации». Если
  вернуться назад с экрана предложений, состояние сохраняется, и события
  «started» повторно не уйдут.
- `offers_scrolled` уходит на каждый законченный жест прокрутки, а не один раз
  за посещение, потому что в свойстве `offset` указано, насколько далеко
  прокрутили. Если для воронки достаточно одного события, можно добавить флаг.
