# Почему задача молчала

Снимок `launchctl print` от 2026-10-18 показывает `runs = 6` и `last exit code = 1`: launchd запускал задачу. Пустой `nightly-review.out` сам по себе не свидетельствует об отсутствии результата — скрипт перенаправляет вывод `claude` в отдельный файл `nightly-review-YYYY-MM-DD.md`.

В `nightly-review.err` для каждого запуска повторяется пара ошибок:

1. `Not logged in · Please run /login`: `claude` завершался до создания обзора. В окружении задачи из `launchctl print` есть `PATH`, но нет `USER`; это вероятная причина, по которой CLI не находил учётные данные в контексте launchd. В снимке нет данных, позволяющих доказать, что добавления `USER` одного достаточно для рабочей авторизации.
2. Сразу после этого zsh сообщал `read-only variable: status`. `status=$?` присваивал значение встроенной переменной zsh и обрывал скрипт до ветки, которая должна была послать сообщение об ошибке. Поэтому не приходили даже сообщения о сбое.

# Что исправлено

- В plist добавлен `USER=vk` для запуска `claude` с ожидаемым именем пользователя.
- Переменная `status` заменена на `rc`; сбои агента и пустой результат теперь вызывают уведомление и завершают задачу с ненулевым кодом. При сбое самого уведомителя причина пишется в stderr.
- Для `claude -p` закрыт stdin через `< /dev/null`, чтобы фоновый запуск не ждал ввода. В stderr нет ошибки об отсутствии prompt: существующий аргумент `"$PROMPT"` уже передавался, поэтому перенос prompt в stdin не требовался.
- В stderr записываются длительность и итог запуска. Успех означает наличие непустого файла обзора и успешный вызов уведомителя.
- В `notify.sh` добавлен `curl -f`, чтобы HTTP-ошибка Telegram не выглядела успешной отправкой, и ограничение ожидания 30 секунд.

# Что пригодилось из заметки коллеги

Пригодились проверка `runs` и `last exit code` вместе с stderr, предупреждение о встроенной переменной zsh `status`, установка `USER`, закрытие stdin при передаче prompt аргументом, измерение длительности и проверка реального результата. Совет передавать prompt через stdin здесь не нужен: ошибка была авторизационной, а не ошибкой передачи prompt. Число запусков подтверждает запуск, но код выхода сам по себе не подтверждает выполненный обзор.

# Проверка и пределы

`zsh -n`, `bash -n` и `plutil -lint` прошли. Локальные заглушки проверили ненулевой код агента, пустой вывод, успешный обзор и сбой уведомителя; тест не обращался к `claude` или Telegram. Заглушка `curl` подтвердила, что его ненулевой код теперь проходит через уведомитель.

Это только исправленный снимок. Plist не переустанавливался, реальный launchd не запускался, авторизация `claude`, доступ к связке ключей и доставка Telegram в живом окружении не проверялись. После переноса изменений нужно заново загрузить агент и проверить свежий файл обзора, stderr и получение сообщений об успехе и принудительном сбое.
