# Аналитика: что сделано

Все 6 событий из `docs/EVENTS.md` отправляются через `Analytics.capture`. Имена и свойства совпадают с документом. Email и телефон не передаются.

`registration_screen.dart`:
- `registration_email_started` и `registration_phone_started` отправляются один раз за визит на экран, при первом изменении поля. Для каждого поля есть флаг в state.
- `loan_amount_changed` (`amount`) отправляется из `onChangeEnd` слайдера, то есть один раз за перетаскивание. `onChanged` только обновляет UI.
- `terms_accepted` отправляется только когда галочку поставили. Снятие галочки событие не шлёт.
- `registration_continue_tapped` (`amount`, `terms`) отправляется при нажатии Continue.

`offer_screen.dart`:
- Экран стал `StatefulWidget`.
- `offers_scrolled` (`offset`) отправляется из `NotificationListener<ScrollEndNotification>` один раз за визит, при первом завершении прокрутки.

## Что пригодилось из заметки коллеги
Весь подход: на PostHog free tier событие на каждый `onChanged` быстро съедает квоту. Из заметки использовано:
- флаг «один раз за визит» для текстовых полей;
- `onChangeEnd` для слайдера;
- `ScrollEndNotification` вместо обновлений прокрутки.

Не использовал `FocusNode` и отправку при потере фокуса: финальные значения полей не нужны, а PII отправлять нельзя. Проверку через grep по `lib/` я не запускал: событий в коде ещё не было. `PostHogConfig.debug` не включал и приложение не запускал, потому что Flutter SDK не проверялся.

## Допущения
- «Один раз» для `offers_scrolled` означает один раз за визит, чтобы сэкономить квоту. Воронке нужен только факт прокрутки. Если нужен каждый конец прокрутки, уберите флаг.
- Поля и слайдер сохраняют состояние только пока открыт экран. При повторном открытии события отправятся снова.
