# Почему задача молчала

`launchctl-print.txt` показывает `runs = 6` и `last exit code = 1`: launchd запускал задачу. В `Library/Logs/nightly-review.err` все шесть запусков имеют одинаковую последовательность: `Not logged in · Please run /login`, затем `read-only variable: status` на строке 19. Следовательно, `claude` завершался с ошибкой авторизации в окружении launchd, а присваивание встроенной переменной zsh `status` аварийно останавливало скрипт до вызова `notify.sh`. Это объясняет отсутствие и обзора, и сообщения об ошибке.

В plist добавлен `USER=vk`, чтобы headless CLI получил имя пользователя, нужное для поиска входа в Keychain. Промпт теперь передается `claude -p` через stdin; этот способ устраняет зависимость от разбора многострочного аргумента. `status` заменен на `rc`. Скрипт пишет код завершения и длительность в stderr, сообщает об ошибке при ненулевом коде или пустом результате. Для Telegram добавлен `curl -f`, чтобы HTTP-ошибка не считалась успешной отправкой.

Из заметки коллеги пригодились проверка `launchctl print` и stderr, предупреждение о переменной `status`, установка `USER`, передача промпта через stdin, измерение длительности и проверка реального результата. Вариант с `< /dev/null` не нужен, поскольку промпт поступает через stdin. Утверждение, что `launchd` вообще не срабатывал, здесь опровергается снимком; сам по себе `last exit code` не подтверждает успешный обзор.

Локально проверены синтаксис обоих скриптов (`zsh -n`, `bash -n`), plist (`plutil -lint`) и отсутствие ошибок форматирования (`git diff --check`). Реальный запуск и доставку Telegram в этом снимке проверить нельзя без обращения к внешним сервисам и исходной домашней директории; измененный plist также потребуется отдельно перезагрузить на исходном Mac.
