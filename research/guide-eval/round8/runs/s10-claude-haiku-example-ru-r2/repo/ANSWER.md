# Аналитика на экранах регистрации и предложений

Реализованы все шесть событий из `docs/EVENTS.md`. Имена и свойства совпадают
с документом. Все отправки идут через `Analytics.capture`.

## Что сделано

### `lib/screens/registration_screen.dart`

| Событие | Где вызывается | Что отправляется |
|---|---|---|
| `registration_email_started` | `onChanged` поля email, один раз на состояние экрана | — |
| `registration_phone_started` | `onChanged` поля телефона, один раз на состояние экрана | — |
| `loan_amount_changed` | `Slider.onChangeEnd` (один раз за жест) | `amount` (int) |
| `terms_accepted` | `CheckboxListTile.onChanged`, только когда галочку ставят (`v == true`) | — |
| `registration_continue_tapped` | `_onContinue`, только когда кнопка активна | `amount` (int), `terms` (bool) |

- Флаги `_emailStartedSent` и `_phoneStartedSent` не дают отправить
  «начал вводить» больше одного раза. Сами `onChanged` по-прежнему обновляют UI.
- Email и телефон в свойства не попадают (PII, как требует документ).
- `Slider.onChanged` оставлен только для обновления UI. Событие уходит из
  `onChangeEnd`, поэтому при перетаскивании слайдера одно событие, а не десятки.

### `lib/screens/offer_screen.dart`

- `offers_scrolled` отправляется из `NotificationListener<ScrollEndNotification>`
  вокруг `ListView`. Свойство `offset` — это `n.metrics.pixels`, double.
- Listener возвращает `false`, чтобы уведомление продолжало всплывать.

## Решения, которые стоит проверить

1. **Что значит «once» для текстовых полей.** Регистрационный экран — корневой
   маршрут `/`, поэтому его состояние живёт, пока запущено приложение. Флаги
   сбрасываются только при его пересоздании. Получается «один раз за сессию
   приложения», а не «за визит». Если нужно за визит, сбрасывать флаги надо
   при повторном входе на экран.
2. **Что такое `offset`.** В документе написано «how far they scrolled». Я
   выбрал текущую позицию прокрутки (`metrics.pixels`), потому что название
   свойства говорит о смещении. Если продукт имеет в виду пройденное расстояние
   за жест, это другое значение, и его нужно считать отдельно.
3. **`onChangeEnd` срабатывает и на простое нажатие** на слайдер, без
   перетаскивания. Это ожидаемо: одно взаимодействие — одно событие.

## Что из заметки коллеги пригодилось

Использовано:
- Флаг «один раз» на состоянии экрана для текстовых полей.
- Перенос события слайдера из `onChanged` в `onChangeEnd`.
- Прокрутка через `ScrollEndNotification`, а не через `ScrollUpdateNotification`.
- Правило «имена и свойства не меняем», чтобы дашборды продолжали работать.

Не использовано:
- `FocusNode` и срабатывание на потере фокуса. Ни одно событие из документа
  не требует финального значения поля, поэтому фокус тут не нужен.
- Шаг с `grep` по существующим захватам. Репозиторий новый: до этой правки
  ни один экран не отправлял события, и проблемных вызовов не было. Структуру
  я проверил чтением файлов.
- Проверка через `PostHogConfig.debug` и PostHog Activity. Я её не выполнял:
  в проекте стоит placeholder-ключ `phc_REPLACE_ME_IN_CI`, а запуска на
  устройстве здесь нет. Это остаётся на вас.
