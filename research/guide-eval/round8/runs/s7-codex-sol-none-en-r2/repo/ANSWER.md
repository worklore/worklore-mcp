# Intervals.icu connection failures

1. **The Connect button never sent the tricoach sign-in token.** The SPA kept it in `localStorage` and added it only in its `fetch` wrapper. The old `<a href>` made a document navigation, so `/api/intervals/auth/init` received no `Authorization` header and returned 401, exactly as `logs/connect-attempt.log` shows. The button now calls that endpoint through the authenticated wrapper, receives an authorization URL as JSON, and navigates to it.

2. **The authorization request asked for both READ and WRITE in the same scope families.** The captured URL requested `ACTIVITY:READ,ACTIVITY:WRITE` and `CALENDAR:READ,CALENDAR:WRITE`; Intervals returned `invalid_request` before consent. [Intervals' OAuth documentation](https://forum.intervals.icu/t/intervals-icu-oauth-support/2759) says WRITE already implies READ and shows one permission per scope family. The request now uses `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`. The generic 400 response does not identify the bad parameter, so the duplicate scopes are the likely cause based on the captured URL and documented rules; this cannot be confirmed without a live authorization attempt.

3. **The app invented a one-hour expiry for an access token with no expiry.** Rivera's logged token response had neither `expires_in` nor `refresh_token`, but the app substituted 3600 seconds and then marked it expired. [Intervals' OAuth documentation](https://forum.intervals.icu/t/intervals-icu-oauth-support/2759) describes access tokens without refresh tokens. A missing `expires_in` now means no scheduled expiry or refresh. If Intervals later returns 401 on an API call, the app marks the connection for reauthorization. Responses that do supply an expiry still follow the refresh or expiry path.

Local verification: `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v test_intervals` covers authenticated initiation, the requested scopes, callback storage and use of a no-expiry token after two hours, and provider 401 handling. No live OAuth exchange was attempted because the repository has placeholder credentials.
