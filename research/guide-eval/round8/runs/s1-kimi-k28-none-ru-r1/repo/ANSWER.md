# Что было не так и что изменено

## Причина

Часы показывали собственные зональные диапазоны, потому что `gen.py` отправлял
HR-таргет в формате, которого Intervals.icu не знает:

```json
"hr": {"units": "%lthr", "value": 68, "end": 75}
```

API такой JSON принимает (он хранит `workout_doc` как есть — поэтому readback
совпадает с отправленным), но при экспорте в Garmin цель не распознаётся, и
в тренировку часов уходит не коридор, а зоны — поэтому все четыре шага
отображались полосами Z2/Z3/Z4 часов, и смена LTHR на часах лишь двигала эти
полосы. Прошлые попытки (`units: "bpm"` с абсолютными значениями → 214–249 bpm,
`start_bpm`/`end_bpm` → константа 101) — это те же неправильные поля, часы
получали мусор или зону по умолчанию.

## Исправление (`gen.py`)

1. Таргет теперь в документированной форме `workout_doc` — объект `target`
   со строкой `value`:
   `"target": {"type": "HR", "value": "117-129bpm"}` (было `"hr"` с
   `units`/`value`/`end`).
2. Конвертация %LTHR → bpm перенесена из (неработавшего) предположения
   «Intervals сам конвертирует» в генератор: по константе `LTHR = 172`
   (порог атлета из README) считаются абсолютные границы коридора. Так таргет
   не зависит от того, какие зоны и пороги настроены на часах.

План (`plans/*.json`) не менялся — он по-прежнему хранит проценты LTHR.

## Проверка

`python3 gen.py plans/tempo-run.json` даёт коридоры, совпадающие с колонкой
«expected on watch» из `readback/watch-notes.md`:

| step | planned (% LTHR) | теперь в JSON |
|---|---|---|
| Warm-up easy | 68–75 | 117–129 bpm |
| Tempo | 88–93 | 151–160 bpm |
| Float | 75–82 | 129–141 bpm |
| Cool-down | 65–72 | 112–124 bpm |

Ничего наружу не отправлялось: `push.sh` не запускался, изменения только
локальные (генератор + README + этот файл).

## Что осталось проверить на устройстве

Формат `target {"type": "HR", "value": "min-maxbpm"}` — документированный
Intervals.icu, но после пуша стоит сверить с readback: новое событие должно
прийти с `target` в `workout_doc`, и часы должны показать коридоры, а не зоны.
