# Исправление диапазонов пульса

В `gen.py` нижняя граница HR-цели теперь записывается в `start` вместо `value`: `{"units": "%lthr", "start": <нижняя>, "end": <верхняя>}`. Изменение действует для обычных шагов и шагов внутри повторов, потому что оба типа используют `hr_target()`.

По `readback/watch-notes.md`, прежние цели с `value` отображались на часах как границы их собственных зон, а не как запланированные интервалы. Присланная заметка коллеги объясняет эту разницу форматов: `value`/`end` даёт цель, привязанную к зонам, а `start`/`end` задаёт коридор Instant HR. Оставил `%lthr`: пороги спортсмена хранятся в Intervals, и при экспорте ожидаются диапазоны в bpm, рассчитанные от LTHR 172, например 129–141 для Float.

Из заметки пригодились именно форма HR-цели `start`/`end` и сохранение единиц `%lthr`. Предложения про `bpm` и `start_bpm`/`end_bpm` не применял: в наших записях такие варианты уже давали неверные значения. Правила для текстового `description` не использовал, поскольку здесь исправляется отображение HR-диапазонов, а в сохранённом ответе API `workout_doc.steps` уже заполнен. Исторический файл `readback/event-184233-as-sent.json` оставил как свидетельство старого запроса.

Локально запустил генератор на `plans/tempo-run.json` и проверил все четыре HR-цели, включая обе цели внутри повтора: у каждой есть ожидаемые `start` и `end`, ключа `value` нет, число повторов осталось 3. Новый запрос в Intervals и проверку на часах не выполнял, поэтому фактическое отображение после синхронизации пока не подтверждено.
