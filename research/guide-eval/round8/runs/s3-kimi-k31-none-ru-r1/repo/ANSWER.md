# Причины

1. **Claude CLI не был аутентифицирован.** Все шесть запусков заканчивались сообщением `Not logged in · Please run /login` в `Library/Logs/nightly-review.err`. Поэтому обзор не создавался.
2. **Обработчик ошибки сам завершался с ошибкой.** В `bin/nightly-review.zsh` код возврата сохранялся через `status=$?`, но `status` — специальная переменная zsh, доступная только для чтения. Zsh прерывал сценарий на этой строке, до вызова `notify.sh`, поэтому не приходили даже уведомления об ошибках.

Само расписание launchd исправно: `launchctl-print.txt` показывает запуск по `StartCalendarInterval` в 02:30, шесть выполненных запусков (`runs = 6`) и последний код возврата 1. Путь к `claude` также не был причиной: команда запускалась и возвращала ошибку аутентификации.

# Исправление

В `bin/nightly-review.zsh` переменная `status` заменена на `exit_code`. Теперь при ненулевом коде возврата Claude сценарий вызывает `notify.sh` с сообщением об ошибке и завершается с исходным кодом. Конфигурация launchd не требовала изменений.

Для появления успешных обзоров дополнительно требуется повторная аутентификация Claude CLI от имени пользователя `vk`: запустить `claude` в интерактивном терминале и выполнить `/login`. Это нельзя исправить изменением снимка файлов; аутентификация и обращения к внешним сервисам здесь не выполнялись.

Проверено локально без обращения к Claude или Telegram: синтаксис обоих сценариев и plist, ветка ошибки с вызовом уведомления и сохранением кода 1, а также успешная ветка с уведомлением и созданным файлом обзора.
