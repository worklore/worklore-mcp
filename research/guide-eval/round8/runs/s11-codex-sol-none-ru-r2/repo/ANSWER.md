# Причина и исправление

Первая публикация проходит, потому что в пустой библиотеке поле `similar` равно `[]`. При второй публикации `related()` добавляет туда оценку сходства. Раньше `similarity()` вычисляла её через обычное деление и возвращала `float`. При `put_item` сериализатор boto3 отклоняет `float` (`Float types are not supported. Use Decimal types instead.`), поэтому обработчик возвращал 500. Это совпадает с трассировкой в `logs/error.log`.

Теперь `similarity()` считает доли и веса через `Decimal` и округляет результат до четырёх знаков. Следовательно, оценки в `similar` совместимы с DynamoDB при любой последующей публикации. Входные поля также проверяются до записи: `slug`, `title` и `body` должны быть непустыми строками, а `tags` — списком строк. Это не даёт клиентскому числу с плавающей точкой попасть в сохраняемый элемент; некорректный запрос получает 400.

Проверка: `python3 -m unittest discover tests -v` — 3 теста прошли, включая три последовательные публикации и отклонение дробного числа в `tags`.
