# Исправление кеширования промпта

В `bot.py` функция `build_system()` теперь возвращает два текстовых блока с `cache_control: {"type": "ephemeral"}`. Первый содержит неизменные инструкции `INSTRUCTIONS`, второй — дату, профиль, зоны, цель, факты и язык спортсмена. После `save_fact` меняется только второй блок, поэтому кешированный префикс с инструкциями может использоваться повторно.

В `logs/usage.jsonl` до исправления после `save_fact` чтение из кеша падало до нуля, а создание кеша вновь составляло 1039–1104 токена. Причина — прежний единственный маркер стоял после объединённых инструкций и фактов.

Из заметки коллеги пригодились разделение стабильной и изменяемой частей на два маркера и проверка через `cache_read_input_tokens` и `cache_creation_input_tokens`. Идеи отбора отдельных фактов и изменения набора инструментов не применялись: все факты уже передаются вместе, а существующий отбор инструментов по ключевым словам сохранён.

Локально проверено: после записи факта первый блок и набор инструментов остаются неизменными, второй блок меняется и содержит новый факт; при смене спортсмена или даты первый блок тоже остаётся прежним. `git diff --check` прошёл. Запросов к Claude не делалось, поэтому фактическое число прочитанных из кеша токенов после исправления пока не измерено. При следующем разрешённом запуске это можно проверить по тем же полям `usage`: после `save_fact` ожидается ненулевое чтение статического префикса и создание кеша только для изменившегося хвоста.
