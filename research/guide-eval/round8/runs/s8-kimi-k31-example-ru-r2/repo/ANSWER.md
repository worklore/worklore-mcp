# Что изменено

- В `bot.py` функция `build_system()` теперь возвращает два системных текстовых блока вместо одного:
  1. неизменяемые `INSTRUCTIONS`;
  2. изменяемый `athlete_context()` с датой, профилем, зонами, целью, фактами и языком.
- Оба блока имеют собственный `cache_control: {"type": "ephemeral"}`. Поэтому `save_fact` меняет только второй блок, а побайтово стабильный первый остаётся пригодным для чтения из кеша.
- Порядок и содержимое инструментов не менялись; существующая фильтрация инструментов сохранена. Факты по-прежнему включаются все, без выбора top-N для каждого сообщения.
- Описание кеширования в `README.md` приведено в соответствие с новой структурой.

# Что пригодилось из заметки

- Объяснение prefix-based кеширования и основное решение: две метки `cache_control` — одна для статических инструкций, другая для изменяемого контекста.
- Требование побайтовой стабильности статического блока и списка инструментов.
- Рекомендация не делать per-message top-N выбор фактов и не менять существующую фильтрацию инструментов.
- Ориентир для проверки: после записи факта должен пересоздаваться только изменяемый хвост, а статический префикс — читаться из кеша.

# Проверка

- `python3 -m py_compile bot.py` — успешно.
- Локальный интеграционный прогон `reply → save_fact → повторный запрос` с двойником API — успешно: оба запроса содержат два кешируемых блока, первый блок совпадает побайтово, новый факт появляется только во втором, список инструментов не меняется.

Запросы к Anthropic не выполнялись, поэтому новые значения `cache_read_input_tokens` и `cache_creation_input_tokens` в реальном API не измерялись.
