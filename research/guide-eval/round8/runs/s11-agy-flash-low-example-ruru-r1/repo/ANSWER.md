# Причина падения и исправление

## 1. Причина ошибки

В логе `logs/error.log` зафиксирована ошибка:
```
TypeError: Float types are not supported. Use Decimal types instead.
```
возникающая при вызове `table.put_item(Item=item)`.

* **Почему первая публикация прошла успешно:**
  При первой публикации база данных DynamoDB была пуста (`table.scan()` возвратил пустой список `Items: []`). В результате функция `related()` вернула пустой список `similar: []`. В сохраняемом объекте `item` не было вычисленных значений похожести.

* **Почему вторая публикация завершилась ошибкой 500:**
  При второй публикации в таблице уже существовала первая запись. Функция `related(story, existing)` вычислила оценку сходства `score` с помощью функции `similarity(a, b)`:
  ```python
  return round(0.7 * tag_score + 0.3 * word_score, 4)
  ```
  В Python операции деления и функция `round(...)` возвращают стандартный тип `float`.
  Клиент boto3 (и сериализатор DynamoDB `TypeSerializer`) не поддерживает тип `float` для числовых атрибутов, требуя вместо этого `decimal.Decimal` (или целые числа `int`). Из-за наличия элементов вида `{"slug": ..., "score": <float>}` в списке `similar` метод `put_item` выбросил исключение `TypeError`, что привело к возврату статуса 500 в `handler()`.

---

## 2. Исправление

1. В `src/app.py`:
   - Импортирован класс `Decimal` из стандартного модуля `decimal`.
   - В функции `similarity(a, b)` возвращаемое значение обёрнуто в `Decimal(str(...))`:
     ```python
     return Decimal(str(round(0.7 * tag_score + 0.3 * word_score, 4)))
     ```
     Это гарантирует совместимость с boto3 и сохраняет точность до 4 знаков после запятой без нежелательных артефактов двоичного представления `float`.
2. В `tests/test_publish.py`:
   - Добавлен интеграционный тест `test_publish_second_story_succeeds_with_similarity_scores`, который публикует первую историю, а затем выполняет публикацию второй истории при непустой таблице. Тест валидирует успешный статус `201`, сохранение записей и корректность структуры `similar`.

---

## 3. Какие части заметки коллеги пригодились

* **Пригодилось:**
  - Описание первопричины: несовместимость типа `float` в Python с DynamoDB (`TypeError: Float types are not supported. Use Decimal types instead`).
  - Объяснение различия в поведении между первой и второй записью: при пустой таблице список похожих историй пуст, и код с `float` не запускался/не сохранялся в DynamoDB.
  - Рекомендация конвертировать вычисляемые значения на границе в `Decimal` (или `int`).
  - Рекомендация добавить тест с предварительно заполненной таблицей (запись второй истории), чтобы предотвратить регресс в будущем.
* **Не пригодилось / пропущено:**
  - Преобразование оценки в целые проценты (`int`): в сервисе использовался расчет с точностью до 4 знаков после запятой (`round(..., 4)`), поэтому преобразование в `Decimal(str(...))` сохранило существующий формат и контракт данных без потери точности.
