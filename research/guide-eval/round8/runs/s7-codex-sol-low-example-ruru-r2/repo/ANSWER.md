# Исправление подключения Intervals.icu

## Причины

1. Кнопка была ссылкой на `GET /api/intervals/auth/init`. Переход страницы не передавал `Authorization` из `localStorage`, поэтому сервер возвращал 401 всем атлетам (`logs/connect-attempt.log`, попытка 1). Теперь кнопка вызывает аутентифицированный `POST` через `fetch`, получает `authorize_url` и переводит браузер по нему.
2. В OAuth scope одновременно стояли `ACTIVITY:READ` и `ACTIVITY:WRITE`, а также `CALENDAR:READ` и `CALENDAR:WRITE`. `WRITE` уже включает `READ`; после добавления календаря ссылка стала отклоняться до экрана согласия (`logs/connect-attempt.log`, попытка 2). Оставлены `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`.
3. Ответ Intervals для Rivera не содержал `expires_in` и `refresh_token`. Код выдумывал срок 3600 секунд и затем сам удалял действующий токен (`logs/connect-attempt.log`, попытка 3). Убраны фиктивный срок и фоновое обновление. При реальном 401 от API токен очищается и статус предлагает подключиться снова.

Обмен кода теперь отправляет только `client_id`, `client_secret` и `code`. Callback проверяет подписанный `state` и существование пользователя; повторное подключение к другому аккаунту атлета отклоняется.

## Что пригодилось из заметки коллеги

Пригодились сведения о бессрочном токене без обновления, включении `READ` в `WRITE`, формате обмена кода, необходимости аутентифицированного `POST` для init и проверке аккаунта при повторном подключении. Совет о подписанном `state` применён к уже существующему HMAC state; JWT для этого не требуется. Шифрование токена в постоянном хранилище здесь неприменимо напрямую: этот демонстрационный сервер хранит подключения только в памяти. Проверку с реальным аккаунтом не проводили: OAuth client в `config.py` содержит заглушки, а отправка запросов внешнему сервису запрещена условиями задачи.

Проверка: `python3 -m py_compile server.py config.py` и локальные проверки scope, полей обмена, хранения токена и подписи state прошли.
