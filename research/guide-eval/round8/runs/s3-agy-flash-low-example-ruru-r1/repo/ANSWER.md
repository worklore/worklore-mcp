# Анализ проблемы и исправления для nightly-review

## Причины, почему задача launchd ни разу ничего не сообщила

При анализе логов (`Library/Logs/nightly-review.err`), конфигурации launchd (`Library/LaunchAgents/com.vk.nightly-review.plist`) и скрипта (`bin/nightly-review.zsh`) было выявлено три взаимосвязанных фактора:

1. **Отсутствие переменной окружения `USER` в контексте launchd**:
   - В логе ошибок зафиксировано: `Not logged in · Please run /login`.
   - Под управлением `launchd` агент запускается с минимальным окружением, где отсутствует переменная `USER`. Утилита Claude Code CLI (а также вызовы macOS Keychain) опирается на `$USER` для поиска учетных данных/токена авторизации. Без `$USER` CLI считает, что пользователь не авторизован, завершает работу с ненулевым кодом выхода и ничего не генерирует.

2. **Попытка записи в read-only переменную `status` в `zsh`**:
   - В скрипте `bin/nightly-review.zsh` строка 19 выполняла `status=$?`.
   - В оболочке `zsh` переменная `status` является специальной встроенной переменной только для чтения (синоним `$?`). Присваивание значения переменной `status` вызывает фатальную ошибку шелла: `read-only variable: status`.
   - Из-за этой фатальной ошибки скрипт немедленно аварийно завершался на строке 19, так и не дойдя до блока обработки ошибок (`if [ $status -ne 0 ]; then "$NOTIFY" ... fi`). Таким образом, скрипт-оповещатель (`notify.sh`) ни разу не вызывался при падении.

3. **Способ передачи промпта в headless-агент**:
   - Изначально передавался многострочный аргумент: `claude -p "$PROMPT" ...`. При запуске в неинтерактивных средах под управлением шелл-планировщика более надежно передавать промпт через stdin (`print -r -- "$PROMPT" | claude -p - ...`), чтобы избежать проблем с чтением стандартного ввода и разбором многострочных строк.

---

## Внесённые исправления

1. **`Library/LaunchAgents/com.vk.nightly-review.plist`**:
   - В словарь `EnvironmentVariables` добавлена переменная `USER` со значением `vk` (имя пользователя системы согласно путям `/Users/vk/...`).
2. **`bin/nightly-review.zsh`**:
   - Переменная `status` заменена на `rc` (`rc=$?` и проверка `if [ $rc -ne 0 ]`).
   - Передача промпта переведена на stdin через `print -r -- "$PROMPT" | claude -p - ...`.

---

## Какие части заметки коллеги пригодились

Из предложенной заметки пригодились следующие части:
- **Анализ через `launchctl print` и логи**: подтверждение того, что задача фактически запускалась планировщиком (код выхода 1), и необходимость смотреть в `Library/Logs/nightly-review.err`.
- **Баг с `status=$?` в `zsh`**: объяснение того, что `status` в zsh — read-only переменная, присваивание которой убивает скрипт до вызова нотификатора ошибки. Рекомендация использовать `rc=$?`.
- **Ловушка с отсутствием переменной `USER` в `EnvironmentVariables` plist-файла**: именно из-за этого Claude CLI выдавал `Not logged in · Please run /login`.
- **Передача промпта через stdin**: использование конструкции передачи через stdin (`print -r -- "$PROMPT" | claude -p ...`), устраняющей проблемы с разбором аргументов и ожиданием ввода в launchd.

Остальные части (про сторожевые таймеры, kickstart на живой системе и т.д.) носили общий контекстный характер и на практике не потребовались.
