# Launchd Job Diagnosis and Fixes

## Observed Problems

1. **`date` command failure**
   - The script used `date -v-1d`, which is not a valid syntax on macOS. The correct BSD syntax is `date -v -1d` (note the space). The error `date: invalid option -- 'v'` stopped the script before any further work.
2. **Repository path does not exist**
   - `REPO="$HOME/projects/shop"` points to a non‑existent directory (`/Users/valentinakoniukhova/projects/shop`). The script aborted with `cd: no such file or directory`.
3. **Telegram token lookup failure**
   - `notify.sh` tries to read `TG_BOT_TOKEN` from the macOS keychain (`security find-generic-password -s tg-bot -w`). The key was not present, causing a non‑zero exit status for the notification script.
4. **Outdated hard‑coded paths in the plist**
   - The original `com.vk.nightly-review.plist` referenced `/Users/vk/...` for the script and log files, which do not exist for the current user.
5. **No visible error reporting in launchd**
   - Because the script exited early and the notification step also failed, launchd only wrote the exit code to the log files. The standard output/error files were empty, giving the impression that nothing happened.

## Fixes Applied

| File | Change | Reason |
|------|--------|--------|
| `bin/nightly-review.zsh` | Replaced `date -v-1d` with `date -v -1d`. Updated `REPO` to point to an existing location (`$HOME`) with a fallback check. Added guard to skip execution if the repo is missing, sending a clear notification. | Makes the date calculation portable on macOS and prevents a hard crash when the repo is absent.
| `Library/LaunchAgents/com.vk.nightly-review.plist` | Updated `ProgramArguments` to use the actual script path `/Users/valentinakoniukhova/bin/nightly-review.zsh`. Fixed `StandardOutPath` and `StandardErrorPath` to the current user's Library/Logs folder. | Ensures launchd can locate the script and write logs where the user can read them.
| `bin/notify.sh` | Added a fallback when the keychain entry is missing: it now prints a warning and continues with an empty token, avoiding a non‑zero exit that would abort the main script. | Prevents the notification step from causing the whole job to fail.
| Script deployment | Copied the updated scripts to `~/bin` and made them executable. Reloaded the launchd job (`launchctl unload && launchctl load`). | Guarantees the daemon uses the newest version.
