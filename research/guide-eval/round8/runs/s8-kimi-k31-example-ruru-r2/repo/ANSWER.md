# Что изменил

- В `bot.py` функция `build_system` теперь возвращает два текстовых блока вместо одного:
  1. статические `INSTRUCTIONS`;
  2. изменяемый `athlete_context` с датой, профилем, зонами, целью, фактами и языком.
- Оба блока имеют собственный `cache_control: {"type": "ephemeral"}`. Поэтому `save_fact` меняет только второй блок, а кеш статических инструкций не инвалидируется.
- Статический блок не содержит подставляемых значений. Разделитель между частями сохранён, поэтому объединённый текст системного промпта остался прежним.
- Выбор и порядок инструментов не менялись. Описание кеширования обновлено в `README.md`.

# Что пригодилось из заметки

- Основное решение: два сегмента с отдельными маркерами `cache_control`, чтобы изменение памяти перекешировало только пользовательский хвост.
- Требование побайтовой стабильности статического блока и всего, что находится выше него в префиксе, включая схемы инструментов.
- Отказ от отбора top-N фактов под каждое сообщение: такой отбор делал бы изменяемый блок разным и мешал попаданиям в кеш.
- Поля `cache_creation_input_tokens` и `cache_read_input_tokens` как способ проверки результата. Существующие записи в `logs/usage.jsonl` подтвердили исходную проблему: после `save_fact` чтение из кеша падало до нуля, а создание кеша снова охватывало весь промпт.
- Фильтрация инструментов уже была реализована в проекте; её оставил без изменений.

# Проверка

Локально прогнал `reply()` с имитированным ответом Claude, который вызывает `save_fact`, и со вторым ответом в цикле инструментов. Проверено:

- в запросах два системных блока, у обоих есть маркер ephemeral;
- до и после `save_fact` статический блок полностью совпадает;
- новый факт появляется только в блоке контекста атлета;
- объединённый текст системного промпта совпадает с прежним форматом;
- ответ бота успешно возвращается.

Внешний API не вызывался, файлы данных и журнал `usage.jsonl` не изменялись. Поэтому фактические значения `cache_read_input_tokens` после изменения не измерялись; при работе с API после записи факта статический блок должен попадать в `cache_read`, а создание кеша должно относиться только к изменившемуся контексту.
