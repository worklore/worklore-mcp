# Исправление кеширования

В `bot.py` функция `build_system()` теперь возвращает два текстовых блока, каждый со своим `cache_control: {"type": "ephemeral"}`:

1. Статический блок содержит только `INSTRUCTIONS`, без даты, имени и других изменяемых значений.
2. Изменяемый блок содержит результат `athlete_context()`: дату, профиль, зоны, цель, долговременные факты и язык.

Поэтому `save_fact` меняет только второй блок, а кеш статических инструкций остаётся пригодным для следующих вызовов. Состав фактов и фильтрация инструментов не менялись. Описание кеширования в `README.md` обновлено.

# Что пригодилось из заметки коллеги

- Основное решение: два кешируемых сегмента вместо одного, чтобы изменение памяти не сбрасывало кеш инструкций.
- Требование байтовой стабильности статического блока: дата и данные спортсмена оставлены только во втором блоке.
- Диагностика по `cache_creation_input_tokens` и `cache_read_input_tokens`: исходные логи подтверждают полное пересоздание кеша после `save_fact`.
- Предупреждение о per-message персонализации: выбор top-N фактов не добавлялся, все факты по-прежнему включаются целиком.
- Замечание о стабильности инструментов: существующая фильтрация сохранена, порядок и схемы инструментов не менялись.

# Проверка

Локально через mocked-ответы Claude выполнен полный цикл `reply()` с `save_fact`. Проверено, что запрос содержит два кешируемых блока, статический блок одинаков для разных спортсменов и дат, а после записи факта между раундами меняется только блок контекста спортсмена. Внешний API не вызывался, поэтому фактические значения `cache_read_input_tokens` после исправления не измерялись.
