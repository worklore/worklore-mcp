# Почему вторая публикация возвращает 500

**Причина.** `similarity()` возвращает `float` (`round(..., 4)`), и этот score кладётся в
`item["similar"]` как `{"slug", "score"}`. boto3 для DynamoDB не принимает `float`
(`TypeError: Float types are not supported. Use Decimal types instead.`).

Первая публикация проходит, потому что таблица пуста: `related()` возвращает `[]`, и ни одного
float в элементе нет (`similar=0` в логе). Начиная со второй публикации в `similar` есть
записи с float-score, и `put_item` падает; handler превращает это в 500. Тесты этого не ловили,
так как проверяли только публикацию в пустую таблицу.

**Исправление.** В `src/app.py` добавлена `to_dynamo()`, рекурсивно заменяющая все `float` на
`Decimal(str(x))`; она применяется к элементу прямо перед `put_item`. Так любое будущее
float-поле (не только score) тоже не сломает запись. Добавлены тесты: публикация второй
истории в непустую таблицу и вложенное преобразование float.

Примечание: `scan` не обходит страницы (лимит 1 МБ); при росте библиотеки related будет считаться
только по первой странице. Это отдельный вопрос, здесь не менялось.
