# Причина

В `logs/error.log` вторая публикация падает в `table.put_item` с `TypeError: Float types are not supported. Use Decimal types instead.` При первой публикации таблица пуста, поэтому `similar` пуст. При следующей `related()` добавляет вычисленный `similarity()` показатель типа `float` в `similar[*].score`; сериализатор DynamoDB такой тип не принимает, и обработчик возвращает 500.

# Исправление

Перед включением показателя в сохраняемый элемент преобразовал его в `Decimal` через строку. Значение и диапазон оценки сохраняются, а в DynamoDB больше не передаётся `float` по этому пути. Добавил тест двух последовательных вызовов `handler()` с непустой таблицей: оба должны вернуть 201, второй элемент должен содержать `Decimal` в `similar`. Локальный `FakeTable` отклоняет `float` так же, как boto3.

# Что пригодилось из заметки коллеги

Пригодились указание на ограничение DynamoDB для `float`, объяснение разницы между пустой и заполненной таблицей и идея тестировать запись после предварительного заполнения. Не использовал перевод показателя в целый процент: это изменило бы формат и точность уже существующей оценки. Публикацию в настоящую таблицу не выполнял по условию задачи.
