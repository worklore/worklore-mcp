# Почему ночная задача молчала

Задача **запускалась**: в `launchctl-print.txt` указаны `runs = 6` и `last exit code = 1`. В `Library/Logs/nightly-review.err` шесть раз повторяются две ошибки подряд:

1. `claude` завершался с `Not logged in · Please run /login`. В окружении задачи из снимка `launchctl print` нет `USER`; в plist были заданы только пути поиска команд. Для работы CLI с учётной записью добавлены `USER=vk`, `LOGNAME=vk` и `HOME=/Users/vk`. Это устраняет видимое отличие окружения от входа пользователя, но снимок не позволяет доказать, что авторизация `claude` после этого доступна: её нужно проверить уже на машине владельца.
2. После ошибки скрипт выполнял `status=$?`. В zsh `status` — переменная только для чтения; присваивание немедленно обрывало скрипт **до** вызова `notify.sh`. Поэтому не приходило даже сообщение о сбое. Переменная заменена на `rc`, а путь ошибки теперь записывает причину в stderr и вызывает уведомление.

Дополнительно скрипт закрывает stdin для `claude -p` (`< /dev/null`), проверяет непустой файл обзора и записывает длительность и исход запуска. Если отправить уведомление не удалось, это видно в stderr и коде завершения. `notify.sh` теперь ограничивает время запроса и считает HTTP-ошибки Telegram ошибкой команды.

## Что пригодилось из заметки коллеги

- Проверка `launchctl print` и stderr: они опровергли предположение, что расписание не срабатывает, и показали точные ошибки.
- Запрет присваивания `status` в zsh: это непосредственная причина отсутствия сообщения об ошибке.
- `USER` в окружении launchd: подходит к наблюдаемому `Not logged in`; также явно указан `HOME`.
- Закрытый stdin при передаче промпта аргументом, проверка реального результата и длительности: добавлены для надёжности.

Совет передавать промпт через stdin здесь не применён: скрипт уже передаёт его одним аргументом `-p`, а журнал не показывает ошибки чтения промпта. Вместо этого stdin закрыт. `last exit code` подтверждает завершение с ошибкой, но сам по себе не подтверждает появление обзора или доставку сообщения.

## Проверка

`zsh -n`, `bash -n` и `plutil -lint` прошли. Локальный запуск с заглушками `claude` и `notify.sh` проверил успех, ошибку `claude` (код 7), пустой результат и ошибку уведомления; соответствующие коды завершения и сообщения получены. Заглушка также подтвердила закрытый stdin. Реальный launchd и Telegram не запускались: этот каталог — снимок, а внешние отправки запрещены. После переноса исправлений на машину владельца нужно проверить доступность авторизации `claude` и фактическое получение уведомления.
