# Исправление кеширования промпта

В `bot.py` системный промпт разделён на два текстовых блока с отдельными `cache_control: ephemeral`. Первый содержит одинаковые для всех спортсменов инструкции, второй — дату, профиль, зоны, цель, факты и язык. После `save_fact` пересобирается только второй блок; первый остаётся байт-в-байт прежним. Постоянные инструкции дополнены пояснениями уже действующих правил, чтобы первый кешируемый префикс был достаточно длинным для кеша Claude. Подбор инструментов по ключевым словам оставлен прежним.

Из заметки коллеги пригодились два кешируемых сегмента, требование стабильного префикса и проверка полей `cache_creation_input_tokens` / `cache_read_input_tokens`. Не применялись отбор фактов по релевантности и переделка фильтрации инструментов: все факты уже загружаются, а текущая фильтрация экономит токены. Схемы инструментов по-прежнему расположены перед системным промптом; смена набора инструментов может дать отдельный промах кеша.

Проверено локально: синтаксис Python, неизменность первого блока для разных спортсменов и дат, изменение только второго блока после нового факта, а также цикл с подставным `save_fact`. Реальный ответ Claude не запрашивался по условию задачи. Для подтверждения в рабочем журнале следующий вызов после `save_fact` должен показывать чтение постоянного префикса из кеша и создание кеша лишь для изменившейся части; точные значения зависят от токенизации и выбранных инструментов.
