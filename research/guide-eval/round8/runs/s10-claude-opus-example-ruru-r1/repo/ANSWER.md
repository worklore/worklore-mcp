# Аналитика регистрации и списка предложений

Все 6 событий из `docs/EVENTS.md` отправляются через `Analytics.capture`
(`lib/analytics.dart`). Имена и свойства точно совпадают со спецификацией.
Email и телефон в свойства не попадают.

| Событие | Где | Когда срабатывает |
|---|---|---|
| `registration_email_started` | `lib/screens/registration_screen.dart`, `onChanged` поля Email | один раз за посещение экрана, при первом вводе (флаг `_emailStartedFired`) |
| `registration_phone_started` | там же, поле Phone | один раз за посещение экрана (флаг `_phoneStartedFired`) |
| `loan_amount_changed` `{amount: int}` | `Slider.onChangeEnd` | один раз за протягивание или тап, когда пользователь отпускает слайдер; `onChanged` только обновляет UI |
| `terms_accepted` | `CheckboxListTile.onChanged` | только при переходе галочки false → true; снятие галочки события не шлёт |
| `registration_continue_tapped` `{amount: int, terms: bool}` | `FilledButton.onPressed` | при нажатии, перед переходом на `/offers` |
| `offers_scrolled` `{offset: double}` | `lib/screens/offer_screen.dart`, `NotificationListener<ScrollEndNotification>` вокруг `ListView` | один раз за каждый жест скролла, когда скролл остановился; `offset` = `metrics.pixels`; учитывается только сам список (`depth == 0`) |

Проверка: `dart format` и `flutter analyze` прошли, ошибок нет. На устройстве
приложение не запускал, отправку событий в PostHog вживую не проверял.
Временные файлы от `flutter pub get` (`.dart_tool/`, `pubspec.lock`, правка
`analysis_options.yaml`) я откатил: в репозитории остались только изменения в
двух экранах и этот файл.

## Что пригодилось из заметки коллеги

Проект на бесплатном тарифе PostHog (см. README). Самый очевидный способ
подключить события (`onChanged`) тратил бы квоту так же, как в заметке.
Пригодилось:
- **Флаг «один раз за посещение» для текстовых полей.** Событие «начал вводить»
  срабатывает при первом нажатии клавиши, а не на каждое.
- **`onChangeEnd` вместо `onChanged` у слайдера.** Одно событие на протягивание
  вместо десятков (у слайдера 49 делений).
- **`ScrollEndNotification` вместо обновлений скролла.** Одно событие на жест.
- **Имена событий и свойства не менять.** Они точно совпадают с
  `docs/EVENTS.md`, на них уже построены дашборды.

Не понадобилось:
- **Слушатели `FocusNode` для тапа или потери фокуса.** В спецификации нет
  событий фокуса, и ни одному событию не нужно итоговое значение поля. Оно
  было бы PII.
- **Решение «один раз за весь поток».** Состояние экрана не переживает
  навигацию, поэтому выбрал «один раз за посещение экрана».
- **Проверка через `PostHogConfig.debug` и PostHog → Activity.** Приложение
  не запускал и во внешний сервис ничего не отправлял.

## Открытые вопросы для продукта
- `offers_scrolled` срабатывает на каждый жест скролла. Это ограниченное
  количество событий, но если для воронки достаточно одного раза за посещение,
  легко добавить флаг. Тогда `offset` будет смещением после первого скролла,
  а не максимальной глубиной.
- `terms_accepted` повторится, если пользователь снимет галочку и поставит
  её снова. Это редкий случай.
