# Почему задача молчала

Задача **запускалась**: снимок `launchctl print` от 2026-10-18 показывает `runs = 6` и `last exit code = 1`. В `Library/Logs/nightly-review.err` для каждого запуска есть пара ошибок:

1. `claude` завершался с `Not logged in · Please run /login`. В окружении launchd из снимка задан `PATH`, но нет `USER`. Для headless CLI это вероятная причина, по которой он не находит сохранённый вход в keychain. В plist добавлен `USER=vk`; подтвердить, что одного этого достаточно для реального входа, по снимку нельзя.
2. После отказа CLI скрипт выполнял `status=$?`. В zsh `status` — переменная только для чтения. Присваивание обрывало скрипт **до** ветки с уведомлением об ошибке. Оно заменено безопасным `rc`, а уведомление вызывается непосредственно при ошибке CLI.

Промпт теперь передаётся CLI через stdin. Скрипт также считает пустой результат ошибкой, записывает длительность запуска в локальный вывод и сообщает в stderr, если уведомление не удалось. `notify.sh` использует `curl -f`, чтобы HTTP-ошибка Telegram давала ненулевой код выхода. Реальная доставка Telegram и авторизация `claude` здесь не проверялись: по условию работа велась только внутри снимка, без внешних сервисов.

## Что пригодилось из заметки коллеги

- Проверка `launchctl print` и `StandardErrorPath`: она отделила факт запуска от результата работы и показала обе ошибки.
- Особенность zsh с `status`: это точное совпадение с причиной отсутствия уведомления.
- `USER` в `EnvironmentVariables`: подходит к ошибке `Not logged in` и отсутствующему `USER` в снимке окружения.
- Передача промпта через stdin, проверка реального результата и длительности: применены как защита от тихого или ложного успеха. Сам промпт в исходном скрипте уже передавался аргументом, поэтому считать его причиной ошибки в этом случае нельзя.

Совет добавлять `< /dev/null` при передаче промпта аргументом здесь не нужен: скрипт теперь передаёт промпт через stdin. Проверка `launchctl kickstart` и фактической доставки требует живой машины и внешнего сервиса; в снимке она не проводилась.

## Проверка изменений

`zsh -n`, `bash -n` и `plutil -lint` прошли. Локальные заглушки `claude` и уведомителя подтвердили три исхода: код 7 от агента даёт сообщение об ошибке и код 7, пустой результат даёт сообщение об ошибке и код 1, непустой результат даёт сообщение об успехе и код 0. Во всех трёх случаях промпт поступил через stdin.
