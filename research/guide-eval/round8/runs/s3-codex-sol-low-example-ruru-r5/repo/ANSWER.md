# Почему ночной обзор молчал

`launchctl-print.txt` показывает `runs = 6` и `last exit code = 1`: launchd запускал задачу по расписанию. Все шесть запусков оставили в `Library/Logs/nightly-review.err` одинаковую пару ошибок.

1. `claude` завершался с `Not logged in · Please run /login`. В окружении задачи из снимка `launchctl print` задан `PATH`, но нет `USER`. Для headless CLI это вероятная причина, по которой он не находил вход через keychain. Добавил `USER=vk` в plist; доступность авторизации на настоящем Mac нужно подтвердить отдельным запуском.
2. Сразу после ошибки скрипт выполнял `status=$?`. В zsh `status` доступна только для чтения, поэтому выполнение обрывалось до ветки с Telegram уведомлением. Заменил переменную на `rc`.

Теперь промпт передаётся `claude -p` через stdin, фиксируются код выхода и длительность работы, а пустой ответ считается ошибкой. При ошибке CLI или пустом результате скрипт отправляет сообщение об отказе. Добавил `curl -f` в уведомитель: HTTP ошибка Telegram теперь даёт ненулевой код выхода вместо ложного успеха.

Из заметки коллеги пригодились проверка `launchctl print` и stderr, правило о переменной `status` в zsh, передача промпта через stdin, `USER` в plist, учёт длительности и проверка реального результата. Совет закрывать stdin через `/dev/null` относится к варианту с промптом в аргументе и здесь не нужен. `launchctl kickstart` и настоящие Telegram/Claude запросы не запускались: это снимок домашней директории, а внешние обращения запрещены условиями задачи.

Локально проверены синтаксис zsh, корректность plist и три сценария с подменёнными командами без сети: успешный ответ, отказ CLI и пустой ответ. Во всех случаях получен ожидаемый код выхода и соответствующее уведомление от локальной заглушки.
