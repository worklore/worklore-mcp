# Почему ночная задача молчала

`launchd` исправно запускал задачу: в `launchctl-print.txt` записано `runs = 6`, расписание соответствует 02:30, а `last exit code = 1`. Пустой `nightly-review.out` не означал отсутствие запусков: фактические ошибки были в `Library/Logs/nightly-review.err`.

Были две причины, повторявшиеся на каждом запуске:

1. **Headless CLI не мог аутентифицироваться в контексте `launchd`.** В журнале шесть раз записано `Not logged in · Please run /login`. В `EnvironmentVariables` plist-файла был только `PATH`, но не было `USER`; без него CLI не находил сохранённый логин в keychain. Поэтому обзор не создавался.
2. **Обработчик ошибки сам аварийно завершался.** После вызова `claude` скрипт выполнял `status=$?`. В zsh `status` — специальная переменная только для чтения, поэтому присваивание завершало скрипт с ошибкой `read-only variable: status`. Это происходило до ветки, которая вызывает `notify.sh`, поэтому не отправлялось даже сообщение о сбое.

Таким образом, Telegram-notifier не был исходной причиной: до его вызова в аварийном пути скрипт просто не доходил.

# Исправления

- В `Library/LaunchAgents/com.vk.nightly-review.plist` добавлено `USER=vk` в `EnvironmentVariables`.
- В `bin/nightly-review.zsh` `status` заменено на обычную переменную `rc`; код ошибки `claude` теперь сохраняется, попадает в сообщение и возвращается из скрипта.
- Промпт передаётся в `claude -p` через stdin (`print -r -- "$PROMPT" | ...`), а не многострочным аргументом. Это профилактическое исправление для надёжного запуска без терминала, а не отдельная причина, видимая в имеющемся журнале.

# Что пригодилось из заметки коллеги

- Проверка `launchctl print`: число запусков и код выхода сразу показали, что планировщик работает.
- Чтение `StandardErrorPath` до построения догадок: журнал содержал обе фактические ошибки.
- Замена zsh-переменной `status` на `rc`.
- Добавление `USER` в окружение агента для доступа CLI к логину в keychain.
- Передача промпта через stdin и проверка как успешного, так и намеренно аварийного сценария.

Пункт про закрытие stdin через `< /dev/null` отдельно не потребовался: промпт теперь подаётся через stdin. Остальные советы из заметки не были причиной этого сбоя и не вносились.

# Проверка

- `/bin/zsh -n bin/nightly-review.zsh` — успешно.
- `plutil -lint Library/LaunchAgents/com.vk.nightly-review.plist` — успешно.
- Реальный `nightly-review.zsh` запущен с локальными заглушками `claude` и `notify.sh`: успешный сценарий создал файл обзора и уведомление; при смоделированном сбое `claude` с кодом 23 скрипт вернул 23 и создал уведомление `nightly review FAILED (exit 23)`.

Настоящие `claude`, keychain и Telegram не вызывались: это снимок домашней директории, а внешние отправки были запрещены. Изменения не загружались в действующий `launchd`.
