# События аналитики: регистрация и предложения

Все шесть событий из `docs/EVENTS.md` подключены через `Analytics.capture`
(`lib/analytics.dart`). Имена и свойства точно как в спецификации. Email и
телефон в свойства не попадают.

| Событие | Где | Когда срабатывает |
|---|---|---|
| `registration_email_started` | `registration_screen.dart`, `onChanged` поля Email | только при первом изменении, за флагом `_emailStartedFired` |
| `registration_phone_started` | там же, поле Phone | только при первом изменении, за флагом `_phoneStartedFired` |
| `loan_amount_changed` `{amount: int}` | `Slider.onChangeEnd` | один раз за протягивание, когда пользователь отпускает; `onChanged` только обновляет UI |
| `terms_accepted` | `CheckboxListTile.onChanged` | только когда галочку ставят (`true`), снятие не отправляется |
| `registration_continue_tapped` `{amount: int, terms: bool}` | `FilledButton.onPressed` | при нажатии, перед переходом на `/offers` |
| `offers_scrolled` `{offset: double}` | `offer_screen.dart`, `NotificationListener<ScrollEndNotification>` вокруг `ListView` | один раз в конце каждого жеста прокрутки, `offset = metrics.pixels`; учитывается только `depth == 0` |

Почему так: README пишет, что проект на бесплатном тарифе PostHog. Если
ставить capture в `onChanged` или в обновление скролла, событие уходит на
каждое нажатие клавиши, каждый шаг слайдера и каждый кадр прокрутки. Квота
так быстро кончается, а смысл событий в воронке от этого не меняется.

Проверка: `flutter analyze` показал "No issues found". Приложение я не
запускал и в PostHog ничего не отправлял.

## Что пригодилось из заметки коллеги
- Флаг «один раз» для текстовых полей (`bool _<field>InputFired`). Взял для
  `*_started`.
- Перенос события слайдера из `onChanged` в `onChangeEnd`.
- `ScrollEndNotification` вместо `ScrollUpdateNotification` или слушателя
  `ScrollController`.
- Правило не менять имена и свойства событий, потому что на них уже построены
  дашборды.

## Что не понадобилось
- Слушатели `FocusNode` для тапа/фокуса и для итогового значения при потере
  фокуса: в спецификации нет таких событий, а итоговые email/телефон
  отправлять нельзя (PII).
- Шаги проверки с `PostHogConfig.debug = true` и PostHog → Activity: я ничего
  не запускал и во внешний сервис не обращался. Если нужна такая проверка,
  можно временно включить `config.debug = true` в `Analytics.init` в
  debug-сборке.

## Открытые вопросы для продукта
- «Один раз» сейчас значит «за жизнь `State` экрана регистрации». Если
  перейти на предложения и вернуться назад, экран остаётся в стеке, поэтому
  `*_started` повторно не отправятся. Если «один раз» должно значить «за
  посещение» или «за установку», нужно решить отдельно.
- `terms_accepted` отправляется при каждой постановке галочки. Если
  пользователь снимет и снова поставит галочку, будет два события.
- `offers_scrolled` отправляется на каждый жест прокрутки, а не один раз за
  экран. Если для воронки достаточно одного события, можно добавить флаг.
