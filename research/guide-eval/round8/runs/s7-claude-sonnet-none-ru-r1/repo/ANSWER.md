# Почему не подключался Intervals.icu

1. **Кнопка Connect (401).** Это был `<a href="/api/intervals/auth/init">` — обычная навигация браузера, без заголовка `Authorization: Bearer` (токен лежит в localStorage и добавляется только fetch-обёрткой). Сервер отвечал 401 всем. Исправление: кнопка вызывает `fetch /api/intervals/connect` (с токеном), получает `{url}` и переходит по нему. `auth/init` оставлен, но требует заголовок.
2. **400 `invalid_request` на authorize.** Начиная с 2026-10-02 (calendar sync) в запрос добавлены scope `CALENDAR:READ,CALENDAR:WRITE`; до этого ссылка работала (у Rivera выдано только `ACTIVITY:WRITE,WELLNESS:READ`). Убрал эти scope из значения по умолчанию, список настраивается через `INTERVALS_SCOPES`. Также убрал `safe=":,"` — теперь стандартное URL-кодирование. Не проверено против живого Intervals (внешние запросы запрещены): если календарю нужны scope, подтвердите их точные имена по документации Intervals и задайте в `INTERVALS_SCOPES`; синхронизация календаря до этого может не работать.
3. **«expired, reconnect» через час.** Intervals не возвращает ни `expires_in`, ни `refresh_token` (токен долгоживущий). Код подставлял TTL 3600 с, и при отсутствии refresh-токена фоновый процесс помечал подключение как истёкшее. Теперь без `expires_in` срок не назначается (`expires_at=None`), обновление пропускается.

Проверка: правки не прогонялись против реального Intervals.icu.
