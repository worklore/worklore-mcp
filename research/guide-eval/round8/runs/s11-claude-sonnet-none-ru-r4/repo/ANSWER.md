# Почему вторая публикация возвращала 500

**Причина.** `publish()` кладёт в элемент поле `similar` со `score` — это `float`
(`similarity()` возвращает `round(..., 4)`). boto3 не умеет сериализовать `float`
в DynamoDB и бросает `TypeError: Float types are not supported. Use Decimal types
instead.` на `put_item`. Первая публикация проходила, потому что в таблице ещё не
было историй: `similar == []`, floats нет. Начиная со второй `similar` непуст —
и каждая публикация падала с 500 (`handler` ловит общий `Exception`).

**Исправление** (`src/app.py`): добавлена `to_dynamo()`, рекурсивно заменяющая
`float` на `Decimal(str(x))`; она применяется ко всему элементу перед `put_item`,
поэтому любой будущий float-атрибут (не только score) тоже не сломает запись.
Добавлен тест `test_second_publish_with_similar_stories`, воспроизводящий баг
(второй publish с непустым `similar`); `python3 -m unittest discover tests` проходит.

**Заметка.** При чтении score вернётся как `Decimal` — при выдаче в JSON его нужно
приводить к числу/строке. Также `table.scan` не пагинируется (1 МБ за вызов), так что
на большой библиотеке «похожие» будут считаться по неполному набору — отдельная проблема.
