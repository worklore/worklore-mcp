# Почему ночная задача молчала

`launchd` запускал задачу: в `launchctl-print.txt` указаны `runs = 6` и `last exit code = 1`. В `Library/Logs/nightly-review.err` шесть раз повторяются две строки:

```text
Not logged in · Please run /login
/Users/vk/bin/nightly-review.zsh:19: read-only variable: status
```

Причины были следующие:

1. **Headless CLI не мог использовать сохранённый логин.** В `EnvironmentVariables` plist-файла был только `PATH`, но не было `USER`. Поэтому вызов `claude` завершался с `Not logged in`, не создавая обзор.
2. **Обработчик ошибки сам падал до уведомления.** В zsh переменная `status` доступна только для чтения. Присваивание `status=$?` сразу после вызова `claude` завершало скрипт, поэтому ветка с `notify.sh` не выполнялась. Это объясняет отсутствие не только обзоров, но и сообщений об ошибках.
3. **Был дополнительный риск зависания.** Промпт передавался аргументом `claude -p`, а stdin оставался открытым. После восстановления входа CLI мог ждать ввод вместо завершения.

# Исправления

- В `Library/LaunchAgents/com.vk.nightly-review.plist` добавлено `USER=vk` в `EnvironmentVariables`.
- В `bin/nightly-review.zsh` `status=$?` заменено на `rc=$?`; ветка ошибки и выход используют `rc`.
- Вызову `claude -p "$PROMPT"` добавлено `< /dev/null`, чтобы он не ждал stdin.

# Что пригодилось из заметки коллеги

Пригодились проверка `launchctl print` вместо предположения, что задача не запускалась, чтение `StandardErrorPath`, замена `status` на `rc`, добавление `USER` и закрытие stdin при передаче промпта аргументом. Также применена идея намеренно вызвать ошибку и проверить уведомление о ней.

Передавать промпт через stdin не потребовалось: существующий способ передачи аргументом сохранён и дополнен `< /dev/null`. Логирование длительности не добавлялось, поскольку оно не устраняет найденные причины.

# Проверка

- `zsh -n bin/nightly-review.zsh` — успешно.
- `plutil -lint Library/LaunchAgents/com.vk.nightly-review.plist` — успешно; значение `EnvironmentVariables.USER` равно `vk`.
- Локальный прогон с заглушками `claude` и `notify.sh` подтвердил:
  - успешный запуск создаёт обзор и вызывает уведомление об успехе;
  - смоделированный сбой с кодом 23 вызывает уведомление об ошибке и возвращает код 23;
  - stdin вызова `claude` действительно подключён к `/dev/null`.

Настоящий агент `launchd`, Claude и Telegram не вызывались: проверка выполнена только внутри снимка, без развёртывания и обращений к внешним сервисам.
