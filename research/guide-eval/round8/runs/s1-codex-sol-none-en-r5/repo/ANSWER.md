# HR target generator fix

Changed `gen.py` to send an Intervals.icu workout `description` instead of a hand-built `workout_doc`. Each planned corridor is now written as a percentage range of LTHR, for example `88-93% LTHR`; repeat blocks and step labels are preserved. Steps with HR targets request `hr=1s` so Garmin uses instant HR targets.

The readback showed that Intervals stored the old `workout_doc` exactly as sent, but the watch displayed its own zone bands rather than the planned corridors. That readback did not prove the Garmin export used those JSON ranges. Intervals' [upload guide](https://forum.intervals.icu/t/uploading-planned-workouts-to-intervals-icu/63624) documents `description` as the workout-text input, and its [syntax guide](https://forum.intervals.icu/t/workout-builder-syntax-quick-guide/123701) documents `% LTHR` ranges and repeat blocks. An [Intervals forum response](https://forum.intervals.icu/t/events-created-via-api-with-workout-doc-the-web-download-produces-an-empty-fit-while-the-api-download-does-not-which-representation-feeds-device-sync/132326) also recommends the description field for API-created workouts. This avoids relying on the old JSON fields that the API accepted but the watch did not honor as an exact corridor. Absolute BPM is not used because the earlier attempt produced invalid watch values.

Updated `README.md` to describe the new output. Locally checked that the sample plan generates all four planned ranges, three repeats, and no `workout_doc`. No event was posted and the watch result remains unverified until a fresh workout is synced.
