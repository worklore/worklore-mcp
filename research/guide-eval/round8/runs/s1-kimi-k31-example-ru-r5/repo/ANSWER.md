# Исправление HR-диапазонов

В `gen.py` в функции `hr_target` ключ нижней границы диапазона заменён с `value` на `start`. Теперь цель имеет вид:

```json
{"units": "%lthr", "start": 68, "end": 75}
```

Изменение применяется ко всем HR-шагам, включая шаги внутри повторов. Проценты LTHR, длительности, названия и остальная структура события не изменены.

## Почему

`value` + `end` заставляют FIT-экспорт Intervals.icu создавать зонную HR-цель, которую часы привязывают к собственным зонам. Поэтому вместо запланированных коридоров на часах отображались их границы зон. `start` + `end` задают коридор Instant HR: Intervals пересчитывает проценты через сохранённый в Intervals LTHR, а часы показывают полученный диапазон в bpm без подгонки под локальные зоны.

## Что пригодилось из заметки коллеги

- Основной вывод о разнице между `value`/`end` и `start`/`end`: именно замена ключа устраняет привязку к зонам часов.
- Рекомендация сохранить `units: "%lthr"` и передавать проценты, а не абсолютные bpm: пересчёт должен выполнять Intervals по своему LTHR.

Советы по текстовому `description`, единицам дистанции и обозначениям зон не применялись: генератор не создаёт это поле, и они не относятся к исправлению HR-целей. Внешнее воспроизведение через API и синхронизацию часов не выполнялось.

## Проверка

Генератор запущен локально для `plans/tempo-run.json`. Полученное событие сравнено с `readback/event-184233-as-sent.json`: все четыре HR-цели содержат `start`/`end`, а остальные данные события совпадают с прежней версией. Отображение на часах локально не проверялось.
