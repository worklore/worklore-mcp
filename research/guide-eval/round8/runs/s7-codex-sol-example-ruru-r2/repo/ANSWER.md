# Исправление подключения Intervals.icu

## Причины

1. Кнопка была ссылкой на `GET /api/intervals/auth/init`. При переходе браузер не передаёт токен tricoach из `localStorage` в заголовке `Authorization`, поэтому каждый запрос получал 401. Это прямо видно в `logs/connect-attempt.log`.
2. После обхода кнопки URL авторизации содержал одновременно `ACTIVITY:READ` и `ACTIVITY:WRITE`, а также `CALENDAR:READ` и `CALENDAR:WRITE`. `:WRITE` уже включает чтение, поэтому повтор области вызывает ошибку `Duplicate scope`. В логе провайдер вернул 400 `invalid_request` до экрана согласия; повтор scope — причина, согласующаяся с этим ответом и появлением ошибки после добавления календаря. Отдельного подтверждения от провайдера в логе нет.
3. Успешный ответ с токеном у Rivera не содержал `expires_in` и `refresh_token`. Сервер подставлял срок в 3600 секунд, затем фоновая задача удаляла действующий access token и показывала `expired, reconnect`. Лог фиксирует именно этот переход; отзыва доступа атлетом не было.
4. Дополнительно `config.py` игнорировал рабочие значения OAuth-клиента и адреса callback из окружения. При запуске этого кода вне локальной среды оставались бы заглушки и `localhost`; логи не позволяют установить, повлияло ли это на описанные обращения.

## Что изменено

- Кнопка вызывает авторизованный `POST /api/intervals/auth/init` через общий `fetch` и переходит по возвращённому `authorize_url`.
- Scope теперь: `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`, без повторения областей.
- Обмен кода отправляет только `client_id`, `client_secret` и `code`. Токен хранится без искусственного срока и фонового обновления. При 401 от API токен очищается, статус предлагает подключиться заново.
- Подписанный `state` содержит назначение и ограничен 15 минутами. При повторном подключении callback отклоняет другой `athlete.id`.
- Конфигурация OAuth теперь читает `INTERVALS_CLIENT_ID`, `INTERVALS_CLIENT_SECRET`, `INTERVALS_REDIRECT_URI` и `APP_SECRET` из окружения; локальные значения по умолчанию оставлены для демонстрационного запуска. Ранее код всегда использовал заглушки и localhost, несмотря на упоминание рабочих значений в окружении в README.

## Что пригодилось из заметки коллеги

Пригодились описание передачи `Authorization` только через `fetch`, правило о повторяющихся scope, формат обмена кода и отсутствие срока/refresh-токена, а также обработка отзыва доступа по 401. Подход к `state` и проверке `athlete.id` тоже использован. Формат JWT не требовался: здесь уже был подписанный HMAC-параметр `state`; к нему добавлены назначение и проверка срока. Рекомендация шифровать токен при хранении на диске к этому демонстрационному серверу с хранилищем только в памяти не относится; реальное постоянное хранилище в репозитории отсутствует.

## Проверка

`python3 -m unittest -v test_intervals` — 5 тестов прошли. Проверены авторизованный POST, отсутствие повторных scope, поля обмена кода, callback и сохранение токена без срока, переход в `reconnect required` после 401, проверка `state` и несовпадения аккаунта. `python3 -m py_compile server.py config.py test_intervals.py`, `node --check static/app.js` и `git diff --check` также прошли. Тесты используют локальный HTTP-сервер и подмену ответов Intervals; реальные запросы к внешнему сервису не выполнялись. Сквозное подключение с настоящим аккаунтом остаётся непроверенным.
