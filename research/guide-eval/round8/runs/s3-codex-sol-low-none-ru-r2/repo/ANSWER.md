# Почему не приходили сообщения

`launchd` запускал задачу: снимок `launchctl print` показывает 6 запусков и последний код выхода 1. В `nightly-review.err` для каждого запуска повторяются две ошибки.

1. `claude -p` завершался с `Not logged in · Please run /login`. У фонового процесса нет доступной авторизации Claude. Вход, работающий в интерактивном терминале, нужно отдельно проверить для той же учетной записи и окружения, в которых запускается LaunchAgent; сам снимок не содержит данных для восстановления авторизации.
2. Сразу после этого скрипт пытался выполнить `status=$?`. В zsh `status` — специальная переменная только для чтения. Ошибка прерывала скрипт до вызова `notify.sh`, поэтому не приходило даже сообщение о неудаче.

В `bin/nightly-review.zsh` переменная заменена на `review_exit`. Вывод и ошибки Claude теперь сохраняются в файле результата, а при неудаче первые 300 байт ошибки включаются в уведомление. В `bin/notify.sh` добавлен `curl -f`, чтобы HTTP-ошибка Telegram приводила к ненулевому коду выхода, а не выглядела как успешная отправка.

Для успешного обзора необходимо восстановить авторизацию Claude в окружении фонового запуска. После этого можно проверить задачу на своем Mac. Содержимое этого снимка не позволяет выполнить такую проверку без обращения к внешним сервисам; здесь ничего не отправлялось и LaunchAgent не перезагружался.
