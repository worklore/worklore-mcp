# Причины и исправления

## Причины
1. **Кнопка Connect не работала ни у кого.** Это была ссылка `<a href="/api/intervals/auth/init">`. Переход по ссылке — обычная навигация страницы, а заголовок `Authorization` (токен из localStorage) отправляют только fetch/XHR. Сервер отвечал 401 `{"error":"unauthorized"}`.
2. **Вставка authorize-ссылки вручную давала 400 `invalid_request`.** В `SCOPES` одна и та же область была указана дважды: `ACTIVITY:READ,ACTIVITY:WRITE` и `CALENDAR:READ,CALENDAR:WRITE`. Права `:WRITE` уже включают `:READ`, поэтому Intervals отвечает ошибкой `Duplicate scope`. Тело 400 это не поясняет. Так сломалась схема «ссылку вставили в браузер», которой подключили Rivera, после релиза календаря 2026-10-02.
3. **Подключение Rivera «истекло» через час.** Токен Intervals.icu не истекает и не обновляется: в ответе нет `refresh_token` и `expires_in`. Код подставлял `DEFAULT_TOKEN_TTL = 3600`, а фоновый обновлятель через час помечал подключение как «expired, reconnect» и стирал рабочий токен. В логе видно: ровно через 3600 с после подключения; приложение в Intervals осталось подключённым.

## Что изменено
- `server.py`: `auth/init` теперь POST и возвращает JSON `{authorize_url}`. GET на этот путь больше не обслуживается.
- `static/app.js`: Connect — кнопка. Она делает авторизованный `fetch` POST и затем `window.location.assign(authorize_url)`.
- `config.py`: `SCOPES = ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`, каждая область указана один раз.
- `server.py`: убран искусственный TTL. Без `expires_in` токен считается бессрочным, и обновлятель его не трогает.
- `server.py`: на 401 от Intervals (токен отозван) подключение помечается «expired, reconnect», токен очищается, а клиент получает 409 вместо падения.

Проверка: запустил сервер локально. POST на `auth/init` вернул JSON с URL, в котором scope без дублей. Реальный OAuth-поток с Intervals.icu я не проходил: для этого нужны настоящие client_id и client_secret.

## Что пригодилось из заметки коллеги
- Пункт 4 (init должен быть POST, а редирект делает фронтенд) — применил, это основная причина.
- Пункт 2 (`Duplicate scope`) — применил. Набор областей взят из заметки: убрал `ACTIVITY:READ` и `CALENDAR:READ`.
- Пункт 1 (токен не истекает, нет refresh_token) — применил: убрал TTL и добавил ленивую обработку 401. Это подтверждают наши логи.
- Не менял:
  - Пункт 3 (обмен кода без `grant_type` и `redirect_uri`). В нашем логе обмен с этими полями прошёл успешно, поэтому оставил как есть.
  - Состояние `state` в виде JWT. Текущая HMAC-подпись уже содержит user id и TTL 15 минут.
  - Проверка совпадения athlete id при переподключении и шифрование токена в хранилище. Хранилище здесь в памяти. Для прода это стоит сделать отдельно.
