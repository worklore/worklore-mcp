# Почему nightly-review молчал

Задача запускалась (`runs = 6`, `last exit code = 1`), но падала и не могла об этом сообщить.

## Причины
1. **`claude -p` падал с «Not logged in · Please run /login»** (см. `nightly-review.err`). В окружении launchd нет `USER`, и CLI не находит логин в keychain. Агент не выполнял работу, выход ненулевой.
2. **`status=$?` в zsh** (`nightly-review.zsh:19`: «read-only variable: status»). `status` в zsh — read-only. Присваивание убивало скрипт до вызова `notify.sh`, поэтому уведомление об ошибке не отправлялось. Именно это сделало сбой беззвучным.

Побочно: `notify.sh` работал вручную, так что он не виноват. Время запуска в README 02:30 — совпадает с plist.

## Исправления
- `bin/nightly-review.zsh`: `status` → `rc`; `claude` запускается с `< /dev/null`; замерена длительность; уведомления не роняют скрипт (`|| echo ... >&2`); проверка, что вывод не пустой (exit 0 ≠ работа сделана).
- plist: добавлен `USER=vk` в `EnvironmentVariables`.

## Что пригодилось из заметки коллеги
- `launchctl print` + лог до теории (у вас уже были оба).
- Не присваивать `status` в zsh — `rc=$?` (точное попадание).
- `USER` в `EnvironmentVariables` (точное попадание — «Not logged in»).
- `< /dev/null` при промпте-аргументе; логирование длительности; проверка реального результата, а не только кода выхода.
- Не пригодилось: передача промпта через stdin (в вашем логе такой ошибки нет, промпт доходит как аргумент), время 16:50 и прочие детали другого случая.

## Что сделать вам
Перезагрузить агент: `launchctl bootout gui/$UID/com.vk.nightly-review; launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.vk.nightly-review.plist`, затем `launchctl kickstart -k gui/$UID/com.vk.nightly-review`. Проверьте: код 0, свежий файл `nightly-review-<дата>.md`, реалистичная длительность, сообщение в Telegram. Затем один раз сломайте скрипт нарочно и убедитесь, что приходит уведомление об ошибке. Я ничего не запускал и не отправлял; правки только в этой папке-снимке — перенесите их в домашнюю директорию. Если «Not logged in» останется, нужно проверить, что `claude` залогинен в keychain этого пользователя (`claude /login`).
