# Вторая публикация возвращает 500: float в DynamoDB

## Причина

В `src/app.py` функция `similarity()` возвращает `round(..., 4)`, то есть Python `float`.
`related()` кладёт этот score в `item["similar"]`, и item уходит в `table.put_item()`.

DynamoDB (boto3) не принимает Python `float`, отсюда
`TypeError: Float types are not supported. Use Decimal types instead.`

Почему первая публикация проходила: таблица была пустой, `existing == []`,
`related()` ничего не считал, `similar` был пустым списком, float не появлялся.
Баг существует только тогда, когда в таблице уже есть данные. Это совпадает с
`logs/error.log`: первый POST `201` (`similar=0`), второй `500`.

Тесты этого не ловили: `tests/test_publish.py` публиковал только в пустую таблицу.

Воспроизведено локально: после одной публикации вторая падает с той же ошибкой.

## Исправление

1. **Граница записи.** Добавлена `to_dynamo(value)` в `src/app.py`. Она рекурсивно
   заменяет каждый `float` на `Decimal(str(value))` (через `str`, чтобы не тянуть
   двоичный шум вроде `0.1000000000000000055…`). Вызов `put_item` теперь:
   `table.put_item(Item=to_dynamo(item))`.
   Внутренняя логика по-прежнему считает в float, конвертация только при записи.
   Поэтому любой будущий float в любом месте item будет покрыт, а не только `similar`.
2. **Тесты на заполненную таблицу.** В `tests/test_publish.py` добавлено:
   - `test_second_publish_with_existing_story_is_stored`: первая запись сидирует
     таблицу, вторая считает score и должна пройти, score должен быть `Decimal`;
   - `test_handler_publishes_twice_over_http_shape`: три публикации через `handler`
     с JSON-телом, ожидаем `201` каждый раз;
   - `test_to_dynamo_converts_nested_floats`: конвертация вложенных float.

## Как убедиться, что не повторится

- На исходном `app.py` новые тесты падают (2 ERROR, 1 FAIL), на исправленном проходят
  (4 теста, OK). Запуск: `python3 -m unittest discover tests`.
- `tests/fake_dynamo.py` уже отклоняет float так же, как boto3. Теперь тесты
  гарантированно доходят до записи с заполненной таблицей, поэтому такой float
  поймается до деплоя.

## Что взято из заметки коллеги

- **Использовано:** идея, что тест должен сидировать таблицу и делать вторую запись
  (это главный новый тест); перевод в `Decimal` на границе записи, а не точечно;
  поиск `round(` и `/` в коде, формирующем item (нашлись только в `similarity()`).
- **Не использовано:**
  - целые проценты вместо `Decimal` (работает, но теряет точность score; `Decimal` проще);
  - «публиковать дважды против реальной таблицы» — у меня нет доступа к AWS, а по правилам
    задачи ничего нельзя публиковать и деплоить. Это нужно сделать вам в staging после
    деплоя.

## Что не делалось

- Ничего не деплоилось, не публиковалось, никуда ничего не отправлялось.
- `logs/error.log` не менялся.
- Изменения не закоммичены.
