# Что изменено

В `bot.py` функция `build_system()` теперь возвращает два системных блока вместо одного:

1. `INSTRUCTIONS` — неизменные инструкции, без даты, имени, профиля и других подставляемых значений.
2. `athlete_context(a, today)` — изменяемый контекст: дата, профиль, зоны, цель, долговременные факты и язык.

Оба блока имеют `cache_control: {"type": "ephemeral"}`. Поэтому `save_fact` меняет только второй блок и его кеш, а байт-стабильный префикс со статическими инструкциями остаётся пригодным для чтения из кеша. Состав инструментов, их фильтрация и загрузка всех фактов не менялись.

В `README.md` обновлено описание кеширования в соответствии с новой структурой промпта.

# Что пригодилось из заметки

- Объяснение префиксного кеширования: изменение одного общего блока раньше делало промахом весь системный промпт после `save_fact`.
- Основное решение: две точки `cache_control` — после статических инструкций и после изменяемого контекста.
- Требование байт-стабильности статической части и инструментов; существующую фильтрацию инструментов оставил без изменений.
- Предупреждение против выбора top-N фактов для каждого сообщения: такую персонализацию не добавлял, чтобы не менять кешируемый хвост на каждый запрос.
- Поля `cache_creation_input_tokens` и `cache_read_input_tokens` использовал для подтверждения исходной проблемы по `logs/usage.jsonl`.

# Проверка

Локально прогнал полный цикл `reply()` с имитатором Claude: `save_fact`, второй раунд того же ответа и следующее сообщение. Во всех трёх запросах первый блок остался байт-стабильным, а новый факт изменил только второй. Также проверено, что статический блок одинаков для разных атлетов и что список инструментов не меняется между раундами. Запросы к внешнему API не выполнялись, файлы данных и журнал usage при проверке не изменялись.
