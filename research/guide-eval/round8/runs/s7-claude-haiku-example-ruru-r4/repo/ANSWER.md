# Intervals.icu: почему не подключались и что исправлено

## Причины

1. **Кнопка Connect возвращала 401 всем.** Это была `<a href="/api/intervals/auth/init">`,
   то есть навигация страницы по GET. Браузер при навигации не шлёт заголовок
   `Authorization`, который SPA держит в `localStorage` (лог 1, тикет #214).

2. **Authorize отвечал 400 `invalid_request`.** Scope содержал две пары, где
   `:WRITE` уже включает `:READ`: `ACTIVITY:READ,ACTIVITY:WRITE` и
   `CALENDAR:READ,CALENDAR:WRITE`. Ошибка началась после добавления календаря
   2 октября (лог 2, тикет #219). Это **гипотеза**, а не доказанный факт: тело
   ответа у нас `{"error":"invalid_request"}`, а не текст «Duplicate scope» из
   заметки коллеги. Живой Intervals я не проверял (по правилам ничего наружу не
   отправляю), поэтому подтвердить можно только проверкой на реальном аккаунте.

3. **«Переподключитесь» через час — наш баг.** Intervals не присылает
   `expires_in` и `refresh_token`, а код подставлял `expires_in = 3600` сам.
   Фоновый refresher через ~55 минут помечал токен `expired, reconnect`
   (лог 3: подключено 17:41:04, expired 18:37:12). Токен у провайдера не
   истекает, так что этой логики быть не должно.

4. **Отзыв токена не обрабатывался.** Если атлет отзывал приложение в
   Intervals, API отдавал 401, а статус в tricoach оставался `connected`.

## Что изменено

- `static/app.js`: кнопка `<button id="connect">`. По клику идёт
  `POST /api/intervals/auth/init` через `api()` (с заголовком), затем
  `window.location.assign(authorize_url)`.
- `server.py`:
  - `auth/init` стал `POST` и возвращает `{authorize_url}` JSON.
  - Убраны `DEFAULT_TOKEN_TTL`, `expires_at`, `refresh_token`, поток refresher.
  - При 401 от Intervals на `wellness` токен очищается, статус становится
    `expired, reconnect`, ответ 409. SPA показывает кнопку «подключиться» со статусом.
- `config.py`: `SCOPES = "ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE"`
  (одна запись на область; `REFRESH_INTERVAL` удалён).

Код exchange (`grant_type`, `redirect_uri`) не менял: по логу 3 он работает.

## Что взято из заметки коллеги

- **Взято:** POST для init с возвращением `authorize_url` (пункт 4 заметки) —
  именно так и исправлена кнопка. Правило «один scope на область, `:WRITE`
  без `:READ`» (пункт 2). Токен без `refresh_token` / `expires_in` и
  ленивая обработка 401 (пункт 1). `athlete.id` из ответа token-эндпоинта
  уже использовался.
- **Не взято:**
  - JWT для `state`: у нас уже HMAC-подпись с user_id и TTL 15 минут, это
    эквивалент. Менять незачем.
  - Проверка совпадения аккаунта при повторном подключении: это вопрос
    политики (разрешать ли смену аккаунта Intervals), решите сами.
  - Упрощение exchange-запроса до трёх полей: текущий работает, а коллега
    пишет только о том, что эти поля не обязательны.

## Проверка

- Локально, против мока Intervals на `127.0.0.1` (мок реализовал правила
  из заметки: дубли scope → 400, без `refresh_token`/`expires_in`, 401 на
  отозванный токен). Пройдено: `POST init` → authorize → callback (302 на
  `/?connected=1`) → status `connected` → wellness 200 → после отзыва
  wellness 409 и status `expired, reconnect` → повторный `POST init` работает.
- Старый GET `/api/intervals/auth/init` теперь 404. `POST` без токена даёт 401.
- Старый scope на моке даёт 400, новый проходит.
- `node --check static/app.js` — синтаксис в порядке.

**Не проверено:** реальный клик в браузере и живой Intervals.icu. Нужно пройти
поток с реальным аккаунтом и с реальным `client_id`/`client_secret`.
