# Исправление кеширования: save_fact больше не вытесняет статические инструкции

## Причина

`build_system()` собирал весь системный промпт (инструкции + контекст атлета) в один
текстовый блок с единственным маркером `cache_control: ephemeral`. Кеш Anthropic — это
хеш по префиксу: `save_fact` дописывал факт в конец блока, менялся хеш всего блока, и
пересозданию подлежали ~1000+ токенов вместо ~15 новых. В `logs/usage.jsonl` это видно
прямо: каждый вызов сразу после `save_fact` имеет `cache_read_input_tokens: 0` и
`cache_creation_input_tokens` размером с весь промпт.

## Что изменил

**bot.py, функция `build_system()`** — теперь системный промпт состоит из двух блоков,
у каждого свой маркер `cache_control: {"type": "ephemeral"}`:

1. Блок 1 — `INSTRUCTIONS` (константа модуля, байтово-идентична для всех атлетов
   и дат). Ничего интерполированного в него не добавлено.
2. Блок 2 — `athlete_context()`: дата, профиль, зоны, цель, факты, язык.

Запись в память меняет только блок 2, поэтому статический префикс (инструменты +
инструкции) остаётся в кеше, а пересоздаётся лишь «хвост» (~240 токенов). Два маркера —
в пределах лимита Anthropic (4 на запрос). Инструменты, фильтрацию по ключевым словам
и `athlete_context()` не трогал.

## Проверка

Реальный API не вызывал (правила запрещают внешние сервисы), проверял свойства кода:

- `python3 -m py_compile bot.py` — синтаксис в порядке.
- Блок 1 байтово одинаков для разных атлетов и разных дат; блок 2 содержит профиль
  и факты и меняется при их изменении.
- Сквозной прогон `reply()` с фейковым LLM: первый раунд вызывает `save_fact`,
  второй — нет. Статический блок в обоих раундах идентичен, «хвост» изменился и
  содержит новый факт; факт сохранился в `data/athletes.json`.

Данные и лог после проверки восстановлены, `git status` показывает только правку `bot.py`.
После деплоя стоит сверить `cache_creation_input_tokens`/`cache_read_input_tokens`
в `logs/usage.jsonl`: после `save_fact` создание кеша должно быть размером с «хвост»,
а чтение — покрывать статический блок.

## Заметка коллеги: что пригодилось

- **Главный приём — два `cache_control: ephemeral` маркера** (статические инструкции /
  изменчивый «хвост»). Применён как есть.
- **Принцип «отказаться от топ-N выборки фактов»** — не внедрял (и не планирую):
  подгружать все факты каждый раз, иначе «хвост» будет отличаться от сообщения
  к сообщению и кеш «хвоста» не будет попадать никогда.
- **Байтовая стабильность всего, что выше маркера** (в т.ч. массива инструментов) —
  учтено: блок 1 проверяется на идентичность между вызовами.
- **Читать `cache_creation_input_tokens` / `cache_read_input_tokens` для верификации** —
  учтено в рекомендации выше.
- **Фильтрация инструментов по ключевым словам** — уже была в проекте (с марта,
  по заметке в NOTES.md), оставлена без изменений; осознанно принят её побочный
  эффект: сообщение с новой группой инструментов перечитывает префикс один раз.

Пропущено как неприменимое: упоминания MCP и Telegram-транспорта (в этом репозитории
только вызов API), «success story» детали вроде точных цифр токенов коллеги.
