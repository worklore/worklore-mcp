# Причины и исправление Intervals.icu

1. Кнопка была ссылкой на `GET /api/intervals/auth/init`. Переход страницы не передаёт `Authorization: Bearer` из SPA, поэтому сервер отвечал `401` всем атлетам. Теперь кнопка делает авторизованный `POST` через `fetch`, получает `authorize_url` и перенаправляет браузер на него.
2. Запрашивались `ACTIVITY:READ` вместе с `ACTIVITY:WRITE` и `CALENDAR:READ` вместе с `CALENDAR:WRITE`. Для Intervals.icu `:WRITE` уже включает чтение, а повтор области вызывает `Duplicate scope`. Оставлены `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`. Записанный в логе `invalid_request` сам по себе не указывает точный параметр; вывод о повторе областей опирается также на заметку коллеги и содержимое URL из лога.
3. Ответ токена в логе не содержит `refresh_token` и `expires_in`, но код назначал срок в 3600 секунд и фоновый процесс помечал рабочее подключение как истёкшее. Удалены искусственный срок и попытки обновления. При `401` от API токен очищается, а интерфейс предлагает подключиться заново.
4. Клиентская конфигурация OAuth была захардкожена, хотя README указывает на значения из окружения. `CLIENT_ID`, `CLIENT_SECRET`, `REDIRECT_URI` и секрет подписи state теперь читаются из переменных `INTERVALS_CLIENT_ID`, `INTERVALS_CLIENT_SECRET`, `INTERVALS_REDIRECT_URI`, `APP_SECRET`; локальные значения остались значениями по умолчанию для разработки.

Из заметки пригодились: схема `POST` для init с `{authorize_url}`, правило об уникальных областях scope, поля обмена кода (`client_id`, `client_secret`, `code`), отсутствие refresh-токена и обработка отзыва по `401`. Callback остаётся без заголовка авторизации: подписанный `state` несёт идентификатор пользователя, назначение и время создания, проверяется в пределах 15 минут. Добавлена проверка, что при повторном подключении `athlete.id` совпадает с ранее привязанным.

Проверка: `python3 -m unittest -v test_intervals.py` — три локальных теста HTTP-потока, срока и назначения state, защиты от смены атлета и реакции на `401`. Реальный OAuth и запрос к Intervals.icu не запускались согласно ограничению на внешние сервисы. В этом репозитории соединения хранятся только в памяти; для постоянного хранилища токен должен быть зашифрован, как советует заметка.
