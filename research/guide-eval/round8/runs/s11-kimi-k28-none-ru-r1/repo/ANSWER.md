# Почему вторая публикация возвращала 500

## Причина

`similarity()` в `src/app.py` возвращала Python-`float` (`round(0.7 * tag_score + 0.3 * word_score, 4)`).

- **Первая публикация** успешна, потому что таблица пуста: `related()` возвращает
  пустой список, и ни одного числа с плавающей точкой в записи нет.
  `put_item` проходит, ответ 201 (см. `logs/error.log`, 09:14).
- **Вторая публикация**: в таблице уже есть запись, `related()` кладёт в поле
  `similar` элементы вида `{"slug": ..., "score": 0.05xx}` — со score типа `float`.
  boto3 (`TypeSerializer` / `dynamodb/types.py`) не умеет сериализовать `float`
  и бросает `TypeError: Float types are not supported. Use Decimal types instead.`
  (строка 25 лога). Исключение доходит до `handler()`, который возвращает 500.

То есть баг проявлялся только при наличии хотя бы одной похожей истории
в таблице — то есть всегда начиная со второй публикации.

## Исправление

`src/app.py`, функция `similarity()`: счёт ведётся в `Decimal`, результат —
`Decimal`, округлённый до 4 знаков (`quantize(Decimal("0.0001"))`), как и раньше.
Это тип чисел, который принимает DynamoDB, поэтому в записи больше не появляется
`float`. Коэффициенты записаны строками (`Decimal("0.7")`), чтобы избежать
артефактов двоичного представления float.

В `tests/test_publish.py` добавлены регрессионные тесты:

- `test_second_publish_stores_decimal_scores` — вторая публикация проходит,
  в таблице 2 записи, все score в `similar` имеют тип `Decimal`;
- `test_handler_returns_201_on_second_publish` — две публикации подряд через
  `handler()` обе возвращают 201.

## Проверка

`python3 -m unittest discover tests` — 3 теста, все проходят.
