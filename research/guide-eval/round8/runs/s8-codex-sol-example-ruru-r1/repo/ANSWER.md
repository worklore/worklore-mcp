# Исправление кеширования

В `bot.py` системный промпт разделён на два текстовых блока с `cache_control: ephemeral`. Первый содержит одинаковые для всех запросов правила и пояснение формата профиля; второй — дату, профиль и долговременные факты спортсмена. После `save_fact` меняется только второй блок, поэтому кеш статического префикса может использоваться снова. Пояснение формата добавлено к постоянному блоку, поскольку при двух базовых инструментах исходные инструкции могли быть короче минимального кешируемого префикса Claude (1024 токена).

Из заметки пригодились разделение по стабильности на два маркера, сохранение всех фактов в контексте и проверка полей `cache_creation_input_tokens` / `cache_read_input_tokens`. Фильтрацию инструментов по ключевым словам и их порядок не менял: она уже есть в проекте и, согласно `NOTES.md`, снижает расход на коротких сообщениях. Отбор фактов под конкретное сообщение не добавлял, чтобы не менять кешируемый хвост при каждом запросе.

Локально проверено: `python3 -m unittest -v test_cache` и `python3 -m py_compile bot.py test_cache.py` проходят. Тест подтверждает, что после записи факта первый блок остаётся неизменным, второй обновляется, а следующий запрос получает новый факт. Исторический `logs/usage.jsonl` не менялся. Фактические счётчики кеша после правки нельзя подтвердить без вызова Anthropic API; такой вызов не выполнялся. Вызовы с другим набором инструментов по-прежнему могут создавать отдельный кешированный префикс.
