# ANSWER

## Проблема

`build_system` в `bot.py` собирал инструкции и контекст атлета в один текстовый
блок с единственным маркером `cache_control: ephemeral`. Промпт-кеш Anthropic
работает как хэш префикса: `save_fact` дописывает факт в хвост блока, хэш
меняется, и вытесняется всё — включая неизменные инструкции. В `logs/usage.jsonl`
это видно прямо: после каждого вызова `save_fact` следующий раунд имеет
`cache_read_input_tokens: 0` и `cache_creation_input_tokens` ~1046–1334 (весь
промпт по полной цене). Бонусный эффект того же бага: хвост атлета лежал в одном
блоке с инструкциями, поэтому даже переключение между двумя атлетами вытесняло
инструкции целиком.

## Изменения

- `bot.py` — `build_system` теперь возвращает **два** блока, у каждого свой
  `cache_control: {"type": "ephemeral"}`:
  1. Статические `INSTRUCTIONS` — константа модуля, байт-в-байт одинаковая для
     всех атлетов и дат.
  2. `"\n\n" + athlete_context(a, today)` — изменчивый хвост (дата, имя, зоны,
     цель, факты, язык). Разделитель `\n\n` сохранён, чтобы итоговый текст
     промпта не изменился.
- `README.md` — фраза про промпт-кеш приведена в соответствие (два сегмента вместо
  одного маркера).

Ничего больше не тронуто: фильтрация инструментов по ключевым словам оставлена
как есть (по NOTES.md это отдельный выигрыш марта).

## Ожидаемый эффект

Запись в память теперь пересоздаёт кеш только для хвоста (~250 токенов) вместо
всего промпта (~1000+). Сигнатура в `logs/usage.jsonl` после `save_fact` должна
стать: `cache_read_input_tokens` ≈ размер блока инструкций (он остаётся горячим),
`cache_creation_input_tokens` ≈ размер хвоста. Инструкции теперь общие для всех
атлетов, так что блок инструкций попадает в кеш и при переключении между
пользователями. Известное ограничение (унаследованное, не лечится этим фиксом):
селекция инструментов сидит в префиксе выше системного промпта, сообщение,
подтягивающее дополнительную группу инструментов (`plan_week`, `predict_race`),
перечитывает префикс один раз; внутри одного сообщения список инструментов
постоянен, а там кеш окупается сильнее всего.

## Проверка

- `python3 -m py_compile bot.py` — синтаксис в порядке.
- Прогон `reply()` с фейковым LLM (без сети и ключа; запись в лог и в
  `data/athletes.json` отключена) — проверено:
  - системный промпт — два блока, у каждого маркер `cache_control`;
  - блок инструкций байт-идентичен до и после `save_fact`, а также между
    атлетами и датами; в нём нет интерполированных значений;
  - хвост меняется после `save_fact` и содержит новый факт;
  - массив инструментов постоянен между раундами одного сообщения.
- Реальный вызов API сознательно не выполнялся (правило «ничего не отправлять во
  внешние сервисы»), поэтому ожидаемую сигнатуру `cache_read`/`cache_creation` в
  `logs/usage.jsonl` стоит подтвердить на реальном трафике.

## Что пригодилось из заметки коллеги

- **Главный фикс — дословно:** два сегмента `cache_control` вместо одного;
  сегмент 1 — статические инструкции (без интерполированных дат, имён, счётчиков),
  сегмент 2 — весь изменчивый хвост. Применено как есть.
- **Рецепт верификации по `usage`:** смотреть `cache_creation_input_tokens` и
  `cache_read_input_tokens`; после записи в память `cache_creation` должен быть
  размера хвоста, а не всего промпта. Использован как критерий приёмки.
- **Требование байт-стабильности всего, что выше кешируемых блоков:** проверено —
  `select_tools` детерминирован (постоянные `CORE_TOOLS`, фиксированный порядок
  групп), менять не понадобилось.
- **«Сопротивляться персонализации» (top-N фактов):** применено по смыслу — в
  текущем коде всегда инжектируются все факты, что правильно для кеша; менять не
  пришлось. Порядок хвоста оставлен как есть (факты и так в конце).
- **Не пригодилось:** фильтрация инструментов по группам — в этом репозитории она
  уже реализована (март), оставлена без изменений; сведения про MCP/Telegram и
  лимит в 4 маркера — к текущему коду не относятся, маркеров стало 2.
