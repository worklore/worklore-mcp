# Почему задача молчала

`launchd` запускал агент: снимок `launchctl print` показывает 6 запусков и последний код завершения 1. Расписание и пути stdout/stderr в plist работают. В `Library/Logs/nightly-review.err` после каждого запуска повторяются две строки:

1. `Not logged in · Please run /login` — `claude` не авторизован в окружении, доступном ночному агенту. Поэтому обзор не создавался.
2. `read-only variable: status` — в zsh `status` является специальной переменной только для чтения. Присваивание `status=$?` останавливало скрипт до проверки ошибки и вызова `notify.sh`. Поэтому даже сообщение об ошибке не отправлялось.

# Исправления

- В `bin/nightly-review.zsh` код выхода сохраняется в `review_status`; при ошибке `claude` вызывается уведомление, а при ошибке самого уведомления пишется сообщение в stderr. То же сделано для уведомления об успешном обзоре.
- В `bin/notify.sh` ошибка чтения токена из Keychain теперь явно пишется в stderr; `curl -f` возвращает ошибку при HTTP 4xx/5xx.

Для получения **самого обзора** нужно авторизовать `claude` для того же пользователя и окружения, в котором работает LaunchAgent. Из снимка нельзя определить, почему его авторизация недоступна, или восстановить ее без учетных данных. После авторизации стоит проверить запуск вручную в таком же окружении и посмотреть `Library/Logs/nightly-review.err`. Если сообщение об ошибке после исправления не придет, этот лог покажет, удалось ли фоновому процессу прочесть токен `tg-bot` из Keychain. Никаких запусков с обращением к Claude или Telegram в этом снимке не выполнялось.
