# События аналитики: регистрация и список предложений

Все события из `docs/EVENTS.md` отправляются через `Analytics.capture`
(`lib/analytics.dart`). Обёртку я не менял. Имена событий и свойства совпадают
со спецификацией. Email и телефон в свойства не попадают (PII).

| Событие | Где | Когда срабатывает |
|---|---|---|
| `registration_email_started` | `registration_screen.dart`, `onChanged` поля Email | при первом символе, **один раз за жизнь экрана** (флаг `_emailStartedFired`) |
| `registration_phone_started` | `registration_screen.dart`, `onChanged` поля Phone | так же, флаг `_phoneStartedFired` |
| `loan_amount_changed` `{amount: int}` | `Slider.onChangeEnd` | один раз за протягивание или тап, когда пользователь отпускает. `onChanged` по-прежнему только обновляет UI |
| `terms_accepted` | `CheckboxListTile.onChanged` | только когда галочку ставят (`true`). Снятие галочки не отправляется |
| `registration_continue_tapped` `{amount: int, terms: bool}` | `FilledButton.onPressed` | перед переходом на `/offers` |
| `offers_scrolled` `{offset: double}` | `offer_screen.dart`, `NotificationListener<ScrollEndNotification>` вокруг `ListView` | один раз за жест скролла, когда список остановился. `offset` — это `metrics.pixels`. Учитываются только уведомления самого списка (`depth == 0`) |

Проверка: `dart format` и `flutter analyze` — без замечаний. На устройстве не
запускал: из песочницы нет ни устройства, ни реального ключа PostHog.

## Что пригодилось из заметки коллеги

Проект на бесплатном тарифе PostHog (сказано в README), а очевидные места для
событий — `onChanged` полей, слайдера и обновления скролла. Это ровно сценарий
из заметки. Если бы я подключил события туда, ввод email давал бы около 20
событий, протягивание слайдера (49 делений) — десятки, скролл — событие на
каждый кадр.

Пригодилось:
- **Текстовые поля:** флаг «один раз за посещение» в состоянии экрана
  (`bool _emailStartedFired`). Это совпадает и со смыслом спецификации:
  «started typing».
- **Слайдер:** событие в `onChangeEnd`, а не в `onChanged`.
- **Скролл:** `ScrollEndNotification` вместо обновлений скролла или слушателя
  `ScrollController`.
- **Правило не трогать имена событий и свойства,** чтобы готовые дашборды и
  воронки работали.
- **Проверка из заметки:** grep по `onChanged` / `addListener` / скролл-нотификациям
  и чтение каждого коллбэка. Я сделал её мысленно по своему диффу: каждый
  capture внутри частых коллбэков стоит за флагом или в «конечном» обработчике.

Не пригодилось или пропущено:
- Слушатель `FocusNode` для событий тапа/фокуса и для итогового значения при
  потере фокуса. В спецификации нет событий фокуса, и ни одному событию не
  нужно итоговое значение поля.
- Вопрос «один раз за посещение или за весь поток» решил так. Флаги живут в
  `State` экрана регистрации. Маршрут `/` остаётся в стеке под `/offers`, и
  при возврате «назад» состояние то же, поэтому повторно `*_started` не
  придут. На деле это «один раз за запуск экрана», то есть за проход воронки.
  Для воронки «начал → продолжил» это как раз нужно.
- Проверка через `PostHogConfig.debug = true` и PostHog → Activity. Это
  требует запуска на устройстве и отправки в PostHog, а работать с внешними
  сервисами запрещено. Стоит сделать вручную перед релизом.

## Решения, которые стоит подтвердить продукту

- `terms_accepted` отправляется при каждой постановке галочки. Если
  пользователь щёлкает её туда-сюда, будет несколько событий. Объём небольшой
  (это дискретные тапы), но при желании легко ограничить одним разом, как поля.
- `offers_scrolled` отправляется на каждый завершённый жест скролла, а не один
  раз за экран. Так `offset` показывает, докуда дочитали. Если для воронки
  нужен только факт скролла, можно добавить флаг «один раз».
