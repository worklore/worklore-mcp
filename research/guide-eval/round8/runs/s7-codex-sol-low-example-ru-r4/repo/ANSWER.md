# Intervals.icu: причины и исправление

1. Кнопка была ссылкой на `GET /api/intervals/auth/init`. При переходе браузер не отправляет `Authorization` из `localStorage`, поэтому запрос получал 401. Теперь кнопка вызывает авторизованный `POST` через `fetch`, получает `authorize_url` и перенаправляет браузер.
2. URL авторизации запрашивал `ACTIVITY` и `CALENDAR` одновременно с `READ` и `WRITE`. Для Intervals.icu это дублирование области доступа; `WRITE` уже включает `READ`. Оставлены `ACTIVITY:WRITE,WELLNESS:READ,CALENDAR:WRITE`.
3. Ответ токена в логе не содержал `expires_in` и `refresh_token`. Код выдумывал срок 3600 секунд и затем принудительно разрывал соединение. Удалены фиктивный срок и обновление токена. При ответе API 401 токен очищается и статус требует переподключения.

Из заметки коллеги пригодились пункты о POST для инициализации, уникальных областях доступа, обмене кода только с `client_id`, `client_secret`, `code`, бессрочном токене и обработке 401. Также добавлены проверка срока и подписи `state` и защита от подключения другого Intervals-атлета при повторной авторизации. Предложение хранить токен зашифрованным относится к постоянному хранилищу; в этом репозитории соединения хранятся только в памяти. JWT из заметки не потребовался: существующий подписанный `state` уже передаёт ID пользователя через callback. Реальную авторизацию с Intervals.icu здесь не проверяли: в `config.py` стоят тестовые OAuth-реквизиты, а внешние запросы запрещены условиями задачи.
