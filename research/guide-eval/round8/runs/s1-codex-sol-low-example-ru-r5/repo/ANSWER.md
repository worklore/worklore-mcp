# Исправление HR-коридоров

В `gen.py` нижняя граница каждой HR-цели теперь записывается в `start` вместо `value`: `{"units": "%lthr", "start": low, "end": high}`. Формат плана и проценты LTHR не менялись. По заметке коллеги `value` вместе с `end` экспортируется как цель, привязанная к зонам Garmin, что согласуется с `readback/watch-notes.md`: часы показывали границы собственных зон вместо запланированных диапазонов. `start` вместе с `end` задаёт точный коридор Instant HR.

Из заметки пригодились различие между `value/end` и `start/end` и рекомендация оставить `%lthr`, чтобы Intervals вычислял bpm по своему LTHR. Попытки с `bpm` и `start_bpm/end_bpm` подтверждают уже записанные в readback неудачные результаты, поэтому эти варианты не использованы. Советы о текстовом `description` и грамматике шагов не относятся к этому дефекту: в сохранённом ответе API `workout_doc.steps` уже заполнен; проблемы отображения шагов в веб-интерфейсе не заявлено.

Проверка: локальный запуск генератора для `plans/tempo-run.json` подтвердил `start/end` и `%lthr` для всех четырёх HR-целей, включая шаги внутри повтора. Синхронизация с часами и проверка фактических bpm не проводились: по условию запроса ничего не отправлялось во внешние сервисы.
