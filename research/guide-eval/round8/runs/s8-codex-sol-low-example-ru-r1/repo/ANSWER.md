# Исправление кеширования

В `bot.py` функция `build_system` теперь отправляет два текстовых блока с `cache_control: ephemeral`: сначала неизменные `INSTRUCTIONS`, затем контекст спортсмена с датой, профилем и долговременными фактами. После `save_fact` меняется только второй блок; первый сохраняет тот же текст и может читаться из кеша. Состав и порядок инструментов не менялись.

В `logs/usage.jsonl` прежние вызовы после `save_fact` имеют `cache_read_input_tokens: 0` и повторно создают кеш примерно на 1000 токенов. Локальная проверка подтвердила, что добавление факта меняет только второй блок запроса, оба блока имеют маркер кеширования, а выбор инструментов остается прежним. Синтаксис Python также проверен. Фактическую экономию по API не измерял: внешние вызовы запрещены условиями задачи.

Из заметки коллеги пригодились разделение статических инструкций и изменяемого контекста на два кешируемых блока и проверка счетчиков `cache_creation_input_tokens` / `cache_read_input_tokens`. Идеи о выборе top-N фактов и изменении фильтрации инструментов не применялись: здесь факты уже передаются целиком, а существующую фильтрацию сохраняем.
