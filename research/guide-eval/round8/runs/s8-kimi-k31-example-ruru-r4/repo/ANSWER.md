# Исправление кеширования

В `bot.py` функция `build_system()` теперь возвращает два системных блока вместо одного:

1. Статический `INSTRUCTIONS` с собственным `cache_control: {"type": "ephemeral"}`.
2. Изменчивый контекст атлета (дата, профиль, зоны, цель, факты и язык) с отдельным таким же маркером.

После `save_fact` меняется только второй блок. Текст инструкций остаётся байт в байт прежним, поэтому запись в память больше не должна вытеснять его из кеша. В `README.md` обновлено описание этой схемы кеширования.

Проверка выполнена локально с имитированным LLM через полный цикл `reply()`: после `save_fact` второй запрос сохранил идентичный первый блок, изменил только контекст атлета и оставил список инструментов неизменным. Обе итерации по-прежнему записываются в usage-лог. Реальные запросы к Anthropic не отправлялись.

# Что пригодилось из заметки

- Основное решение: два сегмента `cache_control` — отдельно для стабильных инструкций и изменчивых данных пользователя.
- Требование держать статический блок стабильным байт в байт и не помещать в него даты, имена или память.
- Проверка по `cache_creation_input_tokens` и `cache_read_input_tokens`: после записи факта чтение из кеша должно покрывать статический блок, а пересоздание — только изменчивый хвост.
- Рекомендация не менять список инструментов внутри одного цикла вызовов; существующая фильтрация инструментов сохранена.

Отбор top-N фактов и изменение агрессивности фильтрации инструментов не применялись: они не нужны для этого исправления и могут ухудшить попадания в кеш.
