# Причина

При первой публикации таблица пуста, поэтому `related()` возвращает пустой список. Начиная со второй публикации `similarity()` вычисляла `score` как Python `float` и помещала его в `similar`. В `logs/error.log` ошибка возникает на `table.put_item(Item=item)`: сериализатор boto3 не принимает `float` (`TypeError: Float types are not supported`). Обработчик превращал эту ошибку в HTTP 500.

# Исправление

Расчёт сходства теперь целиком использует `Decimal`, включая деление, веса и округление до четырёх знаков. В сохраняемом `similar[].score` больше не появляется `float`; формат оценки от 0 до 1 сохранён.

Добавлен тест, который публикует две истории через `handler()` в одну таблицу и проверяет код 201, связанную историю и тип её оценки. `FakeTable` проверяет типы так же, как сериализатор DynamoDB. Проверка: `python3 -m unittest discover tests -v` — 2 теста прошли.

# Что пригодилось из заметки

Пригодились объяснение различия между пустой и заполненной таблицей, указание на запрет `float` в DynamoDB и идея проверять вторую запись на заранее заполненной таблице. Совет переводить оценку в целый процент не использован: он менял бы существующий формат `score`; `Decimal` устраняет ошибку без такого изменения. Проверку на реальной таблице не проводили: задача ограничена текущей директорией и запрещает обращения к внешним сервисам.
